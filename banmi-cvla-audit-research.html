5 条核心批评（按严重程度）

🔴 批评 #1（致命 / License）

banmi-cvla 强制依赖 octanove-vocabulary-profile-c1c2-1.0.csv（C1/C2 词汇）= CC BY-SA 4.0 强 viral copyleft[20]。半米作为商业 K12 教育产品，整个 pipeline 输出会被 ShareAlike 拖入相同 license — 当前不可商用。

README "License: 工具代码 MIT / 数据 CC BY-SA 4.0 (Tono / 东京外国语大学)" 还把 license 主体写错（Tono 的 CEFR-J wordlist 实际是"研究 + 商业可用 需 cite"无具体 license[21]，CC BY-SA 4.0 是 Octanove 的）。

🔴 批评 #2（致命 / 算法误导）

calculate_atos() 自称 "ATOS 2-factor"，实际公式 0.3905 × ASL + 11.813 × ASW − 15.59 跟 Flesch-Kincaid Grade 公式 0.39 × ASL + 11.8 × ASW − 15.59 完全一致（除四舍五入精度差 0.0005×ASL + 0.013×ASW，实测两值差 ≤ 0.05）[22]。

报告输出的 main.atos 和 main.us_grade 用户看似两个独立指标，数学上是同一值。Renaissance ATOS 实际是 open standard 公开公式 + 3 因子（句长 / 字符长 / 词难度）[14]，README 写 "Renaissance 完整 3 因子版未公开" 也是错的。

🟠 批评 #3（严重 / 准度认知）

banmi-cvla 用 FK Grade 作 us_grade 主指标 + derive_lexile 也是 FK 派生 — 但 AMontgomerie 2021 在 1500 文本 6 档 CEFR 上实测 Flesch-Kincaid Grade 仅 34.1% 准确率 / Flesch Reading Ease 仅 12.7%（低于随机 16.7%！）[23]。

banmi-cvla 把这俩当主输出 + 1948 年的旧公式（Dale-Chall 1948 / FRE 1948 / Spache 1953）都没标"古董公式仅做 cross-check"[24]。

🟠 批评 #4（严重 / 性能天花板）

banmi-cvla 复刻 CVLA 3 论文 = 2024 baseline 准度 65.7% exact / 99% adjacent[25]。

2025 SOTA 已经是 EvalYaks LLM 微调 96% / Random Forest + 1181 expert texts 62.6% 6-level + 82.6% 3-level / GPT-4 Turbo r=0.76 with human / Ace-CEFR macro-F1 0.80+[26][27][28]。banmi-cvla 目前等价 2-3 年前的方法。

🟡 批评 #5（中等 / 工程缺陷）

analyze() 阈值 word_count < 10 才报错 — 但业界普遍要求 ≥ 100 words 才统计有效，SMOG 要 30 句[29]。10-99 词输入 banmi-cvla 静默给结果但不可靠。

同时 compute_confidence 的"7 公式 σ<1.0 = high"机制 — 7 个公式共享 <35% 准度底，离散度低 ≠ accuracy 高，是"假置信度"。

1.1 结论一句话

banmi-cvla 是 2024 baseline 的"忠实复刻 + textstat 拼盘"，作为 banmi 内部"先有个能跑的"工具 OK，但不应公开 + 不应商用 + 不应当作权威输出给学生家长看。当前状态：

  • ✅ 能用：CVLA 3 复刻论文部分 90% 对得上（自检 5 档全过，max diff 0.10）
  • ⚠️ 有 caveat 但用户看不到：FK 准度 34% / FRE 12.7% / Lexile 派生误差 ±60L 真实数
  • 🔴 致命问题：Octanove CC BY-SA 4.0 license 阻断商用 / ATOS 实为 FK 改名
  • 🚀 升级路径清晰：SetFit + CLEAR 微调几乎免费 / weighted ensemble 工程简单 / LLM 校验已可商用

02banmi-cvla 源码精读 · 当前方案画像▼

整体 670 行 Python (cvla.py 490 + cli.py 180 + selftest.py 60)。依赖：spacy en_core_web_sm + textstat + wordfreq。

2.1 算法流程图（按 cvla.py 真实代码路径）

analyze(text)
  ├── word_count < 10 → 报错（阈值过低，业界 100 词 ⚠️）
  ├── compute_cvla_metrics(text)            # Part 1: CVLA 3 算法
  │     ├── _nlp() = spaCy en_core_web_sm
  │     ├── content = [NOUN, VERB, ADJ, ADV]
  │     ├── F1 AvrDiff      = mean(CEFR_VAL[lemma]) 实词 1-6
  │     ├── F2 BperA        = (B1+B2+C1+C2 count) / (A1+A2 count)
  │     ├── F3 CVV1         = types / sqrt(2 * tokens)   ⚠️ 真 Guiraud 是 V/√N
  │     ├── F4 AvrFreqRank  = 1500 - 200 × zipf         ⚠️ wordfreq 字幕偏倚
  │     ├── F5 ARI          = textstat.automated_readability_index
  │     ├── F6 VperSent     = VERB count / sent count
  │     ├── F7 POStypes     = unique POS tags
  │     └── F8 LenNP        = mean noun_chunk length    ⚠️ sm 模型 POS 96%
  ├── to_cefr_score(m)                       # 8 个 regression equations 抄论文 §2
  │     ├── CVV1:        × 1.1059 − 1.208,   min 7
  │     ├── AvrDiff:     × 6.417  − 7.184,   min 7
  │     ├── BperA:       × 13.146 + 0.428,   min 7
  │     ├── AvrFreqRank: × 0.004  − 0.608,   min 7
  │     ├── POStypes:    × 1.768  − 12.006,  min 7
  │     ├── VperSent:    × 2.203  − 2.486,   min 7
  │     ├── ARI:         × 0.607  − 1.632,   min 7
  │     └── LenNP:       × 2.629  − 6.697,   min 7
  ├── aggregate(scores)                      # 去 min/max 取剩 6 个 mean
  ├── to_levels(score)                       # CEFR 6 / CEFR-J 12 cutoff (论文 Table 2)
  ├── formulas = {
  │     atos,            # calculate_atos() ⚠️ 实为 FK Grade（见 §8.2）
  │     flesch_kincaid,  # textstat.flesch_kincaid_grade
  │     flesch_ease,     # textstat.flesch_reading_ease ⚠️ 准度 12.7%
  │     gunning_fog, smog, coleman_liau, ari, linsear_write,
  │     dale_chall,      # 1995 修订版？textstat 文档没明说
  │     spache,          # 1953 古董
  │     mcalpine_eflaw,  # 1990s "not scientifically tested" ⚠️
  │     text_standard,
  │   }
  ├── derive_lexile()    = 100 * FK + 200, clip[-200, 1700]  ⚠️ 来源不明
  ├── compute_cefr_coverage()                # CEFR-J 词汇 7 档比例
  ├── compute_confidence()                   # 7 grade-formula std → high/med/low
  └── grade_context()                        # US/CN/ESL 三国对照（经验，无引用）

3.3 ML 方法的准度提升 — 已 doubled

同一个 AMontgomerie 数据集，ML / DL 方法准度[23]：

  • XGBoost: 70.9% — 用 textstat 特征 + spaCy POS + mean parse tree depth
  • DeBERTa-base: 70.2% — 直接 fine-tune transformer
  • BERT-base: 68.6%
  • Random Forest: 68.2%
  • Logistic Regression / SVC: 67.9%

关键发现：XGBoost 用同样 textstat 特征做 baseline 比单个公式高 1 倍 — 这就是 banmi-cvla可以做却没做的事（把 12 公式 + 8 CVLA metrics 作为 features 进 XGBoost）。

5.2 关键 critic：ATOS 实为 FK 的数学证明

CRITIC — Tier 2 致命
calculate_atos() 跟 Flesch-Kincaid Grade 数学等价
cvla.py L222: atos = (asl * 0.3905) + (asw * 11.813) - 15.59
FK Grade 标准公式: 0.39 × ASL + 11.8 × ASW − 15.59[22]

差异：(0.3905-0.39)×ASL + (11.813-11.8)×ASW = 0.0005×ASL + 0.013×ASW。
对 ASL=20 / ASW=1.5：差 = 0.01 + 0.0195 = 0.03 grade（可忽略）。

结论：用户看 banmi-cvla 报告 main.atos = 5.8 和 main.us_grade = 5.6，误以为两个独立指标互证，实际两个都是 FK Grade（atos 改了第 4-5 位小数后的 FK，us_grade 是 textstat.flesch_kincaid_grade 直出）。这是误导性输出。

历史原因：banmi-cvla 早期 ATOS 公式可能用了 "characters per word" 代替 "syllables per word"，cvla.py L210 注释明确说"AWL 单位是 syllables per word, 不是 characters per word ★ 之前 webresearch 给错了"。修正后的公式就是 FK Grade。

具体改进：选一个 — (a) 完全删 calculate_atos()，统一用 FK Grade；(b) 用 Renaissance 真实 ATOS 公式（句长 + 字符长 + word grade level + book length 4 因子），cvla.py 重写 calculate_atos() ~50 行；(c) 用一个 word grade level lookup 表近似第 3 因子（中等工程量）。推荐 (a) — 诚实 + 工程量小 + 不损失信息（FK 已经在）。

5.3 关键 critic：Lexile 经验映射的真实误差

CRITIC — Tier 2
derive_lexile() 误差实测可能远超 README 标的 ±100L
cvla.py L233: lexile = int(round(100 * fk + 200)) + 标 ±100L range。

Lexile vs FK 相关 r=0.89 (强相关)[50]，但方差大：同一 FK Grade 可能对应 ±200L 的 Lexile 范围。

README "经验公式，误差 ±100L (业界经验)" — 没引来源。MetaMetrics 官方 Lexile-CEFR 白皮书[51]用 9 个 benchmark 测试（TOEFL/EIKEN/Aptis 共 34,477 学生）做 alignment，不是简单 FK 派生。

具体改进：
  • (1) 提升 caveat 标 "±150-200L 实测，不是 ±100L"
  • (2) 改用 Cathoven Catile 免费 50 credits API 做权威对标
  • (3) 长期建一个 1000 文本的"Lexile vs banmi-FK"散点图自动校准截距 + 斜率（用 sklearn LinearRegression 拟合）

CRITIC — Tier 2

Coh-Metrix 200+ 维 5 大因子[49]：word concreteness / syntactic simplicity / referential cohesion / causal cohesion / narrativity — 这些"句子之间的连贯性"是真正区分 B2 学术文本和 C1 学术文本的关键，banmi-cvla 8 CVLA features + 14 textstat formulas 全都是词级 / 句内级 surface 特征，没有跨句维度。

7.1 50 年综述：传统公式的 7 大根本性局限

Effortmark / Redish on Readability Formulas 综述[56]指出传统公式核心问题：

  1. 只测可数特征：长句 + 多音节 — 实际是"为了好算"不是"为了准"
  2. 无视文档设计：bullets / 空白 / 排版 — 公式都看不见
  3. 无视读者背景：先验知识 / 文化语境 — 公式假设 reader 是 blank slate
  4. 无视语义：抽象 vs 具象 / 隐喻 / 多义 — 公式不懂
  5. 无视 cohesion：句间连贯 / referential / causal — 见 §5.5
  6. 跨工具差异：同一段同一公式不同工具差 12.9 grade[57]
  7. 跟 comprehension 弱相关：跟"感知难度"相关，但跟实际理解 / retention 不相关

7.2 ESL-specific 公式：McAlpine EFLAW 的"自承未经科学验证"

CRITIC — Tier 4
EFLAW 作为 ESL 主指标的合理性存疑
cvla.py L319-327 把 EFLAW 直接转 CEFR 6 档（<15→A1, ≥43→C2），README "EFLAW 专为 ESL 学习者设计 (最贴合中国学生场景)"。但 EFLAW 官方页明确说 "Not scientifically tested. Use as approximate guideline."[58]

EFLAW = (words + miniwords)/sentences，反传统 readability 设计（强调"短词反而困难 — 因 ESL 学者搞不懂同形异义短词"）— 这个直觉有趣，但没有大规模 ESL 学习者数据验证。

banmi-cvla 把 EFLAW 跟 cefr_6（CVLA 算法）平起平坐放在 Tier 1 主指标里，users 看不出 EFLAW 是猜想性公式。

具体改进：(a) 把 EFLAW 从 Tier 1 移到 Tier 2（保留但降级）；(b) cli pretty 输出标 "EFLAW (实验性 ESL 估算)"；(c) confidence 计算时给 EFLAW 0.5 权重而非 1.0。

banmi-cvla 当前 aggregate() 用"去 min/max 取剩 6 个 mean" — 这是简化版 trimmed mean，不是 IRT。是否值得换 IRT？

反向判断：CVLA 论文官方就用"drop max/min average 6"，这是论文规定的聚合方式，换 IRT 就不是 CVLA 复刻了。结论：保持现状 ✅。如果做 banmi-cvla v2 是自己的算法（不复刻 CVLA），那时再考虑 IRT。

C6 · CVLA 3 + textstat 合集思路对不对？有没有更优雅的？

回答：思路对一半。

对的地方：

  • CVLA 3 是 2025 published 经过 108 文本验证（65.7% exact / 99% adjacent）的开源研究[25]，复刻它有可信度
  • textstat 14 公式给"多公式 cross-check"的逻辑合理（业界 consensus grade 做法[57]）
  • 把"主算法 (CVLA) + 辅助公式 (textstat) + 词汇覆盖 (CEFR-J)"分层是好的工程

不对的地方：

  • 🔴 缺一个 ML 兜底层：AMontgomerie 已经证明同样 textstat 特征喂 XGBoost 准度从 34% 翻倍到 71%[23] — banmi-cvla 算了 14 公式但只做线性组合（CVLA score / FK 派生 Lexile），没把所有特征喂 XGBoost
  • 🔴 没用现成 SOTA 模型：HuggingFace 有 dksysd/cefr-classifier (DeBERTa-v3-large 微调)[53] 和 agentlans/deberta-v3-xsmall-readability 直接可用 — 推理 200ms 给一个 5-10% 的准度提升
  • 🟠 FRE 不该进 all_formulas：12.7% 准度 < random，进了反而拖累 consensus

更优雅的设计（参考 #18 cheap-models）：

analyze(text, mode='fast'|'accurate'):
  features = compute_features(text)   # 8 CVLA + 14 textstat + cohesion + length

  if mode == 'fast':
    cvla_score = run_cvla_algorithm(features)
    return tier_output(cvla_score, features)

  elif mode == 'accurate':
    cvla_score = run_cvla_algorithm(features)
    ml_score   = xgboost_predict(features)     # NEW
    llm_score  = haiku_zero_shot_cefr(text)    # NEW (high-stakes)
    final = ensemble([cvla, ml, llm], weights=[0.4, 0.4, 0.2])
    confidence = pairwise_agreement(cvla, ml, llm)  # NEW
    return tier_output(final, features, confidence)

C7 · 去 min/max 取 6 平均的聚合策略业界用吗？weighted ensemble / IRT 更好？

回答：业界不用这个（这是 CVLA 论文独家做法），但保持现状是对的因为 banmi-cvla 是 CVLA 复刻。

详细解析：

  • "drop max/min, average 6" = trimmed mean 的一种 — 统计学上是 robust statistics 的标准做法（抗 outlier），但截断比例 25%（8 个里去 2 个）相对激进
  • 业界主流：(a) sklearn VotingRegressor weighted average[62]；(b) stacking — 用元 model 学组合规则；(c) IRT — 给每个 base model 估"能力参数"[59]
  • CVLA 论文 §2 选 trimmed mean 因为论文用的是 8 个 hand-crafted features，没有 base model 概念 — 不能 weighted ensemble 因为没"准度差异"概念

结论：

  • ✅ CVLA score 内部聚合保持 trimmed mean（这是复刻论文）
  • 🆕 新增 ensemble 层：在 CVLA score / XGBoost score / LLM score 之间用 weighted average — 因为这三是不同算法，差异有意义

C8 · ATOS 2-factor 简化够不够？

回答：完全不够，而且当前实现是错的。见 §5.2 详证。

核心问题再列一次：

  1. banmi calculate_atos() 数学上 = FK Grade（差异 <0.05）

C13 · "多公式离散度 → 置信度"机制业界做过吗？

回答：业界做过 consensus grade，但 banmi 当前实现有缺陷。

业界做法：

  • average of multiple formulas = "consensus grade" — 业界标准做法[57]
  • good agreement standard = 95% limit of agreement < 1 grade[68]
  • std 不等于 limit of agreement（前者是离散度，后者是 Bland-Altman 风格的 1.96×SD 区间）

banmi-cvla 当前实现问题：

CRITIC — C13

  • 这 7 公式都是 30-42% 准度的传统公式 — 7 个错的高度一致，不代表对 ✅
  • banmi 已经发现 atos = FK Grade 数学等价（§5.2）— 那 std 计算时这两个是同一个数，人为压低 std
  • ARI 跟 Coleman-Liau 也共享 characters-per-word 维度，高度相关
  • 真实独立公式可能只有 3-4 个，std 应该按"独立性加权"
具体改进：
  1. 删 atos 进 grade_vals 列表（因为 = FK）
  2. 加 LLM score 或 CVLA score 进 grade_vals（提供独立维度）
  3. 用 limit of agreement (1.96×σ) 而非 σ 本身做 threshold
  4. confidence label 加上具体数值"high (σ=0.8, 95% LOA ±1.57 grade, 5 个独立 metric)"让用户判断

15FAQ · 12 条 + References▼

Q1banmi-cvla 当前能用吗？+
能用 — 内部 dev / 给 banmi 自己用 OK，跟 CVLA 3 论文持平 65.7% accuracy。不能：(1) 商业产品（Octanove CC BY-SA 4.0 阻断）；(2) 给学生家长当权威成绩；(3) Tier 1 输出当 4 个独立指标看（ATOS / us_grade / Lexile 都是 FK 派生）。
Q2FK Grade 真的只有 34% 准度吗？那 banmi-cvla 怎么还在用？+
AMontgomerie 在 6 档 CEFR 上实测 FK 34.1%[23]。但 FK 是 "grade level" 不是 "CEFR" — 用 FK 算 US Grade（连续值）误差小 ±1-2 grade，转 CEFR 6 档时误差被放大。banmi-cvla 用 FK 作 us_grade 字段 OK，但派生 Lexile 误差累积更大。
Q3为什么 GPT-4 评 CEFR r=0.76 还说"不完美"？+
GPT-4 r=0.76 with human readability rating (CLEAR Corpus)[31] — 比传统公式碾压（FRE r 接近 0）。但 LLM 自己生成 CEFR 文本不稳（Uchida 2025 ChatGPT-4o 生成 vs spec 只 58% 匹配[32]）— 评估 ≠ 生成。LLM 当 second opinion 很强。
Q4SetFit 30 秒训练真能行？+
SetFit 在 8-shot 上 outperform GPT-3，full data fine-tune 通常达 75-80%。HuggingFace 官方教程上 NVIDIA V100 30 秒 $0.025[52]。banmi 实际操作建议用 Colab T4 (免费) 跑 CLEAR Corpus 5000 段，预计 1-3 小时（含数据预处理）。
Q5Octanove license 移除会失去多少功能？+
cvla.py 关键依赖 Octanove 的 = compute_cefr_coverage() 输出 C1/C2 覆盖比例 + F1 AvrDiff 中实词若是 C1/C2 词的难度分。移除后这些词会被标 'unknown'，对 A1-B2 文本基本无影响，对 C1/C2 文本会把 C 级词错算成 unknown（影响 ~5-15% 的 high-level 评估准度）。但商用前必须移。
Q6为什么不直接用 CVLA web 版？+
CVLA 官方 web (https://cvla.langedu.jp/) 限制：(a) 单文 10-1000 词；(b) 30 个 .txt × 10KB 批量上限；(c) 无 API；(d) 输出只 CEFR-J 不出 Lexile / ATOS / 词汇覆盖。banmi-cvla 解决 4 个：无限制 batch / CLI 批处理 / Python lib / 多指标输出。这是 banmi-cvla 真正的价值，不是算法。
Q7cefr_6 跟 us_grade 在 banmi sample 上 disagree 1 档说明什么？+
说明 CVLA 算法（用 8 维特征）跟 FK Grade（用 ASL + 音节）是两个独立判断，这是好事 — disagree 时应该降低 confidence 标志。当前 compute_confidence() 没考虑 cefr_6 vs us_grade 的一致性，只看 7 grade-formula 的 std。改进建议：加 cefr_6 ↔ us_grade 的 cross-check。
Q8CEFR-J 12 档为啥不再细分到 18 档（A1.1/A1.2/A1.3/A2.1/A2.2/A2.3...）？+
Tono CEFR-J 原设计就是 A1-B2 细分 (3+2+2+2)、C 不细分 — 因为 CEFR-J 的目标群体是日本 ESL 学生多在 A-B 区间，C 区分意义不大。banmi 是中国 K12 国际学校，IB DP / A-Level 学生集中在 B2-C1，需要细化 C1（见 §10 #8 改进建议）。
Q9improvements 10 个全做完准度能到多少？+
乐观估算：65% (CVLA baseline) + 5-10% (SetFit) + 3% (ensemble) + 2% (spaCy trf) + 5-10% (LLM verify) + 3-5% (cohesion features) = 83-95%。但这个数字依赖 ground truth 集质量。悲观估算：75-80% (因为各 component 不是独立加和，有 ceiling effect)。务实预期：78-85% 是有理由的目标。
Q10selftest.py 5 档全过怎么还说 65%？+
selftest 测的是"喂论文 Table 1 公式答案，回带验证回归方程系数对不对" — 这只是 implementation correctness 测试，不是 prediction accuracy。65% 是 CVLA 3 论文在 108 段独立验证集上的 prediction accuracy，跟 selftest 是两件事。banmi-cvla 当前没真实 prediction accuracy 测试（这是改进 #9）。
Q11改进 10 条建议优先做哪 3 个？+
阿杰第一周做 #1 (删 ATOS / 改名) + #2 (100 词阈值) + #3 (移除 Octanove) — 三个加起来 5-10 小时，解锁商用 + 消除误导。第二周做 #4 (SetFit) + #5 (ensemble) — 准度 65→75%+。第三周做 #6 (LLM verify) — 给 high-stakes 文本兜底。三周后 banmi-cvla 可商用 SOTA 级别。
Q12这份审查会让阿杰焦虑吗？+
不会。阿杰明确要求"找问题不夸"，这份按要求批评。但 banmi-cvla当前作为内部 dev 工具是合格的，源码工程质量好（CLI 设计 / 4 tier 输出结构 / disclaimers 写到位 / selftest 有 / 模块化清晰），问题集中在算法新颖度 + license + 输出诚实度，都是可在 1-3 周修的。这不是"砸了从头来"级别的问题，是"打磨升级到 SOTA"级别的问题。
