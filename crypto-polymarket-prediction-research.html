1.3 5 条核心结论（每条独立 callout）

🟢 结论 #1 — 工程可行性：个人开发者 100% 能搭起来，全免费数据 + 成熟开源栈

Binance 现货/合约 WebSocket 免费推 orderbook / trades / liquidation 实时流[3]；Polymarket 的 Gamma API（市场元数据/价格）和 CLOB API（盘口/midpoint/spread）完全公开、无需 API key、无需钱包即可读[4]，还有 wss://ws-subscriptions-clob.polymarket.com/ws/market 实时盘口流[9]。Python 栈成熟：ccxt（41.9k star，108 交易所统一 API）[6] + py-clob-client（Polymarket 官方）[10] + LightGBM/XGBoost（推理 5–19ms）[5]。一台 $30/月 的东京 VPS（贴近 Binance AWS ap-northeast-1）就够 MVP 跑[11]。

🔵 结论 #2 — 问题定性：这是"二分类概率预测 + 市场微观结构 alpha"问题，不是时间序列回归

把它建模成预测币价数值（regression）是错的方向。正确建模是binary classification with calibrated probability（P(close_T ≥ close_0)），因为 (a) Polymarket 市场本身就是二元结果（涨/跌），(b) 你需要的是校准良好的概率而不是点估计 — 概率才能直接跟 Polymarket 价格比 edge。短线（5m/15m）之所以比长线可行，是因为5m/15m 内价格主要由订单流不平衡（OFI）驱动而非基本面 — Cont-Kukanov-Stoikov 经典论文证明 OFI 与短期价格变动近似线性关系[12]，这个信号在几十秒到几分钟尺度最强[13]。

🟣 结论 #3 — Feature 比模型重要 10 倍：微观结构 feature 是 5m/15m 唯一真 alpha 来源

2025 年 arxiv 微观结构研究的标题直接点破："Better Inputs Matter More Than Stacking Another Hidden Layer"（更好的输入比多堆一层网络更重要）[14]。对 5m/15m 窗口，真正有预测力的 feature 是盘口失衡（order book imbalance）/ 订单流失衡（OFI）/ 成交流不平衡 / 清算级联 / OI 变化 / funding rate / 大单（whale）。纯技术指标（RSI/MACD）在短线滞后且噪音大，单独用几乎无 alpha — RSI 在强趋势里会长时间钝化、MACD 在横盘里给假信号[15]。新闻 NLP 对 5m 几乎无用（消息已被秒级 priced in），第一版应该完全不做。

🟠 结论 #4 — "预测正确 ≠ 赚钱"：Polymarket 1.8% taker 费 + 滑点是最大杀手，edge 必须够大才扛得住

这是整个项目最容易被忽视、也最致命的一点。2025 年 Polymarket 改制后 crypto 市场 taker 费 1.80%[8]，意味着你每笔吃单交易先亏 1.8 个点。学术界铁律：扣掉交易成本后 Sharpe < 1 的策略直接丢弃[16]。要赚钱，你模型概率必须比市场持续偏离够大（edge > 费用 + 滑点 + 你的概率估计误差）。Kelly 公式告诉你下多少注，但 87% Polymarket 钱包亏钱的真正原因不是预测错，而是下注规模错（over-betting）[17]。用 fractional Kelly（1/4 Kelly）保命。

🔴 结论 #5 — 残酷现实：个人稳定盈利成功率极低，profit 被职业 bot 垄断，这是 adaptive adversarial 战场

Dune 数据：约 84% Polymarket 钱包净亏损，盈利者中大头被少数自动化 bot 拿走，散户整体亏 1.31 亿美元[1]；只有 0.033%（约 840 个地址）赚过 10 万美元以上[1]。Polymarket 5m BTC 市场用 Chainlink 高频预言机即时结算[18]，这种市场已经挤满了跟你用同样数据、同样模型、但延迟更低的 HFT bot[19]。金融市场是 adaptive adversarial system：你发现的任何 alpha 都会被对手交易掉、alpha decay 持续发生[20]。诚实判断：把这当成赚钱机器，大概率亏钱 + 浪费几个月；把这当成学微观结构 + 概率校准 + 生产级 ML 工程的项目，价值巨大。

02问题定义 — 这属于哪类 ML？为什么短线可行？▾

2.1 明确定性：Binary Classification + Calibrated Probability + Market Microstructure Alpha

很多人一上来就把"预测 BTC 价格"做成 time-series regression（LSTM 预测下一根 K 线收盘价），这对本任务是错的方向。我们要做的事，准确归类是这几类的交集：

候选类别是否本质理由
Binary Classification（二分类）✅ 主体Polymarket 市场结果是二元的（T 时刻 close ≥ 起始价 → "up"）[18]。我们要预测的就是 P(up)，天然二分类。
Probability Calibration（概率校准）✅ 核心我们不要 0/1 标签，要校准良好的概率。模型说 0.56 就得真的 56% 会涨，否则没法跟 Polymarket 价比 edge。这是和"普通分类"最大的区别。
Market Microstructure（市场微观结构）✅ alpha 来源5m/15m 的预测力几乎全部来自盘口/订单流微观结构，不是宏观或技术指标[14]。
Event Prediction（事件预测）🟡 部分每个 Polymarket 窗口是一个独立"事件"，但底层信号是连续的微观结构流。
Time Series Regression（时序回归）🔴 不是预测精确价格数值既难又无用 — 你不需要知道 BTC 是 67,432 还是 67,438，只需要知道涨跌方向的概率。
Reinforcement Learning（强化学习）🔴 第一版不用RL 在交易里 sample efficiency 差、sim-to-real gap 大、绝大多数仍停留在仿真阶段[21]。属于高级方向（第 15 章），不是 MVP。

一句话定性：这是一个「基于市场微观结构特征的、校准良好的二分类概率预测」问题，下游接一个概率套利（probability arbitrage）决策层跟 Polymarket 价格比 edge。XGBoost / LightGBM 对这类结构化表格特征 + 需要概率输出（predict_proba）的任务是最佳工具之一，且推理快、好解释、不需 GPU。

2.2 为什么短线（5m/15m）比长线（天/周）可行？

这是反直觉的关键点：越短的窗口，越有可预测的结构性信号。理由：

  • 信噪比反转：长线（天/周）由宏观、情绪、突发新闻主导，这些本质不可预测（接近随机游走）；短线（秒/分）由订单流动力学主导，而订单流有可测量的惯性和失衡。
  • 微观结构信号有物理因果：Cont-Kukanov-Stoikov 证明 OFI 和短期价格变动是近似线性关系（斜率与市场深度成反比）[12]。买盘挂单远多于卖盘 → 价格大概率往上走几个 tick，这不是玄学，是供需的直接表现。这个关系在几十秒到几分钟内最强[13]。
  • 清算级联的可观测性：5–15% 的剧烈短线波动往往是清算级联（多头被强平→砸盘→更多强平）[22]。funding rate > 0.05%/小时 是清算级联的早期预警[22]。这些是可以提前几分钟从衍生品数据看到的。
  • 均值回归（mean reversion）：短线尺度上，过度的盘口失衡常常会回补，VAMP（成交量调整中间价）对短期方向预测优于普通中间价[13]。

⚠️ 但别被"可行"骗了：可行 ≠ 容易赚。短线信号衰减极快（几十秒），意味着你需要极低延迟才抓得住；而 Polymarket 5m 市场恰恰是 HFT bot 密度最高的地方[19]。对个人开发者，15m / 1h 窗口比 5m 更现实（信号衰减慢一点，对延迟容忍度高）。详见第 14、16 章。

2.3 标签（label）怎么定义？这步比选模型重要

label 设计直接决定你和 Polymarket 对齐与否：

  • 对齐 Polymarket 定义：Polymarket "BTC Up/Down" 的 up = 窗口结束价 ≥ 起始价[18]。你的 label 必须完全一致（用同一个起始时间戳、同一个价格源 — Polymarket 用 Chainlink 喂价[18]，你最好也对齐到接近的指数价而不是单一交易所成交价）。
  • 三分类 vs 二分类：有研究做 Down/Sideway/Up 三分类[23]，但 Polymarket 是严格二元（平局算 up），所以二分类更对齐。
  • label 的 timestamp 对齐是 data leakage 高发区：feature 必须只用窗口开始之前的数据，label 用窗口结束的结果。差一秒就泄漏。详见第 10 章。

04数据源 B — Polymarket（Gamma/CLOB API + 市场结构详解）★▾

4.1 Polymarket 市场结构 — 必须先搞懂它怎么运作

Polymarket 不是 AMM（自动做市），是 CLOB（中央限价订单簿） — 跟 NYSE/NASDAQ 一样，你和别的真实挂单者撮合[28]。关键机制：

  • 价格 = 隐含概率：每个结果（YES/NO）是一个 0–1 USDC 的 token，价格就是市场隐含概率。YES=0.20 → 市场认为 20% 概率发生[4]。YES + NO 价格理论上应 = 1.00。
  • off-chain 撮合 + on-chain 结算：订单走链下 operator 撮合（求速度），双方 EIP-712 签名后提交 CTF Exchange 合约原子结算（求安全）[28]。share 是 Gnosis Conditional Token Framework 的 ERC1155 token[28]。
  • 5 分钟 BTC 市场 + Chainlink 即时结算：Polymarket 上线了 5m / 15m / 1h BTC Up/Down 市场，用 Chainlink 高频预言机喂 BTC/USD 价格自动即时结算[18]。up = 区间结束价 ≥ 起始价[18]。这正是阿杰要套利的目标市场。

4.3 你需要从 Polymarket 抓哪些字段做 edge 比较？

  • YES/NO 价格（= 市场隐含概率）→ 跟你的 P(up) 直接比，这是 edge 的核心。
  • bid-ask spread → spread 越宽，你实际成交价越差，吃掉 edge。5m 这种短市场 spread 往往很宽。
  • orderbook imbalance（Polymarket 侧） → 注意：Polymarket 自己的盘口失衡也是信号，但流动性薄时噪音大。
  • liquidity / volume → 极其关键。学术研究发现 Polymarket 市场跨过 10 万美元成交量才开始变成可靠的定价机制，低于此严重错误定价[29]。5m BTC 市场单窗口流动性可能很薄 → 你的"edge"可能只是流动性不足的假象。
  • implied probability 一致性 → 同一事件多个市场（5m/15m/1h）之间、YES+NO 之和是否 = 1，本身就是套利信号（见第 11 章）。

4.4 Polymarket 错误定价的真实规模（套利空间存在但在收窄）

学术 + 链上数据给了硬证据：

  • 一份覆盖 Polymarket 的研究发现 41% 的分析市场存在单市场套利，中位错误定价是本应 = $1.00 的市场只加总到 $0.60[30]。
  • 2024-04 至 2025-04，套利者用 rebalancing / combinatorial 策略赚了约 4000 万美元，top trader 单人从 4049 笔交易赚 200 万美元（均 $496/笔）[30]。
  • 但一份 25 亿美元成交量的 2025 研究里，Polymarket 原始准确率 67.2%，低于 PredictIt 93.1% 和 Kalshi 78.4%[29] — 错误定价多 = 套利空间大，但也意味着噪音大、流动性差的市场居多。

⚠️ 注意时间维度：上述 4000 万套利利润主要是 2024 年零手续费时代的事。2025 年初 Polymarket 改成 taker 收费（crypto 1.8%）后[8]，很多原本能套的 edge 现在被费用吃掉了。这是 adaptive system 的典型表现 — 平台看到套利者赚钱就改规则。

7.2 VAMP — 一个被验证优于普通中间价的衍生特征

Volume-Adjusted Mid-Price（成交量调整中间价）在短期方向预测和大幅波动预测上优于普通中间价和成交量加权中间价[13]。计算上就是把盘口失衡信息融进中间价的偏移量。这是一个"几乎免费的 alpha"——值得作为核心 feature。

7.3 工程实现要点

# 伪代码：OFI 与盘口失衡（每个 tick 更新）
def order_book_imbalance(bids, asks, levels=5):
    bid_vol = sum(v for _, v in bids[:levels])
    ask_vol = sum(v for _, v in asks[:levels])
    return (bid_vol - ask_vol) / (bid_vol + ask_vol + 1e-9)

def ofi(prev_book, curr_book):
    # Cont-Kukanov-Stoikov: best bid/ask 价格与挂单量变化的净流
    e_bid = curr_book.bid_vol if curr_book.bid_px >= prev_book.bid_px else -prev_book.bid_vol
    e_ask = -curr_book.ask_vol if curr_book.ask_px <= prev_book.ask_px else prev_book.ask_vol
    return e_bid - e_ask  # 正 = 买压, 负 = 卖压

🔴 微观结构 feature 的两个致命坑：
(1) 隐藏单/冰山单：可见盘口失衡 ≠ 全部信息，做市商会藏单[13]。你看到的失衡可能是假象（诱多/诱空）。
(2) 信号衰减极快：OFI 信号在几十秒内最强[13]，等你算完、下完单，alpha 可能已经消失。这是为什么 5m 市场被低延迟 bot 主导 —— 个人开发者更现实的窗口是 15m/1h。

9.3 模型服务层：何时触发预测？

  • event-driven 优于定时：不要每秒/每分钟死板预测。在盘口/成交有显著变化时触发预测（事件驱动），既省算力又抓信号。XGBoost/LightGBM 推理 5–19ms[5]，对 5m/15m 窗口绰绰有余 —— 瓶颈不在推理速度，在特征计算 + 下单延迟。
  • XGBoost vs LightGBM 服务选型：超低延迟（<5ms）选 XGBoost（可走 ONNX）；训练快/大数据选 LightGBM[5]。对本任务两者都行，MVP 用 LightGBM（训练快 3–10×、省 30% 内存）[5]。

9.4 模型训练层：XGBoost 适合在线训练吗？

  • XGBoost 支持增量训练：在已有树基础上继续训新树[37]，不必从头重训，能应对金融时序的非平稳性[37]。
  • 但不是真正的 online learning：XGBoost 增量训练有局限（树结构固化）。更稳的做法是 rolling retraining（滚动重训） —— 用 walk-forward optimization，每隔固定周期（如每天/每几小时）用最新窗口数据重训整个模型[37]。FreqAI 内置 self-adaptive retraining，在独立线程重训、不阻塞推理[7]。
  • 推荐：offline 训好 baseline → 定期 rolling retrain（捕捉 regime 变化）→ 别追求秒级在线更新（过拟合风险 + 工程复杂度爆炸）。

10回测系统 + 数据泄漏陷阱（critic ⚠ 为什么金融 AI 容易"假赚钱"）▾

🔴 这章可能是全报告最值钱的一章。个人做量化失败的头号原因不是模型差，是回测骗了自己。López de Prado 的核心论断：大多数金融 ML 失败来自烂数据处理和烂测试，不是烂模型[33]。一个回测里赚 20% 的策略上线后可能变 -1%[38]。

10.1 四大"假赚钱"陷阱

🟠 陷阱 #1 — Lookahead Bias / Data Leakage（前视偏差/数据泄漏）

在决策时点用了当时还拿不到的未来信息，污染了回测[39]。短线场景超高发：(a) feature 用了窗口收盘后才知道的值；(b) label 是前视的（未来收益），标准 K-fold 会把未来信息泄进训练集[39]；(c) 用了未来才发布修订的数据。解法：López de Prado 的 Purged K-Fold Cross-Validation + Embargo —— purge 掉训练集里与测试集时间重叠/泄漏的样本，embargo 在训练集前再删一段缓冲[39]。

🟠 陷阱 #2 — Timestamp Alignment（时间戳错位）

feature 的时间戳和 label 的时间戳差一秒就泄漏。你必须保证：feature 只用窗口开始之前的数据，label = 窗口结束的真实结果，且和 Polymarket 用的 Chainlink 喂价/结算时点对齐[18]。交易所之间、你的本地时钟和服务器时钟之间都可能错位。

🟠 陷阱 #3 — Survivorship Bias（幸存者偏差）

数据集排除了退市/失败的资产，抬高回测收益[39]。crypto 里尤其严重 —— 你回测 BTC 当然活得好好的，但如果策略涉及山寨币，那些归零退市的币不在你的历史数据里，回测会系统性高估。本项目只做 BTC 风险小，但若扩到多币种务必小心。

🟠 陷阱 #4 — Overfitting / 回测过拟合

把策略调到完美贴合历史 = 失去泛化[38]。一个真实案例：2025 年某策略胜率掉 14 个百分点、Sortino 从 +12.26 崩到 -0.42[38]。feature 越多、调参越狠，过拟合越严重。解法：严格的 in-sample / walk-forward / out-of-sample 协议[40]、Combinatorial Purged CV、限制 feature 数量、用简单模型先建 baseline。

10.2 回测必须包含的真实成本（否则全是假的）

  • Polymarket taker 费：crypto 1.80%[8]（这一项就能让大部分散户 edge 归零）。maker 单（限价单）免费[8]。
  • 滑点 / spread：5m 市场流动性薄、spread 宽，你实际成交价 ≠ 中间价。
  • RL 研究里的教训：很多研究假设固定 10bps 成本、不随交易规模/波动率缩放，导致 agent 高频交易、回测收益虚高[21]。你的回测必须让成本随交易规模和流动性变化。

🔴 铁律：QuantStart 给的标准 —— 扣完真实交易成本后 Sharpe < 1 的策略直接丢弃[16]。无数策略扣费前 Sharpe 很高，扣费后变成低 Sharpe 低收益的垃圾[16]。你 paper trade 时一定要把 1.8% taker 费 + 滑点算进去，否则你看到的"edge"是幻觉。

10.3 推荐回测工具

开源里 Jesse 的"零前视偏差回测引擎"被誉为最诚实的开源回测[41]。freqtrade 也有完整回测 + hyperopt。但再好的引擎也防不住你自己制造的泄漏 —— 先理解第 10.1 的四个陷阱，再用工具。

11Polymarket Edge — EV / Kelly / Sharpe（为什么"预测正确"≠"赚钱"）★★▾

11.1 核心 framing：你赚的是"概率差"，不是"猜对涨跌"

假设你模型说 P(up)=0.56，Polymarket YES 价 = 0.47。你的名义 edge = 0.56 − 0.47 = 0.09（9 个点）。但这 9 个点要先扛过：

  • taker 费 1.8%（≈ 0.018 的成本）[8]
  • bid-ask spread（你买 YES 实际成交可能在 0.49 而非 0.47）
  • 你自己的概率估计误差（你的 0.56 真的准吗？校准不好的话 0.56 可能实际是 0.50）

真实 edge = 名义 edge − 费 − 滑点 − 估计误差。9 个点听起来很多，扣完可能只剩 2–3 个点甚至为负。

11.2 期望值（EV）公式

# 买 YES @ price m, 你的真实上涨概率 p
# 赢: 拿回 $1, 净赚 (1 - m); 输: 损失 m
EV_per_dollar = p * (1 - m) - (1 - p) * m - fee
             = p - m - fee          # 化简

# 例: p=0.56, m=0.47, fee=0.018
EV = 0.56 - 0.47 - 0.018 = 0.072    # 每 $1 期望赚 7.2 分 (扣费前 9 分)
# 但还没扣 spread/滑点/估计误差

EV > 0 才值得下注。注意 EV 对你的 p 估计极其敏感 —— p 估高 0.05 就可能把正 EV 变负 EV。

11.3 Kelly Criterion — 下多少注（87% 亏钱的真正原因在这）

Kelly 公式（1956 年 Bell Labs）算最大化长期资本增长率的最优下注比例[42]。预测市场版本：买 YES @ 价 m，净赔率 b = (1−m)/m[42]。

# Kelly fraction
b = (1 - m) / m          # 净赔率
f* = (b * p - (1 - p)) / b   # = p - (1-p)/b

# 例: m=0.47, p=0.56 → b = 0.53/0.47 = 1.128
f* = 0.56 - 0.44/1.128 = 0.56 - 0.39 = 0.17   # 满 Kelly 下 17%
# 实战用 1/4 Kelly → 只下 ~4%

🔴 关键洞察 — 亏钱不是因为预测错，是下注规模错。分析 Kalshi 2021-2025 所有交易发现：亏钱的大多数不是更频繁地猜错结果，而是错在下注多少[17]。87% Polymarket 钱包亏钱[17]，over-betting 是头号杀手。职业玩家只用满 Kelly 的 10–25%（fractional Kelly），对冲估计误差、降低回撤[42]。你必须用 1/4 Kelly 保命。

11.4 Sharpe ratio — 单笔 edge 微小，靠次数累积

单笔 EV 可能微到 +0.072%/笔，但叠 50 笔独立交易能把期望推到约 +3.6%[17]。这意味着：策略靠的是大量小 edge 的统计累积，不是单笔暴富。而要让这个累积成立，你需要 (a) edge 真的为正（最难）、(b) 交易彼此尽量独立、(c) 严格风控不让单笔大亏毁掉全部累积。扣费后 Sharpe < 1 直接放弃[16]。

11.5 套利的另一面：纯无风险套利 vs 概率 edge

  • 纯套利（risk-free）：当 YES + NO < 1（扣费后）时，同时买两边锁定无风险利润。41% 市场存在这种失衡[30]，但这类机会被 bot 秒抢、且改制收费后大幅减少。
  • 概率 edge（本项目）：你认为市场定价错了，单边下注。有风险（你可能才是错的那个）。这正是为什么"预测正确 ≠ 赚钱" —— 你是在赌你的模型比市场共识更准，而市场共识里包含了和你用同样数据的 bot。
🔗 深度子报告：本章只讲了 EV/Kelly 和套利的"概率"框架。想看每种 Polymarket 赚钱策略的真实收益数字 + 链上 wallet 案例 + 亏钱陷阱（套利/做市/信息优势 4 策略 / Théo $8200 万怎么赚的 / 做市 80-200% 年化但被单边市扫穿 / 0.51% 钱包才赚过 $1000），以及 DEX 网格能不能赚、AI+Crypto 6 条路真用 vs 噱头 → Polymarket / DEX / AI+Crypto 实操到底怎么真赚到钱 →

14真实世界难点（critic 泼冷水章 🔴 个人成功率真相）▾

🔴 本章存在的意义：不给虚假希望。前面讲了系统怎么搭、edge 怎么算 —— 那是"理论上"。这章讲"现实里为什么大概率赚不到钱"。读完这章你还想做，就为了学习和挑战去做，而不是为了赚钱。

14.1 八条会杀死你策略的现实

🔴 #1 — 84% 的人亏钱，profit 被 bot 垄断

Dune：约 84% Polymarket 钱包净亏，盈利大头被少数自动化 bot 拿走，散户整体亏 1.31 亿美元[1]。只有 0.033%（~840 地址）赚过 10 万美元以上[1]。WSJ 分析也称 70%+ 用户亏钱[44]。你要打败的不是"市场"，是已经在那里、比你延迟低、资金厚的职业 bot。

🔴 #2 — 交易成本吞掉 edge（改制后更狠）

Polymarket 2025 改制，crypto taker 费 1.80%[8]。这意味着你每次吃单先亏 1.8 个点 —— 大部分散户能算出来的 edge 还没这么大。2024 年套利者赚的 4000 万[30] 是零费时代的事，现在那个窗口大幅收窄了。平台看谁赚钱就改规则，这是 adaptive system。

🔴 #3 — 回测假赚钱（前面整章讲过）

data leakage / lookahead / 过拟合让你的回测收益是幻觉[38][39]。一个回测 20% 的策略上线变 -1% 是常态[38]。你 99% 会先经历"回测很美 → 实盘打脸"。

🔴 #4 — Regime change / 非平稳 / alpha decay

金融市场非平稳，单个 alpha 的有效性随时间剧烈变化[20]。你今天找到的信号，明天可能就失效（alpha decay）。市场是对抗性系统：参与者主动寻找并交易掉可预测的模式[20]。你的模型必须不断重训追 regime，但追得越紧越容易过拟合到噪音。

🔴 #5 — 延迟（你打不过 HFT）

微观结构信号几十秒内最强[13]，5m 市场是低延迟 bot 的主场[19]。你家宽到东京几十毫秒、特征计算几毫秒、Polymarket 撮合延迟 —— 等你下单，盘口失衡的 alpha 早被吃掉了。这是为什么个人更该做 15m/1h 而非 5m。

🔴 #6 — 流动性 + 滑点（小市场是陷阱）

Polymarket 市场过 10 万美元成交量才可靠定价，低于此严重错误定价[29]。5m BTC 单窗口流动性可能很薄 —— 你看到的"edge"可能只是没人挂单的假象，真要下注就把价格推走了（滑点），实际成交远差于你看到的价。

🔴 #7 — 新闻已 priced in + API 不稳定

NLP 的根本无力：能动价的消息在你抓到前已反映在价格里。加上交易所/Polymarket API 偶发宕机、WebSocket 断连、限频封 IP（429/418）[27] —— 实盘里这些"工程意外"会在最关键时刻坑你。

🔴 #8 — 有时 buy-and-hold 就赢了

有研究直接发现：简单 buy-and-hold 优于机器学习模型，预测模型还不能可靠用于算法交易[2]。短线 ML 能稳定超过 50% 随机基线，但幅度小[2] —— 这点小 edge 很容易被成本和执行误差抹平。你花几个月搭的系统，可能跑不赢"啥也不做拿着 BTC"。

14.2 诚实的成功率判断（无来源·基于行业体感的估算 ⚠️）

⚠️ 以下是估算/行业体感，非精确数据：个人开发者从零做这个系统，能稳定（连续 6+ 个月扣费后正收益）盈利的概率，我的诚实估计是个位数百分比（<5%）。而且这极少数成功者，往往是 (a) 有量化/工程背景、(b) 愿意做 15m/1h 而非硬刚 5m、(c) 找到了别人没在用的另类数据或更低延迟、(d) 极度严格的风控和概率校准。对大多数人，结果是：学到很多、亏一点钱（如果上真钱）、几个月后放弃。这和 84% 钱包亏钱的链上事实是一致的[1]。

19FAQ（12 条）▾

Q为什么用 XGBoost 而不是 LSTM / Transformer 预测币价？+
因为这不是"预测价格数值"任务，是"预测涨跌概率"的二分类任务。XGBoost/LightGBM 对结构化表格特征（微观结构 feature）最优、推理 5–19ms[5]、不用 GPU、好解释、predict_proba 直接给概率。LSTM 适合需要精确幅度的场景、Transformer（DeepLOB）需 GPU + 大数据 + 易过拟合[43]，都不适合个人 MVP。
Q"预测正确"和"赚钱"到底差在哪？+
你猜对涨跌方向 ≠ 赚钱。你赚的是"你的概率估计比市场（Polymarket 价格）更准"的那部分 edge，且要扣掉 1.8% taker 费[8] + 滑点 + 你自己的估计误差。名义 edge 9 个点，扣完可能只剩 2–3 点甚至为负。而且 87% 钱包亏钱的真正原因是 over-betting（下注规模错），不是预测错[17]。
Q为什么短线（5m）反而比长线（天/周）可预测？+
长线由宏观/情绪/新闻主导，接近随机游走、不可预测；短线由订单流动力学主导，OFI 与短期价格变动近似线性[12]，盘口失衡有可测量的物理因果。但短线信号几十秒就衰减[13]，对延迟要求高，5m 是 HFT 主场，个人更适合 15m/1h。
Q第一版为什么不做新闻/NLP？+
5m/15m 内能动价的消息在你 NLP pipeline 跑完前早被秒级 priced in 了。砍掉新闻 = 砍掉一整套 NLP + API 成本（X API 2026 改 pay-per-use[31]）+ 法律风险，且能聚焦验证最核心假设：微观结构模型 vs Polymarket 价到底有没有 edge。新闻是第二版的 regime 风险开关，不是短线方向信号。
Q哪个 feature 最重要？+
微观结构 feature 远胜技术指标。Top 3：OFI（订单流失衡，与价格近似线性[12]）、order book imbalance（盘口失衡）、trade flow imbalance（成交流不平衡）[26]。加上 liquidation/funding/OI 做衍生品信号[22]。RSI/MACD 只当 regime 上下文，单独几乎无 alpha[15]。
QMVP 要不要上 Kafka / TimescaleDB / ClickHouse？+
不要。个人单策略 MVP 用 asyncio + DuckDB/parquet 就够。Kafka/Redis/TimescaleDB 是给"已验证有 alpha、要 scale 多策略"的阶段[36]。过早上重型基础设施是用工程复杂度逃避"我有没有 edge"这个根本问题。
QXGBoost 能在线训练吗？+
能增量训练（在已有树上加新树）应对非平稳[37]，但不是真 online learning。更稳的是 walk-forward rolling retraining（定期用最新窗口重训整模型）[37]。FreqAI 内置 self-adaptive retraining，独立线程重训不阻塞推理[7]。别追求秒级在线更新（过拟合 + 复杂度爆炸）。
Q为什么金融 AI 容易"假赚钱"？+
回测里的 data leakage / lookahead bias / 过拟合 / 没扣真实成本，让收益是幻觉[39][38]。López de Prado：大多数金融 ML 失败来自烂数据和烂测试，不是烂模型[33]。解法：Purged K-Fold CV + Embargo + walk-forward OOS + 回测必须扣 1.8% 费和滑点[16]。
QPolymarket 数据要付费吗？要钱包吗？+
读数据完全免费、无需 API key、无需钱包 —— Gamma API（市场/价格）和 CLOB API（盘口/midpoint/spread）都公开[4]，还有免认证的 WebSocket 市场频道[9]。只有真要下单（用真钱 USDC）才需要 Polygon 钱包 + 签名。
QKelly 公式怎么用？为什么用 1/4 Kelly？+
买 YES @ 价 m，净赔率 b=(1−m)/m，满 Kelly f*=p−(1−p)/b[42]。但满 Kelly 假设你概率估计完美，现实里估计有误差，所以职业玩家只用 10–25%（fractional Kelly）对冲误差、降回撤[42]。over-betting 是 87% 钱包亏钱的头号原因[17]，1/4 Kelly 是保命底线。
Q个人做这个成功率到底多高？+
链上事实：约 84% Polymarket 钱包亏钱、profit 被少数 bot 垄断、0.033% 赚过 10 万美元以上[1]。⚠️估算：个人从零做这个系统能稳定（6+ 月扣费后正收益）盈利的概率，诚实估计 <5%。把它当学习项目（学微观结构 + 概率校准 + 生产级 ML）价值巨大；当赚钱机器大概率失望。
Q该从哪个 GitHub repo 开始？+
fork freqtrade（25k+ star，自带 FreqAI 跑 XGBoost/LightGBM[7]）当骨架 + 用 ccxt（41.9k star[6]）接 Binance + 用 py-clob-client[10] 接 Polymarket。回测想要零前视偏差用 Jesse[41]。先 paper trade 4 周看扣费后 edge，再决定要不要上真钱。
