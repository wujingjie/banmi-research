Cursor vs Claude Code：不是谁更强，是自主度与交互范式不同

📅 2026-05-29 🔍 无忌 Deep Research · 3 路并行 🎚️ 自主度光谱，不是二选一 🧠 核心议题：工具会不会让人变笨 🇨🇳 含国内可用性
一句话：到 2026 年 5 月，Cursor 和 Claude Code 的本质差异不是「谁更聪明」——两者可跑同一底层模型，Cursor 自研 Composer 2.5 在 SWE-bench Multilingual 拿 79.8% 已基本追平 Claude Opus 4.7 的 80.5%（成本仅 1/10）[2]。真正的差异是交互范式与自主度：Cursor 是 IDE-first（你开车、逐行看 diff、line-level 接受/拒绝、时刻盯代码，天然练判断力）；Claude Code 是 agent-first（你描述目标、AI 驱动、跑完一批再回审，省力但易脱离理解）[1]。这是光谱不是二元——CC 有 Plan Mode、Cursor 有 Cloud Agent，两端都能往中间靠，是习惯而非工具决定你落在哪。对「工具会不会让人变笨」这一核心担忧，Anthropic 自家 RCT 给了最干净的答案：纯委托 AI 生成代码的人理解测验 <40%，而边用边问概念/要解释的人 65%+[3]。

01执行摘要：5 条最硬结论▼

3 路并行调研（Cursor 深挖 / Claude Code 深挖 / 横向对比+口碑+国内）收敛出的核心判断，每条独立成块，方便扫。

🎚️ 结论 1：本质差异是「自主度/控制权」，不是智力——别问谁更强，问这个任务你要不要保留理解 🟢 多源同口径

Builder.io 原话：「真正的哲学分歧在于控制权——Claude Code 是 agent-first，你描述目标、AI 驱动、你事后审查结果；Cursor 是 IDE-first」[1]。Emergent 把它叫「Execution AI（执行型）vs Editor AI（编辑型）」[1]。证据：Composer 2.5 已追平 Opus 4.7（成本 1/10）[2]，说明「谁更聪明」不再是选型关键变量。选型应按「这个任务我要不要保留理解」来分，而不是按「哪个模型强」。

🧠 结论 2：「工具会不会让人变笨」有实证答案，且是「取决于用法」 🟢 Anthropic 自家 RCT

Anthropic 2026-02 的 RCT（52 名工程师学陌生异步库 Trio）：AI 辅助组理解测验均分 50% vs 手写组 67%（低约 17%，debug 和「判断代码错在哪」差距最大），且 AI 组只快约 2 分钟、不显著[3]。但关键转折在同一研究内部：用 AI 问概念/要解释/边问边独立写的人拿 65%+，纯委托生成代码的人 <40%[4]。Addy Osmani 的「认知卸载 vs 认知投降」框架进一步说明：identical tools 因用法不同产生相反结果[5]。这直接坐实了阿杰的核心洞察——而且是数据，不是哲学。

✅ 结论 3：Cursor = 高频精修 + 时刻在环路；Claude Code = 重活 + 自主长任务 🟡 实务共识为主

实测对比：Claude Code 在 36 项测试中代码质量/正确性赢 67%、同任务 token 用量约 Cursor 的 1/5.5（188K vs 33K）、复杂多文件每美元 8.5 准确分 vs Cursor 6.2；但简单工具函数 Cursor 42 vs 31 性价比更高[6]。Cursor 的 Tab 多行补全被反复称为「上瘾点」，逐行 diff + 内置浏览器视觉调试是 solo dev 首选[9]。实务共识：很多 power user 两个都用，组合月费约 \$40[6]。

⚠️ 结论 4：国内是硬约束——两者直连均被封，Claude/GPT 模型对国内地区严格封禁 🟡 第三方教程为主

Anthropic 封中国 IP（影响 OAuth/API/CLI/VS Code 插件），2025/9 起封、2026/4 起部分用户须政府 ID+自拍验证[13]；Cursor 客户端国内可下可登，但调 AI 接口必须代理且不稳，Claude/GPT 模型对检测到的国内地区严格封禁（账号有钱也用不了），仅收 Visa/MC 双币卡[14]。绕过：VPN / 中转 / 火山引擎方舟（ByteDance，Anthropic 兼容端点，国内可直连，¥40-200/月）[15]。这只影响阿杰自己的开发链路，不影响半米产品架构。

💡 结论 5：对阿杰（独立全栈 + 做学习产品 + 怕工具让人变笨）——默认 Cursor 主力、CC 跑明确边界的重活 🟡 基于背景推断

你是单人维护，最怕的不是慢，是三个月后「看不懂自己项目」——而 CC 的批量自主执行正是这个风险的高发区[11]。所以建议：Cursor 当主力（盯 diff 练判断 + Tab 补全省力 + 视觉调前端），CC 留给明确边界的重活（跨多文件重构、写测试、基建脚本），且在 CC 里用 Plan Mode、控 PR 在 ~100 行以内、跑完逐段读 diff[5]。更深一层：Cursor 的「AI 提议、人确认」diff-review 范式本身就是半米学习产品防「认知投降」的好范本[5]。详见第 11 章。

一句话选型建议

【别站队】把它当光谱用，不是二选一。【主力 Cursor】高频小改、单文件、UI 微调、视觉调试、Tab 补全——心智不切换、性价比高、逼你盯 diff 练判断。【重活给 CC】跨 6-12 文件重构、基建、写测试、大代码库迁移——省 5.5x token、漏改更少，但务必用 Plan Mode 先看计划、逐段审 diff。【别迷信谁更聪明 / 用 AI 更快】Composer 2.5 已追平 Opus 4.7，模型不再是关键[2]；METR 实测资深开发者用 AI 反而慢 19% 却自感快 20%，主观体感严重不可靠[8]。

02本质区别：IDE 协作 vs 终端自主（不是智力，是范式）▼

先把最容易被带偏的问题摆正：这两个工具的差异不在模型聪明度，而在「你对每一步改动有多少控制权」。多个独立来源用几乎相同的话印证了这一点。

Builder.io：「The real philosophical split is about control. Claude Code is agent-first... you review the results. Cursor is IDE-first.」[1] Emergent：Execution AI（执行型）vs Editor AI（编辑型）[1]。两端各自的默认工作流，决定了你日常的「认知姿势」。

2.1 为什么「谁更聪明」是个伪命题

Cursor 自研 Composer 2.5（2026-05-18 发布）在 SWE-bench Multilingual 拿 79.8%，基本追平 Claude Opus 4.7 的 80.5%，token 价 \$0.50/\$2.50 每百万、约 Opus 4.7 的 1/10[2]。CursorBench v3.1：Composer 2.5 63.2% > Opus 4.7 61.6%；Terminal-Bench 2.0：69.3% vs 69.4%[2]。⚠️ 这些 benchmark 多为 Cursor 官方/转述（CursorBench 供应商自评），需谨慎，但多个独立 benchmark 趋同显示已是同档 🟡。结论：模型不是选型关键变量，交互范式才是。

2.2 这是一条光谱，不是二元

← 人在环路 / 控制紧自主 / 放手多 →
Tab 补全打字即预测，按键确认（最高频微决策）
Cmd-K 内联改选中+提示，就地流式 diff，ESC/接受
Composer / CC Plan Mode多文件统一 diff 逐个 accept/reject
CC 默认 agent给目标→规划→执行→跑测试→回审
Cloud / Dynamic Workflows云端 VM / 数百 subagent 并行，开 PR

两端都能往中间靠：CC 有 Plan Mode（执行前人工批准）和可调自主度（从「每个动作都批准」到「分类器自动区分安全/危险」）[10]；Cursor 有 Background/Cloud Agent（云端 Ubuntu VM 跑、开 PR，最接近 CC 自主端，2026-02 起带 Computer Use 能开 localhost 点 UI 验证）[20]。所以——是习惯而非工具决定你落在光谱哪一端。这正是第 6 章 trade-off 的根基。

⚠️ 旧二分法已失效：不要再说「终端 vs IDE」。2026 年 Claude Code 已覆盖 CLI / VS Code 官方插件 / 桌面 App / 浏览器版 IDE（claude.ai/code）多端，不再是纯终端工具[16]；Cursor 3.0（2026-04-02）也把重心从编辑器转向 agent[17]。真正的差异始终是自主度。

03Cursor 全貌（IDE-first，人在环路）▼

3.1 功能光谱：从「几乎不放手」到「半放手」

层层递进：Tab 补全（你打字它预测、按键确认）→ Cmd-K 内联改（选中代码+提示，diff 就地流式出现，ESC 或接受）→ Composer/Agent 多文件（跑工具改多文件，但给你统一 diff 逐个 accept/reject，自动建 checkpoint 可回滚）→ Background/Cloud Agent（云端 VM 跑、开 PR，最接近 CC 自主模式）[16b]。Composer 把改动就地流式呈现在你正看的代码里，让你停在同一心智框架；Agent 模式用 LSP go-to-definition 定位引用后给干净统一 diff，支持排队后续指令、可暂停问澄清[18]。

3.2 Tab 补全：日常黏性核心

用专用模型，并从你的 accept/reject 行为学习。官方称比旧版单行自动补全接受率高约 28%、建议数少约 21%；预测依据=当前文件+打开的 tab+最近编辑+项目 rules[21]。社区反复称之为「上瘾点」——能写出你还没想到的 5-10 行[9]。这是最高频的人在环路微决策。

3.3 @ 上下文 + Rules：人主动喂上下文、定规矩

@Files/@Code/@Docs（可爬第三方文档）/@Codebase（触发整库语义搜索）+ .cursorrules/.cursor/rules（放项目根目录给 AI 常驻指令，对 Chat 和 Cmd-K 都生效）[19]。最佳实践是用 @ 显式给上下文而非靠对话历史猜——这本身就是「人在做判断」的体现，是人在环路范式的一部分[19]。

3.4 2026 版本与定价

版本：3.0(2026-04-02，新界面+Agents Window 可并行跑多 agent+Design Mode 浏览器内标注 UI)、3.4(05-13，全屏 tab+紧凑响应)、3.5(05-19~20，Jira 集成+Cloud Agents+共享 Canvas+/loop)[17]。定价：Free(Hobby，限量 Tab+Agent，无需信用卡) / Pro \$20/mo(年付 \$16，\$20 月度额度，Tab 无限、Auto 无限) / Pro+ \$60(3x) / Ultra \$200(20x) / Teams \$40/seat[22]。2025-06 起付费档含等于档位价的月度额度池，Auto 模式不耗额度，手动选前沿模型才扣[22]。

✅ 强项

  • Tab 补全业界最强 [21]
  • 整库语义索引理解 [16b]
  • VSCode 习惯/扩展/主题零迁移 [16b]
  • 高频小改每美元 42 准确分 vs CC 31 [6]
  • HITL diff review 让你保持判断 [16b]

⛔ 短板

  • 5000+ 行大文件/monorepo 卡顿 [16b]
  • AI 输出不稳需逐行盯（曾漏 async 调 sync 静默 bug）[23]
  • UI 杂乱、Cmd-K 快捷键冲突 [16b]

04Claude Code 全貌（agent-first，目标导向自主）▼

Claude Code 是 Anthropic 的「agent-first」编码工具：你描述目标 → AI 自主规划、多步执行（读写文件、跑命令、跑测试、调 MCP 工具）→ 你审结果[16]。它有 Plan Mode 和可调自主度，也支持 subagents / 动态工作流并行。

4.1 自主能力栈

Subagent：各自独立上下文窗口/系统提示/工具权限，主 agent 负责规划与整合，把有界子任务（代码审查/跑测试/前端 QA/安全检查）派出去，可路由到更便宜模型（如 Haiku）控成本[24]。Hooks：在生命周期/工具事件上确定性触发 shell/HTTP/LLM，做强制规则——提交前跑测试、拦危险命令、编辑后跑 formatter、要求分支名带 issue ID[25]。MCP / Skills / Plugins：MCP 接外部系统（GitHub/Slack/DB/Notion），Skills 封装长流程，Plugin 把以上打包分发[26]。一句话：subagent 决定谁干活，MCP 决定能碰什么。

4.2 2026-05-28 Opus 4.8 + Dynamic Workflows（研究预览）

数百 subagent 并行（动态工作流单次最多 1000 subagents、16 并发），可从 kickoff 到 merge 跑完数十万行代码库级迁移，以现有测试套件为验收标准[7]。Opus 4.8 同价同 1M 上下文，SWE-bench Verified 88.6%、SWE-bench Pro 69.2%，比 4.7 少约 4 倍「让自写代码缺陷蒙混过关」，fast mode 快约 2.5 倍且便宜 3 倍[7]。这是自主度推到极致的代表——也意味着更要主动设防护栏。 🟡 研究预览，实际门槛/并发上限真实数字未确认

4.3 人审/介入机制：这条范式的安全阀

Permission modes：plan（只读）/ accept-edits（自动接受编辑）/ bypass（全跳过，--dangerously-skip-permissions）[27]。2026 新增 Auto Mode：用 Sonnet 4.6 分类器在动作执行前判定，两层防御（输入层扫 prompt injection，输出层 transcript 分类器逐动作判 block/allow），拦 overeager/honest mistake/injection/scope creep 四类；3 次连续或 20 次累计拒绝就升级给人[27]。实测假阳性 0.4%，但只抓到 83% 真危险动作——故仍需人主动监督[27]。

4.4 定价与 token 效率

订阅：Pro \$20/月（含 CC，约每 5 小时 45 条提示+周上限）/ Max 5x \$100/月（多数全天开发不再被限）/ Max 20x \$200/月（约 22 万 token/5 小时窗口+每周封顶，idle 不计）[12]。API 按量：Opus 4.8 \$5/\$25 每百万输入/输出、Sonnet 4.6 \$3/\$15、Haiku 4.5 \$1/\$5[12]。关键效率优势：同任务 token 用量约 Cursor 的 1/5.5（188K vs 33K 实测案例）[6]。VS Code 插件需 1.98.0+[16]。

✅ 强项

  • 自主多步执行、大规模重构/迁移 [6]
  • 代码库探索、复杂调试、测试生成与执行 [6]
  • 1M 上下文，monorepo 按需读文件更稳 [6]
  • subagent 并行编排、token 效率高 [6]
  • 36 项测试代码质量/正确性赢 67% [6]

⛔ 短板

  • 无逐行 line-level 接受/拒绝，批量执行后回审，最易触发「看不懂自己项目」[11]
  • 国内官方封禁，需 VPN/中转有封号风险 [13]
  • 高自主度易让人脱离代码理解 [3]
  • Max 个人档 \$100-200 比 Cursor Pro+ \$60 贵 [12]
  • 团队版贵（10人 \$1250/mo vs Cursor \$400）[11]

06⭐ 自主度 ↔ 思考力 trade-off（核心章）▼

这是整份报告的核心。把上面的范式差异落到阿杰最关心的问题：用这些工具，会不会让人变笨？答案有研究背书，且是「取决于用法」——而工具的默认值会把你推向某一端。

🧠 一句话：工具给默认值，习惯决定结果

Cursor 默认让你盯 diff（认知投入高，被动练判断），CC 默认让你放手跑（认知投入低，省力）。但两者用法都可调——CC 用 Plan Mode 就能逼自己看计划，Cursor 开 Cloud Agent 也能放手。所以会不会变笨，不取决于装哪个，取决于你把它放在光谱哪一端用[4]。

6.1 实证：同一工具，习惯决定理解力差一倍

Anthropic RCT（2026-02，52 名工程师学陌生异步库 Trio）：AI 辅助组理解测验均分 50% vs 手写组 67%（低约 17%，debug 和「判断代码错在哪」差距最大），AI 组只快约 2 分钟且不显著[3]。同一研究的关键分化：用 AI 问概念/要解释/边问边独立写的人拿 65%+，纯委托生成代码的人 <40%[4]。结论：寻求解释保留学习，外包实现削弱学习。⚠️ 样本是初级工程师学陌生库，对资深开发者做熟悉领域是否同样退化未覆盖，外推需谨慎 🟡。

6.2 框架：认知卸载 vs 认知投降（Addy Osmani）

认知卸载=委托 how、保留对 what 的判断；认知投降=停止形成独立观点、把 AI 输出当自己的[5]。研究显示 AI 可用时 73% 的时候人接受了错误答案且信心反升[5]。Osmani 给出五个保 judgment 的习惯：① 先写下预期再看答案；② 批判性读 diff（像审 junior 的代码）；③ 要 AI 反驳自己；④ 累了就停止委托；⑤ 追踪信心来源。结构性防护：要证据非「看起来好」、PR 控在 ~100 行（人能理解的单位）、新系统先让 AI 解释再生成[5]。

6.3 佐证：主观体感不可靠 + 技术债照来

METR RCT（2025-07）：资深开源开发者用 AI 反而慢 19%，但自我感觉快 20%（开发者预测会快 24%、专家预测快 38-39%，结果全反）[8]。技术债 arXiv 研究：自主 agent 提速但维护账单照来——静态分析告警约 +18%、认知复杂度约 +39%，且「把动手思考变成从输出里挑选」时组织会失去判断产出质量的能力[28]。这与「放手跑省力但易脱离理解」的范式判断一致 🟡。

6.4 映射到两个工具

🟢 Cursor：天然偏「练思考」端

  • Tab/Cmd-K/Composer 逼你持续看 diff、按键做判断，判断力在用进废退里被动锻炼 [16b]
  • 「时刻在环路」对要长期 own 代码的人是特性不是 bug [11]
  • 但警惕 review 疲劳：Composer 多文件大改时评测者亲历漏掉 async 调 sync 的静默 bug，放手越多越要刻意逐行看 [23]

🔴 Claude Code：偏「省力但易脱离」端

  • 批量执行后回审、无 line-level diff，最易触发「看不懂自己项目」[11]
  • Dynamic Workflows 本质是把「动手思考」换成「从输出里挑选」[3]
  • 但可设防：用 plan mode 看计划、逐个审 diff、让它解释而非直接接受；用 hooks 强制提交前跑测试当安全阀 [25]

🎯 核心 trade-off 一句话：你想练判断力的核心模块（产品核心逻辑、长期要维护的代码），用偏「人在环路」的姿势（Cursor 盯 diff，或 CC 的 plan mode + 逐个审 + 让它解释）；你不在乎理解的边角活（脚手架、批量重构、测试样板、一次性脚本），放手跑省力。选型按「这个任务我要不要保留理解」来分，而不是按「哪个工具强」。

07实测与社区口碑▼

把口碑分成「实测数据」和「观点共识」两层看——前者可信度更高，后者要警惕主观偏差。

7.1 实测数据（可信度较高）

独立评测（36 项测试）：Claude Code 代码质量/正确性/完整性赢 67%，相同任务省 5.5x token（188K vs 33K），复杂多文件每美元 8.5 准确分 vs Cursor 6.2；但简单工具函数 Cursor 42 vs 31[6]。结论：CC 赢难题，Cursor 赢高频简单活，多数 power user 两个都用[6]。METR：资深开发者用 AI 反而慢 19% 却自感快 20%[8]。

7.2 观点共识（可信度中等，警惕主观）

典型工作流比喻：「Claude Code 是搭房子的施工队，Cursor 是收尾的细木工」——早上用 CC 跨 6-12 文件搭脚手架，下午同一 repo 在 Cursor 里精调 UI/修边界/调文案[6]。solo dev 评价：「对多数 solo SaaS 开发者，Cursor 是更好的日常选择」——社区支持多、无限自动补全、VSCode 工作流成熟，Tab 是「上瘾点」[9]。⚠️ 这类来自观点型文章，war-story 细节偏少，证据强度中等 🟡。

⚠️ 口碑的可信度警告：① 未找到 2026 年针对 Cursor vs CC 的一手 Reddit/HN 原帖（搜索 API 对 reddit 返回空），社区口碑多为二手汇总 🟡；② 多数「3 个月实测」文章经核查偏观点/比喻，缺具体踩坑案例 🔴；③ METR 已证明「用 AI 更快」的体感严重不准——对任何「更快/更省力」的口碑都要打折，建议自己做小对照（同类任务记一次手动、一次 AI 的真实耗时）[8]。

🎯 对阿杰：你已有代理，自己用没问题。但 CC 在国内可用性比 Cursor 更脆弱（官方封 + ID 验证），可考虑「Cursor 做主力交互式编辑、CC 在能稳定连通时跑自主长任务」的混合法。这只影响你的开发链路，不影响半米产品架构——但若未来想把「AI 辅助编码/学习」做进给国内用户的产品里，Cursor/CC 这条路对终端用户门槛太高，得考虑 Trae CN / Cline+火山方舟这类国内直连方案或自建。

09⭐ 何时用 Cursor / 何时用 CC（决策树）▼

不要问「哪个更好」，按下面这棵树问「这个任务的性质是什么」。核心判据：任务范围 + 你要不要保留理解。

Q1：这个任务你以后要不要长期维护、要不要真懂它？
要懂核心逻辑 / 长期 own 的代码 → 偏人在环路（Cursor 盯 diff，或 CC Plan Mode + 逐个审 + 让它解释）[5]
不在乎脚手架 / 一次性脚本 / 测试样板 → 放手跑省力，去 Q2 看交给谁
↓
Q2：任务范围有多大？
高频小单文件改 / UI 微调 / 单函数 / 补全 → Cursor（心智不切换、每美元 42 准确分、Tab 上瘾）[6]
复杂大跨 6-12 文件重构 / 基建 / 大库迁移 / 写测试 → Claude Code（省 5.5x token、漏改更少、monorepo 更稳）[6]
↓
Q3：你在国内、当下能稳定连通吗？
能按 Q1/Q2 选；CC 跑自主长任务务必 Plan Mode + PR ≤100 行 + 逐段审 diff [5]
不稳CC 可用性更脆弱（封 IP + ID 验证）→ 优先 Cursor，或走火山方舟/中转 [13]

✅ 一句话决策

要懂 + 高频小 → Cursor。不在乎懂 + 复杂大 → Claude Code。要懂 + 复杂大 → CC 但开 Plan Mode 把它当「会解释的 junior」逐段审。别让「哪个模型强」进入决策——Composer 2.5 已追平 Opus 4.7，模型不是变量[2]。

10两个都用的组合打法▼

实务共识：多数 power user 两个都装，按任务性质切换，组合月费约 \$40[6]。下面是一套可直接抄的工作流。

🔧 典型一天

上午（重活）：用 Claude Code 跨 6-12 文件搭脚手架 / 跑大重构 / 写测试套件——开 Plan Mode 先看计划再放行，跑完逐段读 diff。下午（精修）：同一 repo 切到 Cursor 精调 UI、修边界、调文案、视觉调试（内置浏览器）——靠 Tab 补全和逐行 diff 保持手感[6]。比喻：CC 是施工队，Cursor 是细木工[6]。

🛡️ 给「单人维护大产品」的护栏（防技术债 + 防变笨）

  • CC 里用 hooks 强制提交前跑测试——挡住高自主度带来的技术债（研究里认知复杂度 +39% 正是放手跑的代价）[25]
  • PR 控在 ~100 行（人能理解的单位），新系统先让 AI 解释再生成 [5]
  • 核心模块绝不纯委托——边问概念边写，把 AI 输出当 junior 的代码审 [4]
  • 不迷信体感——同类任务偶尔记一次手动 vs AI 的真实耗时，校准自己的判断 [8]

11对阿杰（独立全栈 + 做学习产品 + 保持思考）的建议▼

三条直接落到你身上的判断，结合你的三个标签：独立全栈、做 AI 学习产品（半米）、怕工具让人变笨。

1️⃣ 你的核心洞察被实证坐实了，而且证据很硬

Anthropic 自家 RCT：纯委托 AI 生成代码的人理解测验 <40%，而「边用边问概念/要解释」的人 65%+——同样的 AI，习惯决定你变笨还是变强[4]。这不是哲学，是数据。把这条放进半米的产品叙事里很有说服力：你做的是「学习产品」，恰恰可以把「认知投降」设计成产品要避免的反面。Osmani 的解法（先写下预期再看答案、把 AI 输出当 junior 的代码审、让 AI 反驳自己、新系统先让它解释再生成）几乎可以直接迁移成半米的「防变笨」学习机制设计[5]。

2️⃣ 默认 Cursor 当主力，CC 留给明确边界的重活

你是单人维护，最怕的不是慢，是三个月后「看不懂自己项目」——而 CC 的批量自主执行正是这个风险的高发区[11]。所以：Cursor 主力（盯 diff 练判断 + Tab 省力 + 视觉调前端，「时刻在环路」对要长期 own 代码的人是特性不是 bug）；CC 跑重活（跨多文件重构、写测试、基建脚本），且开 Plan Mode、控 PR ≤100 行、跑完逐段读 diff，用 hooks 当安全阀[5][25]。

3️⃣ 别迷信「谁更聪明」和「用 AI 更快」+ 把 diff-review 范式借进半米

Composer 2.5 已追平 Opus 4.7，模型不再是选型关键[2]；METR 实测资深开发者用 AI 反而慢 19% 却自感快 20%，你对「AI 提速」的体感很可能不准——建议自己做小对照[8]。更深一层：Cursor 的「AI 提议、人确认」diff-review 范式恰恰是个好范本——让 AI 做事但把「确认/拒绝/理解」这一步还给人。你的学习产品可以借鉴这种交互来防止学习者外包思考[5]。

⚠️ 国内提醒

你用户在国内，但你自己开发用这俩都得绕墙（Anthropic 封中国 IP，Cursor 限 Claude）[13][14]。若想稳定可看火山引擎方舟（Anthropic 兼容、国内直连、¥40-200/月）[15]。但这只影响你的开发链路，不影响半米产品架构。真要把 AI 编码/学习能力做进国内产品，得另选国内直连方案或自建。

12FAQ▼

Q到底哪个更强？+

问错了。两者可跑同一底层模型，Cursor 自研 Composer 2.5 已基本追平 Claude Opus 4.7（SWE-bench Multilingual 79.8% vs 80.5%，成本 1/10）[2]。真正差异是自主度/交互范式：Cursor 让你逐行看 diff（练判断），CC 让你给目标放手跑（省力）[1]。按「这个任务要不要保留理解」选，不按「哪个模型强」选。

Q用这些工具会不会让我变笨？+

取决于用法，有数据。Anthropic RCT：纯委托 AI 生成代码的人理解测验 <40%，边用边问概念/要解释的人 65%+[4]。核心模块边问边写、把 AI 输出当 junior 的代码审；边角活才放手[5]。⚠️ 该研究样本是初级工程师学陌生库，资深做熟悉领域是否同样退化未覆盖[3]。

Q我是独立全栈，只能选一个，选哪个？+

选 Cursor 当主力。单人维护最怕三个月后看不懂自己项目，Cursor「时刻在环路」对长期 own 代码是特性[11]。Tab 补全省力 + 逐行 diff 练判断 + 内置浏览器调前端，solo dev 公认日常首选[9]。

Q什么时候才该用 Claude Code？+

明确边界的重活：跨 6-12 文件重构、基建、写测试套件、大代码库迁移——CC 省 5.5x token、漏改更少、monorepo 更稳[6]。务必开 Plan Mode 先看计划、控 PR ≤100 行、跑完逐段审 diff，用 hooks 强制提交前跑测试当安全阀[5][25]。

Q两个都装会不会太贵/太乱？+

不会。两个入门档各 \$20，组合约 \$40/月，是很多 power user 的实际配置[6]。工作流清晰：CC 干重活（施工队），Cursor 做精修（细木工），按任务性质切换不冲突[6]。

Q我感觉用 AI 明显更快，这不好吗？+

体感很可能不准。METR RCT 实测资深开源开发者用 AI 反而慢 19%，但自我感觉快 20%，开发者和专家的预测全反[8]。建议自己做小对照：同类任务记一次手动、一次 AI 的真实耗时，再下结论。

Q在国内能用吗？+

都得绕墙。Anthropic 封中国 IP（2025/9 起、2026/4 起部分要 ID+自拍验证），Cursor 客户端可登但 Claude/GPT 模型对国内地区严格封禁、只收双币卡[13][14]。绕过：VPN / 火山引擎方舟（¥40-200/月，换豆包/DeepSeek）/ 中转[15]。CC 比 Cursor 更脆弱，国内优先 Cursor。

QCC 的 Dynamic Workflows / 数百 subagent 我用得上吗？+

大概率暂时用不上。它是 2026-05-28 随 Opus 4.8 发的研究预览，能从 kickoff 到 merge 跑数十万行代码库级迁移、单次最多 1000 subagents[7]，但实际门槛（是否限 Max/企业、并发上限真实数字）未确认 🟡。对单人项目，自主度越高越要主动设防护栏。

QCC 有没有 Cursor 那种逐行 accept/reject？+

未找到明确确认 CC 已加入 Cursor 式的 line-level diff 接受/拒绝 UI——目前证据是「批量执行后回审」为主，配 Plan Mode 在执行前批准 🔴 待确认[11]。这也是 CC 比 Cursor 更易脱离代码理解的结构原因。

Q这跟我做半米学习产品有什么关系？+

关系很大。Cursor 的「AI 提议、人确认」diff-review 范式是防「认知投降」的好范本——让 AI 做事但把确认/拒绝/理解还给人[5]。你的学习产品可以借鉴这种交互防止学习者外包思考；Osmani 的五个保 judgment 习惯也能直接迁移成产品机制[4]。
