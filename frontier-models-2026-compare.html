四大模型对比 2026：Claude Code / Codex / Gemini / Grok

📅 2026-05-29 🔍 无忌 Deep Research · L2 🧩 拆层对比 + 多模型互评 + 流程编排 📚 60+ 来源
一句话：2026 年中，编码 Agent 赛道是 Codex（速度王）vs Claude Code（质量王）两强争霸，Gemini 走"超长上下文 + Antigravity 平台"差异化，Grok Build 刚出生（5 月）架构野心大但跑分还差一截。多模型互评不是噱头——不同训练分布的模型有不同盲点，跨模型审查能补盲，但要警惕"流行性陷阱"。阿杰现有"Codex 跨模型审查"那步方向完全正确，可以系统化升级。

0130 秒结论▼

给阿杰一个能直接拿去用的浓缩版。每条结论都拆成独立块，方便扫。

✅ 结论 1：编码 Agent 是 Codex vs Claude Code 两强，其余追赶 🟢 多源

2026 年 5 月，SWE-bench Verified 上 GPT-5.5 (Codex 后端) 以 88.7% 排第一，Claude Opus 4.8 88.6% 紧贴[1][2]，Gemini 3.1 Pro 80.6%[7]，Grok Build 仅 70.8%[3]。但跑分 ≠ 体感：盲评里 Claude 写的代码 67% 的情况被评"更干净"[11]。

🆕 结论 2：Grok Build 是 5 月刚出的真·编码 Agent，正面打 Claude Code 🟢 多源

不是 Grok 3（那是旧的）。Grok Build 5 月推出早期 beta，是终端里的编码 Agent，主打 8 个并行子 Agent + 每个独立 git worktree + Arena Mode（多 Agent 竞赛择优），背后是专门的 grok-build-0.1 模型[4][5]。架构很潮，但跑分和成熟度都落后，属于"值得盯但还没成"。

🔭 结论 3：Gemini 走差异化——超长上下文 + Antigravity 平台 🟢 多源

Google 当前旗舰 Gemini 3.1 Pro（2026-02-19 预览）拿下 LMArena 第一，号称 10M token 上下文（行业最大）[22]。但它把宝押在 Antigravity agentic IDE/平台上，并且 Gemini CLI 将于 2026-06-18 关停、并入 Antigravity CLI[14]——这条直接影响阿杰的逍遥 bot。

🔁 结论 4：多模型互评有效，但要防"流行性陷阱" 🟢 多源（含论文）

不同 provider 的模型训练分布不同 → 盲点不重叠 → 互审能抓到自审漏掉的 bug[12]。研究显示迭代式共识集成（ICE）可把准确率提升最多 27%[29]。但单纯"投票取共识"会掉进流行性陷阱（多数模型一起错），按多样性择优能拿回 95% 的理论收益[30]。

⚠️ 结论 5：阿杰在国内，这四家全要梯子；国产是真备份 🟢 多源

Claude 2025-09 起封禁中国访问[26]，Gemini、Grok 也被墙[25]。而 DeepSeek V4 (81% SWE-bench)、GLM-5.1 (MIT 开源)、Qwen3.5 在 coding agent 场景已经能打，且便宜 5–30 倍[24]。

给阿杰的一句话编排建议

Claude Code 写 + 规划（无忌/三丰），Codex 跨模型审查（已有，强化它），Gemini 长上下文做"读全库/查资料"（逍遥，但要赶在 6/18 前迁到 Antigravity CLI）。这正好对上你现有的三 bot 分工，下面第 11、12 章给可落地方案。

02先拆层：这是两条不同的赛道▼

阿杰这个问题最关键的认知框架：四家不在同一层比。硬把它们排一个榜是错的。要先拆成两条赛道。

🛠️ 赛道 A：编码 Agent（在 CLI/IDE 里干活）

Claude Code（Anthropic） 和 Codex（OpenAI） 是这条线的两个原住民。比的是 agentic 能力：工具调用可靠性、长任务自主跑、多文件编辑、自我验证、审查能力、子 Agent 编排。Grok Build（xAI）和 Antigravity CLI / Jules（Google）是新近杀进这条赛道的挑战者。

🧠 赛道 B：基座大模型 + 自家产品线

Gemini（Google） 和 Grok（xAI） 更适合从"基座模型 + 生态 + coding 产品"角度看。Gemini 的本体能力（推理、多模态、超长上下文）很强，但它的 coding 落地靠 Gemini CLI → Antigravity；Grok 的本体（Grok 4.3）走"便宜的数字员工"路线，coding 落地靠刚出的 Grok Build。

为什么这么拆？因为 Anthropic 和 OpenAI 在 2025-2026 把战略重心明确压到了"编码 Agent 产品"上（Claude Code / Codex 是各自的拳头产品）；而 Google 和 xAI 的拳头还是基座模型本身，coding 工具是模型的"挂件"。看懂这个，下面所有对比都顺了。🟡 行业格局判断

04Claude Code 深析（无忌/三丰的本体）▼

这就是阿杰跑无忌、三丰用的那个工具。2026-05-28 刚升级到背后是 Opus 4.8。

🟧
Claude Code · Opus 4.8
claude-opus-4-8 · 2026-05-28
质量王

跑分：SWE-bench Verified 88.6%（从 4.7 的 87.6% 升），SWE-bench Pro 69.2%（从 64.3% 升，这项全场最高）[1][2]。

价格：$5 / $25 每百万 token（与 4.7 持平）；可选 Fast Mode 2.5 倍速 $10 / $50，比旧版 fast mode 便宜 3 倍[1]。

无忌/三丰现在底层就是 Opus 4.8。Pro 这项全场第一，意味着处理"真·复杂多文件 GitHub issue"它最稳。

4.1 这次升级的四个关键变化

🆕 1) Dynamic Workflows（动态工作流，研究预览）

这是 Opus 4.8 给 Claude Code 的重磅功能：Claude 自己写编排脚本，一次会话里拉起几十到几百个并行子 Agent（上限 16 并发 / 1000 总数），让它们从不同角度攻同一个问题，还会派"对抗 Agent"去试图反驳已有发现，迭代到答案收敛再汇报[10][31]。专为"几十万行级别的代码库迁移"设计。需要 Claude Code v2.1.154+，Max/Team/Enterprise 可用。

💡 对阿杰的意义：这等于 Anthropic 把"多 Agent 互相对抗补盲"这个理念内置进单个模型了。你现有的"Codex 跨模型审查"是跨厂商补盲（更强），而 Dynamic Workflows 是同厂商内部对抗（弱一些但零成本）。两者不冲突，可叠加——见第 10 章。

🆕 2) 诚实度大幅提升（这条对"审查"特别重要）

Opus 4.8 比 4.7 少 4 倍"放任自己写的代码缺陷不吭声"，比 Sonnet 4.6 少 17 倍"对 agentic 代码做不诚实总结"[1]。换句话说，让 Claude 审自己的代码，它现在更愿意承认问题了——但仍不如让别的模型审（盲点同源）。

3) Effort / Fast Mode 控制

新增 effort 模式控制 + 可选 2.5 倍速 fast mode，让你在"想更快"和"想更深"之间切换[31]。

4) Messages API 任务中途系统消息

可以在长任务跑到一半时插系统消息，调整 Agent 行为[1]。

4.2 Claude Code 的扩展四件套（阿杰已经在用）

Claude Code 的护城河其实是这套扩展机制，阿杰的 skill 体系正建在上面：

  • Skills：把反复粘的 playbook 打包成可调命令，按需加载、不占常驻 context——这正是阿杰那一堆 /research、/plan、/笔记 skill 的底层[13]。
  • Subagents：独立 context 窗口、独立工具列表，并行干活、隔离脏输出（搜索/日志）只回summary[13]。
  • Hooks：事件触发的确定性脚本（PreToolUse 等），不会幻觉，适合做安全护栏（拦危险 bash、扫密钥）[13]。
  • MCP：接外部工具/数据（阿杰的 Roam、Discord、Gmail 全是 MCP）。

⚠️ 最大短板：rate limit。社区共识是 Claude Code 代码质量更好，但用量限制来得太快，重度用户一天能被打断好几次，所以很多人才转去 Codex 当日常主力[11]。这是"质量好但不够耐用"的核心痛点。

05OpenAI Codex 深析（阿杰的"跨模型审查"那一步）▼

这是阿杰工作流里 codex exec --full-auto 审 git diff 那一步背后的工具。2026 年它进步飞快。

⬛
OpenAI Codex · GPT-5.5
CLI v0.135.0 · 2026-05-28
速度王

跑分：GPT-5.5 在 SWE-bench Verified 88.7%（全场第一）、Terminal-Bench 2.0 82.7%（SOTA）[1][6]。社区实测处理"高量、样板、迭代式编辑"比 Claude Code 约快 2.5 倍[9]。

价格：GPT-5.5 $5/$30 每百万 token；GPT-5.5 Pro（深思版，做长周期重构）$30/$180[6]。Codex 内上下文 400K。

Codex 的差异化武器恰恰是 内置 review agent——提交前自动审 diff。这正是阿杰工作流第 5 步在用的能力。

5.1 2026 年 5 月 Codex 的关键进化

  • Goal Mode 成默认（v0.133.0, 5/21）：定义"目标 + 成功标准"然后走人，Codex 自己朝目标驱动，能跑几小时甚至几天[16]。
  • 原生 subagents + MCP + hooks + auto-review：以 GPT-5.5 为后端，Codex 现在有原生子 Agent、MCP server 支持、自动审查、hooks、远程 Codex Cloud 任务[6]。
  • 浏览器操作：Codex app 能开内置浏览器，点 UI、复现视觉 bug、验证本地修复[6]。
  • 5 月密集发版：v0.131→v0.135，5/18 到 5/28 十天连发五版，加了 codex doctor 诊断、Vim 模式、权限 profile、本地历史搜索[16]。

🔑 Codex 的杀手锏：独立 review agent

2026 年 Codex 的核心差异化，是它有一个独立的内置审查 Agent，在你 commit 前批判你的 diff[9]。这跟阿杰工作流第 5 步"commit 后跑 codex exec 审 git diff"是同一个能力——阿杰已经踩在正确的路上了。

5.2 Codex 的盲点偏向（互评时要知道）

研究/实战观察：Codex 擅长执行层细节——那些在特定运行条件下才暴露的 bug（重试逻辑、轮询间隔、负载下的优雅降级）；而 Opus 偏重架构和数据流，擅长抓"组件交互处的意外问题"，但容易忽略运维细节[12]。两者盲点正好互补——这是为什么"Claude 写 + Codex 审"这个组合特别灵。

06Gemini 这条线（逍遥的本体 + 大变动）▼

阿杰特别问的：Gemini 3 / Deep Think / Gemini CLI / Antigravity 这条线到 2026-05 的状态。这里有个对逍遥 bot 的关键预警。

6.1 模型本体：Gemini 3 Pro → 3.1 Pro + Deep Think

🔷
Gemini 3.1 Pro (+ Deep Think)
2026-02-19 预览 · 当前 Google 旗舰
长上下文王

时间线：Gemini 3 Pro 2025-11-18 随 Antigravity 一起发；Gemini 3.1 Pro 2026-02-19 预览，是当前旗舰[17][20]。

跑分：LMArena 第一、WebDev Arena 第一（Elo 1443）；GPQA Diamond 94.3%、ARC-AGI-2 77.1%；SWE-bench Verified 80.6%[7]。

Deep Think：更高算力的推理配置（类比别家的"深思"档），冲科研/工程难题。HLE 41.0%、GPQA 93.8%、ARC-AGI-2 45.1%（Gemini 3 Deep Think 数据）[17]。仅 Google AI Ultra 消费档 + 部分 API 白名单可用[19]。

上下文：Gemini 3.1 Pro 号称 10M token（行业最大，是别家旗舰的 10 倍）[22] 🟡 单源，待官方再确认。

价格：API $2/$12 每百万 token（<200K prompt），长 prompt 涨到 $4/$18[19]。消费档 Free / AI Pro $20 / AI Ultra（$249.99，I/O 2026 上有降到 $99.99 的说法 🔴 冲突）[19]。

Gemini 真正的差异化资产是 10M 上下文 + LMArena 第一的通用智能。coding 跑分（80.6%）落后两强约 8 分，但"读全库 / 跨百文件追依赖 / 长资料综述"它最强。

6.2 ⚠️ 重大变动：Gemini CLI 将于 6/18 关停，并入 Antigravity

⛔ 逍遥 bot 直接受影响

Google 2026-05-19 宣布：2026-06-18 起，Gemini CLI 和 Gemini Code Assist IDE 扩展对 AI Pro / Ultra / 免费档用户停止服务，统一并入 Antigravity 平台，包含全新的 Antigravity CLI（Go 写的，更快，能后台编排多 Agent）[14][15]。

注意：只有走 Gemini Code Assist Standard/Enterprise license 或 GitHub 集成的组织用户不受影响。个人/免费档要在 6/18 前迁移到 Antigravity CLI[14]。

🚨 给阿杰的行动项：逍遥是"Gemini CLI bot，通过 cc-connect 跑"。如果逍遥底层是个人/免费档的 Gemini CLI，6/18 之后会停止响应。需要在 6 月中前确认逍遥的接入方式，并测试迁到 Antigravity CLI（或直接走 Gemini API / Vertex）。详见第 12 章决策树。

6.3 Antigravity：Google 的 agentic IDE/平台

🪐
Google Antigravity 2.0
2025-11-18 首发 · 2026-05-19 升 2.0（I/O）
全栈平台

2025-11 随 Gemini 3 发布时是个"Cursor 竞品 IDE"；2026 I/O 升 2.0，扩成桌面 IDE + CLI + SDK + Gemini API 里的 Managed Agents 档 + 企业部署路径的全平台[18]。带编辑器/终端/浏览器控制 + Agent Manager 并行编排多 Agent。

可用模型：Gemini 3 Pro/Flash、Claude Sonnet 4.6、Claude Opus 4.6、GPT-OSS 120B（多模型托管）[18]。

Antigravity 是 Google 把 coding 落地"平台化"的赌注。但下面这条批评必须看。

⚠️ Antigravity 最大争议：credit 系统不透明 + rate limit

评测里被点名最多的就是定价/额度：credit 系统不透明（"你不知道一个 credit 买到什么，根本没法做成本规划"），rate limit 让它"作为日常主力不可靠"[23]。建议团队"先拿真实工作量跑一周再决定"。

6.4 Jules：Google 的异步编码 Agent

另一条线 Jules（Google Labs）：跑在 Gemini 上（Pro 规划 / Flash 轻活），在隔离云 VM 里从 GitHub issue 队列任务、产出 PR[27]。内部 Jules V2 (Project Jitro) 走"目标驱动 / KPI 驱动开发"，但"是未来不是现在"[27]。

07Grok / Grok Build（重点：5 月刚出的新东西）▼

阿杰特别纠正过：不是 Grok 3（旧的）。重点查的是刚推出的 Grok Build。先说本体再说 Build。

7.1 本体：Grok 4.3（"便宜的数字员工"）

⬛
Grok 4.3
2026-04-30 · xAI 当前旗舰
性价比

规格：1M token 上下文、原生视频输入、始终开启推理、function calling[8]。

跑分：Artificial Analysis 智能指数 53，低于 GPT-5.5 (60) 和 Gemini 3.1 Pro (57)，但价格只有零头；GPQA Diamond 约 90%；但 agentic coding（如 SWE-bench Pro）落后 Claude Opus 双位数百分点[8]。

价格：$1.25 / $2.50 每百万 token（比前代输入降 40%、输出降近 60%）[8]。

xAI 自己定位 4.3 "不是 AGI 前沿争夺者，而是能干活的便宜数字员工"。coding 不是它强项。

实测口碑："是真进步但不是革命，属于打磨上市"；代码回答更紧凑，能装依赖、产文档；但没有持久记忆（不像 Claude Projects），多数开发者认为"Claude Opus 4.7 仍是更好的选择"[28]。🟢 多源

7.2 ⭐ Grok Build：xAI 的编码 Agent（正面打 Claude Code/Codex）

🔨
Grok Build (grok-build-0.1)
2026-05 早期 beta · 终端编码 Agent
最新 / 未成熟

它是什么：终端原生编码 Agent，自然语言描述任务，它自主 plan→search→build。明确对标 Claude Code[4][32]。

背后模型：grok-build-0.1，xAI 首个专为 agentic coding 训练的模型（能重构大库、调工具、产结构化输出、持续循环到任务完成）[3]。🔴 部分来源写 grok-code-fast-1，名称冲突

这是 xAI 第一次认真做"编码 Agent 产品"，不是聊天。架构上甚至比很多 v0.1 更野心勃勃。

Grok Build 的招牌特性（这几条是稳的共识）

  • 8 个并行子 Agent，每个跑在独立 git worktree——消除共享状态冲突[4][32]。
  • Arena Mode（即将上线）：让多个 Agent 独立解同一个问题、竞赛排名择优，再把最好的结果给你——而不是单结果让你接受/拒绝[32]。这其实是"互评/择优"思路的产品化。
  • Plan Mode 默认开：动手前先出分步计划，你可以批准/逐步评论/重写，签字才跑[9]。
  • Local-first：源码不上传 xAI 服务器[4]。
  • 256K 上下文 + ACP（Agent 协调协议）+ 无头自动化[9]。

⚠️ 跑分 / 成熟度：明显落后

SWE-bench Verified 70.8%，对比 Codex 88.7% / Claude Code 88.6%（Opus 4.8；当时对比基准用的是 4.7 的 87.6%），差约 18 分[3]。社区评价："v0.1 展示了多数首版工具不敢碰的架构野心（并行 worktree、Plan Mode、ACP），xAI 赌的是'多 Agent 并行 + 人在环规划'长期会赢过原始跑分。这是个站得住的赌注，但还没兑现"[33]。

定价 / 可用性

最初仅限 SuperGrok Heavy（$300/mo），2026-05-24 扩展到 SuperGrok ($30/mo) 和 X Premium+ ($40/mo)[4]。API 价 $0.20 / $1.50（一说 $1/$2，冲突）[5]。对阿杰：在国内 Grok 走 X，被墙，需梯子；且 beta 不稳。建议"观望，不进生产"。

10多模型互评机制（对着阿杰工作流写）▼

阿杰工作流第 5 步已有"Codex 跨模型审查"。这章把"为什么有效 + 怎么系统化升级"讲透。

10.1 为什么跨模型互评有效（机制）

核心：盲点不重叠 🟢 多源 + 论文

当 Claude 写完一个函数、你再让 Claude 审，它看的是匹配自己内部模式的代码，更容易看到它预期看到的、漏掉它预期不到的。每个模型的盲点由它的训练数据、RLHF 过程、架构塑造。换一个不同 provider 的模型来审，偏见不以相同方式重叠，于是能抓到自审漏掉的 bug[12]。这正是阿杰 CLAUDE.md 里写的"同模型审自己代码盲点一致，不同模型才抓得到"——这条判断有扎实的研究支撑。

10.2 互补的具体形状（谁补谁）

Opus（Claude）偏重架构 + 数据流，擅长抓组件交互处的意外问题，但易忽略运维细节（轮询间隔、重试、负载降级）；Codex（GPT）偏向相反——执行层细节，抓特定运行条件才暴露的运行时 bug[12]。所以"Claude 写 → Codex 审"是架构脑 + 执行脑的组合，不是简单的"多一道关"。

10.4 ⚠️ 必须避开的"流行性陷阱"

不要简单"投票取共识" 🟢 论文

研究警告：训练分布相似的模型会在"语法看着对、语义其实错"的答案上收敛，简单的共识选择会过滤掉少数派的正确解、放大共享错误——这叫流行性陷阱[12][30]。

解法：按多样性择优，而不是按多数。不同模型的分歧本身带结构化信息——有时少数派才对。多样性策略能拿回 95% 的"完全独立集成"的理论收益，哪怕只有两个模型[30]。所以阿杰用 Claude(无忌/三丰) + Codex + Gemini(逍遥) 跨三家，天然多样性高，比"两个 Claude session 互审"强得多。

10.5 阿杰三 bot 的现状盘点

⚠️ 一个隐患：无忌和三丰是同源

无忌（Claude Code）和三丰（另一个独立 Claude Code session）都是 Claude。让三丰审无忌的代码，属于同源互审，盲点重叠，补盲效果有限（只解决"换个 context 重新看"的价值，不解决"不同训练分布"的价值）。真正的跨模型补盲来自 Codex（GPT）和逍遥（Gemini）。这意味着：

  • 三丰更适合做并行干活（agentmaxxing）和PM/产品视角的对抗（不同角色 prompt），而不是"代码盲点补盲"。
  • 代码层的真补盲，靠 Codex 审查那一步（已有，方向对）。
  • 引入 逍遥（Gemini）做第三只眼，能再拉高多样性——尤其它 10M 上下文适合"读全库后做整体性审查"。

10.6 系统化升级方案

把现有"commit 后跑一次 codex exec"升级成分层互评流水线（细节见第 11 章）：

  1. L0 模型内自查（零成本）：开 Opus 4.8 的 Dynamic Workflows / 对抗 Agent，让 Claude 自己先收敛一轮[10]。
  2. L1 跨模型代码审查（已有，强化）：Codex review agent 审 git diff——这是架构脑 vs 执行脑的关键补盲。
  3. L2 第三方仲裁（按需）：当 Claude 和 Codex 分歧时，才召逍遥（Gemini 长上下文）读全库做仲裁——而不是无脑三方投票（避开流行性陷阱）。
  4. L3 角色对抗（PM/CTO 双轮）：阿杰的 /review skill 已经在做（Codex 当 CTO、独立 Opus 当 PM 对抗式复审）——这是产品/架构层的互评，与代码层互补。

14FAQ · 12 条▼

Q2026 年 5 月，编码 Agent 到底谁第一？+

没有绝对第一。跑分上 Codex(GPT-5.5) 88.7% SWE-bench Verified 略胜 Claude Code(Opus 4.8) 88.6%[1]；但 SWE-bench Pro（更难）Claude 69.2% 反超 Codex 58.6%。体感上 Claude 代码更干净（盲评 67%），Codex 更快更耐用（65% 人日常用）[11]。结论：可靠性选 Claude，速度成本选 Codex，多数 pro 两个都用。

QGrok Build 是什么？真能打 Claude Code 吗？+

是 xAI 2026 年 5 月刚推的终端编码 Agent，明确对标 Claude Code。招牌是 8 个并行子 Agent + 独立 git worktree + Arena Mode（多 Agent 竞赛择优）[4]。但 SWE-bench 只有 70.8%，落后两强约 18 分，还是 v0.1 beta[3]。架构野心大，但还没兑现，现阶段别进生产。

QGrok 3 和 Grok Build 是一回事吗？+

不是。Grok 3 是旧的聊天模型。当前 xAI 旗舰聊天模型是 Grok 4.3（2026-04-30）[8]；Grok Build 是独立的编码 Agent 产品，背后是专门的 grok-build-0.1 模型，跟聊天模型是两码事。

QGemini CLI 要没了？逍遥怎么办？+

是的，2026-06-18 Gemini CLI 对个人/免费档停止服务，并入 Antigravity（含新的 Antigravity CLI）[14]。如果逍遥底层是个人档 Gemini CLI，6/18 后会停。三条路：迁 Antigravity CLI / 改走 Gemini API 或 Vertex / 若有 Code Assist Standard+ license 则不受影响。见第 12.3 节。

Q为什么不直接让 Claude 审自己的代码就好？+

因为同一个模型审自己，看的是匹配自己内部模式的代码，盲点一致——更容易看到它预期的、漏掉它预期不到的[12]。换不同 provider 的模型审，偏见不重叠，能抓到自审漏掉的。Opus 4.8 诚实度提升了 4 倍，让自审好一些，但仍不如跨模型。阿杰的"Codex 跨模型审查"判断完全正确。

Q多模型互评是不是模型越多越好？+

不是。关键是多样性不是数量。简单"多数投票"会掉进流行性陷阱——相似模型一起在"语法对语义错"的答案上收敛，把少数派正确解过滤掉[30]。研究显示按多样性择优，哪怕只两个模型也能拿回 95% 的理论收益。阿杰跨 Claude/Codex/Gemini 三家，多样性已经足够。

Q无忌和三丰互审有用吗？+

有用但有限。两个都是 Claude，同源、盲点重叠，互审只拿到"换个 fresh context 重看"的价值，拿不到"不同训练分布"的补盲价值。建议三丰转去做并行独立任务或不同角色（PM）的对抗，代码层真补盲交给 Codex。见第 10.5 节。

QGemini 的 10M 上下文有什么实际用处？+

它是别家旗舰（1M）的 10 倍[22]。实际用处：一次性吞下整个中小型代码库做整体性分析、跨上百文件追逻辑、长资料综述、读全库后做"整体性代码审查"。这是它相对 Claude/Codex 的差异化优势区。但注意这是单源数据，建议官方再确认。

Q官方 benchmark 能信吗？+

要打折看。同一模型换个 scaffold 能差十几分（Grok 4 自报 72-75%，独立测 58.6%）[1]。官方自报数普遍偏高。看 benchmark 一定看清测试条件 + scaffold，并结合 LMArena（人类盲评）和社区实测口碑交叉验证。

Q阿杰单人全栈，需要搞全套多 Agent 编排吗？+

不需要，会过度工程。优先级：(1) 保留强化 Codex 审查那一步（最小投入最大补盲）；(2) 把逍遥迁移做掉（不做会断）；(3) 分歧仲裁当锦上添花。Dynamic Workflows / agentmaxxing 等重型并行，等真有几十万行迁移任务再用。见第 12.4 节。

Q国产模型能替代这四家吗？+

部分能。DeepSeek V4 (81% SWE-bench)、GLM-5.1 (MIT 开源、曾超 Opus 4.6 某 coding 项)、Qwen3.5、Kimi K2.6 在 coding agent 场景已经"能打"，且国内直连 + 便宜 5-30 倍[24]。建议当"断网备份"和"成本敏感批量任务执行层"，把贵的 Claude/Codex 留给关键审查。

QCodex 审查那步具体怎么写更好？+

明确让 Codex 聚焦执行层 bug——重试逻辑、边界条件、并发、资源泄漏、负载降级。因为这正是 Codex 相对 Claude 的盲点优势区[12]，而 Claude 自己已经盯架构/数据流了。别让 Codex 泛泛审"有没有 bug"，针对性提示能让两个模型盲点互补最大化。见第 11.4 节。
