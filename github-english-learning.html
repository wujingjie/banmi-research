GitHub 上的英语学习开源生态：能抄什么进半米

📅 2026-06-06 🔍 ~30 次检索 + 13 次 repo/README 实查 🧩 筛子：半米能借鉴什么 🧒 终端是东南亚 K12 🌏 海外视角默认

一句话定调：英语学习开源生态里，「算法」和「数据」可以直接拿，「整套 app」基本都不能直接用。最该抄的三样是 FSRS 间隔算法（数学+多语言 port 全开源、MIT、半米的 Roam SRS 该升级到它）、wav2vec2 发音逐音素打分栈（Echoic/speechocean762 把「儿童英语发音评分」这件难事开源了，含一半儿童语料）、CEFR 分级词表数据（A1–C2 现成、可商用）。整套 app（Lute / LinguaCafe / LibreLingo）只值得「抄架构 / 抄 UX」，不值得 fork——它们要么 GPL 传染、要么成人自学向、要么已停更。

本篇按半米的四个维度组织：行为引擎（Ch2 FSRS）→ 内容管线（Ch3–5 阅读器/字幕/分级数据）→ AI 个性化（Ch6–7 发音评测/LLM 私教）→ 开放架构（Ch8 词典/插件标准）；再覆盖方法论（Ch9）与经典书（Ch10），横切对比（Ch11），K12 儿童适配性专章（Ch12），最后是给阿杰的可借鉴路线决策树（Ch13，最重要）+ 可玩 mini demo。每个项目都标了 star / 活跃度 / license / 借鉴方式。规模/星数为查证当日快照，已尽量双源核对。

📌 三条最关键发现（先扫这个）：

  • FSRS 不是「Anki 的一个插件」，是一套语言无关的开源记忆调度算法——已有 10+ 语言 port（py/rs/go/ts/dart/swift…）[3]，半米完全可以把 Roam-based 间隔复习的「固定 1/2/4/7/15…天」升级成 FSRS 的「按每个孩子的回忆表现自适应」。🟢
  • 儿童英语发音逐音素打分，开源已经把管线跑通了「不靠云 API」——Echoic（wav2vec2 + WhisperX，MIT，2026 仍有 commit）做出了逐音素颜色打分 + 练习热力图[9]；训练/评测语料 speechocean762 半数是儿童、可商用[10]。这是半米「AI 个性化」维度最大的现成杠杆。但两个要点别忽略：Echoic 是 37★ 单人原型(0 正式 release)、宜「读思路自己重搭」而非直接当生产后端[38];speechocean762 说话人母语全是中文(Mandarin-L1),不代表印尼/马来/泰/越口音,上线前需自建 SEA L1 小样本校准集（详见 Ch6）。🟡
  • HiKid 几乎就是「banmi 的开源近亲」——给非英语国家儿童的本地 AI 英语口语 pal（Qwen3 + 本地 ASR/TTS，MIT，2026 活跃）[13]。不是竞品威胁，是「同一命题的另一种实现」，最值得逐文件读它的交互设计与 prompt。🟢

01全景：开源英语学习生态长什么样，半米站在哪▾

先把地图铺开。GitHub 上的英语/语言学习开源生态，可以干净地切成「三类东西」——这个切分直接决定了哪些能拿、哪些只能看：

① 算法 / 模型（最该拿）。FSRS 间隔算法、wav2vec2 发音打分、Whisper ASR、本地 TTS（Piper 等）。这些是数学和权重，没有 UI 包袱、没有「成人 vs 儿童」之分，license 多数宽松（MIT/Apache/BSD）可以直接嵌进任何产品。半米最大的红利在这一类。但「宽松」不能想当然——本轮复核就抓到几个反例：WhisperX 是 BSD-2 不是 MIT、其 diarization 模型权重另有 CC-BY-4.0 门控;Piper 已归档、续作 piper1-gpl 转成了 GPL-3;voice/diarization 等模型权重的 license 经常和代码 license 不是一回事,要分开核（详见 Ch7/Ch11）。

② 数据 / 标准（第二该拿）。CEFR 分级词表、词频表、发音语料、词典格式标准。这些是静态资产，下载即用，关键只看 license 能不能商用。半米的「内容管线」维度可以靠这些省掉大量人工分级。

③ 整套 App（基本只能看，不能 fork）。Lute、LinguaCafe、LibreLingo、asbplayer、jidoujisho……每一个都是「为某一类成人自学者、某一种学习流程」打磨的完整产品。它们的价值在「架构 / UX / 交互范式」，不在代码本身——要么 license 传染（GPL/AGPL），要么形态是「一个人戴耳机自学」，下沉到东南亚 K12 小孩需要推倒重做。

避免复述半米已有的

半米已有：SciShow Kids 视频词表管线、Roam-based 词汇间隔复习、Language Reactor 字幕精读工作流。本报告刻意不重复这些，专挑「半米还没有但值得抄」的：① 把固定间隔升级成 FSRS 自适应（Ch2）；② 发音/口语评测这一整块半米目前是空白（Ch6）；③ CEFR 自动分级替代人工选词（Ch5）；④ LLM 对话私教（Ch7）。这四块是增量，不是复述。

02行为/习惯引擎：FSRS & SRS 全家桶（半米最该抄的算法）▾

这是整份报告里投入产出最高的一章。半米已经在做间隔复习（Roam SRS、间隔 1/2/4/7/15/30/60/90 天），但那是固定间隔——不管这个孩子昨天答得多顺、还是卡了三次，下次复习时间都一样。FSRS 干的事就是把这个「一刀切日历」换成「按每个孩子每张卡的真实记忆状态动态算」。

FSRS 到底是什么

FSRS（Free Spaced Repetition Scheduler）= 一个基于「DSR 记忆模型」的开源间隔调度算法。它对每张卡片建模三个量[2]：Difficulty（难度）、Stability（稳定性，记忆能撑多久不忘）、Retrievability（可提取性，此刻还能想起来的概率）。每次复习你给一个反馈（忘了/难/一般/简单），算法更新这三个量，再把「下次复习时间」精确算到「你恰好快要忘、但还没忘」的那个点——这正是记忆科学里最高效的复习时机。FSRS-6 用 21 个可优化参数，optimizer 会用机器学习从你的历史复习记录里拟合出最适合你的参数[1]。

关键：FSRS 是「算法」不是「Anki 的功能」

这是最容易被误解、也最关键的一点。很多人以为 FSRS 是 Anki 里的一个开关，其实核心算法是一个独立的、语言无关的开源库，Anki 只是它最有名的一个调用方。证据是它的 port 矩阵：

借鉴方式（明确）：抄算法 / 直接集成。半米要做的不是 fork 任何 app，而是 pip install fsrs（或对应语言 port），把 Roam SRS 里「固定间隔」那一层换成「调 FSRS 算下次复习时间」。MIT license 商用零障碍。当前算法代是 FSRS-6。版本号要分清三条线，别混为一谈：

  • 官方 Python 库 py-fsrs：最新 release v6.3.1（2026-03-10）[37]——这是半米 pip install fsrs 实际会装到的那个，v6.0 起为「同一天复习两次以上」新增了 2 个参数。
  • Anki 配套的 fsrs4anki：最新 release v6.1.3（2025-09-08）[1]，对应 FSRS-6 已进 Anki 25.09。注意它和 py-fsrs 的版本号不是一回事（两个独立仓库各自打 tag），别看到「6.1.3 vs 6.3.1」就以为有矛盾。
  • 「进 Anki 主线」要拆成三处分别看：FSRS-6 已是 Anki Desktop（25.09）内置调度器；AnkiDroid（v2.24.0, 2026-05[11]）也已内置；底层算法库（py-fsrs / fsrs-rs）独立维护。三者成熟度都足够，但分属不同发布节奏。

落地要点（FSRS 用在儿童身上,几个非显然的工程坑）:FSRS 的输入是「每次复习的评分(Again/Hard/Good/Easy)」,但小孩没有稳定的元认知自评能力——你不能指望 6 岁孩子准确说「我对这词记得有点难」。所以半米要把「评分」从「让孩子自评」改成「系统从行为代理推断」:

  • 用「对错 + 作答延迟」当 rating 代理:答对且快→Good/Easy;答对但慢/犹豫→Hard;答错→Again。让系统替孩子生成 FSRS 输入,孩子只管答题。
  • 冷启动:新卡没有历史,先用 FSRS 默认参数;积累足够复习记录后再用 optimizer 按这个孩子(或这个群体)拟合参数,别一开始就追求个性化参数。
  • 家长代答 / 多人同设备:低龄场景常是家长帮点、或一台设备多个孩子——要能识别/隔离「谁在答」,否则 FSRS 的记忆状态会被污染(家长替答的「会」不等于孩子会)。
  • 入队对象分三类:不只是「词」——phoneme(发音弱项,接 Ch6)/ word / sentence 都可以是独立的「待复习对象」,各自有 stability。发音错音天然 stability 低 → FSRS 自动让它更频繁出现,这正是「行为引擎驱动发音练习」的接口。

游戏化 / streak：行为引擎的另一半（向 Duolingo 抄设计而非代码）

FSRS 解决「什么时候复习」，但解决不了「孩子今天愿不愿意打开」。后者是 Duolingo 封神的地方，而且它的机制是公开拆解过的、可以直接借设计思路：

  • streak（连续天数）的本质是「损失厌恶」而非「成就感」——用户不是在「推进」连胜，是在「保护」它不断[22]。Duolingo 靠 streak 把次日留存从 12% 拉到 55%[22]。🟢
  • Streak Freeze（连胜冻结）反而降低流失——给焦虑用户一个「断一天也没事」的缓冲，churn 降约 21%[22]。对小孩尤其重要：别让「断签」变成「干脆放弃」。
  • 每天一节短课 + 联赛 + 角色 + 通知构成习惯回路[22]。

⚠️ K12 适配警告：把 streak 重构成「复原力机制」，别照搬「损失厌恶 + 留存数字」。上面那些 Duolingo 数字（12%→55%、churn-21%）是成人产品的留存指标，不能直接当半米的设计依据——它们证明的是「损失厌恶能拉成人留存」，而对儿童，「保护连胜」的损失框架恰恰可能把「断一天」放大成「挫败 → 干脆放弃」，还可能触发不健康的强迫性打卡。给半米的设计转向：🟡 判断

  • 叙事用成就框架不用损失框架：「你已经坚持了 N 天，真棒」而非「别让连胜断了」。
  • 用周目标替代纯日连胜（如「本周练 4 天」），天然容错，不会因为某一天落空就归零。
  • 内置宽限 / Streak Freeze：给「断一天也没事」的缓冲，配无羞辱文案（不出现红叉、哭脸、责备）。
  • 把「掉线/disengagement」当一类一等指标来监测（连续未登录、单次时长骤降、放弃率），用来触发「降难度 / 换形式 / 通知家长」，而不是用来惩罚孩子。

这条在 Ch12 还会展开。核心：streak 对半米的价值是「帮孩子建立可持续的学习节律（复原力）」，不是「用焦虑把留存数字做上去」。

03内容管线①：沉浸式阅读器（Lute / LinguaCafe / openkoto）▾

「沉浸式阅读器」是开源生态里最成熟的一类：导入任意文本/电子书/字幕 → 点词查义 → 标记「认识/不认识」→ 生词进复习。它们都源自一个老祖宗 LWT（Learning With Texts），再各自现代化重写。对半米的价值是「点读 + 生词追踪 + 已知词率统计」这套交互范式，不是代码。

最值得半米读的是 openkoto。它是这三个里唯一「AI 原生」的——不是「点词查静态词典」，而是「高亮任意句子，问 LLM 这是什么意思 / 语法怎么拆」[6]。这正是半米「AI 个性化 + 内容管线」交叉点的形态。技术栈 Tauri+Rust 偏桌面，半米若是 Web/移动可只借「LLM 即时释义」的交互设计与 prompt 模式。

⚠️ license 更正（原报告说「Apache-2 最干净可借码」是错的）：openkoto 的 LICENSE 不是纯 Apache-2.0，而是「Apache-2.0 + 附加条款」[6]。实查 LICENSE 文件，附加条款包括：① 未经书面授权不得运营多租户(multi-tenant)环境；② 不得移除/修改 console 与应用里的 LOGO 及版权信息（除非完全不使用其前端）；③ 交互设计声明有外观专利、版权归作者(hikariming, 2024)。对半米的含义：当「交互范式 / prompt 模式」的灵感来源完全没问题（设计思路不受版权约束），但别直接 fork 它的前端代码进商业产品——半米恰恰是「多租户 SaaS」形态，正好踩在它限制的点上。要借码必须先做法律审查或联系作者拿商用授权。🟡

⚠️ license 红线：LinguaCafe 是 GPL-3[5]——如果半米是闭源商业产品，不能 fork 它的代码（GPL 会传染要求你也开源）。但「看它的 dashboard 怎么做、已知词率怎么可视化、导入源怎么组织」是完全合法的——UX 不受版权约束。Lute（MIT）反而可以借码，但它 UI 老派、形态成人自学向，对 K12 要重做交互。

对半米的净判断

半米已有 Language Reactor 字幕精读工作流，阅读器这块不是空白，所以优先级中等。真正的增量是 openkoto 式的「LLM 即时释义/语法拆解」——把「孩子读绘本/分级读物时点一个不懂的句子，AI 用孩子能懂的话解释 + 给个例句」做进半米。这比自建一个完整阅读器划算得多：借交互范式，不重造轮子。

04内容管线②：字幕精读 / sentence mining 开源栈▾

这是 Language Reactor 的开源世界。核心方法叫 sentence mining（挖句子）：看带字幕的视频 → 遇到「刚好能懂大部分、只差一两个词」的句子 → 一键把「视频片段 + 截图 + 字幕 + 音频」做成一张复习卡。半米已有 LR 工作流，所以这章重点是「LR 的开源替代品长什么样、能不能把这条管线自有化」。

⚠️ K12 适配性低。整条 sentence mining 方法论是成人自学者的产物——它假设学习者会自己判断「哪句话该挖」、会管理 Anki deck、有元认知去经营自己的复习。东南亚 K12 小孩做不到。所以对半米：抄「片段→卡」的技术管线（机器能做的部分），但「挑哪句」要由半米的 AI/课程体系自动替孩子决定，不能指望孩子自己挖句子。这是「成人向需游戏化/自动化改造」的典型例子（Ch12 详述）。

🔴 关键概念区分：CEFR 等级 ≠ 适龄(age suitability)。CEFR 衡量的是语言难度（A1 的词「简单」），但不保证话题适合儿童——A1/A2 词表里照样有 war、kill、beer、divorce 这类语言简单但话题不适龄的词;反过来,适合低龄孩子的话题（动物、颜色、家庭）也可能用到 B1 的词。所以半米拿 CEFR 数据时,必须再叠一层独立的「年龄/年级 + 话题适龄」过滤,不能用「A1 = 适合低龄」这个错误等式直接驱动给孩子推什么。这一层 CEFR 数据本身给不了,得半米自己建（或借儿童分级读物的 leveling 体系）。

🔴 freshness 警报：wordfreq 已被作者主动冻结（2022 年停更）。原因很硬核也很有时代意味——作者明确说「AI 生成文本污染了网络语料，可靠采集词频的方法已经不存在了」[16]。这不影响半米使用：它的数据是 2021 年前的真人语言快照，对「常用词分级」这种慢变量足够好，Apache/CC license 也允许商用。但要知道：它不会再更新，别指望它收录 2023 年后的新词。

借鉴方式：分层拿数据（修正版）。给半米的具体做法——主分级用 olp-en-cefrj 里权威标注的 CEFR-J(A1-B2)+Octanove(C1/C2) 给词打等级,长尾/未覆盖词用 Words-CEFR-Dataset 的推断值当候选标签补位（标记为「推断,待复核」）;再用 wordfreq/COCA 给词频排序（决定「先教哪个」）。最后务必叠一层「话题适龄」过滤（CEFR 只管难度不管适龄,见上方红框）。几张表 join 一下,半米的词表分级就从「人工拍脑袋」变成「权威标注为主 + 推断补位 + 适龄兜底」。仍是「内容管线」里最便宜的一次升级——零模型、零训练,但合规与适龄这两层别省。注意 Octanove 部分是 CC-BY-SA,若直接随产品再分发要处理 ShareAlike。

06AI 个性化①：发音 / 口语评测（半米最大的现成杠杆）▾

这是半米目前的空白维度，也是本报告认为第二该抓的杠杆（仅次于 FSRS）。「孩子读一句英语，AI 告诉他哪个音发错了、错在哪」——这件事过去要么靠云 API（科大讯飞/微软/SpeechSuper，按次收费、数据出境），要么很难自建。现在开源已经能端到端做到。

底层原理：GOP（Goodness of Pronunciation）

发音打分的经典方法叫 GOP。思路：让语音模型（过去是 Kaldi DNN，现在是 wav2vec2/HuBERT/WhisperX 这类自监督模型）去识别学习者每个音素（phoneme），比对「学习者实际发的音」和「标准应该发的音」的概率差，差越大 = 发得越不准。最终输出可以细到逐音素的 0–2 分，也能聚合成单词级、句子级的准确度/流利度/完整度分[10]。

为什么 Echoic + speechocean762 仍是半米最好的起点组合（但要降温,见下）：

  • Echoic 把最难的工程拼通了——逐音素颜色打分、单词级拆解、可调权重（准确 0.5/流利 0.3/完整 0.2）、甚至 365 天练习热力图（这本身就是「行为引擎」资产！）[9]。MIT license 可直接借码。但它是参考实现/原型,不是生产组件（见下方 checklist）。
  • speechocean762 半数语料是儿童[10]——这是它最大的价值:儿童语音的声学特征（音高高、共振峰偏移、发音不稳定）和成人差很多,用成人语料训出来的打分器套小孩会乱评,有含儿童的可商用标注语料是稀缺资源。但有个硬限制:它的说话人母语全部是 Mandarin(中文 L1)。
  • 全本地可跑——wav2vec2/WhisperX 都能本地推理,不必把孩子的录音传给第三方云（数据合规对 K12 是硬要求,见 Ch13 第 0 步）。

⚠️ speechocean762 是「儿童 Mandarin-L1 基线语料」,不是「东南亚儿童语料」。它的说话人母语全部是中文[10]——而半米的孩子母语是印尼语 / 马来语 / 泰语 / 越南语。不同 L1 的母语干扰模式完全不同（比如泰语没有词尾辅音连缀、印尼语元音系统更小、越南语是声调语言),用 Mandarin-L1 训出的打分阈值直接套在 SEA 孩子身上,会把「不同 L1 的正常发音模式」误判成错误。给半米:把 speechocean762 当「冷启动基线 + 工程验证语料」,但上线前必须自建一个 SEA L1 小样本校准集（每个目标母语收一批儿童读标准句,人工标注,用来校准/微调阈值）。这是发音评测能不能真用的关键一步,别跳过。🟡

🎯 口音偏见 framing（必须前置想清楚）:发音评测的目标是 intelligibility(可懂度) + classroom English,不是 native accent。二语发音研究的共识:重口音不等于难懂,native-like 发音也不是沟通成功的前提[45]。而像 speechocean 这类打分体系,常把「heavy accent」直接降到最低分(1 分),量表本身带 native-bias（低分挂在口音、高分才谈可懂度）[45]。对半米这层尤其要警惕:目标不该是「把 SEA 孩子的英语磨成美音」,而是「让他说得清楚、别人听得懂、能在课堂用」。落地准则:① 评分内核盯「这个音会不会造成误解/混淆」,不盯「像不像母语者」;② 前端避免任何「纠正口音」式的羞辱文案（不要「你的口音很重」),改成「这个词试试这样说会更清楚」;③ 把多样化 L1 语音纳入校准集(接上一条),减少量表偏见。🟡 判断

⚠️ Echoic 是「参考实现/原型」,不是「拿来即上线的生产组件」——别把它当黄金标准照搬。实查:它0 个正式 GitHub Release（只有 7 个 git tag）、无可见测试目录、37★、单人项目、无公开 benchmark[38]。它的价值是「让你看懂逐音素打分这条管线怎么拼」,半米应逐文件读它的思路,然后用更稳的组件自己重搭评分服务,而不是直接把它当后端跑生产。半米选型前过一遍这个 production-readiness checklist:

  • release / 版本管理:有没有正式 release、语义化版本、changelog?（Echoic:无正式 release）
  • 测试:有没有单元/集成测试、CI?（Echoic:未见测试目录）
  • benchmark:打分与人类老师评分的相关系数有没有公开?（Echoic/多数开源:无）
  • issue velocity / bus factor:维护者几个人、issue 响应快不快?（Echoic:单人、低星,弃坑风险高）
  • 模型下载与体量:依赖哪些模型、多大、能不能离线缓存?（Echoic:WhisperX+wav2vec2 ~1GB,首次自动下载）
  • CPU/GPU 延迟:目标端(平板/低端机)上一句话的打分要几秒?有没有量化/CPU 路径?（需自测,Echoic 未给）

⚠️ 诚实标注:发音打分准确度本身是个难题。逐音素 GOP 在儿童、口音重、背景噪音场景下误判率不低,学界仍在用 LLM/多模态模型刷榜[10]。给半米的建议:先把发音评测做成「鼓励性反馈」而非「严格判分」——告诉孩子「这个 /θ/ 音再试试,舌头放牙齿中间」,而不是冷冰冰打「62 分」。打分用于内部驱动复习调度（哪些音该多练）,对孩子展示的是正向引导。🟡 判断

MVP 评测协议:怎么验证「评分对半米的孩子准不准」

「开源能跑」≠「对半米的孩子准」(Ch14 也标了)。半米上线发音评测前,应跑一个轻量但严谨的评测协议,把误判风险量化出来:

  • 小样本设计:SEA 目标人群儿童(如 50 人 × 30 句),覆盖主要母语(印尼/马来/泰/越)、年龄段、性别。
  • 人类老师双评分(double-rating):每条录音至少 2 名英语老师独立评分,算评分者间一致性(inter-rater agreement)作为「人类天花板」。
  • 模型-人类相关系数:把模型分与人类均分做相关(Pearson/Spearman),低于阈值就别上线给孩子看分。
  • 误判(false positive)阈值:重点盯「孩子发对了却被判错」——这种打击信心,比「发错了没抓到」更伤,要单独设容忍上限。
  • 噪音 / 设备分层:分安静/嘈杂、好麦/廉价平板麦分别测——SEA 真实环境噪音大、设备杂,音频质量本身会引入偏差[45]。

这套协议也是「自建 vs 云 API」对比的实验底座:同一批录音同时喂自建栈和云 API,谁的「模型-人类相关」高、误判低,数据说话。

⚠️ TTS 选型避坑(已更正旧报告的 Piper 描述)：

  • Piper 的 license 状态变了,别再当「Apache-2 随便用」。原 rhasspy/piper 确实是 MIT,但已于 2025-10-06 被作者归档(read-only),仓库顶部公告开发已迁到 OHF-Voice/piper1-gpl[34];而续作 piper1-gpl 的许可证是 GPL-3.0(顾名思义)[35]。对闭源/SaaS 半米的含义:用旧 MIT 版=吃停更风险,用新版=吃 GPL 传染评估。另外:piper 的语音模型(voice models)是单独授权的,不随代码许可走,选哪个嗓音都要单独核对那个 voice 的 license。🟡
  • Coqui XTTS-v2 音质口碑最好,但禁商用且公司已倒。它是 Coqui Public Model License(禁止商用),母公司 2024 初关停[19]——别把商业产品压在它身上。
  • 给半米的净建议:本地 TTS 若要 Piper 嗓音,先确认具体 voice model 的 license 可商用,并就「MIT 旧版(停更) vs GPL 新版」做一次取舍;同时把商业云 TTS(OpenAI/Google/ElevenLabs/Azure)当一等候选——儿童+海外场景,云 TTS 音质更好、维护成本低,单人团队不该默认「自建本地 TTS 一定更优」(见下方云 vs 自建对比)。

08操作系统式开放架构：词典 popup 标准 / 插件 / 互操作▾

半米自我定位是「学习操作系统」，所以这一维度看的不是单个功能，而是「生态怎么互操作、用了什么开放标准」。开源世界这里有两个事实标准值得半米学习架构。

标准一：Yomitan —— popup 词典 + 开放词典格式

Yomitan（~2.6k star，GPL-3，JS，2026-05 仍密集发版）[21]是 Yomichan 的继任者，是「悬停即查词」浏览器扩展的事实标准。对半米最有价值的不是它的扩展本身，而是它定义的开放词典格式——任何人都能把词典转成 Yomitan 格式，于是一个词典能被整个生态复用[21]。它还通过 AnkiConnect 把「查到的词」一键变成 Anki 卡。这就是「操作系统式」的精髓：定义格式，让组件可插拔。

标准二：AnkiConnect —— 让一切都能往 Anki 喂卡

asbplayer、Yomitan、jidoujisho、vocabsieve 全都通过 AnkiConnect（Anki 的本地 HTTP 插件）把卡片送进 Anki[7]。这是整个开源语言学习生态的「中央车站」——Anki(+FSRS) 当复习引擎，所有内容工具当生产前端，AnkiConnect 当总线。

对半米的架构启示（这是本章真正的价值）：开源生态用「开放格式 + 本地 API 总线」实现了 Yomitan / asbplayer / Anki 三个独立项目的无缝协作。半米要做「学习操作系统」，应该学这个解耦思路：

  • 把「复习调度」独立成服务（内部就是 FSRS），任何内容模块（视频词表、阅读生词、发音弱项）都往它喂「待复习项」——就像所有工具都往 Anki 喂卡。
  • 定义半米自己的「学习对象」开放格式（一个词/一个句/一个音素弱项长什么样），让 SciShow 管线、LR 字幕、发音评测都产出同一种对象——而不是每个功能各做各的数据结构。
  • 词典/释义层抽象成可替换组件（今天用 Wiktionary，明天换 LLM 释义），像 Yomitan 的可插拔词典。

⚠️ Yomitan/jidoujisho 都是 GPL-3，别 fork 进闭源半米；学的是它们的架构思想和格式设计，不是抄码。开放格式本身（如何描述一个词条）不受版权约束，可以自由参考。

标准三：Kolibri —— 东南亚低带宽场景的「离线内容操作系统」

Kolibri（learningequality/kolibri，~1.1k★，MIT，Python/Vue，v0.19.4 / 2026-05 活跃,机构 Learning Equality 维护)[40]是离线优先(offline-first)的 K12 教育平台,专为低带宽 / 低连通地区设计——而这正是半米东南亚终端的真实网络环境(乡镇学校、家庭流量有限、网络不稳)。前面 Yomitan/AnkiConnect 解决的是「组件互操作」,Kolibri 解决的是另一个半米绕不开的问题:内容怎么在「时好时坏甚至没网」的环境里分发、缓存、同步。它的几个架构点直接对口半米:

  • 内容包 / 频道(content channels):把课程内容打包成可离线分发的「频道」,U 盘/局域网/偶发联网都能装——半米的 SciShow 词表、分级读物、发音练习句库都可以照这个思路做成「内容包」。
  • 设备间离线同步:学习进度/成绩在没有持续互联网时也能在本地服务器与设备间同步,等有网再回传——对半米的 FSRS 复习状态、发音弱项数据如何「断网也不丢、有网才上云」是现成参考。
  • 教师(coach) + 学习者 + 家长工作流:Kolibri 区分了教师布置/批改、学习者练习、管理者看板的角色——半米要进东南亚学校/家庭,这套多角色 + 离线的工作流模型很值得抄架构。

对半米的净判断:Kolibri 是「内容分发 + 离线同步」这一层最该对照的开源样本,MIT 还可借码。半米不必 fork 整个平台(它是个大系统),但「内容包格式 + 离线优先同步 + 多角色工作流」这三件,是半米作为「学习 OS」在 SEA 落地时迟早要解决的工程,而 Kolibri 已经把这条路在低带宽场景验证过多年。建议放进 backlog,等核心学习闭环(FSRS/发音)跑通后,做分发层时回头读它。

09方法论体系：可理解输入 / Refold / 四股 / shadowing▾

这一层不是代码也不是数据，是「教学法的算法」——决定半米「教什么顺序、用什么方式」的底层逻辑。半米的「行为驱动 AI 学习」如果有理论靠山，就是这些。

① 可理解输入（Comprehensible Input, Krashen）—— 一切的地基

Krashen 的输入假说：语言是「习得」的，不是「学」的——靠接触「比你当前水平略高一点（i+1）、但你能听懂大部分」的输入[23]。配套还有「情感过滤假说」：焦虑、自我怀疑、无聊会像一道滤网，挡住输入[23]——这对儿童尤其重要。Refold 把它量化成一个可操作的数字：当你能懂 70–90% 时，大脑能用上下文补出剩下的 10–30%，习得就发生在这里[24]。

对半米的直接含义：「难度自适应」不只是 SRS 的事，是内容推送的事。半米给孩子推的视频/读物/句子，应该始终卡在「这个孩子能懂 ~80%」的甜区——太简单无聊（情感过滤升高）、太难挫败（同样升高）。结合 Ch5 的 CEFR 分级 + Ch6 的发音弱项数据，半米可以给每个孩子算一个「可理解输入难度档」并动态调整推送。这是把 Krashen 工程化成产品的核心机会。

② Refold / MIA / AJATT —— 沉浸法的工程化谱系

开源工具链（asbplayer/Yomitan/sentence mining）背后的方法论就是这一支。谱系：Antimoon → AJATT（Khatzumoto）→ MIA（Matt vs Japan）→ Refold[25]。核心主张：大量听/读母语内容 + 挖句子做 Anki，输出（说/写）推迟到有强基础后，显式语法可选[24]。

⚠️ Refold 是成人自学者的方法，下沉到 K12 要大改。它假设学习者有超强自驱、会自己经营 Anki、能忍受「沉默期」。小孩没有这些。半米能借的是「可理解输入 + 间隔复习 + 推迟强制输出」的内核，但「自己挖句子、自己管复习」这些必须由半米的 AI/课程替孩子做掉（呼应 Ch4）。

③ Paul Nation 的「四股」(Four Strands) —— 课程配比的标尺

Nation 主张一门语言课的时间应均分到四股（各约 25%）[26]：意义聚焦输入（听/读，其中一半应是泛读）、意义聚焦输出（说/写）、语言聚焦学习（刻意学词汇/语法/发音）、流利度发展（在已会的范围内提速）。还有两条硬指标：泛读材料应让学习者认识 95–98% 的词；高频词靠刻意学、低频词靠教「学习策略」[26]。

对半米：四股是一把现成的「课程体检尺」。半米现在偏重「输入 + 词汇刻意学」（SciShow 词表、SRS），四股提醒它别漏了「输出」（说/写，正好接 Ch6 发音 + Ch7 LLM 陪练）和「流利度」（限时已会内容的提速练习）。「95–98% 已知词」这条还能直接驱动 Ch5 的分级推送逻辑。

④ Shadowing（影子跟读）/ 泛读 / 窄听

  • Shadowing：边听边几乎同步复述，练韵律、工作记忆、发音肌肉[27]。对半米：和 Ch6 发音评测天然咬合——孩子 shadow 一句，AI 评分 + 标错音，是一个完整的口语训练闭环。
  • TPRS（用故事教，Total Physical Response Storytelling）：专为课堂儿童设计的可理解输入法——限制词汇、不停提问、用故事承载目标结构[28]。这是本章对 K12 最对口的方法，半米的「讲故事 + 提问」式内容可以直接参照（HiKid 也用了讲故事）。
  • 泛读 / 窄听：大量易懂材料（泛读）、围绕同一话题反复听不同材料（窄听），都是把可理解输入「量」做上去的手段。

这些书是上面方法论的「原始论文」。对半米的用途：当要解释「为什么半米这么设计」时，引用这些是最硬的背书；也是给阿杰本人补 SLA 内功的书单。

12K12 儿童适配性专章：哪些能直接下沉、哪些要改造▾

这是半米和所有这些开源项目最大的断层：绝大多数开源语言学习工具，是「高自驱成人自学者」造给「高自驱成人自学者」的。东南亚 K12 小孩既没有那个自驱，也没有那个元认知。这章把每类机制判一遍「能不能下沉」。

一条贯穿全章的铁律：把「学习者要做的元认知」全部转移给半米的 AI/系统。成人自学工具的隐藏前提是「学习者会自己决定学什么、何时复习、挑哪句、判断难度」。K12 产品的核心增值，恰恰是替孩子做完这些决策——孩子只需要「来玩 / 来读 / 来说」，难度、选材、复习时机、弱项追踪全部由半米后台用 FSRS + CEFR + 发音评测算好。这正是半米相对这些开源工具的护城河：开源工具给了引擎，半米给了「不需要自驱也能跑」的外壳。

两个「天生儿童向」的开源样本，半米必须研究：

  • HiKid（MIT）——非英语国家儿童的本地 AI 口语 pal。学它怎么把「练口语」伪装成「和 AI 玩」[13]。
  • Antura（BSD-2，Unity）——给（含难民）儿童的识字游戏，多语言含英语，靠迷你游戏关卡教字母/拼读[33]。学它的游戏化关卡设计——这是半米目前相对薄弱、而 Antura 已验证有效（拿过 EduApp4Syria 奖）的部分。

🔴 儿童语音合规(COPPA/FTC)是半米的「第 0 步」,不是后续——因为半米要收儿童语音。发音评测和 AI 口语陪练的输入就是孩子的录音,一旦上线就落进美国 COPPA(以及各地等价法规)的射程,儿童语音录音被明确视为个人信息。FTC 2017 执法政策给了一个狭窄豁免:仅当「① 语音只用作书面文字的替代(如语音指令/搜索) ② 不作他用(不做行为画像、不做声纹识别、不卖不分享给第三方) ③ 用完只短暂保留并立即删除 ④ 隐私政策明确告知收集与删除策略」四条全部满足时,FTC 才不追究「未取得可验证家长同意」;而一旦录音里带姓名等其它个人信息,或要长期保留用于训练/追踪,豁免立即失效,必须走可验证家长同意[39]。给半米的硬动作(必须前置):

  • 可验证家长同意(parental consent):若要保留/训练儿童语音,先有家长同意流程,别先收了再补。
  • 本地处理优先 + 即用即删:能在设备/本地完成评分就别上云;非留不可的录音设短保留期、用完即删(呼应 HiKid 全本地路线)。
  • 保留 / 删除策略 + 数据最小化:明确「存什么、存多久、谁能看、怎么删」,默认只存「评分结果/弱项标签」而非原始录音。
  • audit log + 数据出境地图:记录儿童数据的访问与流向;画清楚「哪条数据从印尼/泰国的设备,经过哪个云,落到哪个区域的存储」——SEA 多国也有本地数据法。
  • 内容安全护栏:LLM 陪练要防「孩子说了不该说的 / AI 生成不适宜内容」,这层所有开源陪练项目都没认真做,半米必须自建。

这一步在 Ch13 决策树里被前置为「第 0 步」,先于所有功能。它不是法律意见(具体合规请律师过),但方向明确:儿童 + 语音 + 商业产品,合规是地基不是补丁。🟡

13★ 半米可借鉴路线决策树：按优先级排，每条标投入产出▾

这是全报告最重要的一章。把前面所有发现，收敛成「阿杰下一步具体做什么、按什么顺序、投多少、得多少」。分档：第 0 步合规地基 → 直接集成 → 抄算法 → 抄方法论 → 只看 UX。

0先于一切 · 儿童合规 & 数据架构（地基,不是后续）

为什么排第 0:半米要收儿童语音(发音评测/口语陪练的输入就是孩子录音),这让它一上线就进 COPPA/FTC 等儿童隐私法规的射程,儿童语音录音被明确视为个人信息[39]。这一步没搭好,后面第 3/4 步(发音、陪练)就是合规地雷。必须前置的设计(先于功能):

  • 可验证家长同意(parental consent):要保留/训练儿童语音前先有同意流程;若只把语音当「文字替代、用完即删、不作他用、隐私政策告知」可走 FTC 狭窄豁免,但带姓名等其它个人信息即失效[39]。
  • 本地处理优先:能本地/端侧评分就别上云(呼应 HiKid 全本地);默认只存「评分结果/弱项标签」,不存原始录音。
  • 保留 & 删除策略 + 数据最小化:明确存什么、存多久、谁能看、怎么删。
  • audit log + 数据出境地图:记录儿童数据访问与流向,画清从 SEA 设备经哪个云落到哪个区域(SEA 多国有本地数据法)。

投入：中(设计+流程,非纯代码)。产出：不做就别上线(它是「能不能合法运营」的前提,不是加分项)。非法律意见,具体请律师过;但方向明确:儿童+语音+商业产品,合规是地基。

优先级排序（投入产出）

1立刻做 · 把 SRS 升级成 FSRS（直接集成）

做什么：选半米后端语言的 FSRS port（py-fsrs / fsrs-rs / ts-fsrs…），把 Roam-based 间隔复习的「固定 1/2/4/7…天」换成「调 FSRS 按孩子表现算下次时间」。

投入：小（一个库 + 改调度层，无需训练，MIT 零授权成本）。产出：大（每个孩子的复习从一刀切变自适应，是「行为引擎」的根本升级）。K12 适配：算法中性，只需把「评分 UI」改成小孩友好。

2立刻做 · CEFR + 词频自动分级（直接拿数据）

做什么：主分级用 olp-en-cefrj 里权威标注的 CEFR-J/Octanove,长尾词用 Words-CEFR-Dataset 推断值当候选标签补位(标「待复核」),再用 wordfreq/COCA 排词频,给半米现有词表/内容自动打「难度档 + 教学顺序」。

投入：很小（几张表 join，纯查表，零模型）。产出：中-大（选词分级从人工变自动，且为 Ch9 的「可理解输入难度自适应」打地基）。三个别省的兜底：① CEFR 等级要再叠一层「话题适龄」过滤(CEFR≠适龄);② Words-CEFR 是推断非权威标注,只当辅助;③ Octanove 部分是 CC-BY-SA,直接随产品再分发要处理 ShareAlike。

3重点投入 · 发音评测 MVP（抄算法 + 借 Echoic 码）

做什么：把 Echoic（MIT）当参考接线图读懂思路(它是 37★ 单人原型、0 正式 release,别直接当生产后端[38]),按发音栈 5 层分别选型自建评分服务(对齐层用 MFA、G2P 用 CMUdict+g2p-en 避开 GPL eSpeak、打分层自封装+benchmark,见 Ch6 矩阵);用 speechocean762 当冷启动基线,但务必自建 SEA L1 小样本校准集(它母语全是 Mandarin,不代表印尼/马来/泰/越口音)。framing 定死:目标是 intelligibility(可懂度)不是 native accent,前端不做口音羞辱。这是半米最大的能力空白 + 最高的差异化。

投入：中-大（有参考实现和基线语料，但分层重搭 + SEA 校准集 + 反馈设计要打磨，比「直接 fork Echoic」更实在）。产出：很大（口语/发音是半米目前完全没有、且家长极在意的能力）。先做成「鼓励引导」不是「严格判分」;评测前先确认第 0 步合规到位(收的就是儿童录音)。替代起点:MVP 可先用云发音评测 API(Azure/ELSA)验证产品价值,再迁自建——单人团队别默认自建更优(见 Ch7)。

4验证性投入 · AI 口语陪练（抄 HiKid 交互 + 借码）

做什么：逐文件读 HiKid（MIT，专为非英语国家儿童），照搬「纯语音不打字 + 故事/游戏包装 + 本地 ASR/TTS」的产品哲学；TTS 用 Piper（Apache-2）打底。和第 3 步的发音评测合成「shadow 一句 → 评分 → 对话」完整口语训练。

投入：中。产出：中-大（但儿童+AI 的内容安全护栏是硬成本，必须前置）。建议：先窄——一个话题、一个固定角色，跑通安全和趣味，再扩。

5抄方法论（零代码，改产品逻辑）
  • 可理解输入 i+1 / 70–90% 懂（Krashen/Refold）→ 内容推送始终卡「孩子能懂 ~80%」的甜区，结合第 2 步分级数据实现。
  • Nation 四股 → 当「课程体检尺」，补齐半米偏弱的「输出（接第 3/4 步）」和「流利度」。
  • TPRS 故事法 → 用 AI 生成「限词汇 + 多提问」的适龄故事（最 K12 对口）。
  • Duolingo streak（带宽容机制） → 习惯回路，但用成就框架、配 Streak Freeze。

投入：小（改逻辑/prompt）。产出：中（让半米的机制有 SLA 理论靠山、配比更合理）。

6只看 UX / 不投入码（参考即可）
  • openkoto（Apache-2）→ 抄「LLM 即时释义/语法拆解」交互（这条若做，可并进第 4 步）。
  • LinguaCafe / Lute → 看「已知词率可视化、导入源组织、dashboard」UX，不 fork（GPL）。
  • asbplayer → 半米若想把 LR 这条外部依赖自有化，参考其字幕对齐/片段造卡（MIT 可借，但优先级低，因 LR 工作流已能用）。

# 伪代码 — 把 Roam 固定间隔换成 FSRS 自适应（py-fsrs 风格）
from fsrs import Scheduler, Card, Rating

scheduler = Scheduler()            # 内置 FSRS-6 默认参数（可用孩子历史复习记录优化）
card = Card()                      # 一张词卡的记忆状态：difficulty / stability / due

# 孩子复习后，给一个反馈（K12 前端把它包装成 表情/星星，别让孩子做元认知自评）
#   Rating.Again=忘了  Hard=有点难  Good=会  Easy=太简单
card, review_log = scheduler.review_card(card, Rating.Good)

print(card.due)        # → FSRS 算出的「下次该复习的时间」（不是固定 1/2/4/7 天）
print(card.stability)  # → 记忆稳定性，越大代表记得越牢、间隔可拉越长

# 半米后台：把所有 due 已到的卡聚成今天的复习队列 → 推给孩子
#   弱项（发音错音/常忘的词）天然 stability 低 → FSRS 自动让它们更频繁出现

代码片段 ② · 发音逐音素打分流程（Echoic 思路）

# 伪代码 — 孩子读一句英语，输出逐音素分（Echoic = WhisperX + wav2vec2 + phonemizer）
audio   = record_child_voice()                 # 孩子的录音（全本地，不上云）
target  = "the cat sat on the mat"             # 标准句子
ref_ph  = phonemize(target)                    # 标准音素序列: ð ə  k æ t  s æ t ...

# 1) wav2vec2 对录音做音素级识别 + 与标准对齐（forced alignment）
hyp_ph, align = wav2vec2_align(audio, ref_ph)

# 2) GOP：逐音素比对「实际发音概率」vs「标准音素概率」，差越大=越不准
scores = []
for ph, post in zip(ref_ph, align.posteriors):
    gop = goodness_of_pronunciation(ph, post)  # 0~1
    scores.append((ph, gop))

# 3) 聚合 + 加权（Echoic 默认 准确0.5 / 流利0.3 / 完整0.2）
word_scores, sentence_score = aggregate(scores, weights=(0.5, 0.3, 0.2))

# 4) ★K12 关键：不展示冷冰冰数字，转成鼓励性引导
#    /θ/ 偏低 → "这个 th 音再试试，舌头轻轻放牙齿中间~ 你刚才已经很接近啦！"
#    低分音素 → 喂回 FSRS（stability 调低）→ 之后这个音的练习会更频繁出现
feedback = to_kid_friendly(word_scores)

FAQ常见问题（11 条）▾

Q如果只能抄一样进半米，抄哪个？＋

FSRS（Ch2/Ch13 第 1 步）。投入最小、收益最确定、MIT 零授权风险，直接把半米「行为引擎」核心定位升一级——从 Roam 固定间隔升到「按每个孩子表现自适应」。一个库 + 改调度层就能上。想要最大差异化则选发音评测（第 3 步），但那个工程量更大。

QFSRS 不就是 Anki 里的一个开关吗，半米能单独用？＋

能。这是最大的误解——FSRS 核心是一个独立的、语言无关的开源算法库，Anki 只是它最有名的调用方。它有 py/rust/go/ts/dart/swift 等 10+ 个 port（MIT）[3]，半米选后端语言对应的那个直接 import 即可，完全不依赖 Anki。

Q这些整套 app（Lute / LinguaCafe / LibreLingo）能不能直接 fork 改成半米？＋

基本都不建议。原因两层：① license——LinguaCafe(GPL)、LibreLingo(AGPL)、Yomitan/jidoujisho(GPL) 都是传染许可，fork 进闭源商业产品会要求你也开源；② 形态——它们都是成人自学者的完整产品，下沉到 K12 要推倒交互重做。Lute(MIT)/asbplayer(MIT)/openkoto(Apache) 可借码，但价值主要在「架构/交互范式」，不在整 app。

Q发音评测能不能不自建，直接买云 API？＋

可以，而且短期更省事（微软/科大讯飞/SpeechSuper 都有成熟发音评测 API）。权衡：云 API 上手快但按次收费、数据要出境（K12 录音的合规风险）；自建（Echoic 路线）前期工程量大但全本地、零边际成本、数据不出设备。建议：MVP 阶段可先用云 API 验证产品价值，确认值得做后再迁到自建省成本 + 解合规。这个 trade-off 值得单独出一份成本对比（Ch14 已标）。

QHiKid 已经做了「儿童 AI 英语口语」，半米还有戏吗？＋

有，而且 HiKid 是利好不是威胁。它证明了「本地 AI 儿童口语 pal」这条路一个开源原型走通了，但它只是一个口语对话玩具——没有课程体系、没有 FSRS 行为引擎、没有 CEFR 分级内容管线、没有发音评测的弱项追踪。半米的护城河恰恰在这些「让不自驱的孩子也能系统进步」的层。把 HiKid 当「免费的交互设计参考实现」逐文件读[13]，而不是当对手。

Q为什么说成人自学工具不能直接给 K12 小孩用？＋

因为它们的隐藏前提是「学习者会自己做元认知」——自己决定学什么、何时复习、挑哪句挖、判断难度。小孩没有这个自驱和元认知（Ch12）。K12 产品的核心增值就是替孩子把这些决策全做掉，孩子只负责「来玩/来读/来说」。所以借的是引擎（FSRS/发音/分级），不是「让用户自己经营 Anki deck」那套自学流程。

Qstreak / 游戏化对小孩有没有副作用？＋

有。Duolingo 的 streak 靠「损失厌恶」驱动（保护连胜不断）[22]，对成人是动机，对小孩断签可能直接变成挫败和放弃。半米抄 streak 必须同时抄宽容机制（Streak Freeze）、把叙事从「别搞砸」改成「你已坚持 N 天真棒」（成就框架），并引入家长视角。游戏化是好工具，但 K12 要用「鼓励」而非「惩罚断签」的版本（Ch12）。

Qwordfreq 停更了，词频数据还能用吗？＋

能用。作者 2022 年主动冻结，原因是「AI 生成文本污染了网络语料、可靠采集词频的方法不存在了」[16]——这是个时代性的好理由。但它的数据是 2021 年前的真人语言快照，对「常用词分级」这种慢变量足够好，Apache/CC license 允许商用。唯一限制：它不会再更新，不收 2023 年后的新词。要更新的词频可补 COCA 等其他源。

Q这套东西用国产模型/工具行不行？＋

本报告默认海外视角（阿杰在海外，Claude/GPT/Gemini 当首选，ASR/TTS 用 Whisper/Piper 等开源）。国产可作「可选补充」：发音评测云 API 科大讯飞成熟、Qwen3 本地小模型（HiKid 就用了）适合离线陪练。但「学英语」这件事上，英语母语数据/模型/语料的生态更厚，开源栈也更全，海外开源优先更稳。

Q「操作系统式架构」具体指半米该怎么做？＋

学开源生态的解耦思路（Ch8）：把「复习调度」独立成服务（内部就是 FSRS），任何内容模块（视频词表/阅读生词/发音弱项）都往它喂「待复习项」——就像 asbplayer/Yomitan 都往 Anki 喂卡、AnkiConnect 当总线。再定义半米自己的「学习对象」开放格式，让所有功能产出同一种对象。这样半米才是真的「学习 OS」而不是一堆各做各的功能。

Q阿杰单人开发，这么多能不能一起上？＋

不能，也不该。六档按优先级排好了（Ch13），别同时开。先把第 1 步 FSRS 跑通上线（一个窄而确定的胜利），再启动第 3 步发音评测的窄 MVP（一个话题、鼓励性反馈），其余进 backlog。先窄、跑通、再宽——这也是军师一贯的拉回。
