怎么打造 AI Agents：小白能照着走的实操能力阶梯

📅 2026-05-29 🔍 无忌 Deep Research · 5 路并行 🪜 无代码 → 框架 → 手搓 🇨🇳 国产平台/中文资源正面覆盖 📚 真实来源 inline 引用
一句话：打造 AI Agent 不是「学不学得会」的问题，是「从哪一级上手」的问题。本报告把它写成一条三级能力阶梯——① 不写代码就能搭（国内首选扣子 coze.cn，5 分钟拖出第一个能用的 bot[9]）→ ② 轻量代码框架（先 CrewAI / OpenAI Agents SDK，~20 行跑通[18]）→ ③ 手搓最小 agent 理解原理（约 50-80 行 Python 的 while 循环，看穿框架本质[29]）。贯穿全篇的一条心智模型：agent = 大脑 LLM + 手（工具调用）+ 记忆 + 循环，和 chatbot 的区别是「会做不只会说」，和工作流的区别是「自己决定怎么做」[1]。国内小白零障碍：几乎所有框架都能改 base_url 接 DeepSeek / 通义千问，无需翻墙、有免费额度[22]。

01执行摘要：给小白的 5 条最关键结论▼

5 路并行调研（概念地基 / 无代码平台 / 代码框架 / 手搓原理 / 学习路径+避坑）收敛出的核心判断，每条独立成块，方便扫。

🪜 结论 1：别纠结「学什么」，走「三级能力阶梯」就对了 🟢 多源

最优路径是三级阶梯：① 先用无代码平台（国内首选扣子 / 腾讯元器 / 阿里百炼，10 分钟拖出第一个能用的 agent，先建立成就感）→ ② 上轻量框架（先做完免费课，再用 CrewAI / smolagents / PydanticAI 写第一个代码 agent）→ ③ 手搓约 50-80 行 Python 的 while 循环看穿原理[30]。关键：别一上来就写代码、别一上来就上 LangChain，先在无代码平台用免费额度跑出一个窄场景 agent 找到手感[30]。

✅ 结论 2：先记住一个心智模型——agent = LLM + 工具 + 记忆 + 循环 🟢 多源

任何 agent 拆开就 4 件事：大脑（LLM）+ 手（工具调用）+ 记忆 + 循环[2]。和 chatbot 的区别是「会做不只会说」，和工作流的区别是「自己决定怎么做」（Anthropic 官方：工作流走预设代码路径，agent 由 LLM 动态决定用什么工具）[1]。最关键纠错：LLM 不执行工具，只输出「我想调用这个工具」的 JSON，真正执行靠你的代码——懂这点心智模型就对一半[2]。

🇨🇳 结论 3：国内小白零障碍——国产平台直连 + 国产模型免费额度 🟢 多源

无代码首选扣子 coze.cn（中文、直连、抖音扫码登录、一键发微信/抖音）[9]；要写代码时几乎所有框架都能改 base_url 接 DeepSeek / 通义千问，无需翻墙、有免费额度（DeepSeek 新用户送 500 万 token[28]，智谱新用户送 2000 万 token 永久有效、阿里百炼新用户 90 天免费[14]）。海外的 Zapier / Lindy 等先放着，等你有梯子且要接 Gmail/Slack 再碰[13]。

⛔ 结论 4：最贵的坑是无限循环烧 token——第一天就设硬上限 🟢 多源

2025 年 11 月一篇广为流传的博文称：一个跑 4 个 LangChain agent 的市场调研 pipeline 意外进入无限循环跑了 11 天、账单 4.7 万美元（🟡 单篇博文轶事、未独立核实，数字当警示而非铁证）[31]。但教训成立：第一天就给 agent 设迭代/token/时间/花费硬上限（ReAct 循环典型设 15-25 步上限）[3]；不可逆操作（发消息/改库/付款）必须人工确认[35]。

⚠️ 结论 5：两个「别过度工程化」的坑——多 agent 后置、旧 AutoGen 别学 🟢 多源

① Multi-agent（多智能体协作）坚决后置：单 agent 能搞定就别上多 agent，一上来就搭多 agent「又慢又贵又难调」[5]。② 新项目别从旧 AutoGen 起步：微软 AutoGen 已进入维护模式（只修 bug、不加新功能），官方继任者是 2026-04 GA 的 Microsoft Agent Framework 1.0——新项目直接用 MAF。旧 AutoGen 维护模式公告之前的教程 API 大概率过时，但 multi-agent 概念本身仍可借鉴，别照抄代码即可[19]。

一句话路线建议

【第 0 步·懂】记住「agent = LLM + 工具 + 记忆 + 循环」，看 Anthropic《Building Effective Agents》建立「能简单就别复杂」的认知[1]。【第 1 步·搭】打开扣子 coze.cn，照模板拖 5 分钟搭出第一个 bot[9]。【第 2 步·写】做完 HuggingFace 免费课，用 CrewAI 或 OpenAI Agents SDK 写第一个代码 agent，模型接 DeepSeek[18]。【第 3 步·拆】照抄一个 80 行的最小 agent 跑一次，读 smolagents 源码看穿原理[20]。详见第 13 章决策树。

🧭 预期校准：今天的 AI 系统大多还在「L1-L2」级 🟡 单源

Vellum 的 L0-L5 agentic 阶梯（2025-12）：今天多数 AI 系统在 L1 基础响应，L2 会用工具这一层创业最活跃，L4 全自主仍受限，L5 全创造远未到达[8]。这条戳破「agent 已全自主」的炒作——你做的第一个 agent 就在 L2，完全够用、也最实用。各家分级口径不统一，属理解脚手架。

02先建心智模型：Agent 到底是什么▼

动手之前先把脑子里的图画对。这一章给三句话的心智模型，建立对了，后面所有工具/框架/范式都只是「在这 4 件事上做花样」。

2.1 三句话分清 Chatbot / 工作流 / Agent

① Chatbot（聊天机器人）

只会说，不会做。你问它答，它不去外面查资料、不操作任何东西。比如普通的问答 bot。

② Workflow 工作流（按写死的步骤做）

会做，但按预先写死的步骤走。Anthropic 官方定义：工作流是 LLM 和工具走「预定义代码路径」[1]。流程是人定的，它只是照做。

③ Agent 智能体（自己决定怎么做）

自己决定流程、能据反馈调整。Anthropic 官方：agent 由 LLM「动态自主决定如何完成任务、用什么工具」[1]。分水岭就是「谁控制流程」。

⚠️ 小白最容易被误导的一点：「agent」这个词被市场严重滥用，很多产品叫 agent 实际上只是 workflow[1]。判断标准永远是那一句：流程是 LLM 自己决定的（agent），还是人写死的（workflow）。

2.2 任何 agent 拆开就 4 件事

🧠 LLM
大脑：理解 + 决策
🛠️ 工具
手：function calling 调用
💾 记忆
短期上下文 + 长期向量库
🔁 循环
反复思考-行动-观察

白话拆解：

  • 大脑（LLM）=理解你要什么、决定下一步干嘛。
  • 手（工具调用 / function calling）=这里有个关键纠错：LLM 并不亲自执行工具，它只输出一段结构化 JSON，意思是「我想调用 查天气 这个工具，参数是北京」；真正去执行的是你的代码，执行完把结果喂回给 LLM[2]。懂这点，心智模型就对一半。
  • 记忆（memory）=短期（这次对话的上下文窗口）+ 长期（跨会话存到向量库）。第一个 agent 只用短期记忆就够，长期记忆涉及 embedding / 向量库对小白偏抽象，不必一上来就上[2]。
  • 循环（loop）=反复「思考 → 行动 → 观察」直到任务完成。

💡 中文等价公式：国内资料常写的 「智能体 = 大模型 + 规划 + 记忆 + 工具」 和上面 4 件事是同一回事[7]。先记住任意一个版本即可。

03架构范式说人话（ReAct / 范式 / RAG / MCP）▼

所有「范式」都是在第 2 章那 4 件事上做花样。小白不用全懂，只需把下面几个词当「黑话词汇表」会用即可，第一个 agent 只需 ReAct + 工具调用。

3.1 ReAct——最该先懂的范式

ReAct = Reasoning + Acting（推理 + 行动），本质就是一个 while 循环：Thought（想下一步）→ Action（调工具）→ Observation（看返回结果）→ 再 Thought，循环到任务完成才停[2]。源自 2022 年 Yao 等论文，比纯推理或盲目调工具效果显著更好（在 ALFWorld 基准 +34%、WebShop +10%）[32]。这三步规则常直接写在 system prompt 里。

⛔ 手搓务必加上限：纯 ReAct 容易死循环烧 token，生产环境必须设 max iterations（典型 15-25 步）和 token 预算上限[3]。这是第 11 章会反复强调的第一坑。

3.2 四大设计范式（Andrew Ng）——黑话词汇表

吴恩达 2024 年提出、已成行业通用语言，记住四个词的含义即可[4]：

范式白话小白要不要先用
Tool Use 工具使用决定调用哪个工具✅ 第一个 agent 就用
Reflection 反思检查并改进自己的输出🟡 进阶
Planning 规划把大任务拆成子任务🟡 进阶
Multi-agent 多智能体多个专长 agent 协作⛔ 坚决后置

⚠️ 别过度工程化：易让小白误以为「必须四范式全上」。第一个 agent 只用 Tool Use + 简单 loop，其余后置[4]。

3.3 Multi-agent 多智能体——为什么要后置

多个专长 agent 分工，通常有一个 orchestrator/supervisor（编排者/主管）负责拆任务、分派、汇总，它自己不干活只规划路由，像呼叫中心的派单经理[5]。判断标准：单 agent 能搞定就别上多 agent——单 agent 适合自包含的短链条任务；多 agent 才适合复杂长链条/多专长/可并行的任务[5]。小白最易掉的坑就是一上来就搭多 agent，又慢又贵又难调。

3.4 RAG——和 agent 是两回事

RAG（检索增强生成）：LLM 回答前先去外部知识库（通常是向量库）检索资料、再基于资料生成答案，解决「知识过时」和「瞎编」[6]。流程：问题转成向量 → 向量库匹配相关片段 → 喂给 LLM 生成。关键认知：RAG 只让答案更准，它不做决策、不行动——这是它和 agent 的根本区别[6]。比喻：RAG 像给 LLM 加了研究笔记，agent 像项目经理。两者常组合——agent 把 RAG 当成一个工具来用。做「自家文档问答助手」用 RAG 就够，不必上 agent。

3.5 MCP——2025-2026 接工具的事实标准

MCP（Model Context Protocol，模型上下文协议）是 Anthropic 2024-11 推出的开放标准，相当于「AI 世界的 USB-C 接口」[11]。解决的痛点是 N×M 集成难题：一个工具写成一个 MCP server，就能被所有支持 MCP 的客户端（Claude / ChatGPT / Cursor / VS Code）调用，一次接好、到处可用。server 暴露三种东西：Tools（可调函数）、Resources（可读数据）、Prompts（可复用模板）。

为什么学了不会过时：2025-03 OpenAI 采纳、2025-04 Google Gemini 支持、2025-12 捐给 Linux 基金会的 Agentic AI Foundation 中立治理[11]；下载量从 2024-11 约 10 万涨到 2025-04 超 800 万，已有 5800+ servers、300+ clients[11]。小白上手门槛：在 Claude Desktop / Cursor 里配现成 server 很低，自己写 server 稍进阶。

⚠️ 安全提醒：MCP 概念偏抽象，安全面（恶意 server、prompt injection 提示注入、权限边界）需注意——配第三方 server 时是真实隐患[11]，别随便装来路不明的 server。

06路线二·代码框架横评（小白先学哪个）▼

要写点代码的框架分三档：① 最低门槛入门（CrewAI / OpenAI Agents SDK）→ ② 工业级主力（LangChain/LangGraph / LlamaIndex）→ ③ 用来看懂原理（smolagents / Pydantic AI）。还有几个偏特定生态的（微软/谷歌/Anthropic）小白别当起点。

07路线三·手搓最小 Agent（看穿原理）▼

这是破除框架黑箱的关键一步。结论先说：一个 agent 的本质极其简单——agent = LLM + 工具 + 一个 while 循环。所有框架都只是在这个循环外面包了一层管理（上下文、安全、成本），核心循环是同一段代码穿不同的衣服[29]。

7.1 最小 agent 的 6 行循环逻辑

循环逻辑只有六行：① 调 LLM（带上工具定义）→ ② 如果返回了 tool_call 就执行工具、把结果塞回消息历史 → ③ 继续循环 → ④ 直到 LLM 不再要工具、直接出文本就停[29]。五大组件：语言模型、工具（函数 + JSON schema）、消息历史、while 循环、停止条件[29]。

7.2 OpenAI function calling 的 5 步流程

function calling 是手搓 agent 的第一道门槛，本质 5 步[43]：

  1. 定义工具：给每个函数写 JSON schema（名字 + 参数描述）。
  2. 模型返回 tool call：LLM 不执行，只输出「我想调用哪个工具、参数是什么」。
  3. 本地执行：你的代码解析 tool_calls，真正跑那个函数。
  4. 把结果回传：以 {role:'tool', tool_call_id, content} 追加到消息历史。
  5. 拿最终答案：再调一次 LLM，它基于工具结果给出回答（或继续要下一个工具）。

💡 2025 新增 Responses API：经典 Chat Completions 仍可用[43]。小白照旧用 Chat Completions（解析 response.choices[0].message.tool_calls）即可。

7.4 新手最常见的坑（消息顺序）

⛔ 最常见新手坑：把工具结果在 assistant 消息之前 append。消息历史顺序必须是 [用户] → [assistant 含 tool_calls] → [tool 结果(带 tool_call_id)] → [assistant...]，顺序反了会校验失败——这是 OpenAI Chat Completions 风格 API 的通用约束[29]。⚠️ 但各家国产 provider 仍有细节差异（如阿里 Qwen 兼容端点对 tool_call_id 的要求、tools 与 stream=True 的兼容性、支持工具调用的模型范围各不同），照搬前先看对应官方文档。

08核心概念深一点：工具/记忆/上下文/RAG/MCP▼

跑通第一个 agent 后，这几个概念决定你能不能做出「好用」的 agent。小白第一个项目不必全上，但要知道它们是啥、什么时候加。

8.1 工具设计——要像写 prompt 一样下功夫

⚠️ 最常见失败模式之一：工具集臃肿、功能重叠，导致「选哪个工具」的决策点模糊[35]。Anthropic 的建议：Agent-Computer Interface（ACI，agent 和工具之间的接口）要靠完善的工具文档和测试精心打造；工具应自包含、容错、用途极清晰，参数描述性强无歧义。生产级实践含：工具优先、单工具单职责、外部化 prompt 管理、KISS 原则（保持简单）[35]。

8.2 记忆——短期够用，长期后置

记忆分两层：短期=这次对话的上下文窗口（第一个 agent 只用这个就够）；长期=跨会话存到向量库，IBM 又细分为语义/情景/程序三类[2]。长期记忆涉及 embedding（把文字转成向量）/ 向量库，对小白偏抽象，不必一上来就上。

8.3 上下文 & RAG & MCP——快速回顾

  • 上下文（context）：喂给 LLM 的所有信息（指令 + 历史 + 工具结果 + 检索资料）。管理它是 2025 新兴的「上下文工程」话题 🟡 待补研究，本报告未深挖。
  • RAG：见第 3.4 节——让答案更准但不行动；agent 把 RAG 当工具用。做「自家文档助手」用 RAG 即可[6]。Agentic RAG（agent 自主决定检索什么）是进阶概念 🟡 待补研究。
  • MCP：见第 3.5 节——接工具的事实标准，现成 server 生态巨大；配第三方 server 注意安全[11]。

💡 小白第一个项目的取舍：记忆只用短期、RAG 只在「要读自家文档」时加、MCP 只在「想接现成工具」时配。别一上来就把这些全堆上去。

⚠️ 待补研究（evidence gap）：① 国产模型（智谱/Qwen/DeepSeek）对 function calling 和 MCP 的原生支持及中文文档质量未深挖；② 上下文工程作为 2025 新兴框架词只顺带提及；③ Agentic RAG 作为 RAG↔agent 过渡话题未深挖。

10第一个 agent 做什么不劝退▼

第一个项目别贪大。Anthropic 反复强调「start simple——先单次 LLM 调用 + 检索 + 示例，简单方案不够用了再加 agentic 复杂度」[1]。选个窄而可衡量的场景。

✅ 推荐的入门项目（窄、可衡量）

  • FAQ 客服 bot——喂一份文档，回答关于它的问题（用 RAG，无代码平台 10 分钟）
  • 资料整理助手——给链接/文本，自动总结归类
  • 个人助理——查天气/查资料/简单待办（最适合手搓练 ReAct）
  • 编码助手——读文件/列目录/改代码（Thorsten Ball 同款，手搓最佳练手）

⛔ 第一个 agent 别碰

  • 多 agent 协作系统——又慢又贵又难调，坚决后置[5]
  • 长期记忆 + 向量库——对小白偏抽象，第一个用短期记忆即可[2]
  • 不可逆操作（自动付款/删库/群发）——必须先有 human-in-the-loop[35]
  • 全自主无人值守——今天的系统大多还在 L1-L2[8]

💡 为什么选「窄而可衡量」：窄 = 容易跑通、容易调试、容易有成就感；可衡量 = 你知道它「做对了没有」（FAQ 答得准不准、总结全不全），方便后面加评估。Agent 的能力上限取决于它能访问的数据和工具——先做小，跑通了再扩[46]。

11常见坑与避坑▼

这些坑每条都有真实代价，按「最贵→最常见」排。

🔴 坑 1：无限循环烧 token（最贵）🟢 多源

2025 年 11 月真实案例：4 个 LangChain agent 的市场调研 pipeline 意外进入无限循环，跑了 11 天、账单 4.7 万美元——agent 因概率本质误判终止信号而反复调同一工具[31]。避坑：硬上限（迭代/token/时间/花费）在生产中不可妥协，且预算限制必须多层（每会话/每用户/每工具），不能只在应用层[31]。手搓时第一天就在 while 循环里写 for step in range(15)。

🟡 坑 2：工具集臃肿、功能重叠 🟢 多源

工具太多、职责重叠会让模型「选哪个工具」决策模糊，是最常见失败模式之一[35]。避坑：单工具单职责、用途极清晰、参数无歧义、像写 prompt 一样写工具文档[35]。

🟡 坑 3：上下文爆炸 / 消息顺序错 🟢 多源

循环跑多了消息历史越堆越长（上下文爆炸，又慢又贵）；手搓时把工具结果在 assistant 消息之前 append 会直接校验失败[29]。避坑：控制历史长度、严格保证 [assistant 含 tool_calls] → [tool 结果] 顺序。

🟡 坑 4：过早上框架 / 过度工程化 🟢 多源

Anthropic：框架会掩盖底层代码让调试变难、并诱使你过早加复杂度，应先用直接 API 调用理解机制再上框架[1]。尤其别一上来就上多 agent[5]、别学旧 AutoGen[19]。

🟡 坑 5：幻觉 / 缺评估 🟢 多源

LLM 会瞎编（幻觉），且 agent 是概率系统、难调试。避坑：要接私有/实时知识用 RAG 降幻觉[6]；从一开始就铺日志和评估（见第 12 章），否则你根本不知道 agent 好不好。

12评估、调试、部署上线（小白够用版）▼

Agent 难调试（概率系统、多步），所以「怎么知道它好不好」和「上线前要铺什么」是必修。这里只讲小白够用的最小实践。

12.1 调试的眼睛：trace / 可观测

调 agent 要看 trace（执行树）——每一步选了什么工具、传了什么参数、检索了什么。推荐 Langfuse（开源、19000+ stars、MIT，2025-06 把 LLM-as-judge 评估/标注/prompt 实验全开源转 MIT）[47]；用 LangChain 的人配 LangSmith 自动集成。纯无代码平台用户用平台自带日志即可，OpenAI Agents SDK 自带 tracing[36]。

12.2 评估：Evaluation-Driven Development

评估应作为开发的持续环节，用 LLM-as-judge（让另一个 LLM 当裁判）规模化评估 + 人工复核兜底高风险样本[48]。agentic 系统评估要超越单模型基准，看整体行为：工具选择准确性、多步推理连贯性、任务完成率；生产环境评估须异步跑、不阻塞响应[48]。

12.3 上线前三件套

预算限制 + 护栏 + 监控，必须在 agent 接触真实用户/数据/外部系统之前就位[35]：

  • 护栏 + human-in-the-loop：不可逆操作（发消息/改库/付款）必须显式人工确认；定义决策边界（如密码重置可自主、>$500 退款转人工）[35]。
  • 监控/日志：上线前先记全量日志（每次工具调用、输入输出、每任务成本、trace ID、上报事件）[35]。
  • 预算限制：多层硬上限（呼应第 11 章那 4.7 万美元的教训）[31]。

⚠️ 推荐学习顺序（Brightdata roadmap）：定目的 → 设计工作流（节点图）→ 选数据源 → 选模型 → 集成工具(MCP) → 实现逻辑(框架) → 测试迭代(含边界用例) → 部署监控；先判断「到底需不需要完整 agent 还是简单 workflow」[46]。

15FAQ▼

Q完全不会写代码，能做 AI agent 吗？+

能，而且应该从这里开始。直接打开扣子 coze.cn（中文、国内直连、抖音扫码登录），照模板拖拽 5 分钟就能搭出第一个能用的 bot 并一键发到微信/抖音[9]。想要更强可定制再上 Dify（理念和扣子几乎一样）。

QAgent 和 ChatGPT、和 workflow 到底差在哪？+

一句话：chatbot 只会说不会做，workflow 会做但按写死的步骤走，agent 自己决定怎么做。Anthropic 官方区分标准是「谁控制流程」——workflow 走预定义代码路径，agent 由 LLM 动态决定[1]。注意很多产品叫 agent 其实只是 workflow。

Q国内用，要不要翻墙？模型选哪个？+

无代码用国产平台（扣子/元器/百炼）全部国内直连[9]；写代码时几乎所有框架都能改 base_url 接 DeepSeek / 通义千问，无需翻墙、有免费额度（DeepSeek 新用户送 500 万 token[28]）。海外的 Zapier/Lindy 才需要翻墙。

Q第一个该学哪个代码框架？+

先 CrewAI（团队比喻、~20 行、1 小时跑通）或 OpenAI Agents SDK（一条命令、自带 tracing），二者学习曲线被多篇评测列为最低[18]。千万别一上来学 LangGraph（概念多易劝退）或旧 AutoGen（已停更）[19]。

Q手搓一个 agent 到底要写多少代码？+

很少。核心循环约 35 行，含工具的完整最小 agent 约 60-80 行 Python[30]。Thorsten Ball 用 315 行 Go 写出能改代码的编程 agent，结论是「一个 LLM、一个循环、足够的 token，没有秘密」[41]。

QLLM 是自己执行工具吗？+

不是。LLM 只输出一段 JSON 说「我想调用这个工具、参数是什么」，真正执行靠你的代码，执行完把结果喂回给 LLM[2]。懂这点，agent 的心智模型就对一半。

QRAG 是不是 agent？需要先学 RAG 吗？+

不是。RAG 只让答案更准，不做决策不行动，这是它和 agent 的根本区别[6]。如果你只想做「自家文档问答助手」，用 RAG 就够，不必上 agent。两者常组合——agent 把 RAG 当一个工具用。

QMCP 必须学吗？难不难？+

是 2025-2026 接工具的事实标准，值得了解，学了不会很快过时（已被 OpenAI/Google 采纳、捐给 Linux 基金会）[11]。在 Claude Desktop/Cursor 里配现成 server 门槛低，自己写 server 稍进阶。⚠️ 配第三方 server 注意安全（恶意 server、prompt injection）[11]。

Q第一个 agent 该做什么项目？+

选窄而可衡量的：FAQ 客服 bot、资料整理助手、个人助理、编码助手[1]。别碰多 agent、长期记忆、不可逆操作、全自主无人值守——这些都该后置[5]。

Q我会不会一不小心烧很多钱？+

有这个风险——2025 年 11 月有 agent 无限循环跑 11 天烧 4.7 万美元的真实案例[31]。避坑：第一天就设迭代/token/花费硬上限（ReAct 循环典型 15-25 步上限），且预算限制要多层[3]。练手用国产模型免费额度，基本花不到钱。

Q怎么知道我的 agent 做得好不好？+

要看 trace + 做评估。用 Langfuse（开源免费）看每一步选了什么工具、传了什么参数[47]；用 LLM-as-judge 规模化评估任务完成率、工具选择准确性，高风险样本人工复核[48]。无代码平台用自带日志即可。

Q为什么大家都说「别一上来就用框架」？+

Anthropic 官方明确：框架会掩盖底层代码让调试变难、并诱使你过早加复杂度，建议先直接用 LLM API 理解机制，很多 agent 模式几行代码就能实现，只在性能确有提升时才加复杂度[1]。这也是本报告把「手搓」放进阶梯的原因。
