一句话定调：小贝技术上没有一处是「做不出来」的——开源底座齐全，单人 + AI 完全能拼起来。真正决定成败的不是「能不能写」，而是「按什么顺序写、先验证哪个窄楔子、哪些坑会吃掉你三倍工期」。本报告把小贝拆成 ~13 个原子功能逐一给开源底座（标 ✅可 fork / 🟡借架构 / ⛔只能看），给单人+AI 的类比工期（标⚠️非承诺），划三阶段，画 roadmap 节奏图，最后诚实回答「能不能逆向欧路抄码」（答案：合法的是看交互 clean-room，反编译抄码不划算）和「要不要立项/办软著」（答案：写一页项目章程＝必做；软著＝可选不急；科技项目立项＝单人 indie 不需要）。

三个最关键判断（先扫这个）：① 没有任何一个开源 App 值得整体 fork——最接近的桌面近亲（glucose_media_player / yall-mp）要么 EUPL/GPL 传染、要么形态不对，价值在「读架构」不在「抄代码」；该 fork 的是算法/库层（whisperX BSD-2、ts-fsrs/fsrs-rs MIT/BSD-3、subtitle.js MIT），整 App 层只借交互。② 工期瓶颈不在写代码，在集成/调参/跨端打磨/合规打包——AI 几小时写完的逐句对齐逻辑，可能要花几周调精度；最该先上的是「一个本地视频能逐句精听跟读」的窄 demo（M0–M3），别一上来铺全功能。③ 逆向不是路——中国《软件保护条例》第十七条允许「为学习设计思想/原理而研究」，但反编译抄代码超出此边界且对单人毫无收益（AI 自己能写得更干净），合法且推荐的只有「装来用、看它交互怎么设计」这一层。

② 三阶段（一句话）

1阶段一 · 窄楔子（验证有人要）
「导入一个本地视频 → 自动转写出字幕 → 逐句循环精听 + 逐句跟读录音回放」跑通。出口：种子用户愿意天天用这一条链路。暂不做发音评分/SRS/挖空。
2阶段二 · 核心精学闭环
加 shadowing 影子跟读、发音评分（云·讯飞）、挖空字幕精听、生词进 SRS（FSRS）、双端签名公证正式分发。出口：留存 + 付费意愿验证。
3阶段三 · 放量 + 变现 + 降本
变现（订阅/买断）、把发音评分从云迁本地降成本/解合规、性能与多视频库管理、国内分发合规（ICP 备案等）。出口：单位经济成立。

先上什么（拍板）：阶段一的 M0–M3 = 「一个本地视频能逐句精听 + 跟读回放」。理由：这是小贝的不可替代内核（任意本地文件 + 全本地处理），也是最便宜能验证「有没有人真的要」的窄链路。发音评分/SRS/挖空都是「锦上添花」，等内核被证明有人用再加——别在没人用的产品上先堆复杂功能。

③ 总工期量级 🔴 类比估算/行业体感，非承诺

对「海外单人 + AI 辅助写码」：乐观 ~2–3 月（只到阶段一可玩 demo）/ 现实 ~4–6 月（到阶段二精学闭环 + 双端正式分发）/ 悲观 ~8–10 月（对齐精度/发音评分体验/跨端打包反复打磨 + 合规）。⚠️ 这是类比同复杂度单人媒体类 Tauri 项目的体感，不是承诺——真实工期由「对齐和发音评分调到能用」这两处的反复次数决定，可能差 2–3 倍。详见 Ch4。

④ 立项 & 逆向（一句话结论）

立项：单人 indie 的「立项」=写一张一页纸项目章程（愿景/范围做什么不做什么/成功指标/里程碑/预算/时间盒）——必做、半小时的事（Ch9 给模板）。软著登记：基础登记自 2017-04 起免费、周期约 30 工作日、非上线必需[21]，要权属凭证或上架部分渠道时再办，不急。科技项目立项（政府科技计划/高企）：是企业拿政府经费的审批流程[24]，单人 indie 完全不需要。

逆向：能不能逆向欧路/LR 抄功能？合法且推荐的只有一层——装来用、研究它的交互/产品设计（中国《软件保护条例》第十七条允许「为学习设计思想和原理而使用软件」[18]；trade secret 通过合法反向工程获得也不算侵权[20]）。但反编译它的二进制去抄代码超出「学习思想原理」边界、踩著作权/EULA/反法红线，且对单人毫无收益——AI 自己写得更干净、可维护、无法律风险。结论：🟢 看交互学产品设计；⛔ 别反编译抄码。

读这张矩阵的方法：🟢 的六个（1/2/10/11 + 大半个 5）是「AI 一把过、堆几天就有」的——它们不构成风险，不值得纠结。真正决定项目成败的是三个 🔴：#4 逐句对齐精度、#7 发音评分体验、#13 跨端打包签名。这三个的共同点是「代码 AI 能写，但写完离能用还很远，要反复在真实环境里调」——工期和心力都该重仓在这里（Ch4/Ch7 深挖）。中间一档 🟡 是「路清楚、按部就班做」的主体工作量。

注意 #4 和 #5 的依赖链——这决定了 roadmap 顺序：没有转写（#3）就没有字幕，没有对齐（#4）就没有可靠的句级时间戳，没有句级时间戳逐句循环（#5）就做不出来；没有录音（#6）就没法发音评分（#7）。所以底层链路必须按 播放→字幕/转写→对齐→逐句→录音→评分 的顺序搭，不能跳（Ch6 roadmap 会把这条依赖画成甘特图）。

最重要的一条结论：没有任何一个「整 App」值得 fork。最像小贝的四个近亲——glucose_media_player（EUPL-1.2 copyleft）、yall-mp（GPL-3）是copyleft 传染，fork 进闭源商业产品要么违规要么被迫开源；asbplayer（MIT 但是浏览器扩展，碰不到本地文件，形态根本不对）；HiKid（MIT 但Electron + macOS-only，壳和平台都不是小贝要的）。它们的价值全在「读架构 / 抄交互范式」，不在代码本身——这跟父报告/github-eng 报告的判断一致：「算法和库可以拿，整套 app 基本只能看」[3]。

该真 fork 的是「库层」——三件套

真正能 ✅ 直接 fork 进小贝（闭源）的，是这几个 license 友好的库/算法：

  • whisperX（BSD-2）——逐句/逐词对齐的事实标准，22.4k★、2026-05 仍活跃[5]。代码 BSD-2 可商用；小贝只用它的强制对齐（forced alignment）那部分，用不到 diarization（说话人分离），正好绕开 pyannote 模型 CC-BY-4.0 + HF 门控这层麻烦。🟢
  • ts-fsrs（MIT）/ fsrs-rs（BSD-3）——SRS 调度算法，2026-06 都更到 FSRS v6[6][7]。选型建议：小贝是 Tauri，复习调度若放前端用 ts-fsrs（JS，最省事）；若想放 Rust 后端统一管数据，fsrs-rs 是纯 Rust 无重依赖，天然贴 Tauri 后端。二选一即可，别两个都引。🟢
  • subtitle.js（MIT）——字幕解析，435★，2022 后停更但格式稳定可用（SRT 完整、VTT 部分）[11]。⚠️ 若需要 ass/ssa 完整支持，再找补充库或自己补。🟡
  • whisper.cpp（MIT，父报告已定）+ tauri-plugin-sql/store（MIT/Apache）+ Web 录音 API——这几个 license 全干净，直接用。

关键项展开：glucose_media_player —— 最该「读」的那个

glucose_media_player 几乎是「小贝的开源骨架预览」：Tauri + Svelte + Rust，Windows 向，本地 Whisper 转写生成字幕、srt/vtt/ass 全支持、从 MKV/MP4 直接抽内嵌字幕、双音轨、画中画，99★、v3.6.1（2026-06）非常活跃[8]。它已经把小贝阶段一要解决的「Tauri 里怎么播本地视频、怎么调本地 Whisper、怎么渲染字幕」全趟过一遍。但它是 EUPL-1.2（一种 copyleft/有 share-alike 性质的欧盟公共许可），不能 fork 进闭源商业产品——正确用法：装来用、读它的 src 目录结构和 Tauri 配置、理解它怎么接 Whisper，然后用 AI 自己重写一遍干净的实现。这跟逆向章的精神一致：学思路合法，照搬受 license/版权约束的代码不合法。🟡 EUPL 性质以其 LICENSE 为准

04整体开发难度真相 + 工期估算（单人 + AI 辅助）▾

先把一句反直觉的真相说清楚：对小贝，写代码不是瓶颈。父报告已反复确认「这条链路每一环都有成熟开源、AI 都能拼起来」——本章承接它，回答「那真正吃工期的是什么、单人+AI 大概多久」。

瓶颈不在「写」，在这四处「写完离能用还很远」：

  • ① 集成质量：13 个功能各自跑通是一回事，串成「不卡、不崩、状态一致」的整体是另一回事。单人项目最容易死在「每个零件都行、合起来全是边角 bug」。
  • ② 调参（尤其对齐 + 发音评分）：whisperX 对齐在干净录音上很好，但用户的视频有背景音乐、口音、多人对话——把它调到「逐句循环不切错词」要在真实素材上反复试[5]。发音评分要把云 API 的多维分映射成用户能看懂、不打击信心的反馈，这是产品调校不是写代码。
  • ③ 跨端打磨：Tauri 用系统 WebView，Win/Mac 渲染、codec、文件路径、权限行为有差异；不能在 Mac 上交叉编译 Windows 包，要 CI 矩阵（父报告 Ch3）。
  • ④ 合规打包：双端签名公证、中国 Windows 签名路径、SmartScreen 冷启动——是持续工程税（见《签名公证 spec》），不是一次性。

05三阶段划分：每阶段功能清单 + 出口标准 + 耗时▾

三阶段的设计原则：每阶段只验证一件最关键的事，验证通过才进下一阶段。别把「全功能」当目标，把「下一个验证」当目标。

1阶段一 · 窄楔子：验证「有人要这条链路」

功能清单（只做这些）：导入一个本地视频 → （无字幕则）whisper.cpp 本地转写 → whisperX 逐句对齐 → 字幕逐句高亮渲染 → 逐句循环精听（AB 复读）→ 录音 + 回放对比。不做：发音评分、shadowing、挖空、SRS、签名公证（开发期自用/给种子用户可临时绕过，见签名 spec 的 MVP 策略）。

✅ 出口标准（验证指标）：① 找 5–10 个真实目标用户（国内 Windows 英语学习者），② 给一个能用的 demo，③ 看有没有人主动连用 3 天以上、愿意拿自己的剧/网课视频来精学。有人天天用 → 进阶段二；没人用 → 停下来想为什么，别急着堆功能。

耗时：乐观 ~4 人周 / 现实 ~7 人周 / 悲观 ~12 人周（#4 对齐是最大变量）。🔴 类比估算

2阶段二 · 核心精学闭环：验证「留存 + 付费意愿」

功能清单：shadowing 影子跟读 + 发音评分（云·讯飞 ISE，接入见姐妹 spec）+ 挖空字幕精听 + 生词进 SRS（FSRS）+ 本地数据存储 + 双端签名公证正式分发 + updater。这一阶段把「精听 → 跟读 → 评分 → 生词复习」串成完整闭环。

✅ 出口标准：① 次周/次月留存达到自定阈值（如周留存 >30%），② 有一定比例用户表达付费意愿（愿意为发音评分/无限视频付费），③ 发音评分反馈被用户认为「有用、不打击信心」。留存 + 付费意愿双证 → 进阶段三。

耗时：乐观 ~5 人周 / 现实 ~9 人周 / 悲观 ~16 人周。🔴 类比估算

3阶段三 · 放量 + 变现 + 本地化降本：验证「单位经济成立」

功能清单：变现（订阅/买断/额度）+ 发音评分从云迁本地（gopt/kaldi GOP 自建，降云成本 + 解数据出境合规，父报告 Ch7 已定「确认价值再迁本地」）+ 多视频库/资料管理 + 性能优化 + 国内分发合规（ICP 备案、必要时软著）。

✅ 出口标准：① 付费转化 × 客单价 > 获客 + 云评分成本（单位经济为正），② 本地发音评分质量被用户接受（不显著差于云），③ 分发合规无阻碍。单位经济成立 → 可考虑加投/扩张。

耗时：乐观 ~3 人周 / 现实 ~6 人周 / 悲观 ~12 人周（本地化发音评分是最大变量）。🔴 类比估算

⚠️ 阶段划分的纪律：发音评分本地化故意放到阶段三，不要提前。父报告已拍「MVP 用云、确认价值再迁本地」——因为自建本地 GOP（gopt/kaldi）是个大坑（要训练/调校/建 SEA 口音校准集，见 github-eng 报告 Ch6），在「还不知道有没有人要」的阶段就去啃它是浪费。同理 SRS、挖空都放阶段二，阶段一就死磕「逐句精听跟读」这一条链路把它做到顺。

🍎 vs 🪟 Mac 端和 Windows 端，是一起开发还是先做完一个？

核心代码一起开发，不是「先做完一端再从头做另一端」。你选了 Tauri，它的根本价值就是一套代码、两端构建——前端 UI + Rust 后端写一遍，tauri build 分别出 Mac 包和 Win 包。上面 M0–M11 的功能链路绝大多数是平台无关的，写一次两端都有，根本不存在「做两遍」。把「先做完 Mac 再从头做 Windows」当默认节奏，是对跨平台框架最大的误解。

但平台差异点要从第一天就并行盯，别攒到最后：

  • WebView 内核不同：Windows 走 WebView2（Chromium 内核）、Mac 走 WKWebView（Safari 内核）——同一段前端在两边的渲染 / 音视频 / 录音 API 行为可能有差异，尤其录音和媒体这类小贝重度依赖的能力。
  • sidecar 二进制各编一份：whisper.cpp / ffmpeg 要按每个 OS 各编译一份，不能跨平台交叉编译（父报告 Ch3）。
  • 签名公证两套、原生解码器、文件路径权限两端各有差异（见《签名公证 spec》）。

纪律：从第一天就上 CI 矩阵双端构建（tauri-action）+ 一台真 Windows 机 / VM 持续测。最经典的坑就是「Mac 上跑得好好的，最后打 Windows 包全是问题」——差异攒到最后才碰，代价最大。

真正能「错开」的是上线发布顺序，不是开发本身：你日常在 Mac 上开发（主力 debug 在 Mac），但目标用户 Windows 优先，这俩有张力。建议节奏：① 先发 Mac（公证便宜标准化、$99 免 DUNS、notarytool 四步，先给种子用户验证「产品到底有没有人要」）→ ② Windows 紧随主攻（目标主力，但签名最贵最难，要先解决云签名 / SmartScreen 冷启动，见签名 spec），或两端同时发、Windows 先接受初期 SmartScreen 摩擦。一句话：代码一起写、平台差异 CI 矩阵从第一天并行盯、上线可 Mac 先行验证 + Windows 主攻——绝不是串行做两遍。

07哪些简单哪些复杂（深入）：最该轻松对待 vs 最该重仓▾

Ch2 给了矩阵，这里挑最两极的几个深挖——告诉你「为什么简单」「为什么复杂」「坑在哪」，好让你心力分配对。

🟢 最简单的几个（别在这上面纠结）

① 字幕渲染 + 逐句高亮——纯前端。解析用 subtitle.js（MIT）[11]，渲染就是把当前时间对应的那句 DOM 高亮。唯一坑：时间轴漂移（字幕和音画对不上）——但这恰恰是 M3 对齐要解决的，渲染本身不难。
② SRS 接 FSRS——调库就完事。ts-fsrs/fsrs-rs 把算法全封装好，你只需「记录用户对生词的回忆评级 → 调 scheduler 拿下次复习时间」[6][7]。难的不是算法，是「生词卡怎么生成、复习入口放哪」这种产品设计。
③ 基础播放 + 数据存储——HTML5 video + tauri-plugin-sql（SQLite）[4]，AI 一把过。

🔴 最复杂的几个（重仓在这）

① 逐句/逐词强制对齐精度（#4）——小贝的真·技术核心难点。whisperX 的 wav2vec2 强制对齐在干净朗读上能到词级 ±50ms[5]，但用户的视频是真实素材：背景音乐、笑声、多人抢话、口音、语速快——这些会让对齐「切错词、整句偏移」，直接毁掉「逐句循环」体验（循环到一半切到下一句）。坑：① 音乐/噪声段要先 VAD 切掉再对齐；② 对齐失败的句子要有 fallback（退回 whisper 自带的粗时间戳）；③ 不能当硬 SLA，要在目标媒体/口音上实测（父报告已警示）。这是最该花时间反复调的地方。

② 发音评分集成 + 调参（#7）。MVP 接讯飞 ISE（姐妹 spec 给了接入细节）——接口调通不难，难在把云返回的「准确度/流利度/完整度 + 音素级分」翻译成用户看得懂、不打击信心的反馈。坑：① 分数怎么呈现（数字会让人焦虑，颜色/进步曲线更友好）；② 录音质量差时别给假低分（要先判录音是否有效）；③ 本地化（阶段三）是另一个量级的坑——自建 GOP（gopt BSD-3 / kaldi Apache）要训练、要建 SEA 口音校准集、PCC≈0.45 的基线达不到云水平（github-eng Ch6 已详述）[15][16]。所以本地化故意压到阶段三。

③ 跨端打包签名（#13）。不是「写代码」难，是持续工程税：CI 矩阵分平台 build（不能 Mac 上交叉编译 Win）、中国个人 Windows 签名路径特殊（Azure 无资格 → 云签名）、SmartScreen 信誉冷启动——全在《签名公证 spec》里展开。坑：每次发版都要走这套，且 SmartScreen 警告靠下载量累积、买 EV 也买不掉首发警告。
④ 挖空字幕精听交互（#9）。技术不难但交互设计活多：挖哪些词（按词频/CEFR 难度，可借 github-eng 报告的分级词表数据）、判对错的容错（拼写错/同音词/大小写）、提示梯度（首字母→音标→放弃看答案）。开源参考少，基本自研，但逻辑清楚。

心力分配建议：🟢 那几个用 AI 快速堆完、别返工纠结；把 70% 的调试心力压在 #4 对齐精度 和 #7 发音评分体验 这两个「决定产品好不好用」的点上。#13 签名按姐妹 spec 照做即可，别自己发明。

08★ 逆向工程市面软件：能不能、合不合法、值不值▾

阿杰问：能不能逆向欧路「每日英语听力」/ Language Reactor 这类，把它们的功能搬过来？分三块诚实回答——法律边界、技术可行性、值不值。先给结论：合法且推荐的只有「看交互学产品设计」（clean-room 精神），不是反编译抄码；而且多数时候不值，因为 AI 自己能写。

⚠️ 以下是一般性法律梳理，非法律意见；真要做有风险的动作前请咨询专业律师。

① 法律边界

中国法

《计算机软件保护条例》第十七条：「为了学习和研究软件内含的设计思想和原理，通过安装、显示、传输或者存储软件等方式使用软件的，可以不经软件著作权人许可，不向其支付报酬。」[18] 学界普遍认为此条可作为有限度的软件反向工程合法性依据，但明确限于「学习和研究设计思想与原理」的目的——也就是说，研究它「怎么设计的、用了什么思路」是允许的；把研究结果变成抄袭其代码表达则超出此边界。[18]

《反不正当竞争法》/ 商业秘密：最高法司法解释明确，通过合法的反向工程获得商业秘密不构成侵权；但若以不正当手段（如盗取、违约）获取后再托词「反向工程」，法院不予支持。[20] 著作权层面，软件的表达（代码）受保护、思想（功能/原理）不受保护——「思想/表达二分」是底线。

EULA 禁止逆向条款的效力：厂商可在 EULA 写「禁止逆向」，但其效力受法定例外限制——即便用户签了禁逆向协议，若行为落入第十七条等法定豁免（学习思想原理、为兼容性等），仍可主张豁免。[19] 反之，超出豁免（如抄代码表达）则 EULA + 著作权双重约束。

海外（美国）

DMCA §1201(f) 互操作性例外：合法取得软件副本者，为实现独立开发程序与其他程序的互操作，可规避访问控制措施以识别/分析必要元素。[25] 但该例外严格限于实现兼容性，不是「随便逆向一切」的通行证；且必须合法获得软件。clean-room（净室）逆向是行业公认降低法律风险的做法：A 组分析目标、写出「功能规格」（不含受版权代码），B 组只看规格、独立实现——这样产出的代码不接触原代码表达，规避著作权侵权。EFF 的逆向 FAQ 是这块的经典参考。[25]

③ 值不值（诚实结论）

反编译抄码：⛔ 不值，别做。三个理由：① 法律风险高——抄代码表达踩著作权红线，超出「学习思想原理」豁免；② 收益低——抄来的是混淆过的别人代码，难维护、和你的架构对不上，还不如重写；③ AI 已经能写——小贝要的功能（播放/对齐/录音/评分/SRS）本报告已证明开源底座齐全、AI 能拼，自己写出来的更干净、可控、零法律风险。花精力反编译别人的，是把简单的事做难、把合法的事做险。

✅ 合法且推荐的做法（clean-room 精神）：① 装来用、研究欧路/asbplayer/LR 的交互与产品设计（哪些功能好用、流程怎么排、文案怎么写）——第十七条「学习设计思想和原理」明确允许[18]；② 读开源近亲的源码（asbplayer MIT、glucose 读架构）学实现思路；③ 用 AI 基于这些「思路」独立实现，不接触受 license 约束的具体代码。判断：🟢 学交互/产品设计、读开源——放手做；⚠️ 抓网络协议——灰区谨慎；⛔ 反编译闭源抄代码——不做。

09★ 立项：什么叫立项 + 怎么立（海外单人版）▾

「立项」是个被用混的词，至少有两层意思，对单人 indie 影响完全不同。先拆清楚，再给最小可行清单。

两层「立项」分清楚

「立项」指什么语境单人 indie 要不要
① 项目章程（project charter）产品/项目管理：写清做什么、不做什么、成功指标、里程碑、预算必做（半小时一页纸，给自己定方向）[26]
② 软件著作权登记官方知识产权：拿软件的权属证明可选不急（免费、非上线必需）[21]
③ 科技项目立项政府科技计划/高新企业：申请政府经费的审批不需要（面向企业拿政府钱，单人 indie 无关）[24]

① 产品语境的「立项」= 一页纸项目章程（必做）

项目章程是项目启动期的产出，说明项目的目标、范围、里程碑、成功标准、风险、预算、时间线[26]。对单人 indie，不需要正式文档，一张纸/一个 note 写死下面这几栏就够——它的价值是逼你在动手前把「不做什么」想清楚，防止发散（正合无忌一贯提醒阿杰的「先挑一个窄的跑通」）。

📋 小贝最小项目章程模板（照填即可）：

  • 愿景（一句话）：把你硬盘里任意英语视频，变成一套全本地的逐句精学私教材料。
  • 范围·做什么（阶段一）：本地视频导入 + 本地转写 + 逐句对齐 + 逐句循环精听 + 录音回放。
  • 范围·不做什么（关键栏）：阶段一不做发音评分、不做 SRS、不做挖空、不做签名公证、不做多视频库管理、不做移动端、不做云同步。
  • 成功指标：5–10 个真实用户里有人主动连用 3 天以上、愿意拿自己的视频来精学。
  • 里程碑：M0 脚手架 → M1 播放字幕 → M2 转写 → M3 对齐+逐句 → M4 录音（=阶段一出口）。
  • 预算：开发期 $0（自用不签名）；上线期 Mac $99/年 + 讯飞按量 + 可选 Win 证书（见签名 spec）。

  • 最大风险：对齐精度（#4）调不到能用；没人要这条链路。

② 软件著作权登记（可选、不急）

结论（承接父报告，给「要不要办 + 怎么办」）：

  • 要不要：父报告已述「软著非 ICP/App 备案的必需前提」。它是「所有权证据」，不是「上线许可」。阶段一/二不急办；想要权属凭证防抄袭、或上架某些国内渠道（部分商店要软著）时再办。
  • 费用：中国版权保护中心的基础登记服务自 2017-04 起免费（国家版权局停征登记费/证书费）[21]；找代理则另付代理费。
  • 周期：自行申请约 30 个工作日取证（案例口径约 41 天含补正）[21]；加急代理可缩短（付费）。
  • 流程：注册→实名认证→在线填报（提交源代码前后各 30 页 + 软件说明书）→提交→受理→审查→领证[21]。只要「创作完成」即可登记，不要求软件已发布/上线。
  • ⚠️ 海外单人提醒：软著登记是中国的制度，申请人需中国主体/个人身份信息；阿杰若以海外身份/无国内主体，办软著的可行性与必要性都更低——除非确有上架国内渠道的硬需求，否则这一项基本可以先放着。

③ 科技项目立项（单人不需要）

「科技项目立项」是另一回事——指政府科技计划项目的审批/启动，企业与政府签「科技计划项目合同书」，约定验收考核指标（经济/技术指标）以换取政府经费支持[24]；与「高新技术企业认定」「科技型中小企业」是配套的政策体系。这是给「在中国注册、要拿政府研发补贴的企业」用的，海外单人 indie 做一个商业 App 完全不涉及，不用管。只有当小贝某天落成国内公司主体、想申请政府科技补贴时才相关。

🎯 海外单人开发者的最小可行立项清单：① 写一页项目章程（上面模板，半小时）✅ 现在就做；② 软著——先不办，有国内上架/防抄硬需求再说；③ 科技项目立项——忽略。一句话：立项对你 = 写清「做什么、不做什么、怎么算成功」，官方那套登记/申报基本都不是现在的事。

❓FAQ 常见问题（12 条）▾

Q小贝一个人多久能做出来？＋

单人+AI 辅助：乐观 ~2–3 月到阶段一可玩 demo，现实 ~4–6 月到阶段二精学闭环+正式分发，悲观 ~8–10 月（含反复调参/合规）。🔴 类比估算非承诺。真实工期由「对齐精度 + 发音评分体验」这两处的反复次数决定，可能差 2–3 倍。兼职做会显著拉长。

Q一个人够不够？＋

够，但要守纪律。技术上每个功能都有开源底座、AI 能拼（Ch3/4）。单人最大的风险不是「写不出」，是「发散——把十个半成品功能铺开却没一个做顺」。守住「阶段一只做窄楔子、先验证有人要」就够一个人扛。

QAI 能写到什么程度？哪里帮不上？＋

样板/胶水代码省 70%+；有开源参考的功能省 50–60%；要调参/调体验的（对齐精度、发音评分反馈、跨端兼容）只省 20–30%——因为问题在真实数据/真实设备里，不在代码里，AI 写得快但你得反复试。AI 缩的是写代码时间，缩不掉调试打磨时间，而后者是小贝大头（Ch4）。

Q哪个功能最该先做？＋

「一个本地视频能逐句精听 + 跟读回放」这条窄链路（M0–M4）。这不是偏好，是技术依赖：转写→对齐→才能逐句，录音→才能评分（Ch6）。而且这条链路正好是小贝的不可替代内核，最便宜能验证「有没有人要」。发音评分/SRS/挖空都依赖它存在、且都该在验证内核之后才加。

Q能不能直接 fork 一个现成开源 App 改改就用？＋

不能。最像小贝的近亲——glucose_media_player（EUPL-1.2 copyleft）、yall-mp（GPL-3）是 copyleft 传染，fork 进闭源商业产品要么违规要么被迫开源；asbplayer（MIT 但是浏览器扩展，碰不到本地文件）、HiKid（MIT 但 Electron+macOS-only）形态/平台都不对。它们价值在「读架构/抄交互」，不在代码。该 fork 的是库层：whisperX(BSD-2)/ts-fsrs(MIT)/subtitle.js(MIT)（Ch3）。

Q能不能抄欧路/Language Reactor 现成的？逆向合法吗？＋

合法且推荐的只有一层：装来用、研究它的交互/产品设计（中国《软件保护条例》第十七条允许「为学习设计思想和原理而使用软件」）。反编译它的二进制抄代码超出此边界、踩著作权/EULA 红线，且对单人毫无收益——AI 自己写得更干净、可维护、零法律风险。结论：🟢 看交互学产品设计、读开源近亲源码；⛔ 别反编译抄码（Ch8）。

Q最该 fork 的开源是哪几个？＋

四件套：① whisperX（BSD-2，逐句对齐，22.4k★活跃）；② ts-fsrs 或 fsrs-rs（MIT/BSD-3，SRS，Tauri 前端用 ts、后端用 rs 二选一）；③ subtitle.js（MIT，字幕解析，停更但稳定）；④ whisper.cpp（MIT，转写，父报告已定）。这几个 license 全干净可商用。整 App 层只读架构（glucose/asbplayer）不 fork（Ch3）。

Q最复杂、最该花时间的是哪几块？＋

三个 🔴：① 逐句强制对齐精度——whisperX 在噪声/口音/音乐段会切错词，毁逐句体验，要在真实素材上反复调；② 发音评分体验——接讯飞不难，难在把多维分翻译成不打击信心的反馈；本地化(gopt/kaldi)是另一个量级的坑；③ 跨端打包签名——持续工程税（Ch7）。把 70% 调试心力压在 ① ②。

Q要不要先办软著？＋

不急。软著基础登记自 2017-04 起免费、周期约 30 工作日，但非上线必需，只要「创作完成」即可登记。它是所有权证据不是上线许可。阶段一/二先不办，想要防抄凭证或上架某些国内渠道时再办。⚠️ 软著是中国制度，需中国主体/身份；阿杰若以海外身份办，可行性和必要性都更低，基本可先放着（Ch9）。

Q「立项」到底是要干嘛？我一个人也要立项？＋

对单人 indie，「立项」=写一页纸项目章程（愿景/范围做什么不做什么/成功指标/里程碑/预算/时间盒），半小时的事，必做——价值是逼你动手前想清「不做什么」，防发散。Ch9 给了小贝的填空模板。官方那套「软著登记」可选不急、「科技项目立项」（政府科技计划）单人完全不需要。

Q停更的开源还能用吗（subtitle.js / aeneas）？＋

分情况。subtitle.js（MIT，2022 停更）——能用，字幕格式是慢变量、格式稳定，停更不影响；若要 ass 完整支持再补。aeneas（AGPL，2017 停更）——别用，三重问题：AGPL 传染 + 停更 8 年 + 精度不如活跃的 whisperX，对齐直接用 whisperX（Ch3）。判断原则：停更的「数据/格式类」库可用，停更的「带传染 license 的核心算法」别碰。

Q发音评分一开始就要做本地的吗？＋

不要。父报告已拍「MVP 用云（讯飞 ISE）、确认价值再迁本地」。自建本地 GOP（gopt BSD-3 / kaldi Apache）要训练/调校/建 SEA 口音校准集、基线 PCC≈0.45 达不到云水平——在「还不知道有没有人要」的阶段啃它是浪费。本地化故意压到阶段三（Ch5/Ch7）。用户的跟读录音不含版权，走云合规没问题（视频本体才是死锁本地的硬约束）。
