本文是《小贝》报告的代码签名 + 公证落地子规格。父报告第 4 章已拍板四件事：① 微软 Azure Trusted/Artifact Signing 中国个人/组织没资格（仅 US/加/欧/英组织 + US/加个人）[3]；② CA/B Forum 自 2023-06-01 起 OV 和 EV 私钥都强制存硬件 token / 云 HSM[1]；③ EV 已不再即时绕过 SmartScreen，与 OV 同走信誉累积[6]；④ Mac 走 Apple Developer Program $99/年 + Developer ID + 公证[9]。本 spec 把这四条结论往工程落地展开——买哪家证书、CI 里 token 插哪、Tauri 2.x 的每个配置键叫什么、命令怎么敲。

一句话定调：小贝有三条互相独立的签名链路，别混——① Windows Authenticode 代码签名（OS 级，给 SmartScreen 看）；② macOS 代码签名 + Apple 公证（OS 级，给 Gatekeeper 看）；③ Tauri updater 包签名（应用级 minisign，给自动更新看）。第三条跟前两条完全是两回事：updater 签名是 Tauri 自己的 Ed25519 密钥，不需要 CA、不花钱，但忘了配会导致自动更新永远失败。每条价格/资格/命令/配置键都带 inline 引用，悬停 [1] 看来源；查不实的明确标 ⚠️ 以官网为准，绝不编造。

📌 三条最关键规格（先扫这个）：

  • Windows 最大坑 = 硬件 token 在 CI 里插不进去。CA/B Forum 2023-06-01 起 OV+EV 私钥都必须存 FIPS 140-2 Level 2 / CC EAL4+ 硬件（USB token 或云 HSM）[1]。GitHub Actions 的云 runner 插不了实体 U 盾 → 必须走云签名服务（SignPath OSS 免费档 / SSL.com eSigner / Certum cloud），或自托管 runner 插实体 token。这是小贝 Windows 落地单独成章的工程坑（Ch5）。🟢
  • 中国个人开发者的 Windows 现实路线：Azure 无资格[3]；国内 CA（沃通 OV ¥3588 / EV ¥4288）仅向单位签发、需营业执照[4]；纯个人最现实是 ① 国际 CA（如 Certum）的「开源 / 个人」代码签名证书走云签名[5]，② 或以个体工商户 / 公司主体申请 OV。MVP 阶段甚至可先 Mac 公证 + Windows 暂不签（接受初期 SmartScreen 警告，给官网「被拦截怎么办」图文），放量再上正规证书（Ch14）。🟢
  • Tauri 2.x 三套配置键（2.x 已核实，与 1.x 有别）：Win = bundle.windows.{certificateThumbprint, digestAlgorithm, timestampUrl, signCommand}（signCommand 用 %1 占位走云签名）[7]；Mac = bundle.macOS.{signingIdentity, providerShortName, entitlements, hardenedRuntime} + 一套 APPLE_* 环境变量[8]；updater = plugins.updater.pubkey + 环境变量 TAURI_SIGNING_PRIVATE_KEY[11]。🟢

02为什么必须签名公证（不签的后果）▾

签名公证不是「锦上添花」，是能不能让普通用户装上的生死线。逐端列后果。

不做这件事用户实际看到什么后果
Windows 不签名下载时 SmartScreen 蓝框「Windows 已保护你的电脑 · 未知发布者」，下载按钮可能被浏览器直接拦/标红[6]小白用户直接关掉，卸载率/流失率飙升
Windows 签了名但无信誉仍可能弹 SmartScreen，但有发布者名字；点「更多信息 → 仍要运行」可继续[6]有摩擦但可越过，靠下载量累积信誉化解
macOS 不签名/不公证Gatekeeper 弹「无法打开，因为来自身份不明的开发者」/「Apple 无法检查其是否包含恶意软件」[9]需右键→打开或去系统设置放行，对小白是劝退级摩擦
Tauri updater 不配签名不是装机问题——而是自动更新根本跑不起来：Tauri updater 强制校验 minisign 签名，没配 pubkey/签名直接报 InvalidSignature[11]每次发版都要用户手动重下，失去 Tauri 自动更新的核心价值

对小贝尤其致命的两点：① 小贝目标用户是国内非技术英语学习者（含 K12 家长/学生），不是开发者——他们看到「未知发布者」蓝框的第一反应是「这是病毒」然后关掉，不会去点「仍要运行」。② 国内 Windows 生态还有 360 / 腾讯电脑管家等第三方安全软件，对新签名、低下载量的 exe 也可能误报甚至直接删除[6]（父报告 Ch4 已提示）。所以签名 + 信誉 + 提交各家白名单是组合拳，缺一不可。

反过来说，签名公证齐全的收益：Mac 端「双击即开」零摩擦；Win 端虽不能保证首发零警告，但有发布者身份 + 时间戳，杀软误报申诉、信誉累积都有据可依；updater 链路通了，以后每次发版用户无感静默更新——这正是 Tauri 选型的核心价值之一（父报告 Ch3）。

04★ Windows 证书类型拍板：OV vs EV vs 云签名▾

Windows 这端的第一个决策：买什么类型的证书、找谁买。先把选项摊开，再给中国个人开发者的现实路线。

三个维度先理清

  • 证书等级：OV（组织验证）vs EV（扩展验证）。历史上 EV 的卖点是「首发即绕过 SmartScreen」——这个特权已没了。2024-08 起微软把 EV 代码签名 OID 从受信根程序里移除，EV 与 OV 在 SmartScreen 面前同等对待，都靠下载量/时间累积信誉[6]。所以现在花大价钱买 EV 也买不到「首发不弹警告」了 —— 这直接改变了 OV/EV 的性价比。
  • 私钥存哪：硬件 token vs 云 HSM。CA/B Forum 2023-06-01 起，OV 和 EV 私钥都必须存 FIPS 140-2 Level 2 / CC EAL 4+ 合规硬件——物理 USB token（U 盾）或云 HSM[1]。「买个证书装本机直接签」的老路已死。这条决定了 CI 怎么签（Ch5）。
  • 云签名服务：Azure Trusted Signing。微软自己的云签名（~$10/月、直集成 CI）很香——但中国个人/组织没资格：公共信任证书目前仅向 US/加/欧/英「组织」+ US/加「个人」开放，2025-04 起对其他国家暂停新验证请求[3]。对小贝直接出局，别照欧美教程规划。

05★ Windows 硬件 token + CI 自动签名难题（最大工程坑）▾

这是 Windows 落地唯一真正的工程难题，单独成章。其余都是照文档配，这块是要做架构决策的。

问题本质：CA/B Forum 2023-06-01 起，代码签名私钥必须非可导出地存在 FIPS 140-2 Level 2 / CC EAL4+ 硬件里（USB token 或云 HSM）[1]。而 GitHub Actions 的云 runner 是一次性虚拟机，你没法往它的 USB 口插一根实体 U 盾。于是「CI 自动构建 → 自动签名 → 自动发版」这条流水线，在 Win 端被实体 token 卡住了。这就是为什么 Mac 端 CI 签名很顺、Win 端却要专门解决。

三条解法对比

解法怎么做CI 自动化成本适合谁
A. 云签名服务 ★证书私钥托管在 CA/服务商云 HSM，CI 通过 API/CLI 远程签名，不碰实体 token。SignPath OSS / SSL.com eSigner / Certum SimplySign / Azure（中国无资格）[13]✓ 全自动订阅/按次（SignPath 开源免费、Certum 开源 €49–69、SSL.com eSigner Tier1 $100/月）[5][12]小贝首选（个人/小团队、要 CI）
B. 自托管 runner + 实体 token自己有台常开的 Win 机器，插着 U 盾，注册成 GitHub self-hosted runner，签名步骤在它上面跑~ 半自动（机器要常开、token 要在位）U 盾证书成本 + 一台机器电费已有国内 CA U 盾、不想付云签名月费
C. 本地手动签名CI 只构建不签名，下载产物到本机用 signtool + U 盾手动签，再传回发布✗ 纯手动仅证书成本发版频率极低的早期 MVP

拍板：小贝走 A（云签名）。理由：① 个人开发者不想维护一台常开插着 U 盾的机器（解法 B 的隐性运维成本高、token 还可能掉线）；② Tauri 的 bundle.windows.signCommand 配置项就是为云签名设计的——用 %1 占位符把待签文件路径传给任意云签名 CLI[7]，集成干净；③ SignPath（若开源）直接免费、SSL.com eSigner 有成熟 GitHub Action（sslcom/actions-codesigner）[13]、Certum SimplySign 也支持云签。唯一代价是月费/按次费，但省下的运维和可靠性远超这点钱。

云签名怎么进 GitHub Actions（以 SSL.com eSigner 为例）

eSigner 提供官方 GitHub Action，CI 里调一个 step 就把产物远程签了——不下发任何实体 token 到 runner，凭证以 4 个 secret 注入[13]：

# GitHub Actions step（说明性，落地以 SSL.com 文档为准）
- name: Sign Windows installer (cloud, no token)
  uses: sslcom/actions-codesigner@develop
  with:
    command: sign
    username: ${{ secrets.ES_USERNAME }}
    password: ${{ secrets.ES_PASSWORD }}
    credential_id: ${{ secrets.CREDENTIAL_ID }}
    totp_secret: ${{ secrets.ES_TOTP_SECRET }}   # 自动化 OTP
    file_path: path/to/小贝_x.y.z_x64-setup.exe
    output_path: signed/

⚠️ 上为说明性片段，参数以 SSL.com 官方 GitHub Actions 集成文档 为准[13]。SignPath / Certum SimplySign 的接法不同，思路一致（云端签、CI 注入凭证）。

两种集成模式，别搞混：① 独立 step 签名（上例）——CI 先用 Tauri 构建出未签名 exe，再用 eSigner action 单独签，最后用 minisign 签 updater 产物。这种最稳，对 Tauri 透明。② Tauri signCommand 内联——把云签名 CLI 写进 bundle.windows.signCommand（%1 占位），Tauri 构建时自动调它签[7]。模式②更优雅但 CLI 要能在 runner 上无交互运行（eSigner CKA / CodeSignTool 可以）。小贝建议先用①跑通，再考虑②。

⚠️ 不要做的事：① 不要把证书私钥/U 盾密码明文塞进仓库或 workflow——用 GitHub Secrets；② 不要指望「云 runner 装个驱动就能模拟 token」——合规硬件私钥不可导出，模拟不了；③ 不要因为嫌麻烦就在 Win 端跳过时间戳（Ch6）——没时间戳的签名在证书过期后全部失效。

06Windows 签名落地步骤（可照做）▾

从「决定买证书」到「signtool verify 通过」的完整 step（Tauri 官方 Windows 签名指南给了整体流程框架[2]，下面按小贝的云签名路线展开）。假设走云签名路线（Ch5 拍板）。

1选 CA + 下单
按 Ch4 决策树选：开源 → SignPath Foundation / Certum 开源版；闭源有主体 → 国内 CA OV 或国际 CA OV；闭源无主体 MVP → 先缓或个人产品线。下单时选云签名 / 云 HSM 版本（非实体 U 盾版），才能接 CI。
2身份验证（最耗时）
OV：验证组织真实性（营业执照、电话回访等），1–5 个工作日[4]；EV：更严更久。个人/开源产品线（Certum）验证个人身份，相对快。这步是周期瓶颈，提前办。
3拿到云签名凭证
不是拿到一个 .pfx 文件——而是拿到云签名账号 + credential ID + API 凭证 / TOTP secret（SSL.com eSigner）或 SimplySign 账号（Certum）。证书私钥永远在服务商云 HSM 里，你只拿调用凭证。
4配置签名（Tauri 或独立 step）
两种：① 独立 step 用云签名 CLI/Action 签构建产物（Ch5 例）；② 写进 bundle.windows.signCommand（%1 占位）让 Tauri 自动签[7]。本机有 token 时也可设 certificateThumbprint 让 Tauri 调 signtool[7]（Ch9）。
5RFC3161 时间戳（必加）
签名时带时间戳服务器，证明「签名发生在证书有效期内」——证书过期后已签的包仍有效。signtool：signtool sign /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 file.exe[15]。Tauri 设 bundle.windows.timestampUrl[7]。可选 TSA：DigiCert http://timestamp.digicert.com / Sectigo http://timestamp.sectigo.com / Certum http://time.certum.pl[15]。
6验证签名
signtool verify /pa /v 小贝_x.y.z_x64-setup.exe 应显示证书链有效 + 时间戳存在。或右键 exe → 属性 → 数字签名页确认发布者名字正确。
7SmartScreen 信誉积累策略
签名只给「身份」，不给「信誉」。信誉靠下载量+时间累积，微软不公布阈值[6]。策略：① 全程用同一张证书签（换证书=信誉重置）；② 官网放统一下载入口引导量；③ 主动提交 Microsoft 文件分析 + 360/腾讯管家白名单；④ 官网首屏给「弹 SmartScreen 怎么办」图文（点更多信息→仍要运行）。

⚠️ 时间戳是隐形生死线：没加时间戳的签名，证书一过期，所有已发布的包签名立即失效，用户重装时全弹未知发布者。加了时间戳则永久有效。所以 Win 签名必加 /tr，CI 里别图省事省掉。🟢

关于 digest 算法：统一用 SHA256（/fd SHA256 /td SHA256 或 Tauri digestAlgorithm: "sha256"）[7]。注意 DigiCert 时间戳服务器对 /td SHA512/SHA384 有兼容问题，SHA256 最稳[15]。

07macOS：Apple Developer 注册 + Developer ID 证书▾

Mac 端比 Win 端简单、便宜、标准化。先把账号和证书办下来。

个人档 vs 组织档

档位需要什么能签 Developer ID 分发吗中国可注册？
个人 / 个体（Individual）仅一个开 2FA 的 Apple Account + 达法定年龄[16]，无需 D-U-N-S✓ 可（App Store 外分发官方支持）[9]✓ 中国大陆可注册，需身份验证，可用 Apple Developer app 本地支付完成[17]
组织（Organization）需 D-U-N-S 编号 + 法人实体验证[16]✓ 可，且证书显示公司名~ 需公司 + D-U-N-S

对小贝的拍板：个人档够用，先办个人档。① 个人开发者不需要 D-U-N-S，只要 Apple ID + $99/年[16][10]；② App Store 外直接分发 DMG/PKG 官方完全支持[9]，不强制上 Mac App Store；③ 中国大陆个人可注册（需身份验证，Apple Developer app 支持本地支付）[17]。唯一差别：个人档证书的「开发者」显示你的个人名，组织档显示公司名——MVP 用个人名完全 OK，等品牌成熟再迁组织档。🟢

创建 Developer ID Application 证书（5 步）

1加入 Apple Developer Program
$99/年[10]。只有 Program 成员（账号持有者）才能签发 Developer ID 证书[9]。
2分清两种 Developer ID 证书
Developer ID Application（签 .app/.dmg，小贝用这个）vs Developer ID Installer（签 .pkg 安装器）。小贝分发 DMG 主要用前者；若做 .pkg 安装器再加后者。
3本机生成 CSR
钥匙串访问 → 证书助理 → 从证书颁发机构请求证书，生成 CSR（证书签名请求）。私钥留在你的本机钥匙串。
4在 developer.apple.com 签发
Certificates 页 → 新建 → 选 Developer ID Application → 上传 CSR → 下载 .cer → 双击导入钥匙串，和私钥配成可用签名身份。
5导出 .p12 给 CI 用
钥匙串里选「证书+私钥」→ 导出为 .p12（设密码）。CI 里 base64 成字符串存进 APPLE_CERTIFICATE secret，密码存 APPLE_CERTIFICATE_PASSWORD[8]（Ch11）。

查签名身份名：security find-identity -v -p codesigning 列出可用身份，形如 Developer ID Application: 你的名字 (TEAMID)——这串就是 Tauri 的 signingIdentity / APPLE_SIGNING_IDENTITY 值[8]。TEAMID 也是 APPLE_TEAM_ID。

08macOS：签名 + 公证 + staple（完整命令序列）▾

拿到 Developer ID 证书后，分发前要走「签名 → 公证 → 订书钉」三步。Tauri 构建时大部分能自动做（Ch9），这里给底层命令，便于排查和理解。

⚠️ altool 已死，用 notarytool。旧的 xcrun altool 上传公证通道2023-11-01 起停用，必须改用 xcrun notarytool（Xcode 14+）[18]。网上 2023 年前的教程很多还在用 altool，照抄会直接失败。

四步命令序列

1codesign 签名（开 hardened runtime）
公证要求开 hardened runtime（--options runtime），并按需附 entitlements：
codesign --force --deep --options runtime --entitlements Entitlements.plist --sign "Developer ID Application: 名字 (TEAMID)" 小贝.app[9]
2存公证凭证（一次性）
xcrun notarytool store-credentials "小贝-profile" --apple-id you@mail.com --team-id TEAMID --password APP_SPECIFIC_PWD[18]。把凭证存进钥匙串，后续提交引用 profile 名即可。app-specific password 在 appleid.apple.com 生成。
3提交公证并等回执
先把 .app 打进 .dmg 或 zip，再提交：
xcrun notarytool submit 小贝_x.y.z.dmg --keychain-profile "小贝-profile" --wait[18]。--wait 阻塞到 Apple 扫描完（通常几分钟，偶尔更久），返回 Accepted 才算过。
4staple 订书钉 + 验证
xcrun stapler staple 小贝_x.y.z.dmg 把公证票钉进包里（用户离线也能验）[18]。最后 spctl -a -t open --context context:primary-signature -v 小贝_x.y.z.dmg 或对 .app 用 spctl -a -v 小贝.app 验证 Gatekeeper 放行（显示 accepted · source=Notarized Developer ID）。

两种公证凭证方式（二选一）：① app-specific password（Apple ID + 团队 ID + 专用密码）——简单，适合个人；对应 Tauri env APPLE_ID / APPLE_PASSWORD / APPLE_TEAM_ID[8]。② App Store Connect API key（Issuer ID + Key ID + .p8 私钥文件）——更适合 CI/团队，不依赖个人 Apple ID 密码；对应 Tauri env APPLE_API_ISSUER / APPLE_API_KEY / APPLE_API_KEY_PATH[8]。小贝 CI 推荐用 API key（不绑个人密码、可吊销）。

关于 entitlements 与 hardened runtime：hardened runtime 默认禁掉一些能力（JIT、未签名内存、dyld 注入等），公证强制要求开[9]。小贝若用到 WKWebView/某些 native 能力，可能要在 Entitlements.plist 里声明对应 entitlement（如 com.apple.security.cs.allow-jit）。Tauri 模板自带一份合理默认，按需改（Ch9）。⚠️ 具体要哪些 entitlement 取决于小贝实际用到的 native API，需联调确认

10★ Tauri updater 签名（独立第三条链路，别和 OS 签名混）▾

这章讲的密钥跟 CA、跟 Apple 完全没关系。updater 签名是 Tauri 自己的 minisign（Ed25519）公私钥对，用来证明「这个更新包确实是小贝官方发的，没被中间人替换」。它是 Tauri updater 插件的硬性前置——没配，自动更新直接报 InvalidSignature，再贵的 CA 证书也救不了[11]。

四步配齐 updater 签名

1生成 minisign 密钥对
tauri signer generate -w ~/.tauri/小贝.key[11]。产出两个文件：小贝.key（私钥，绝密、永久保管）和 小贝.key.pub（公钥）。可设密码保护私钥。
2公钥进 tauri.conf.json
把 .pub 内容填进 plugins.updater.pubkey，并设 active: true + endpoints（更新源 URL，如 GitHub Release 的 latest.json）[11]。这是 2.x 的插件式结构。
3私钥进 CI 环境变量
TAURI_SIGNING_PRIVATE_KEY（私钥内容或路径）+ TAURI_SIGNING_PRIVATE_KEY_PASSWORD（若设了密码）[11]。CI 里存成 GitHub Secret。构建时 Tauri 自动用它签更新产物，生成 .sig。
4注册插件
Rust 端 lib.rs 加 .plugin(tauri_plugin_updater::Builder::new().build())[11]。前端调更新 API 时，Tauri 下载更新包 → 用 conf 里的 pubkey 校验 .sig → 通过才安装。

updater 工作原理（为什么签名缺一不可）

小贝 App 检查更新时发生什么？
↓
① 请求 endpoints 拿 latest.json（含新版本号、下载 URL、对应 signature）
② 下载更新产物（.nsis.zip / .app.tar.gz）
③ 用 conf 里的 pubkey 校验产物的 minisign 签名——这步就是防篡改的核心[11]
签名对 安装更新 · 签名错/缺 报 InvalidSignature，拒绝安装

⚠️ 私钥丢了 = 灾难级后果：如果你弄丢了 minisign 私钥，就再也无法给「已经装了小贝的老用户」推送任何自动更新——因为他们的 App 内置的是旧 pubkey，只认旧私钥签的包，换新密钥对他们一律校验失败[11]。老用户只能手动重新下载安装。所以 minisign 私钥必须像命根子一样备份（密码管理器 + 离线备份），比 CA 证书还金贵（CA 证书丢了能重买，updater 私钥丢了老用户更新链就断了）。

再强调一次三条链路别混：① Authenticode（Win，CA 证书，给 SmartScreen）；② Apple 公证（Mac，Developer ID，给 Gatekeeper）；③ updater minisign（两端共用，给自动更新）。updater 签名跟「Windows 弹不弹未知发布者」「Mac 能不能双击打开」完全无关——那是①②的事。updater 只管「自动更新包是不是真的」。🟢

11GitHub Actions CI 双端矩阵（带签名公证）▾

把三条链路全装进一个 CI workflow。核心约束承接父报告：不能跨平台编译——Mac 包必须 macOS runner、Win 包必须 Windows runner[9]（父报告 Ch3）。所以是矩阵：两个 runner 各自构建+签名，updater 私钥两端共用。

⚠️ 为什么不能一个 runner 全包了：Tauri 打包依赖各 OS 的原生工具链（Win 的 NSIS/WiX、Mac 的 codesign/notarytool），且 codesign/公证只能在 macOS 上跑、signtool只能在 Windows 上跑。所以小贝的发版 CI 天然是 matrix: [macos-latest, windows-latest] 两路并行。

workflow.yml 骨架（说明性）

name: release
on: { push: { tags: ['v*'] } }
permissions: { contents: write }   # 发 Release 要写权限
jobs:
  build:
    strategy:
      matrix:
        include:
          - { platform: 'macos-latest',   args: '--target universal-apple-darwin' }
          - { platform: 'windows-latest', args: '' }
    runs-on: ${{ matrix.platform }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
      - run: npm ci
      # —— tauri-action：构建 + 自动签名 + 公证 + 出 updater 产物 ——
      - uses: tauri-apps/tauri-action@v0
        env:
          # 链路③ updater（两端都注入）
          TAURI_SIGNING_PRIVATE_KEY: ${{ secrets.TAURI_SIGNING_PRIVATE_KEY }}
          TAURI_SIGNING_PRIVATE_KEY_PASSWORD: ${{ secrets.TAURI_SIGNING_PRIVATE_KEY_PASSWORD }}
          # 链路② Mac 签名+公证（仅 macos runner 用到）
          APPLE_CERTIFICATE: ${{ secrets.APPLE_CERTIFICATE }}
          APPLE_CERTIFICATE_PASSWORD: ${{ secrets.APPLE_CERTIFICATE_PASSWORD }}
          APPLE_SIGNING_IDENTITY: ${{ secrets.APPLE_SIGNING_IDENTITY }}
          APPLE_ID: ${{ secrets.APPLE_ID }}
          APPLE_PASSWORD: ${{ secrets.APPLE_PASSWORD }}
          APPLE_TEAM_ID: ${{ secrets.APPLE_TEAM_ID }}
        with:
          tagName: ${{ github.ref_name }}
          args: ${{ matrix.args }}
      # 链路① Win 云签名：若没走 Tauri signCommand 内联，可在此加独立 step
      #   - uses: sslcom/actions-codesigner@develop  （仅 windows runner）

⚠️ 上为说明性骨架（依据 tauri-action 与各服务文档结构整理[19][8]），非完整可运行——落地以 tauri-action 当前文档为准。Win 云签名既可写进 signCommand 由 tauri-action 自动调，也可作独立 step；环境变量名以 v2.tauri.app 为准。

tauri-action 帮你做什么：它在各 runner 上构建 Tauri 应用、按注入的 env 自动签名/公证、产出 updater 资源，并可上传到 GitHub Release[19]。Mac 端会自动处理 .p12 导入临时钥匙串 → 签 → 公证；Win 端按 signCommand/thumbprint 签。注意：默认 GitHub Token 只读，发 Release 要在仓库设置里给 workflow「读写权限」或在 yml 写 permissions: contents: write[19]。

❓FAQ 常见问题（12 条）▾

Q不签名会怎样？真的装不上吗？＋

能装但摩擦极大。Windows 弹 SmartScreen「未知发布者」蓝框（小白多半关掉）[6]；Mac 弹 Gatekeeper「来自身份不明开发者，无法打开」[9]，要右键打开/系统设置放行。对小贝的非技术国内用户，这是劝退级（Ch2）。还有 360/腾讯管家对新 exe 可能直接误删。

QOV 够不够？非得买 EV 吗？＋

OV 够。EV 历史卖点是「首发即绕过 SmartScreen」——这个特权 2024-08 起没了，微软把 EV OID 从受信根移除，EV 与 OV 同走信誉累积[6]。现在多花钱买 EV 也买不到「首发不弹警告」，所以选 OV 即可（Ch4）。

Q为什么签了名 Windows 还弹 SmartScreen？＋

签名给「身份」，不给「信誉」。SmartScreen 信誉靠下载量+时间累积，微软不公布阈值[6]。新 App 信誉起来前仍可能弹（点更多信息→仍要运行可继续）。化解：同一证书持续签、引导下载量、提交白名单、官网放图文指引（Ch6）。

Q云签名安全吗？私钥在别人那儿不怕吗？＋

这正是 CA/B 规则的设计——私钥非可导出地存在服务商的 FIPS 140-2 L2/EAL4+ 云 HSM 里[1]，你通过鉴权远程调用签名，私钥本身不下发。比把 U 盾插在一台常开机器上更可控（机器被黑 vs 云 HSM 审计）。CI 凭证用 GitHub Secret 管理（Ch5）。

Q中国个人开发者到底能怎么签 Windows？＋

三条路：① 开源 → SignPath Foundation（免费）[14] 或 Certum 开源版（~€49–69）[5]；② 有公司/个体户主体 → 国内 CA OV ¥3588[4] 或国际 CA OV+云签名；③ 闭源无主体 MVP → 先缓（接受警告+图文指引），放量再补主体。Azure Trusted Signing 中国无资格，别走[3]（Ch4）。

Q硬件 token 在 GitHub Actions 里怎么插？＋

插不了——云 runner 是一次性 VM，没法插实体 U 盾。解法是云签名服务（私钥在服务商云 HSM，CI 远程调用，如 SSL.com eSigner 的 sslcom/actions-codesigner action[13]），或自托管一台插着 token 的 runner，或本地手动签。小贝走云签名（Ch5）。

QMac 公证要多久？会卡住吗？＋

通常几分钟，偶尔更久（Apple 服务繁忙时可能拖到几十分钟甚至更长）[18]。用 notarytool submit --wait 阻塞等回执，返回 Accepted 才算过。注意 altool 已于 2023-11-01 停用，必须用 notarytool[18]（Ch8）。

Q中国个人能注册 Apple Developer 签 Mac 吗？＋

能。个人档只要 Apple ID（开 2FA）+ $99/年，无需 D-U-N-S[16]。中国大陆个人可注册，需身份验证，且 Apple Developer app 支持本地支付完成购买[17]。App Store 外直接分发 DMG 官方支持[9]（Ch7）。

Qupdater 签名忘了配会怎样？＋

自动更新直接废。Tauri updater 强制校验 minisign 签名，没配 pubkey/没签更新包，App 检查更新时报 InvalidSignature 拒绝安装[11]。这跟 CA 证书无关，是 Tauri 自己的 Ed25519 密钥（Ch10）。所以第一天就要配齐。

Q证书 / updater 私钥丢了怎么办？＋

分两种：① CA 代码签名证书丢了 → 重新签发/重买，影响有限（新包用新证书签，信誉可能重置）；② updater minisign 私钥丢了 = 灾难 → 已装的老用户内置旧 pubkey，只认旧私钥签的包，换新密钥后他们一律校验失败，再也收不到自动更新，只能手动重装[11]。所以 updater 私钥要离线 + 密码管理器双备份（Ch10）。

QTauri 2.x 配置键跟 1.x 一样吗？照老教程行吗？＋

不一样，别照 1.x。2.x 变化：① macOS 配置块是 bundle.macOS；② updater 是独立插件 plugins.updater（1.x 是 tauri.updater）；③ 环境变量 TAURI_SIGNING_PRIVATE_KEY（1.x 是 TAURI_PRIVATE_KEY）[11]。本 spec 全按 2.x 核实[7][8]（Ch9）。

Q能不能省钱不签 Windows？上 Microsoft Store 行吗？＋

两个省钱选项：① MVP 阶段 Windows 暂不签，接受 SmartScreen 警告 + 官网放「被拦截怎么办」图文（Ch14）；② 走 Microsoft Store（MSIX 打包），微软免费给商店应用签名[20]，省自购证书钱、SmartScreen 待遇也更好。代价是要做 MSIX 打包+过审+（国内商店）软著（Ch13）。
