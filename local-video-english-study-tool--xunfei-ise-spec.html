讯飞 ISE 接入 spec：小贝云端发音评分 WebAPI 接入子规格

← 返回 小贝主报告
📅 2026-06-11 🎙️ 科大讯飞 ISE 智能语音评测 🖥️ Tauri（Mac + Win） 🔌 WebAPI / WebSocket 🇨🇳 国内云首选 📐 技术规格 spec

本文是《小贝》报告的讯飞 ISE 接入子规格。父报告（本地视频英语精学桌面 App）第 7/8/13 章已拍板：云端发音评分主推科大讯飞 ISE（Azure 作海外/备选）、跟读录音「不含版权、属可上云那一类」、离线时降级到本地 GOP/SSL、中国用户 Windows 优先。本 spec 把「怎么接」一层层写到能开工的颗粒度——鉴权握手、business 参数、音频分帧、XML 结果如何解析成逐词逐音素颜色打分、Tauri 里 secret 为什么必须在 Rust 后端。

一句话定调：小贝是 Tauri 跨平台桌面端（Mac+Win），讯飞官方没有 macOS 原生 SDK（平台列表只有 Android/iOS/Linux/Windows/WebAPI[6]），所以接入形态写死 WebAPI（WebSocket 流式），由 Rust 后端发起握手与上传，APIKey/APISecret 只存后端、绝不进前端。每个 API 参数 / 字段 / 计费数字都带 inline 引用（讯飞官方文档为主），悬停 [1] 看来源。查不到的（如超量统一单价）明确标 ⚠️ 需控制台确认，绝不编造。

📌 三条最关键规格（先扫这个）：

  • 形态：WebAPI(WebSocket) 写死，不用 SDK。地址 wss://ise-api.xfyun.cn/v2/open-ise[1]。理由：① 讯飞无 Mac 原生 SDK（官方平台列表 = Android/iOS/Linux/Windows/WebAPI）[6]，Tauri 要 Mac+Win 一致只能走 WebAPI；② SDK / WebAPI 额度归属/是否共用以控制台为准⚠️ 需控制台确认[2]——统一走 WebAPI 仍是更简洁的选择（免 Mac SDK 缺位问题）；③ APISecret 必须在 Rust 后端做 HMAC 签名，绝不暴露前端。🟢
  • 鉴权：HMAC-SHA256 握手 URL（date/host/request-line 三段签名 → base64 → 拼 authorization）[1]。每次连接前在 Rust 端现算，URL query 带 authorization / host / date 三个参数。签名串里 host=ise-api.xfyun.cn、request-line=GET /v2/open-ise HTTP/1.1。🟢
  • 结果：XML（base64 编码在 JSON 信封里），外层有 wrapper：xml_result → read_sentence → rec_paper → sentence → word → syll → phone；英文引擎 phone 节点用 dp_message 承载逐音素读对/读错标记 → 映射成小贝「逐音素颜色打分」（perr_msg 是中文引擎 phone 字段）。四维总分 total_score / accuracy_score / fluency_score / integrity_score / standard_score 挂在内层 read_sentence/sentence 上[1]。🟡 ⚠️ wrapper 层级与 phone 字段名随引擎/版本变，落地前解码一条真实英文返回确认

02讯飞 ISE 是什么 + 在小贝里扮演什么▾

科大讯飞 ISE（Intelligent Speech Evaluation，智能语音评测 / 语音评测）是讯飞开放平台的一项「语音扩展」能力：给定一段评测文本（单词/句子/篇章）+ 用户朗读的录音，返回多维发音评分——总分、准确度、流利度、完整度，并下钻到每个单词、每个音素的得分与读对/读错标记[3]。它支持中英双语（英文引擎 en_vip、中文 cn_vip），专门面向中国人英语口语评测，是国内发音评测的标杆能力[3]。

在小贝里扮演什么

小贝的精学闭环里，「逐句跟读 / shadowing 影子跟读 + AI 打发音分」是最有学理支撑的差异化功能（父报告 Ch7/Ch10）。讯飞 ISE 就是这块的云端评分引擎：

小贝场景讯飞 ISE 提供处理位置
逐句跟读：用户读字幕里这一句read_sentence → 句级四维分 + 逐词 + 逐音素录音上云评测
单词卡跟读：单个生词发音read_word → 词级分 + 音素级录音上云评测
Shadowing：跟读整段read_chapter → 篇章级流利度/完整度录音上云评测
视频内容本体（画面/原声）—（讯飞不碰）死锁本地

对齐父报告「录音可上云」边界：上传给讯飞的是用户自己的跟读录音 + 一小段评测文本——不含视频版权内容本体，所以它属于父报告第 8 章界定的「可上云那一类」[4]。版权敏感的视频/音频本体、本地转写出的字幕，永远不出设备。但「录音可上云」不等于「无声上云」：仍要在 UI 明确告知「这段录音会上传到讯飞评测」并取得同意（Ch10）。

定位提醒：讯飞 ISE 是评分引擎，不是识别引擎——它假设用户在读「给定文本」，按文本逐音素对齐打分。它不负责「用户读了什么」的自由转写（那是语音听写 IAT 的活）。小贝的评测文本来自字幕里那一句，本来就是已知的，正好对口。

03★ 接入形态拍板：WebAPI(WebSocket) vs 各端 SDK▾

这是本 spec 最关键的一次拍板，决定后面所有章节的写法。结论：小贝写死 WebAPI（WebSocket 流式），由 Rust 后端发起；不集成各端 SDK。

决定性事实：讯飞官方平台列表是「Android / iOS / Linux / Windows / WebAPI」，没有 macOS 原生 SDK[6]。Windows SDK 是 32/64 位 C/C++ DLL（msc.dll / msc_x64.dll）[7]，能在 Win 端用，但 Mac 端无对应物。小贝要 Mac+Win 一套代码一致体验，SDK 路线在 Mac 上直接断了——只能走 WebAPI。

三条拍板理由

小贝该用 WebAPI 还是各端 SDK？
↓
① Mac 无 SDK 讯飞官方无 macOS 原生 SDK[6]；Tauri 要双端一致 → SDK 路线在 Mac 上不可行，WebAPI 是唯一跨平台解。
② 额度归属以控制台为准 SDK / WebAPI 免费礼包（个人 1 万 / 企业 10 万）是否共用，当前官网未明确⚠️ 需控制台确认[2]。无论共用与否，统一走 WebAPI 仍更简洁（免 Mac SDK 缺位问题），不必两端混用。
③ secret 安全 WebAPI 鉴权要用 APISecret 现算 HMAC 签名；secret 绝不能进前端 JS（任何人开 DevTools 就能扒）。放 Rust 后端 + WebAPI 一举两得：签名在后端、调用在后端。SDK 反而要把 license/key 打进客户端二进制，逆向风险类似。
↓
✅ 拍板：WebAPI（WebSocket），Rust 后端发起握手与上传，前端只录音 + 渲染

WebAPI 路线的额外好处：① Rust 生态有成熟 WebSocket（tokio-tungstenite）+ HMAC（hmac/sha2）+ base64 crate，握手与流式上传都好写；② 不引入 C/C++ FFI、不打包平台二进制（不像父报告里 whisper/ffmpeg 那样要 sidecar），讯飞这块零原生依赖；③ 升级讯飞协议只改后端，前端无感。唯一代价：必须联网（离线降级见 Ch11），且每次评测一次网络往返（国内节点延迟低）[3]。

⚠️ 不要做的事：① 不要在前端 JS 里放 APIKey/APISecret 直连讯飞——secret 泄露 = 别人盗刷你的额度/账单；② 不要假设 SDK 版额度能顶 WebAPI 调用，二者是否共用以控制台为准[2]；③ Win 端不要为了「省一次网络往返」单独接 Windows SDK，会让 Mac/Win 两套评分口径不一致、维护翻倍。

04鉴权 spec：APPID/APIKey/APISecret + HMAC 签名握手▾

WebAPI 用的是讯飞统一的「WebSocket 握手鉴权」：把鉴权信息算成签名，拼进 WSS URL 的 query 参数里，连接时一次性校验[1]。三把钥匙在控制台创建应用后拿到。

三把钥匙（控制台获取）

凭证用途放哪
APPID应用标识，进首帧 common.app_id可进配置（非密钥）
APIKey签名里 api_key="..." 字段Rust 后端
APISecretHMAC-SHA256 的密钥（最敏感）只在 Rust 后端，绝不进前端

HMAC-SHA256 签名握手（6 步）

1生成 RFC1123 时间戳
date = "Wed, 10 Jul 2019 07:35:43 GMT" 格式（GMT）[1]。服务器校验时钟偏差，偏太多返回 403。
2拼签名原文（三行，\n 连接）
host: ise-api.xfyun.cn ＼n date: {RFC1123} ＼n GET /v2/open-ise HTTP/1.1[1]
3HMAC-SHA256 + base64
signature = base64( HMAC-SHA256(signatureOrigin, APISecret) )[1]
4拼 authorization 原文
api_key="{APIKey}", algorithm="hmac-sha256", headers="host date request-line", signature="{signature}"[1]
5authorization base64
authorization = base64(authorizationOrigin)[1]
6拼进 WSS URL query
wss://ise-api.xfyun.cn/v2/open-ise?authorization={...}&date={urlencoded RFC1123}&host=ise-api.xfyun.cn[1]。date 记得 URL 编码。

签名算法伪代码（Rust 后端，说明性）

// 仅示意，落地实现留工程 session
use hmac::{Hmac, Mac}; use sha2::Sha256; use base64::Engine;

fn build_ise_ws_url(api_key:&str, api_secret:&str) -> String {
  let host = "ise-api.xfyun.cn";
  let path = "/v2/open-ise";
  let date = httpdate::fmt_http_date(SystemTime::now()); // RFC1123 GMT

  // step2: 三行签名原文
  let origin = format!("host: {host}\ndate: {date}\nGET {path} HTTP/1.1");

  // step3: HMAC-SHA256 + base64
  let mut mac = Hmac::<Sha256>::new_from_slice(api_secret.as_bytes()).unwrap();
  mac.update(origin.as_bytes());
  let signature = base64::engine::general_purpose::STANDARD
      .encode(mac.finalize().into_bytes());

  // step4-5: authorization 原文 → base64
  let auth_origin = format!(
    "api_key=\"{api_key}\", algorithm=\"hmac-sha256\", \
     headers=\"host date request-line\", signature=\"{signature}\"");
  let authorization = base64::engine::general_purpose::STANDARD
      .encode(auth_origin.as_bytes());

  // step6: 拼 query（date/host 需 url-encode）
  format!("wss://{host}{path}?authorization={}&host={host}&date={}",
          urlencoding::encode(&authorization),
          urlencoding::encode(&date))
}

关键安全约束：APISecret 永远只在 Rust 后端。前端（WebView / JS）拿不到也不该拿到 secret——它只通过 tauri::invoke 把「录音 + 评测文本 + 题型」交给后端，后端现算签名、连讯飞、回传分数。这样即使有人逆向前端 bundle，也扒不到密钥。这也是 Ch3 选 WebAPI-后端模式而非前端直连的核心原因。

常见鉴权错误：401=缺 authorization 参数或签名校验失败（多半是签名原文换行/字段拼错）；403=时钟偏差超限或 IP 白名单拒绝[1]。先确认 ① date 是 GMT 且与服务器时间接近；② 签名原文严格三行、用 \n；③ headers 字段顺序 host date request-line 不能乱。

05请求 spec：business 参数 + 音频要求 + 评测文本格式▾

握手成功后，按「首帧（参数+文本）→ 音频帧 → 末帧」的节奏发 JSON。第一帧带 common（APPID）+ business（题型/语种）+ 评测文本；之后每帧带 data（音频分片 base64）[1]。

评测文本格式（英文）

英文评测文本随首帧（cmd=ssb 或 ttp）上传，按题型用不同标记包裹[1]：

题型文本格式例

句子 read_sentence / 篇章 read_chapter用 [content] 头 + 正文文本[content]\nNice to meet you.
自定义音标（可选）[vocabulary] 段给自定义 IPAword/IPA/

编码注意：文本按 tte 指定编码（统一 utf-8）；讯飞文档示例里文本前会带 UTF-8 BOM（﻿）前缀[1]——联调时若结果异常先检查 BOM 与换行。小贝的评测文本直接取字幕里那一句英文，套 [content]\n{句子} 即可。

06★ 返回结果 spec → 小贝 UI 映射（逐词逐音素颜色）▾

这是把「讯飞返回」翻译成「小贝界面」的核心章。讯飞结果是 XML，base64 编码后塞在 JSON 信封的 data.data 里，data.status=2 时为最终结果[1]。

JSON 信封 → 解码 → XML

{
  "code": 0, "message": "success", "sid": "ise000...",
  "data": { "status": 2, "data": "PHJlYWRfc2VudGVuY2Ug..." }  // base64(XML)
}

Rust 后端拿到后：① 判 code==0；② base64_decode(data.data) → XML 字符串；③ 解析 XML 取分数树 → 转成小贝自定义的结构体回传前端。

XML 结构（逐层下钻）

官方解码 sample 外层有 wrapper：根是 xml_result，里面外层 read_sentence → rec_paper → 内层 read_sentence，再 sentence > word > syll > phone。四维总分挂在内层 read_sentence/sentence 上（不是裸根）：

<xml_result>
 <read_sentence>
  <rec_paper>
   <read_sentence total_score="92.5" accuracy_score="100.0"
      fluency_score="87.6" integrity_score="100.0" standard_score="90.1"
      is_rejected="false" beg_pos="0" end_pos="150">
     <sentence content="Nice to meet you">
       <word content="Nice" total_score="95.2" dp_message="0">
         <syll content="nice">
           <phone content="n"  dp_message="0"/>   <!-- 英文:dp_message 承载读对/读错 -->
           <phone content="ai" dp_message="0"/>
           <phone content="s"  dp_message="128"/> <!-- 读错/替换 -->
         </syll>
       </word>
       <word content="meet" total_score="61.0" dp_message="0"> ... </word>
     </sentence>
   </read_sentence>
  </rec_paper>
 </read_sentence>
</xml_result>

注：以上为依据讯飞文档 + 解码官方 sample 整理的示意片段🟡。英文引擎 phone 节点用 dp_message 承载逐音素读对/读错（perr_msg 是中文引擎 phone 字段）；wrapper 层级可能随版本/题型变化，解析器按 tag 名遍历定位 sentence/word/syll/phone，不要假设固定根路径；具体数值/属性/字段名以实际返回为准[1]。

逐音素颜色打分是小贝的杀手锏 UI，靠 <phone> 节点的逐音素错误标记字段（英文引擎为 dp_message）。这要求 Ch5 同时满足三件事：① ise_unite="1"（总开关）+ ② rst="entirety" + ③ extra_ability 开 syll_phone_err_msg（+ multi_dimension），缺 ise_unite=1 则音素/多维全部返回空[1]。映射逻辑：标记=0 → 绿、轻微/警示档 → 黄、明确读错 → 红；点开单词把这一串 phone 平铺成可点的色块，告诉用户「meet 的 /iː/ 读短了」。Mini Demo（Ch14）就是这个交互的可玩原型。

07题型映射：read_word / sentence / chapter → 小贝场景▾

category 选错，评分维度就对不上。小贝三个核心跟读场景对应三个 category[1]：

小贝场景category评测文本重点维度建议时长
单词卡跟读（生词发音）read_word[word]\n{单词}准确度 + 音素级1–2 秒
逐句跟读（字幕这一句）read_sentence[content]\n{句子}四维全 + 逐词逐音素2–8 秒
Shadowing 影子跟读（整段）read_chapter[content]\n{多句段落}流利度 + 完整度（韵律/连贯）10–60 秒

选型逻辑：① 用户在小贝里点单个生词读 → read_word，重点看「这个词读没读准」；② 跟读字幕里的一句（最高频）→ read_sentence，拿全套四维 + 逐词逐音素，喂 Ch6 的颜色 UI；③ shadowing 整段 → read_chapter，这时流利度/完整度比单音素准确度更重要（shadowing 练的是节奏韵律，父报告 Ch10 有学理）。

实践建议：小贝默认对「逐句跟读」用 read_sentence 即可覆盖 80% 场景。read_chapter 适合 shadowing 模式开启时；篇章评测对录音质量/完整度更敏感，UI 上要引导用户「读完整段再停」。其余英文题型（simple_expression/topic/retell 等开放题）[1]面向口语考试，小贝精学场景用不上，不接。

08集成架构（小贝 Tauri）：录音 → Rust 后端 → 讯飞 → 渲染▾

整条链路一句话：前端录音 → invoke Rust command → Rust 现算签名连讯飞 WSS → 流式上传 → 解析 XML → 回传结构化分数 → 前端渲染颜色。secret 与所有讯飞调用都在 Rust 后端。

密钥

CORS

前端职责收到最小：① getUserMedia 录音并转 16k/16bit/单声道 PCM（或交后端重采样）；② invoke 把 {评测文本, category, 音频} 交后端；③ 拿回结构化分数渲染。前端完全不碰讯飞域名、不碰密钥、不组签名。Rust 后端是唯一对讯飞说话的人。

录音格式落地提示：WebView 的 MediaRecorder 常出 webm/opus，不是讯飞要的裸 PCM。两条路：① 前端用 AudioWorklet 取 Float32 → 转 16k Int16 PCM 再交后端；② 前端给原始流、由 Rust 后端用 symphonia/rubato 解码重采样到 16k 单声道（更稳，推荐）。这块属落地实现，留工程 session；本 spec 只钉「最终喂讯飞的是 16k/16bit/mono PCM」这个约束[1]。

  • 超量计费（已读到真实套餐阶梯）：超出免费额度在控制台买套餐，按量阶梯降价（均为 1 年有效、流式版）[2]：

MVP 够不够 + 放量成本测算

「1 次交互」≈ 一次完整评测请求。假设一个重度用户每天精学跟读 30 句（= 30 次）：

  • 单用户：30 次/天 × 30 天 ≈ 900 次/月。个人礼包 1 万次 ≈ 约 1 个月重度用户，或十几个测试用户跑一个月；要更多额度走企业认证 10 万次（≈ 10 个重度用户/月）。比旧版「5 万次」紧不少，但 MVP 冷启动验证够用。
  • 放量后（有真实套餐价）：1000 个日活、人均 30 次/天 = 3 万次/天 ≈ 90 万次/月。这时必然超免费额度，落在套餐二档（150 万次 / 38.7 元/万次），90 万次 ≈ ¥3.5k/月量级；继续放量到千万级走套餐四（20 元/万次）单价再降 ~half。这是从官网套餐页直接读到的真实阶梯价[2]，比横向估算可靠。
  • 横向辅证（降级）：腾讯云口语评测后付费 5 元/千次、套餐低至 3.5 元/千次（父报告 Ch7）[5]——与讯飞套餐阶梯量级相近，仅作交叉验证，不再是主测算依据。
  • 成本可转嫁：父报告 Ch11 已定「云端能力按量增值」——发音评分给免费额度、超出走会员/按量，云成本和收费挂钩，不亏。

给小贝的配额结论：① MVP 阶段：WebAPI 个人礼包 1 万次够把功能跑通 + 十几个测试用户验证一个月（比旧数紧，重度单人约 1 个月就见底，放量需企业认证 10 万次或买套餐）；② 放量阶段：已有真实套餐阶梯（套餐二 38.7 元/万次起），可据此直接测算成本拐点，再决定「继续云 / 迁本地 SSL」（父报告 Ch7「云先本地后」）；③ 并发 50 路对桌面端「一人一次评一句」的零散调用远远够用，不是瓶颈。

10合规与隐私：录音上云的 PIPL 最小同意▾

录音上云就触发 PIPL。讯飞 ISE 隐私政策的要点 + 小贝该做的最小合规动作如下[10]。

讯飞对上传数据怎么处理（文档要点）

  • 采集什么：音频、评测文本，以及设备标识（不同端：Android ID/OAID、iOS UUID、Linux MAC 等）；运行日志默认关闭[10]。
  • 是否用于训练：政策允许对去标识化 / 匿名化后的信息做「模型算法训练」[10]——这点必须知道：你的用户录音可能被（去标识后）用于改进讯飞模型。
  • 保留期：「为实现处理目的所必需的时间内」保留；日志按网络安全法至少留 6 个月[10]。
  • 开发者义务：必须告知终端用户「应用使用讯飞 ISE、个人信息会共享至科大讯飞」，提供隐私政策链接，并给用户行使数据权利的便捷机制[10]。

小贝的 PIPL 最小合规清单

1明示同意（单独勾选）
首次开启「发音评分」时弹明确说明：「这段跟读录音会上传到科大讯飞云端进行发音评测」+ 讯飞隐私政策链接，用户单独同意后才上云。默认不开、可随时关。
2最小化
只传这一句的录音 + 这一句文本，绝不传视频本体、不传整段连续录音、不夹带设备指纹之外的额外信息（对齐父报告 Ch8 边界表）。
3可删除 / 可关闭
本地录音用户可一键删；云端评测属一次性调用（讯飞返回分数即用途完成）。在隐私设置给「关闭云评分、改用本地 GOP」开关（Ch11）。
4儿童额外同意
讯飞明确要求：终端用户为不满 14 周岁未成年人时，开发者须取得父母/监护人对处理其个人信息的同意[10]，并适用《科大讯飞儿童隐私保护政策》。小贝若有 K12 / 儿童用户，必须做家长同意流程，否则违规。

⚠️ 儿童语音是高压线。小贝目标人群含 K12（父报告定位），儿童语音是 PIPL 下的敏感个人信息。三条硬约束：① 14 岁以下必须监护人同意；② 适用讯飞儿童隐私政策；③ 默认把儿童账号的云评分设为关闭/需家长开启，能用本地 GOP 就别上云。这块出事代价远大于一点评分精度，宁可保守。

对齐父报告边界：父报告第 2 章脚注和第 8 章都强调——「版权内容（视频本体）绝不上传」是硬约束；「用户可选的云端文本/录音任务」是另一回事，营销话术别混为一谈。小贝「默认全本地、云评分是可选开关」相比欧路（AI 字幕/跟读评分默认走云）正是差异化卖点[4]，合规上也更稳。

在线讯飞 ↔ 离线本地 GOP 切换策略

对齐父报告 B5（第 7 章）：发音评分在线主用讯飞 ISE、离线降级到本地 GOP/SSL。切换决策树：

用户点「跟读评分」时
↓
有网 + 用户已同意上云 + 额度未耗尽 → 走讯飞 ISE（四维 + 逐词逐音素，最准）
无网 / 用户关了云评分 / 儿童账号未开 → 降级本地 GOP/SSL（父报告 Ch7 选型，音素级，PCC 较低但能用、不出设备）
配额超限(11201) → 降级本地 + 后台提示「今日云评分额度用完，已切本地」
↓
UI 标明当前评分来源（云/本地），分数口径不混淆

切换的两个坑：① 口径不一致——讯飞和本地 GOP 的分数分布不同，切换时 UI 要标「本次为本地评分」，别让用户以为「今天突然变严了」；② 降级要无感但透明——网断了自动切本地继续能用（不卡死），但要让用户知道当前用的是哪套。父报告 Ch7「云先本地后」校准计划的第④条（阈值+置信度显示）在这里也适用：本地低置信时显示「不确定」而非硬给分。

本地降级引擎不在本 spec 范围：本地 GOP/SSL（Echoic·wav2vec2 路线）的选型与校准已在父报告第 7 章详述，本 spec 不重复。这里只钉「讯飞失败/离线时切到本地」这个降级接缝，以及两套分数的 UI 口径处理。

接入差异一句话：Azure 不用自己组 HMAC 握手——它有官方 Speech SDK（含 JS），传 key+region 即可，但 Tauri 里同样建议放 Rust 后端调 REST（避免 key 进前端）。评分结果结构不同（Azure 是 JSON，字段名 AccuracyScore/Phonemes 等），小贝若双接要做一层统一评分模型适配，让 UI 不感知后端是讯飞还是 Azure。详细计费口径（STT 基线 + prosody add-on）见父报告 Ch7[4]。

#[tauri::command]
async fn ise_eval(
  text:String, category:String,
  pcm:Vec<u8>
) -> Result<Score,String> {
  let url = build_ise_ws_url(
     KEY, SECRET);          // Ch4 签名
  let (mut ws,_) =
     connect_async(url).await?;
  ws.send(first_frame(      // business+text
     &text,&category)).await?;
  for chunk in pcm.chunks(1280){
     ws.send(audio_frame(chunk)).await?;
  }
  ws.send(last_frame()).await?;
  let xml = recv_until_status2(
     &mut ws).await?;       // base64 decode
  Ok(parse_ise_xml(&xml)?)  // → 四维+词+音素
}

15FAQ 常见问题▾

Q一句话，小贝该用 WebAPI 还是 SDK？＋

WebAPI（WebSocket 流式），Rust 后端发起。因为讯飞没有 macOS 原生 SDK（平台列表 Android/iOS/Linux/Windows/WebAPI）[6]，Tauri 要 Mac+Win 一致只能走 WebAPI；且 secret 必须在后端组 HMAC 签名，前端直连会泄密。

QAPISecret 能不能放前端？＋

绝对不能。前端 bundle 可逆向，secret 泄露=别人盗刷你账单。它只在 Rust 后端做 HMAC 签名，前端通过 invoke 把录音/文本交后端，后端对讯飞说话（Ch4/Ch8）。上线前 grep 前端产物确认 0 命中。

Q逐音素颜色打分靠哪个字段？＋

XML 里 <phone> 节点的逐音素错误标记——英文引擎是 dp_message（0=读对），perr_msg 是中文引擎 phone 字段⚠️ 字段名以真实英文返回为准[1]。前提是 business 同时开 ise_unite="1" + rst="entirety" + extra_ability=...;syll_phone_err_msg，缺 ise_unite=1 音素/多维返回空。映射：0→绿、警示→黄、读错→红（Ch6）。

Q返回是 XML 还是 JSON？要不要 base64 解码？＋

外层是 JSON 信封（code/message/sid/data），真正结果是 XML，base64 编码后塞在 data.data 里，data.status=2 为最终结果[1]。后端先 base64 解码再解析 XML（Ch6）。

Q音频要什么格式？前端录的能直接传吗？＋

要 16k/16bit/单声道 PCM（流式版固定 16k，非 16k 报 68675；编码 raw/MP3/speex-wb）[1]。WebView 的 MediaRecorder 常出 webm/opus，不能直传——前端用 AudioWorklet 转 16k PCM，或交 Rust 后端重采样（推荐，Ch8）。每 40ms 发 1280B、单帧不超 19200B。

Q逐句跟读用哪个 category？＋

read_sentence（拿全四维 + 逐词逐音素，覆盖 80% 场景）。单词卡用 read_word，shadowing 整段用 read_chapter（重流利/完整）。开放题 topic/retell 等小贝用不上不接（Ch7）。

Q免费额度多少？SDK 和 WebAPI 共用吗？＋

新用户实名礼包 个人 1 万次 / 企业 10 万次（流式版），应用默认每日 500 次上限[2]。SDK / WebAPI 额度是否共用，当前官网未明确⚠️ 需控制台确认。超量走控制台套餐阶梯（套餐二 150 万次 38.7 元/万次起，Ch9 有完整价目）。

Q免费礼包够 MVP 吗？放量要花多少？＋

够冷启动验证但比旧版紧：单重度用户约 900 次/月，个人 1 万次 ≈ 约 1 个月重度或十几个测试用户跑一个月；要更多走企业认证 10 万次。放量（1000 日活×30 次/天≈90 万次/月）落套餐二档（150 万次 / 38.7 元/万次）≈ ¥3.5k/月量级——这是官网套餐页真实阶梯价[2]，腾讯云 3.5–5 元/千次[5]仅作辅证（Ch9）。

Q儿童用户上云评分有什么坑？＋

大坑。讯飞明确要求14 岁以下须取得监护人同意，并适用其儿童隐私政策[10]。儿童语音是 PIPL 敏感信息。小贝若有 K12 用户：儿童账号默认不上云、需家长开启、能用本地 GOP 就别上云（Ch10）。

Q没网的时候发音评分还能用吗？＋

能，降级到本地 GOP/SSL（父报告 Ch7 选型，音素级、不出设备、精度稍低）。切换由 Ch11 决策树驱动：有网+已同意+有额度走讯飞，否则走本地。UI 要标明当前评分来源，避免「分数口径突变」的困惑。

Q什么时候该上 Azure 而不是讯飞？＋

① 小贝出海/服务海外用户；② 需要 prosody 韵律维度（仅 en-US）；③ 已在 Azure 生态。否则国内一律讯飞（国内节点低延迟、音频境内云合规更顺）。详见父报告 Ch7[4]。双接要做统一评分模型适配（Ch12）。

Q鉴权老报 401/403 怎么排查？＋

401=签名校验失败（多半签名原文拼错），403=时钟偏差/IP 白名单[1]。三查：① date 是 RFC1123 GMT 且与服务器时间接近；② 签名原文严格三行用 \n（host/date/request-line）；③ headers 字段顺序 host date request-line 不能乱（Ch4）。
