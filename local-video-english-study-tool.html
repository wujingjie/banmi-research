本地视频英语精学桌面 App：工程形态 + 本地处理栈 + 国内精学市场

📅 2026-06-11 🔍 ~30 次检索 + 多源核对 🖥️ Mac + Windows 桌面 App 🔒 内容只在本地处理 🇨🇳 面向中国用户 🤖 代码全由 AI 编写

一句话定调：小贝 这个产品技术上完全可行、市场空位真实但收窄，工程拍板是 Tauri 2.x + 打包 whisper.cpp/ffmpeg 为 sidecar + 发音评分「MVP 先用云 API（首选讯飞 ISE）、确认价值再迁本地」。「用户导入本地视频 → 小贝在本地转写/对齐 → 逐句跟读 + 影子跟读 + 发音评分」这条链路，每一环都有成熟开源件可由 AI 拼起来。但要把话说清醒：技术不是真风险——AI 都能写、栈都成熟；真风险在集成质量、法律打包（FFmpeg/codec/分发合规）、Windows 分发信任、以及用户工作流契合这四处。其中「好安装」（双端签名/公证/SmartScreen）尤其被低估，且中国个人开发者的 Windows 签名路径和欧美完全不同（见 Ch4）。

另一个清醒前提：中国用户假设 Windows 优先（不是 Mac 优先）+ 移动/云盘使用习惯重，所以小贝先要验证的窄楔子是「本地视频精听/跟读工作台」，而不是一上来就喊「全本地精学操作系统」。本篇按三条主线组织：主线 A 形态与分发（Ch3 Electron/Tauri 四维对比、Ch4 签名公证年成本 + 法律合规）→ 主线 B 本地处理栈（Ch5 转写、Ch6 逐句对齐、Ch7 发音评分【重点·主推讯飞 ISE】、Ch8 本地/云边界）→ 主线 C 功能与市场（Ch9 国内竞品全景、Ch10 精学方法真伪、Ch11 变现）。Ch12 是可玩 Mini Demo，Ch13 是给小贝的产品路线决策树（最重要）。每个具体数字/价格/性能都带 inline 引用，鼠标悬停 [1] 可看来源。规模/价格为查证当日快照。

📌 三条最关键发现（先扫这个）：

  • 工程形态选 Tauri 2.x，但「体积小」要分清「壳」和「真实占用」——Tauri 空壳确实比 Electron 小一个数量级（同款 todo app ~8.6MiB vs 180–244MiB）[1][2]，但小贝的真实落盘体积由 sidecar（ffmpeg+whisper 二进制）、Windows 上 WebView2 离线运行时（内嵌固定版约 +127MB）[3]、可选 Python/WhisperX、以及 whisper base/small 模型下载（1–2GB）主导——首启后实际可达数百 MB ~ GB 级。Tauri 的真正优势是「下载的安装器壳小、首装转化高」，不是「装完只占 8MB」。另一个必须知道的坑：不能在 Mac 上交叉编译 Windows 安装包，要用 CI 矩阵分平台构建[6]（不是 blocker，CI 模板现成）。🟢
  • 本地处理栈整条链路都能跑通，普通无独显笔记本也行（但「10×实时」是有条件的）——whisper.cpp 在 Apple Silicon 用 Metal 跑 base 模型可达约 10× 实时，但取决于芯片/模型/量化/beam/散热/是否真启用 Metal-CoreML[8]；逐句/逐词时间戳用 whisperX（wav2vec2 强制对齐，通常够字幕/逐句循环，精度需在目标媒体/口音/噪声实测，不当硬 SLA）[11]。发音评分是唯一「纯本地基线达不到云端水平」的一环：开源 GOP 基线与人工评分的相关性只有 PCC≈0.45[14]。推荐边界：MVP 用云发音 API（主推讯飞 ISE，国内标杆、低延迟、面向中国人英语评测，有免费额度起步）验证价值，确认值得再迁自建本地栈省成本+解合规[23]。🟡
  • 「自带本地视频做精学」的空位真实但已收窄，必须诚实承认有最接近的竞品——Language Reactor / Trancy 都是浏览器扩展，处理不了硬盘里的 mp4，且 LR 国内不可用[18]。但国内的欧路「每日英语听力」桌面版（Win/Mac）已经做到了相当多：导入本地文件 + AI 字幕生成、打开任意网站视频、一键校对字幕时间轴、切音轨/内置字幕、单句精听、桌面版跟读打分[22]——它就是最接近的竞品，不能再说「桌面+本地文件无人占」。小贝的差异化收敛到「系统化精学闭环（逐句跟读+shadowing+发音评分+SRS 一体）× 全本地处理 × 任意本地文件」这个组合，以及更深的精学体验，而非「无人做」。🟡

1工程形态：Tauri 2.x，不是 Electron
安装器壳小一个数量级（~8.6MiB vs 244MiB）[1][2]、空载内存省一半多[1]、打包本地二进制走官方 sidecar 干净[4]、自带 updater 且默认签名校验[7]。但别误读体积：小贝真实占用由 sidecar、WebView2 运行时、模型下载主导，首启后可达数百 MB~GB 级（Ch3 给「壳 vs 真实」两个数）。代价：Windows 渲染走系统 WebView2（Win11 预装、Win10 安装器自动拉）[3]，渲染一致性略弱于 Electron[2]；且必须 CI 矩阵分平台构建[6]。对「代码全由 AI 写」的单人项目，下载壳小/分发体验的收益远大于这点代价。
2「好安装」是真正的工程税，提前预算（中国开发者路径特殊）
Mac：Apple Developer Program $99/年 + Developer ID 签名 + 公证（notarytool），过 Gatekeeper 后用户双击即开[19]。Windows：2023 年起代码签名证书私钥强制存硬件/云 HSM——注意微软 Azure Trusted/Artifact Signing 中国个人开发者没资格（仅限 US/加/欧组织 + US/加个人）[33]，中国个人/小团队现实路径是国内 CA（沃通等）或国际 CA 经销商的 OV/EV 代码签名证书[34]；且 EV 已不再自动绕过 SmartScreen，新签名首发仍可能弹警告[20]。国内直接下载分发可行，但要分清 ICP/APP 备案的真实门槛（Ch4 新增合规小节）。
3本地转写/对齐链路：成熟，普通笔记本能跑
转写选 whisper.cpp（跨平台 + Apple Metal 加速，是 sidecar 嵌入的最佳选择）[8]；逐句/逐词时间戳选 whisperX（wav2vec2 对齐，词级 ±50ms，足以支撑逐句播放 + 跟读）[11]。base/small 模型 1–2GB 内存即可，无需独显[9]。
4发音评分：本地基线达不到云端，主推讯飞 ISE
纯本地开源 GOP 基线与人工评分相关性只有 PCC≈0.45[14]，而云 API 提供准确度/流利度/完整度多维成熟评分。结论：发音评分是「评分可上云」那一类（跟读录音是用户自己的、不含版权）。MVP 云评分主推科大讯飞 ISE——国内标杆、低延迟、专门面向中国人英语评测，单词/句子/篇章/音素多维，有免费额度起步、WebAPI+各端 SDK[23]；Azure 作海外/备选[16]。把版权敏感的「视频内容」死死锁在本地。
5市场空位收窄：要做「系统化精学闭环」而非「又一个本地播放器」
LR/Trancy 是在线扩展、碰不了本地文件、LR 国内不可用[18]；但欧路「每日英语听力」桌面版已支持本地导入+AI字幕+校轴+精听+跟读打分[22]，是最接近的竞品。小贝的差异化 = 任意本地文件 × 全本地处理 × 把跟读/shadowing/发音评分/SRS 串成一套系统化精学闭环（比泛听 App 更深的精学体验），而不是「无人做」的真空。

与上一份报告的关系：同目录《GitHub 英语学习开源生态》已覆盖 FSRS 间隔算法、发音评测开源生态、whisper 概览。本报告焦点不同——把「桌面 App 工程形态（Electron/Tauri/签名/打包本地二进制/自动更新）」和「国内精学市场全景」这两块上一份没深入的挖深。复习算法仍沿用上一份的结论（FSRS），本报告不重复。

02产品定位与市场空位：「自带本地视频精学」是真空位吗▾

先把切入点立住——如果空位是假的，后面工程做得再漂亮也没意义。结论：空位是真的，但比初稿设想的更窄——欧路「每日英语听力」桌面版已经占了「桌面+本地视频导入」这块大半，必须把边界诚实说清，否则容易自我感动。

关键差异点：扩展形态的天花板是「它只能看到浏览器里那个网页的视频」。你下载到本地的美剧、买的网课视频、播客 mp3、自己录的素材——扩展看不见也碰不到。而「桌面 App + 读本地文件」恰好把这个天花板掀掉。LR 在国内不可用（需要科学上网且服务在墙外）[18]，更是直接让一大批国内用户用不上这条最佳实践。

国内竞品里有没有人占了这个位（据实收紧）

诚实修订：欧路「每日英语听力」桌面版（Win/Mac）比初稿设想的能干多了，它就是最接近的竞品。实查其桌面版更新日志，已上线：通过「我的资源」播放本地文件 + AI 字幕生成（9.7.3/9.7.4）、打开任意网站视频（26.4.2）、一键校对字幕时间轴、切换视频音轨和内置字幕（26.4.2）、单句精听（9.7.3）、桌面版跟读打分（25.9.1 向全用户免费）[22]。也就是说，「桌面 + 导入本地视频 + 字幕对齐 + 跟读评分」这条链路它已经走通了大半，不能再说「没人占」。

它的相对短板（也是小贝可切的差异化）在于：① 整体仍是泛听/资源库导向（VOA/BBC/CNN/新概念是主体），本地导入是其中一个能力而非产品核心；② 跟读评分/AI 字幕等关键能力走云，不是「全本地、可纯离线」；③ 没把「围绕你自己的一部剧，跟读+shadowing+发音评分+生词进 SRS」串成一套系统化精学闭环，更像「能精听的播放器」而非「精学私教」。详见 Ch9。

所以收窄后的差异化 = 三重组合而非「四重无人区」：① 任意本地视频/音频 × ② 全本地处理（默认离线、可选上云，把版权内容死锁本地）× ③ 系统化精学闭环（逐句跟读+shadowing+发音评分+精听+SRS 一体，比泛听 App 更深）。欧路桌面版满足了「桌面+本地导入+部分精学」，但 ②（全本地）和 ③（系统化闭环+更深精学体验）这两点尚有真实空间——这才是诚实的切入点，是「做得更专、更闭环、更隐私」，不是「无人做」。

定位一句话

「把你硬盘里的任意英语视频，变成一套像私教课一样的精学材料——逐句听、跟着读、影子练、AI 打发音分、挖空听写、生词进复习——全程在你自己电脑上跑，一个字节都不上传。」

⚠️ 注意：「绝不上传」是小贝的产品承诺也是合规护城河，但要诚实——若用户选择对接云端做发音评分（讯飞 ISE）/翻译，那一小段不含版权的文本/录音会出境（见 Ch8 边界表）。「版权内容（视频本体）绝不上传」是硬约束，「用户可选的云端文本任务」是另一回事，营销话术别混为一谈。相比欧路（AI 字幕/跟读评分默认走云），小贝「默认全本地、云端是可选开关」正是可打的差异点。

03主线 A1：Electron vs Tauri 四维对比 → 明确推荐 Tauri ★▾

阿杰只关心四点，我就只答这四点，最后给拍板。结论先行：选 Tauri 2.x。四维里它赢三个半，唯一让步是渲染一致性，对一个单人 + AI 写码的本地工具项目无关痛痒。

① 一套代码同时产出 Mac + Windows 安装包：成熟度与坑

这是最容易踩的认知坑，先说清楚。无论 Tauri 还是 Electron，「一套前端代码同时出 Mac + Windows 安装包」都成熟，但都不能在一台 Mac 上交叉编译出 Windows 安装包。Tauri 因为依赖各平台原生库和工具链，「当前阶段无法做有意义的交叉编译」，官方推荐用 CI 矩阵（GitHub Actions 等）在各平台原生 runner 上分别构建——Windows 包在 windows-latest 上 build、Mac 包在 macos-latest 上 build[6]。官方提供 tauri-action，一键在三平台编译并上传 GitHub Release[6]。

✓ 对本项目的含义：这不是 blocker。CI 模板现成，AI 一次配好后每次 push 自动出双端包。但阿杰心里要有数——开发期想本机测 Windows 版，得有台 Windows（或虚机/CI artifact），不能在 Mac 上 tauri build --target windows 直接出 .exe（Linux/Mac 上用 NSIS 交叉编译 Windows「可行但有坑、测试少」，不建议依赖）[6]。Electron 同理，也是 CI 矩阵分平台 build，这点两者打平。

② 安装包体积 + 安装体验：分清「空壳基准」和「小贝真实占用」

先纠一个常见误读：「Tauri <10MB」是空壳 hello-world / todo benchmark，不是小贝装完只占 8MB。这类对比测的是「框架本身的最小体积」，对一个要内嵌 ffmpeg+whisper、可能再带 Python/WhisperX、首启再下 1–2GB 模型的媒体处理 App没有直接代表性。下面给「壳 vs 真实」两个数，别拿空壳数字当卖点。

Tauri 体积优势的正确表述：优势在「下载的安装器壳小」——面向中国用户、走「官网直接下载」的工具，下载一个几 MB 的壳 vs 一个 200MB 的，首装转化率有差别；模型/sidecar 可在首启时按需下载，不必塞进安装器。但装完后真实占用由 sidecar 二进制 + WebView2 运行时（Win11 预装、Win10 在线拉 bootstrapper 约几 MB；若做完全离线包内嵌 WebView2 固定版会 +127MB[3]）+ whisper 模型（1–2GB[9]）主导，可达 GB 级。营销文案别承诺「只占 8MB」。

③ 打包/调用本地二进制（whisper.cpp / ffmpeg）的难易：sidecar

这是小贝的命门——必须能可靠地内嵌并调用 whisper.cpp 和 ffmpeg。Tauri 的 sidecar 机制为此量身定做。

Tauri sidecar 怎么工作（实查官方文档）：在 tauri.conf.json 的 bundle.externalBin 里登记二进制路径，文件名必须带平台 target triple 后缀（如 whisper-aarch64-apple-darwin / whisper-x86_64-pc-windows-msvc.exe），打包时按当前平台自动挑对的那个塞进安装包；运行时用 app.shell().sidecar("whisper")（Rust）或 Command.sidecar()（JS）调起，并在 capabilities 里授予 shell:allow-execute/spawn 权限[4]。已有真实案例把 ffmpeg 作为 sidecar 嵌入做媒体转码，同样路径适用于 whisper.cpp[4]。

⚠️ 已知坑：macOS 上把动态链接的 ffmpeg 当 sidecar 可能遇到 dyld 库找不到的问题（社区 issue 有记录）[4]。规避：用静态编译的 whisper.cpp / ffmpeg 二进制，或确保依赖库一并打包。这对 AI 写码是可处理的工程细节，不是结构性障碍。Electron 也能做（把二进制放 resources 外，用 child_process spawn），但 Tauri 的 sidecar 是「一等公民」，路径解析、权限、打包都有官方约定，更不容易出错。

这是被严重低估的一块。「能 build 出安装包」和「用户双击能顺利装上、不被系统拦」是两件事。后者是持续的工程税，必须提前预算进项目。

macOS：Developer ID 签名 + 公证 + Gatekeeper

流程Mac 端三步
  1. 加入 Apple Developer Program（$99/年），账号持有者才能签发 Developer ID 证书[19]。
  2. 用 Developer ID 证书签名 app/dmg/pkg——让 Gatekeeper 认出「这是可信开发者」[19]。
  3. 公证（notarization）：用 xcrun notarytool 把签好的包传给 Apple 自动安全扫描，通过后「订书钉」一张票（staple），Gatekeeper 据此放行[19]。（注意 2023-11 起 altool / Xcode 13 及更早的上传通道已停，必须 Xcode 14+ 或 notarytool。）

对安装体验的影响：签名+公证齐全 → 用户双击直接打开，无摩擦。没公证 → macOS 弹「无法验证开发者、可能是恶意软件」，用户得右键→打开或去系统设置里放行，对小白是劝退级摩擦。直接下载分发（DMG/PKG，不上 Mac App Store）官方完全支持，同一个包就能给用户[19]。

Windows：代码签名 + SmartScreen（中国开发者路径与欧美不同）

⚠️ 初稿硬伤已修正：Azure Trusted/Artifact Signing 中国个人开发者没资格。微软官方文档明确：Artifact Signing（原 Trusted Signing）的公共信任证书目前仅向 US/加/欧/英的「组织」开放，个人开发者仅限 US 和加拿大，且 2025-04 起对其他国家暂停了新验证请求[33]。所以「~$10/月 Azure Trusted Signing 当默认 Win 签名路径」对中国个人/小团队不成立——别照初稿规划。

政策大背景：CA/Browser Forum 自 2023-06-01 起要求所有代码签名证书（OV 和 EV）私钥必须存在认证硬件——物理 USB 令牌（U 盾）或云 HSM[21]，传统「买个证书装本机签」的路走不通了。中国个人/小团队的现实路径是走国内 CA（沃通 WoSign / 天威诚信等）或国际 CA 的经销商买 OV/EV 代码签名证书：

  • 国内 CA 实价（沃通，查证当日）：OV 代码签名 ~¥3588/年、EV ~¥4288/年（多年更便宜）[34]。注意：沃通这类国内 CA 的代码签名证书面向「单位/组织」（需营业执照），不向个人签发[34]——纯个人开发者通常得通过国际 CA 经销商找少数仍受理个人 OV 的产品，或以个体工商户/公司主体申请。
  • 国际 CA 经销商：OV/EV 证书年价区间约 $200–$600（EV ~$247–$581）[20]，私钥走 U 盾或云签名服务（如经销商提供的 KeyLocker/云 HSM），可接 CI。

一句话：中国开发者签 Windows，要么走国内 CA（需公司主体、¥3500–4300/年量级），要么走国际 CA 经销商的 OV/EV（$200–600/年 + U 盾/云签名）——没有微软 Azure 那条 $10/月的近路。

⚠️ SmartScreen 的真相（结论不变，证据换微软官方口径）：微软已取消「EV 证书首发即绕过 SmartScreen」的特权——现在 EV 签名文件和 OV 一样，要走同一个「靠下载量积累信誉（reputation）」的过程[20]，微软官方也将 SmartScreen 信誉描述为随分发量/时间累积、而非证书类型直接决定[35]。意思是：花大价钱买 EV 也买不到「首发不弹警告」了。新签名 App 在下载量起来前，Windows 仍可能弹「SmartScreen 已阻止」蓝框（用户点「仍要运行」可继续）；首装时还会经历「未知发布者」摩擦。这是新产品冷启动绕不开的，靠时间+下载量化解。

国内直接下载分发可行性

可行，是小贝的分发主路，但「直接下载」≠「零门槛、什么都不用办」。不上 Mac App Store / 微软商店，从自己的官网（或国内对象存储 + CDN）直接提供 DMG/EXE 下载——Mac 端官方支持[19]，Windows 端本就是常规做法。好处：①绕开应用商店审核（小贝要读本地视频、调本地二进制，商店审核反而麻烦）；②国内用户无需账号、无需翻墙；③更新走 App 内置 updater（Tauri 自带）。分发的是「工具壳」，用户的视频内容从不上传，托管端只放无版权的 App 安装包和模型文件。但真实门槛在「托管」上——见下「国内分发合规」小节。

⚠️ 行业体感提醒：国内 Windows 生态有 360/腾讯电脑管家等第三方安全软件，对新签名、低下载量的 exe 也可能误报/拦截，建议提交各家白名单 + 官网给明确的「如被拦截怎么办」指引。🟡 行业体感

法律与合规（闭源商业 App 必读）

FFmpeg 打包义务（版权许可，独立于专利）：FFmpeg 默认 LGPLv2.1+，但若 build 中含 libx264/libx265 等 GPL 组件则整体变 GPL，含 --enable-nonfree 时二进制根本不可分发[36]。小贝作为闭源商业 App 必须：① 用 LGPL build、避开 GPL/nonfree flags；② 动态链接（用 DLL/共享库而非静态编入），并随附与二进制对应的 FFmpeg source + 你的 configure/build config；③ 在官网下载页/「关于」框/EULA 放 LGPL notice（如「This software uses code of FFmpeg licensed under the LGPLv2.1」）并声明不拥有 FFmpeg；④ EULA 不得禁止逆向工程（LGPL 要求）[36]。这是 AI 写码层面看不见、但发布前必须办的合规活。

codec / 专利风险（独立于 FFmpeg 的版权合规）：H.264/H.265/AAC/MP4 的专利许可与 FFmpeg 的版权许可是两码事——即便 FFmpeg 合规打包，使用这些编码本身仍可能触及 MPEG-LA/Access Advance/Via LA 等专利池。降暴露策略：桌面播放优先用 OS 原生解码器（macOS AVFoundation / Windows Media Foundation，专利费由系统/硬件厂商承担），FFmpeg 主要用于音频提取（抽 16k 单声道喂 whisper）和转码 fallback，而非作主力播放解码器。这样既能播绝大多数本地视频，又把专利暴露面压到最低。🟡 一般性合规判断，非法律意见；商业化前建议就 codec 专利单独咨询。

国内分发合规（据实，别写成「直接下载就行」）：

  • ICP 备案：只要小贝的官网/下载页/自动更新源/模型 CDN 托管在中国大陆，对应域名就需 ICP 备案（用腾讯云/阿里云国内 CDN 的域名必须先备案）[37]。规避思路：把这些放境外服务器（如香港）则不强制备案，但国内访问速度/稳定性要权衡。
  • App 备案：工信部「App 备案」专指移动 App（安卓/iOS/小程序/快应用）；纯下载的桌面 App 不等同于移动 App 备案[37]。但只要网站/更新/模型 CDN 托管在大陆，触发的是 ICP 备案（上一条），别和移动 App 备案混淆。
  • 软件著作权（软著）：一般是可选的所有权证据，非上线/备案前提——软著登记并非 ICP 或 App 备案的必需条件[37]。想要权属凭证/上架部分渠道时再办即可。

一句话：「直接下载分发」在技术上成立，但托管在大陆 = 要 ICP 备案（有公司主体更顺）；移动 App 备案对纯桌面 App 不适用；软著可选。🟡 一般性合规梳理，非法律意见。

05主线 B3：本地转写 whisper.cpp vs faster-whisper（普通无独显笔记本）▾

本地转写是整条精学链路的第一环——把视频里的英语音频变成带时间戳的文字。两个开源主力：whisper.cpp（C++，ggml）和 faster-whisper（Python，CTranslate2）。准确率两者基本一致（同一套 OpenAI 权重，WER 相差 <0.1% 绝对值）[9]，差别在速度、跨平台、嵌入难易。

普通笔记本的硬件门槛

不需要独显。模型内存占用：tiny/base ~1GB、small ~2GB、medium ~5GB[9]。对「逐句精学」场景，base 或 small 已经够用（英语清晰语音、有原字幕可校正），1–2GB 内存任何近五年的笔记本都扛得住。faster-whisper 的 int8 量化能再降 ~40% 显存/内存、提速约 2×，WER 几乎不掉[9]。Apple Silicon 上 whisper.cpp 走 Metal 直接拉满，是 Mac 用户的最佳体验[8]。

🏆 推荐：whisper.cpp 作为嵌入式转写引擎。三个决定性理由：① 单二进制、零运行时依赖，完美契合 Tauri sidecar（faster-whisper 要拖 Python 进来，嵌入桌面 App 笨重）；② 跨平台后端最全，且是 Mac 上唯一能吃 Metal 加速的，而小贝 Mac 用户占比大；③ 准确率与 faster-whisper 无实质差距。例外：若某些重型批处理场景在纯 x86 CPU 上追求极致吞吐，可在 Windows 端额外考虑 faster-whisper，但为了一致性和嵌入简洁，首选统一用 whisper.cpp。

📎 顺带：FFmpeg 近期已内置 whisper 音频 filter，可在 ffmpeg 命令链里直接出 SRT/JSON 转写[24]——小贝反正要打包 ffmpeg 抽音轨，未来这条路可能进一步简化「抽音→转写」的工程。🟡 较新、需实测稳定性

06主线 B4：逐句/逐词对齐 whisperX vs aeneas vs MFA▾

「逐句播放 + 跟读」要求每句话、最好每个词都有精确的起止时间戳。Whisper 原生时间戳很粗（句级 ±500ms 量级），所以要加一层强制对齐（forced alignment）。三个选项各代表一种思路。

一个反直觉的学术结论：论文实测里，老派的 MFA（Kaldi GMM-HMM）在「严格的音素边界精度」上反而打败 whisperX 和 MMS 这些现代端到端 ASR 对齐——MFA 在 ≤10ms 这种紧误差界上明显更准（mean boundary error TIMIT 21.9ms）[10]。但这是「语音学研究级」的精度需求。对「让学习者逐句播放、跟读不串句」的产品需求，whisperX 的词级 ~±50ms 量级通常够用——足以支撑字幕显示和逐句循环，人耳基本感知不到这点偏差[11]。但别当硬 SLA：实际精度随目标媒体、口音、背景噪声、模型而变，上线前应在小贝真实素材（如用户常看的美剧/网课/口音音频）上抽测，验证逐句切分不串句。

🏆 推荐：whisperX。理由：① 转写 + 对齐一条龙，与 whisper 同生态，AI 拼起来最省事；② 词级 ~±50ms 量级足够支撑「逐句播放、点词跳转、跟读不串句」全部交互（需在目标素材实测）[11]；③ 直出 SRT/VTT/JSON 多格式，挖空字幕/双语字幕都好做[11]。注意两点：(a) whisperX 是 BSD-2-Clause（初稿误写 BSD-4，已核实更正——实查其 LICENSE 为 BSD 2-Clause，可闭源商用），其说话人分离用的 pyannote 模型权重另有 license + HuggingFace 门控，做发音/对齐其实用不到分离，可不引入那部分[12]；(b) whisperX 基于 Python，嵌入桌面 App 比纯 whisper.cpp 重——可作为「批处理对齐服务」打包，或只在需要词级对齐时调用。MFA 留作「极致精度」的可选；aeneas 因 AGPLv3 传染 + 非词级设计，闭源 App 必须避开，不作主力。

07主线 B5【重点】：发音评分 本地选型 vs 云端【主推讯飞 ISE】→ 推荐边界 + 校准计划 ★▾

这是整份报告最需要给「清晰边界」的一章。发音评分（pronunciation assessment）是 shadowing / 跟读的灵魂功能，但它恰好是纯本地最吃力、云端最成熟的一环。先看证据，再给边界。

纯本地能到什么水平：开源 GOP/Kaldi 的真实天花板

关键数字（注意口径）：发音评测的标准开源基准是 speechocean762 语料（5000 句、250 名说话人，其中 125 成人 + 125 儿童，母语全是中文）[13]。在它上面跑经典 NN-GOP（Kaldi gop_speechocean762 recipe）做音素级评分，与人工专家评分的相关性只有 PCC ≈ 0.45（MSE 0.16）[14]。但这个 0.45 是「经典 GOP 基线」的数，不是「本地发音评分的全景天花板」——论文作者自己都说「这是不用最新技术的经典基线，结果不算强」[14]。更现代的 wav2vec2/GOPT/SSL 路线能把这个数明显推高（Echoic 这类开源项目就用 WhisperX + wav2vec2 做了逐音素颜色打分原型，MIT，全本地，模型约 1GB）[15]，但要拼装、要校准，不是开箱即用。本地发音评分的真实选型见下表，别只拿 GOP 0.45 给本地判死刑。

🏆 推荐边界（明确）：分阶段，MVP 云评分写死讯飞 ISE。

  • MVP / 早期：用云 API，主推科大讯飞 ISE。发音评分的「准」直接决定用户信不信这个功能，开源 GOP 基线的 PCC 0.45 给出的分数容易让用户觉得「乱打分」失去信任。讯飞 ISE 多维成熟、面向中国人英语评测、国内低延迟，能让功能一上来就可信，免费额度足够验证[23]。Azure 作海外/备选（需 prosody 时），腾讯云作国内备选（3.5–5 元/千次）[16][17b]。
  • 关键合规前提：发音音频片段不含版权（是用户自己的跟读录音，不是视频内容），所以它属于「可上云」那一类（见 Ch8）。版权敏感的视频本体永远不上传；但仍要在 UI 明确告知「这段录音会上传到讯飞评测」并取得同意。
  • 成长期 / 确认价值后：迁本地（SSL/Echoic·wav2vec2 路线）。动机有二：省掉按次成本、彻底消除录音出境的合规顾虑。代价是工程量大 + 要做下面的「校准计划」。

「云先本地后」的校准计划（迁本地前必须做的功课）：本地评分能不能上线，不取决于「跑通模型」，取决于「分数让目标用户信」。落地清单：

  • ① 目标口音集：收集小贝目标用户（中国 K12 / 成人 Mandarin-L1）真实跟读录音，覆盖不同年龄/水平/地域口音，别只用 speechocean762 现成集。
  • ② 评分 rubric：明确每个维度（音素准确/单词/句子流利/完整）打分定义，与讯飞云端口径对齐，保证迁移前后用户感受一致。
  • ③ 人工标注 mini-eval 集：请专家对一小批（数百句）做金标准评分，作为本地模型 vs 云 vs 人工的对照基准，量化 PCC/MSE。
  • ④ 阈值 + 置信度显示：低置信度时不硬给分，显示「这句没听清/不确定」，避免乱打分毁信任；阈值在目标口音集上调。
  • ⑤ 反馈 UX：以鼓励 + 可懂度为主（见下口音 bias），给「哪个音再练」的具体可操作建议，而非冷冰冰一个数字。

用 ① 在云阶段就攒数据，③ 做对照——本地模型达到「与云端 PCC 接近 + 用户主观可接受」才切换，否则继续用讯飞。

⚠️ 口音 bias 必读：speechocean762 的说话人母语全是中文（Mandarin-L1）[13]——这对「面向中国用户」的小贝是利好（语料人群匹配，本地校准时拿来当起点很合适）。但注意 native-accent bias：该语料的金标准评分由母语者标注，本身可能带「越像美音越高分」的倾向；学界明确提醒发音评测应以「可懂度（intelligibility）」而非「像母语者口音」为目标，许多评分量表会把「有口音」误判成「发错」[25]。对 K12 / 中国学习者，小贝应给「鼓励性、以可懂度为准」的反馈，比冷冰冰追求「美音满分」更健康——这也是上面校准计划第 ⑤ 条的核心。

08主线 B6：本地 vs 云端 清晰边界表 + 桌面可靠性工程清单▾

这张表是整个产品的合规与架构基石——它一句话回答「什么死锁本地、什么可以上云」。原则很简单：凡是触及版权内容（视频/音频本体、画面、原声）的处理，一律本地；凡是不含版权的纯文本任务、或用户自己的录音，可选上云。

架构落地：把这条边界做成产品的「信任契约」。① 默认全本地，云端能力做成可选开关，用户不开就 100% 离线可用（满足最在意隐私/没网的用户）；② 任何上云的数据（单词、单句、跟读录音）在 UI 上明确标注「这一步会联网，发送的是 XX」；③ 整片字幕、整段转写永不批量上传——即使做云端翻译，也按「逐句、用户点哪句传哪句」的颗粒度，而非「把整集字幕甩给云 API」。这样既守住版权红线，又能用云端的强文本能力提升体验。

⚠️ 注意：「单句翻译/释义可上云不构成侵权」是工程与合规的常见实践判断，非法律意见；商业化前若规模大，建议就「转写文本/字幕的版权边界」单独咨询专业法务。🟡 行业实践，非法律意见

三个关键结论

① 真买单的：词汇+SRS（背单词三巨头垄断头部）、跟读打分（每日英语听力/可可的核心活跃功能）。说明「能量化进步 + 有即时反馈」的功能最黏人。

FAQ常见问题（12 条）▾

Q到底选 Tauri 还是 Electron？一句话。＋

Tauri 2.x。小贝要官网直接下载（安装器壳小利首装，~8.6MB vs 244MB[1][2]——注意这是「壳」，装完含 sidecar+模型仍是 GB 级）+ 内嵌 whisper.cpp/ffmpeg（sidecar 干净[4]）+ 单人 AI 写码（Rust 工具链不再是门槛）。唯一让步是渲染一致性，对功能型工具无感。

Q「一套代码出 Mac+Windows 安装包」是不是一台 Mac 就能搞定？＋

不是。Tauri（和 Electron）都不能在 Mac 上交叉编译 Windows 安装包，要用 CI 矩阵在各平台原生 runner 上分别构建（Windows 包在 windows-latest 上 build）[6]。官方 tauri-action 一键搞定三平台。代码是一套，但构建要分平台跑——CI 模板现成，不是 blocker，但别幻想本机一条命令出双端包。

Q普通笔记本（没有独显）跑得动本地转写吗？＋

跑得动。base/small 模型只要 1–2GB 内存、不需要 GPU[9]。Apple Silicon 上 whisper.cpp 走 Metal，base 约 10× 实时[8]，一集 20 分钟的剧几分钟就转完。Windows 纯 CPU 也有 ~15× 实时[8]。对「精学」场景 base 精度足够（清晰英语+可校正）。

Q发音评分能不能纯本地做，不依赖云？＋

能做，但短期不建议作首发。开源 GOP 基线与人工评分相关性只有 PCC≈0.45[14]（注意这是经典基线、不是本地天花板，SSL/wav2vec2 能更高）。建议 MVP 用云 API、主推讯飞 ISE（面向中国人英语、国内低延迟、有免费额度[23]），确认价值后再迁本地（SSL/Echoic 路线）省成本+解合规，迁前要做口音校准集（Ch7）。发音录音是用户自己的、不含版权，属「可上云」类（Ch8）。

Q「绝不上传」和「可选对接云端」会不会矛盾？＋

不矛盾，关键是颗粒度。硬约束是版权内容（视频/音频本体、整片字幕/转写）永不上传。可上云的只有「孤立单词释义、单句翻译、用户自己的跟读录音、对话私教」这些不含版权的文本/录音任务，且做成可选开关、明确告知（Ch8 边界表）。营销话术别把两者混为一谈。

QWindows 上签了名为什么还弹 SmartScreen 警告？＋

因为微软已取消「EV 证书首发即绕过 SmartScreen」的特权——现在签名文件都要靠下载量/分发量积累信誉[20][35]。新 App 在信誉起来前仍可能弹蓝框（点「仍要运行」可继续），首装还有「未知发布者」摩擦。花大价钱买 EV 也买不到「首发不弹」了。靠时间+下载量化解，官网给「被拦截怎么办」指引（Ch4）。

Q双端签名一年要花多少钱？＋

注意中国开发者路径和欧美不同：Mac 端 Apple Developer Program $99/年[19]。Windows 端不能用微软 Azure Trusted/Artifact Signing（中国个人/组织没资格，仅限 US/加/欧/英）[33]，得走国内 CA（沃通等）的 OV ~¥3588/EV ~¥4288/年（需公司主体）[34]，或国际 CA 经销商的 OV/EV $200–581/年 + U 盾/云签名[20]。所以双端签名总成本量级是「$99 + ¥3.5k–4.3k/年」或「$99 + $200–600/年」，不是初稿设想的 ~$220/年（Ch4）。

QLanguage Reactor / Trancy 不是已经很好用了吗，为什么还要做？＋

它们是浏览器扩展，只能处理网页流媒体（YouTube/Netflix），碰不了你硬盘里的 mp4，且 LR 在国内不可用[18]。小贝的空位正是「桌面 App 读本地任意视频 + 全本地处理 + 系统化精学」——这是扩展形态结构上做不到的事（Ch2）。

Q国内有没有已经做了本地视频精学的？＋

有，且比初稿设想的更强：欧路「每日英语听力」桌面版（Win/Mac）已支持本地/网盘视频导入 + AI 字幕生成 + 一键校对字幕时间轴 + 切音轨 + 单句精听 + 桌面版跟读打分[22]——它就是最接近的竞品，「桌面+本地视频」这块不能说「无人占」。小贝的差异不是「无人做」，而是「做得更专」：全本地默认离线（欧路 AI 字幕/评分走云）+ 系统化精学闭环（跟读+shadowing+发音评分+SRS 一体）+ 围绕「你自己的剧」深度精学。其余竞品（可可/流利说/百词斩等）全不支持本地文件（Ch9）。

Q逐句对齐用 whisperX 够准吗？要不要上 MFA？＋

对小贝够用。whisperX 词级对齐在 ~±50ms 量级[11]，足以支撑逐句播放/点词跳转，人耳基本感知不到——但别当硬 SLA，实际精度随媒体/口音/噪声变，上线前在目标素材抽测。MFA 在「音素边界 ≤10ms」级更准[10]，但那是语音学研究级需求且更重。whisperX 与 whisper 同栈、AI 拼起来最省事（BSD-2-Clause 可闭源商用），首选它，MFA 留作可选。

Q第一个版本最少做哪几个功能？＋

就两个 P0：① 本地导入+转写+词级对齐+逐句播放；② 双语/挖空字幕+点词查义。这俩跑通就已经做到了所有竞品做不到的事（本地文件+全本地+逐句精学），且都是成熟开源件。跟读/发音评分/复习是 P1/P2，验证完核心体验再加（Ch13）。先窄后宽。

Q这个产品最大的风险在哪？＋

不在技术（AI 都能写、栈都成熟）。真风险四处：① 集成质量/可靠性（转写/对齐/评分串稳，模型下载/崩溃恢复/杀软误报，Ch8）；② 法律打包（FFmpeg LGPL + codec 专利 + ICP 备案，Ch4）；③ Windows 分发信任（中国开发者签名路径特殊 + SmartScreen 冷启动，Ch4）；④ 工作流契合 + 贪多（Windows 优先、欧路桌面版已是最接近竞品；别一上来做「精学操作系统」）。对策：先把「本地视频精听/跟读工作台」这根窄针扎透，再长（Ch13）。
