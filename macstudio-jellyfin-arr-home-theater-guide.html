Mac Studio 私人影院搭建手册：Jellyfin + arr 套件 + DS418 存储 + Apple Vision Pro

📅 2026-05-31 🔍 ~55 次检索 + 官方文档实查 🖥️ Mac Studio (Apple Silicon) 跑全套 💾 DS418 退成纯 NAS 存储 🥽 观看端 Apple Vision Pro

一句话蓝图：Jellyfin 原生装 Mac（吃 VideoToolbox 硬解）+ arr 四件套跑 Docker（好管理）+ DS418 SMB 挂载当仓库 + AVP 用 Infuse 直连看片。

全篇最关键的结论先抛：Docker Desktop for Mac 里的容器拿不到 VideoToolbox 硬件转码——这是 Jellyfin 官方文档白纸黑字写明的[1]。所以 Jellyfin 必须原生装在 macOS 上才能硬解 4K/HDR；arr 这些不吃转码的工具放 Docker 反而更省心。这是「路线 A」，本篇推荐它，理由全在 Ch2。

01架构总览：为什么弃群晖、用 Mac Studio▼

阿杰你完全不熟这套东西，所以我先把「整个系统长啥样、每个零件干嘛、为什么这么摆」讲清楚，再进操作。读完这章你脑子里要有一张图。

为什么 DS418 不能扛主力

群晖 DS418 的两个硬伤

  1. CPU 是 ARM（Realtek RTD1296），装不了官方 Docker：群晖的 Container Manager / Docker 套件只支持 Intel/AMD x86 机型，DS418 这类 ARM 入门 NAS 在套件中心根本搜不到 Container Manager。[2] 想跑 arr 套件就没了根基。已核实·机型限制
  2. 没有 Intel 核显（QuickSync），Jellyfin 没法硬件转码：DS418 既无 Intel iGPU 也无独显，Jellyfin 即使勉强跑起来也只能软件转码，4K 高码率必卡。

结论：DS418 当「跑应用的服务器」是死路。但它当「存硬盘的仓库」完全够格——4 盘位、SMB/NFS 共享稳定，正好退成纯 NAS。

设备角色跑什么

这套系统是怎么运转的（数据流）

用大白话串一遍，理解了这条链你就懂为什么要装这么多东西：

  1. 你在 Radarr（电影管家）里搜一部电影、点「想要」。
  2. Radarr 通过 Prowlarr（情报中心）去各个「索引器」找这部片的种子。
  3. 找到后把种子丢给 qBittorrent（下载工）开始下。
  4. 下完，Radarr 自动把文件改名、归类、搬进媒体库（DS418 上），Bazarr 顺手配好中英字幕。
  5. Jellyfin（放映厅）扫到新片，刮削海报简介，整整齐齐摆出来。
  6. 你戴上 Vision Pro，打开 Infuse 连 Jellyfin，点播放。

整个过程除了第 1 步和第 6 步，中间全自动。这就是 arr 套件的价值：把「找片→下片→整理→上架」做成流水线。

  • ③ Prowlarr — 索引器统一入口（给 Radarr/Sonarr 喂片源）

  • ⑧ AVP 客户端 — Infuse / Swiftfin
  • ⑨ 常开设置 — 防睡眠 + 自启，让 AVP 随时能连

02核心决策：Mac 上硬件转码怎么搞（全篇最关键）▼

这一章是整篇的命门。如果这里搞错，AVP 看 4K 会卡成幻灯片。我先把结论钉死，再讲为什么、怎么验证。

✅ 最终推荐：路线 A —— Jellyfin 原生装 Mac + arr 套件用 Docker

原因一句话：Docker on Mac 拿不到 VideoToolbox 硬件转码，Jellyfin 必须原生才能硬解；arr 这些不碰转码，放 Docker 反而最好管。

核实：Docker on Mac 能不能用 VideoToolbox 硬解？

结论：不能。这是 Jellyfin 官方文档明文写的

Jellyfin 官方 Apple 硬件加速文档原话（2026 现状）：「当 Jellyfin 跑在 macOS 上的 Docker 容器里时，用于转码的 ffmpeg 无法访问 macOS 用于 GPU 加速的 VideoToolbox 框架」，并明确「在 macOS 上无法像 Linux 那样把宿主机 GPU 共享给容器，所以 macOS 的 Docker 容器里 ffmpeg 只能用软件编码器」。[1]官方文档·已核实

技术根因：Docker Desktop for Mac 把 Linux 容器跑在一个轻量虚拟机里，底层是 macOS 的 Hypervisor.framework——它能虚拟 CPU/内存，但不提供任何虚拟 GPU 支持。[3] 所以容器里的 ffmpeg 物理上够不着苹果的视频编解码引擎。这不是配置问题，是架构限制，调参也解决不了。多源交叉

有没有「Docker 里硬解」的偏方？ 有人用 SSH 隧道把容器里的 ffmpeg 调用转发到宿主机原生执行[3]，但这是高度 hacky 的折腾，对「完全不熟命令行」的阿杰是灾难。直接 Jellyfin 原生装就绕过了整个问题，零折腾。

那「路线 B：全套 Docker，靠 Apple Silicon 软解扛」行不行？

能用，但不推荐——而且对你这个场景，真正该追求的是「根本不转码」

Apple Silicon 的 CPU 确实强，软件解码 4K HEVC/AV1 在 M 系列上单路一般扛得住。但有三个坑：

  1. 多路并发会爆 CPU：软解一路 4K HEVC 就吃掉好几个大核，同时两三路或者带 HDR 转 SDR 的 tone-mapping，CPU 占用飙高、风扇狂转、可能丢帧。硬解则轻松——官方说连入门 M1 都能同时硬解 3 路 4K Dolby Vision HEVC 10-bit 并做 tone-mapping，"Max" 芯片多一个编码引擎，单路能上 4K 120fps。[1]
  2. 软件编码画质/效率差：软件 x264/x265 编码慢且耗 CPU，硬件 VideoToolbox 编码又快又省电。
  3. 白白浪费 Mac Studio 的硬件：你买了带强力媒体引擎的机器，结果让它软解，等于买跑车走路。

🎯 真正的北极星：Direct Play（直接播放，根本不转码）

这里有个关键认知，能帮你彻底安心：转码只在「客户端放不了源文件的编码格式」时才发生。如果 AVP 上的播放器（尤其 Infuse）本身就能解码这部片的格式（HEVC/H.264/AV1 + 各种字幕），Jellyfin 就原样把文件流过去（Direct Play），完全不转码，Mac 几乎零负载。

Vision Pro + Infuse 的解码能力很强，绝大多数片子都能 Direct Play。所以 VideoToolbox 硬解是你的「安全网」——平时用不上，碰到客户端啃不动的冷门格式时它兜底，不至于软解卡死。两手都要：选对客户端争取 Direct Play（Ch11），同时配好硬解兜底（本章）。机制·多源

03前置准备 + 把 DS418 挂到 Mac 上▼

动手前先把地基打好：Mac 上装好 Docker，DS418 上建好文件夹，然后把 NAS 挂到 Mac。这章的「同一挂载点」原理务必看懂，否则后面 arr 搬文件会慢得离谱。

3.1 Mac Studio 装 Docker Desktop + Homebrew

1装 Docker Desktop for Mac
  1. 浏览器打开 docker.com/products/docker-desktop，下载 Apple Silicon 版（别下错 Intel 版）。
  2. 双击 .dmg，把 Docker 图标拖进「应用程序」。
  3. 打开 Docker，按提示授权，等右上角菜单栏的小鲸鱼图标变绿（变绿 = Docker 引擎已就绪）。
  4. 建议进 Docker 设置 → General，勾选 "Start Docker Desktop when you sign in"（开机自启，常开服务器必须）。
菜单栏鲸鱼图标常驻且为绿色/稳定状态；终端跑 docker --version 能打出版本号。
2装 Homebrew（Mac 的软件管家，后面装 Jellyfin/工具会用）

打开「终端」(Terminal，在 应用程序 → 实用工具)，粘贴官网这一行回车，按提示输密码等装完：

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

装完它会提示你跑两行 echo ... >> ~/.zprofile 把 brew 加进 PATH——照着复制粘贴跑即可（Apple Silicon 的 brew 装在 /opt/homebrew）。

终端跑 brew --version 能打出版本号。

3.2 DS418 上建共享文件夹

核心原则（划重点）：media 库和 downloads 必须放在同一个共享文件夹下，作为两个子目录。原因见 3.4 的 hardlink 原理。

1在群晖建一个总共享文件夹
  1. 登录群晖 DSM → 控制面板 → 共享文件夹 → 新增。
  2. 名字就叫 data（这是关键：一个总伞，下面分子目录）。
  3. 建好后，在 File Station 里进 data，新建两个子文件夹：media（最终媒体库）和 torrents（下载临时区）。
  4. 再在 media 下建 movies 和 tv；在 torrents 下建 movies 和 tv。

最终结构（这就是 TRaSH Guides 推荐的标准布局[4]）：

data/                  ← 一个共享文件夹（一个挂载点）
├── torrents/          ← qBittorrent 下到这里
│   ├── movies/
│   └── tv/
└── media/             ← Radarr/Sonarr 把成品归类到这里
    ├── movies/        ← Jellyfin 的电影库指这里
    └── tv/            ← Jellyfin 的剧集库指这里
2建一个专用账号 + 开 SMB
  1. 控制面板 → 用户与群组 → 新增一个用户，比如 mediauser，给它对 data 文件夹的读写权限。（用专用账号比用 admin 安全。）
  2. 控制面板 → 文件服务 → SMB → 勾选「启用 SMB 服务」。记下群晖的局域网 IP（比如 192.168.1.20）。
在 Mac 访达 → 前往 → 连接服务器，能用 smb://192.168.1.20 看到 data 文件夹。

3.3 把 DS418 挂到 Mac（开机自动挂载）

为什么不能只在访达里点连接？ 访达手动连接的挂载点在 /Volumes/data，但路径不稳定、重启会掉、且 Docker 容器要引用一个固定可靠的宿主机路径。我们要让它开机自动挂载到固定位置。

方案（推荐·最简）访达连接 + 登录项自动重连
  1. 访达 → 前往 → 连接服务器，输入 smb://192.168.1.20/data，用 mediauser 登录，勾选「在钥匙串中记住密码」。挂载后会出现在 /Volumes/data。
  2. 系统设置 → 通用 → 登录项 → 「打开时」点 +，把刚挂载的 data 宗卷加进去。这样每次登录自动重连。[5]

这是对小白最稳的方案。它的挂载点是 /Volumes/data，docker-compose 里就映射这个路径。

进阶（可选，更稳的开机自动挂载）：macOS 可以用 autofs 配置一个固定挂载点（比如 /Users/Shared/data），编辑 /etc/auto_master 和一个 map 文件实现「访问即挂载、重启不掉」。[5] 但配置要碰 sudo 改系统文件，对你偏折腾。先用上面的登录项方案跑通，稳定后想要更可靠再上 autofs。进阶·按需

SMB vs NFS：Mac 连群晖默认用 SMB，对单用户大文件读写够快、最省心，本篇就用 SMB。NFS 在某些场景吞吐更高但权限/配置更绕，不建议小白起步用。如果将来播放大码率 4K 卡顿且确认是 NAS 读取瓶颈，再研究 NFS 或上万兆网络。判断

3.4 ⭐ 最重要的原理：hardlink「秒搬」与同一挂载点

为什么 media 和 torrents 必须在同一个挂载点下

当 qBittorrent 下完一部片放在 torrents/movies/，Radarr 要把它「搬」进 media/movies/。这里有两种搬法，天差地别：

  • 硬链接（hardlink）+ 即时移动：如果两个目录在同一个文件系统/挂载点，搬动是「秒完成」的——不真复制数据，只是建一个指向同一份数据的新名字。不占额外空间、瞬间完成，还能让 qB 继续做种的同时 Jellyfin 已能播。[4]
  • 跨挂载点 = 退化成完整复制：如果 media 和 torrents 在不同的共享/挂载，系统没法 hardlink，只能整个文件复制一遍——一部 40GB 的 4K 蓝光要复制几分钟到十几分钟，还占双倍空间。[4]

所以前面才坚持把 media 和 torrents 都放在群晖那一个 data 共享下——挂到 Mac 后它们在同一个 /Volumes/data 挂载点里，hardlink 成立，搬片秒完成。

这是 arr 新手第一大坑。很多人把 downloads 和 media 设成两个独立共享，结果每次入库都全量复制、硬盘塞满、速度奇慢，还以为是网络问题。记住：一个 data 伞，下面分 torrents 和 media 两个子目录。
本章完成标志：Mac 上 /Volumes/data 里能看到 torrents 和 media 两个文件夹，且能在里面新建/删除测试文件（说明读写权限 OK）。

04一份 docker-compose.yml（arr 套件，复制即用）▼

这一份文件把 qBittorrent + Prowlarr + Radarr + Sonarr + Bazarr 五个容器一次性定义好。后面每章是「配置」它们，但「启动」就靠这一份。先放上来，逐行讲。

4.1 先搞清两个数字：PUID / PGID

Linux 容器要知道「用哪个用户身份读写文件」，否则下载的文件 Mac 这边可能没权限动。这两个值要填你 Mac 当前用户的 uid/gid（LinuxServer 镜像用 PUID/PGID 让容器以你的身份读写文件，避免权限错乱[6]）。终端跑：

id -u    # 打出你的 UID，比如 501
id -g    # 打出你的 GID，比如 20

记下这两个数（Mac 第一个用户通常是 501 和 20），填进下面 compose 的 PUID/PGID。标准做法

4.2 建项目目录 + 放文件

1建一个放配置的文件夹

终端跑（在你的用户目录下建 arr 文件夹，里面再建各容器的 config 目录）：

mkdir -p ~/arr/{qbittorrent,prowlarr,radarr,sonarr,bazarr}
cd ~/arr

然后用任意文本编辑器（如「文本编辑」或 VS Code）在 ~/arr/ 下新建文件 docker-compose.yml，粘贴下面内容。

4.3 docker-compose.yml 全文（逐行注释）

# ~/arr/docker-compose.yml
# arr 套件五件套 · Mac Studio + DS418(SMB 挂载在 /Volumes/data)
# 镜像全部用 linuxserver.io（社区标准，Apple Silicon arm64 原生支持）[见 ref 6]

services:

  # ── 下载客户端：qBittorrent ──
  qbittorrent:
    image: lscr.io/linuxserver/qbittorrent:latest
    container_name: qbittorrent
    environment:
      - PUID=501              # ← 改成你 id -u 的值
      - PGID=20               # ← 改成你 id -g 的值
      - TZ=Asia/Shanghai      # ← 时区，海外按当地改，如 America/Los_Angeles
      - WEBUI_PORT=8080       # qB 网页管理端口
    volumes:
      - ./qbittorrent:/config            # qB 的配置存本地
      - /Volumes/data:/data              # ★关键：整个 data 挂进去，保证同挂载点 hardlink
    ports:
      - 8080:8080            # 网页 UI
      - 6881:6881            # BT 监听
      - 6881:6881/udp
    restart: unless-stopped

  # ── 索引器统一入口：Prowlarr ──
  prowlarr:
    image: lscr.io/linuxserver/prowlarr:latest
    container_name: prowlarr
    environment:
      - PUID=501
      - PGID=20
      - TZ=Asia/Shanghai
    volumes:
      - ./prowlarr:/config
    ports:
      - 9696:9696
    restart: unless-stopped

  # ── 电影管家：Radarr ──
  radarr:
    image: lscr.io/linuxserver/radarr:latest
    container_name: radarr
    environment:
      - PUID=501
      - PGID=20
      - TZ=Asia/Shanghai
    volumes:
      - ./radarr:/config
      - /Volumes/data:/data              # ★同一个 /data，内部路径才和 qB 一致 → hardlink 成立
    ports:
      - 7878:7878
    restart: unless-stopped

  # ── 剧集管家：Sonarr（不追剧可删掉这一段）──
  sonarr:
    image: lscr.io/linuxserver/sonarr:latest
    container_name: sonarr
    environment:
      - PUID=501
      - PGID=20
      - TZ=Asia/Shanghai
    volumes:
      - ./sonarr:/config
      - /Volumes/data:/data
    ports:
      - 8989:8989
    restart: unless-stopped

  # ── 字幕管家：Bazarr ──
  bazarr:
    image: lscr.io/linuxserver/bazarr:latest
    container_name: bazarr
    environment:
      - PUID=501
      - PGID=20
      - TZ=Asia/Shanghai
    volumes:
      - ./bazarr:/config
      - /Volumes/data/media:/media       # Bazarr 只需要看 media（成品库）
    ports:
      - 6767:6767
    restart: unless-stopped

⭐ 这份 compose 的灵魂：每个容器里都把 /Volumes/data 映射成 /data

注意 qB、Radarr、Sonarr 都写 - /Volumes/data:/data。这样它们容器内部看到的路径完全一致（都是 /data/torrents/... 和 /data/media/...），在同一个文件系统里 → hardlink 才能成立（呼应 Ch3.4）。[4] 千万不要给 qB 映射 /downloads、给 Radarr 映射 /movies 这种各管各的——那是新手最经典的「为什么我入库这么慢」翻车点。

4.4 启动 + 验证

1一行命令拉起全套
cd ~/arr
docker compose up -d

第一次会下载镜像（几分钟），下完五个容器自动后台运行。以后改了 compose 重跑同一条命令即可。

跑 docker compose ps 看到 5 个容器都是 running/Up；浏览器逐个打开 localhost:8080(qB)、localhost:9696(Prowlarr)、localhost:7878(Radarr)、localhost:8989(Sonarr)、localhost:6767(Bazarr) 都能出界面。

不想敲命令？Docker Desktop 图形界面备选

Docker Desktop 有「Containers」面板能看到这五个容器、点开/停/看日志，但用 compose 文件创建仍是最干净的方式（一个文件记录全部配置，搬家/重装一键恢复）。建议：创建用命令行那一行 docker compose up -d，日常监控/重启用 Docker Desktop 图形界面点按钮，两者结合最舒服。

05qBittorrent：下载客户端（必装）▼

目标：让 qB 跑起来、改掉默认密码、设好下载目录和分类，为后面 Radarr 自动投喂做准备。arr 自己不下载，所有片都靠 qB 实际下。

1首次登录改密码
  1. 浏览器开 http://localhost:8080。
  2. linuxserver 镜像首次启动会在容器日志里生成临时密码：Docker Desktop → qbittorrent 容器 → Logs，找到 "temporary password" 那行；用户名 admin。
  3. 登录后 → 工具(齿轮) → Web UI → 设置一个你自己的用户名密码，保存。
老版本默认密码是 admin/adminadmin，新版改成日志里的随机临时密码。登录不上先去看容器日志。
2设默认下载路径
  1. 设置 → Downloads → Default Save Path 填 /data/torrents（这是容器内路径，对应 NAS 的 data/torrents）。
  2. 建议勾选「Keep incomplete torrents in」并填 /data/torrents/incomplete，让没下完的片单独放，下完再移到分类目录。
3建分类（categories）

左侧 Categories 右键 → Add category，建两个，后面 Radarr/Sonarr 会用：

  • radarr → Save path /data/torrents/movies
  • sonarr → Save path /data/torrents/tv

这样 Radarr 下的片自动进 movies 子目录，Sonarr 进 tv，清清爽爽。

务必把 设置 → Downloads → Default Torrent Management Mode 设为 Automatic，否则按分类自动归目录不生效，下载不会进 category 文件夹，Radarr 也就找不到成品 → 整条流水线在「导入」这步断掉。[9]
qB 能登录、Default Save Path 是 /data/torrents、有 radarr/sonarr 两个分类。手动拖一个测试种子能下到 /Volumes/data/torrents/（在 Mac 访达里能看到文件出现）。

06Prowlarr：索引器统一入口（必装）▼

目标：在 Prowlarr 里一次性配好所有「索引器」（片源站点），它会自动把这些源同步给 Radarr 和 Sonarr——以后加新源只在这一处加。[7]

1设登录密码

开 http://localhost:9696，首次进 Settings → General 设个用户名密码（Authentication 选 Forms / Basic），保存。后面 Radarr/Sonarr/Bazarr 都一样先设认证。

2添加索引器（Indexers）
  1. Indexers → Add Indexer → 搜你要用的站点。
  2. 公开源（如 1337x、The Pirate Bay 这类公共 tracker）直接加即可，免费无门槛。
  3. 私有站（需要账号的 PT/会员站）要填你的 API key / cookie / 用户名密码。
  4. 每加一个，点 "Test" 按钮，绿勾才算通。
合规留意：你接什么索引器、下什么内容，决定了合规性。公共盗版 tracker 上的版权内容有法律风险；建议优先用合法来源（见 Ch14）。工具本身合法，怎么用是你的责任。
3连接 Radarr / Sonarr（关键一步）
  1. Prowlarr → Settings → Apps → Add → 选 Radarr。
  2. Prowlarr Server 填 http://prowlarr:9696，Radarr Server 填 http://radarr:7878。
    这里要用容器名（radarr、prowlarr）而不是 localhost！因为容器之间是通过 compose 创建的内部网络互相找的，localhost 在容器内指的是容器自己，连不到对方。
  3. API Key：去 Radarr 的 Settings → General 复制它的 API Key 填进来。
  4. Test → 绿勾 → Save。同样方式再加一个 Sonarr（http://sonarr:8989）。

配好后，Prowlarr 会自动把所有索引器推送同步到 Radarr 和 Sonarr（Full Sync：在 Prowlarr 改动索引器会同步到各 app），你在那两边就能直接搜片了——以后加新源只在 Prowlarr 这一处加[7]。

Prowlarr 里至少 1 个索引器 Test 通过；Apps 里 Radarr（和 Sonarr）显示已连接；去 Radarr 的 Settings → Indexers 能看到 Prowlarr 同步过来的源。

07Radarr：电影自动化主力（必装）▼

目标：Radarr 是电影流水线的总指挥。配好它「连 qB（下载）+ 收 Prowlarr 的源 + 设媒体路径 + 设质量/命名规则」，之后搜片→下片→入库全自动。

1设认证

开 http://localhost:7878，Settings → General 设用户名密码。顺手记下这页的 API Key（Prowlarr/Bazarr 要用）。

2连接下载客户端 qBittorrent
  1. Settings → Download Clients → + → qBittorrent。
  2. Host 填 qbittorrent（容器名！不是 localhost），Port 8080，填 qB 的用户名密码。
  3. Category 填 radarr（对应 Ch5 建的分类）。
  4. Test → 绿勾 → Save。
3设媒体根目录（Root Folder）
  1. Settings → Media Management → 拉到底 Root Folders → Add Root Folder。
  2. 填 /data/media/movies（容器内路径，对应 NAS 的 data/media/movies，也是 Jellyfin 电影库要指的地方）。
务必填 /data/media/movies 而不是 /data/torrents！torrents 是下载临时区，media 才是归类后的成品库。两者同在 /data 下 → 入库走 hardlink 秒搬（Ch3.4）。
4开启 hardlink + 重命名
  1. Settings → Media Management → 勾选 Rename Movies（自动按规范命名）。
  2. 同页 File Management → 勾选 "Use Hardlinks instead of Copy"（默认开，确认它是开的）。这就是让入库走秒搬而非复制的开关。[4]
  3. 命名格式（Standard Movie Format）建议直接套用 TRaSH Guides 的推荐字符串[8]，能确保 Jellyfin 正确识别。一个常用模板： 
    {Movie CleanTitle} ({Release Year}) {imdb-{ImdbId}} {edition-{Edition Tags}} [{Quality Full}][{MediaInfo VideoDynamicRangeType}][{Mediainfo VideoCodec}]
5设质量 Profile（要 4K 就选 4K）
  1. Settings → Profiles → Quality Profiles。
  2. 因为 AVP 看 4K 是硬指标，建议用/复制一个包含 Bluray-2160p / WEB-2160p (4K) 的 profile，把 4K 档勾上、排在高位。
  3. 进阶：TRaSH Guides 提供「Custom Formats」可以精细控制要 HDR/DV、要特定音轨、避开烂压制组[8]。第一次先用默认 4K profile 跑通，玩熟了再上 Custom Formats 调优，别一上来钻牛角尖。
4K 提醒：4K 文件巨大（单片 20–80GB），确保 DS418 容量够；且要让 AVP Direct Play（Ch11）避免转码，否则即使硬解也是负载。
Radarr 里：Download Client(qB) Test 绿、Root Folder 是 /data/media/movies、Hardlink 开、有一个含 4K 的质量 profile、Indexers 有 Prowlarr 同步来的源。Movies → Add New 搜一部片能出结果。

08Sonarr：剧集自动化（追剧再装，可跳过）▼

Sonarr ≈ Radarr 的剧集版，专管电视剧/连续剧（按季按集追更）。如果你主要看电影，这一章可以直接跳过（compose 里那段也可删）。要追剧再回来配，步骤和 Radarr 几乎一模一样。

配置（和 Radarr 对照着做）

1认证 + 连 qB

开 http://localhost:8989，设密码，记 API Key。Settings → Download Clients → qBittorrent，Host 填 qbittorrent、Port 8080、Category 填 sonarr。

2根目录 + hardlink + 命名
  1. Root Folder 填 /data/media/tv。
  2. Media Management 勾 Rename Episodes + Use Hardlinks。
  3. 命名套 TRaSH Guides 的 Sonarr 模板[8]（剧集对命名更敏感，季/集号要规范，否则 Jellyfin 认不出第几季第几集）。
3索引器已自动有了

因为 Ch6 已把 Sonarr 加进 Prowlarr 的 Apps，源会自动同步过来，这里不用再配。

Sonarr：qB Test 绿、Root Folder /data/media/tv、有源、Series → Add 能搜到剧。

09Bazarr：自动中英字幕▼

目标：让 Bazarr 自动给每部入库的片下中文 + 英文字幕，挂在视频旁边，Jellyfin/AVP 播放时直接能选。

1认证 + 连 Radarr/Sonarr
  1. 开 http://localhost:6767，设密码。
  2. Settings → Radarr：Address 填 radarr（容器名）、Port 7878、填 Radarr 的 API Key，Test → Save。
  3. 同样配 Sonarr（sonarr / 8989 / API Key），如果你装了 Sonarr。
2设语言（中 + 英）
  1. Settings → Languages → Languages Filter 加 Chinese 和 English。
  2. 新建一个 Languages Profile 同时包含中文、英文，设为默认；在 Radarr/Sonarr 设置里把这个 profile 应用上。
3加字幕源（Providers）
  1. Settings → Providers → 加几个免费/常用源：OpenSubtitles（要注册免费账号填进去）、Subscene 等。[9]
  2. 中文字幕想要质量更好，可以加针对中文的源（社区有 ChineseSubFinder 等独立工具，Bazarr 本身的 OpenSubtitles 中文也够日常用）。中文源质量按需调
Bazarr 连上 Radarr 后能列出你库里的电影；对一部片点「手动搜字幕」能搜到并下载中/英字幕，文件出现在该片目录旁（如 电影.zh.srt / 电影.en.srt）。

10Jellyfin：原生装 Mac + VideoToolbox 硬解配置▼

重头戏。按 Ch2 的决策，Jellyfin 原生装在 macOS 上（不是 Docker），这样才能开 VideoToolbox 硬解。

10.1 装 Jellyfin Server（原生）

Jellyfin 官方有 macOS 菜单栏 .app（仓库 jellyfin/jellyfin-server-macos，2026 已到 10.11.x，自带 ffmpeg/ffprobe，开箱即用 VideoToolbox 硬解）[10]。装法二选一，都行：

  • 方式 A（推荐·图形）：去 jellyfin.org/downloads/macos，下 arm64 (Apple Silicon) 的 .dmg（如 jellyfin_10.11.x-arm64.dmg，已签名公证），打开 DMG 把 Jellyfin.app 拖进「应用程序」，双击运行。它在菜单栏出现一个小图标，后台跑服务。[10]
  • 方式 B（命令行·一行）：装了 Homebrew 的话，brew install --cask jellyfin 同样装这个菜单栏 app（需 macOS ≥ 12），打开即可。两法均核实
认准 arm64（不是 x86/Intel）。装好后服务监听 http://localhost:8096，菜单栏图标可 Launch/Quit。Jellyfin 是 macOS 原生进程，不在 Docker Desktop 列表里——这正是它能用 VideoToolbox 的原因。Apple Silicon 跑此 app 建议 macOS 14+（低版本需升级或用 x86 包）。
1首次设置向导
  1. 浏览器开 http://localhost:8096，进入设置向导：选语言、建管理员账号密码。
  2. 添加媒体库：Add Media Library → 类型选 Movies → 文件夹指向 NAS 上的电影库路径。
    关键路径区别：Jellyfin 是原生跑的，不用容器内的 /data/... 路径，而是用 Mac 的真实挂载路径 /Volumes/data/media/movies。同理剧集库指 /Volumes/data/media/tv。（arr 在容器里看到的是 /data/media，Jellyfin 在 Mac 上看到的是 /Volumes/data/media——指向同一份文件，只是视角不同。）
  3. 再 Add 一个 Shows 库指 /Volumes/data/media/tv（若装了 Sonarr）。
  4. 完成向导。Jellyfin 开始刮削海报/简介，稍等就能看到电影墙。

10.2 ⭐ 开 VideoToolbox 硬件转码

前提（官方要求）

  • Jellyfin server 10.9.0 及以上 + jellyfin-ffmpeg 6.0.1-5 及以上 才有原生 Apple Silicon 支持（现在装的最新版远超这个，自动满足）。[1]
  • macOS 12 及以上。[1]
1在管理后台打开硬解
  1. Jellyfin 右上角 → Dashboard（管理后台）→ Playback → Transcoding。
  2. Hardware acceleration 下拉选 Apple VideoToolbox。
  3. 勾选要硬件解码的编码格式：H264、HEVC（2017 年及以后的 Mac 都支持 HEVC 编解码）；AV1 解码需要 M3 及以上芯片才有。[1]
  4. 勾选 Enable hardware encoding（让编码也走硬件，而非只解码）。
  5. HDR→SDR 的 tone-mapping 想要可一并勾上（VideoToolbox 支持，官方称 M1 即可边硬解 4K Dolby Vision 边 tone-map[1]）。
  6. Save。

10.3 验证硬解真的生效（关键检查点）

不能光看设置开了就以为生效，要实测。方法：

  1. 找一部会触发转码的片来放（比如故意用一个低画质/不兼容设置的客户端，或在播放时手动降码率，逼 Jellyfin 转码）。
  2. 播放时进 Dashboard → Activity / 播放，看这条流的详情：如果显示 「Transcoding (hw)」或带 VideoToolbox 字样，说明硬解生效。
  3. 同时开「活动监视器」(Activity Monitor) 看 CPU：硬解时 CPU 占用很低（视频引擎在干活，不占 CPU）；如果一转码 CPU 就飙到 80%+，说明没走硬解、退化成软解了，回去检查设置。
如果 Hardware acceleration 下拉里没有 VideoToolbox 选项，多半是 Jellyfin 装成了 Docker 版（Ch2 说过 Docker 看不到 VideoToolbox）。确认你装的是原生 macOS 版。
本章完成：Jellyfin 电影墙有海报；Dashboard 硬解选 VideoToolbox 已 Save；逼一次转码时活动里显示 hw 转码 + Mac CPU 占用低。

11Apple Vision Pro 观看端▼

目标：在 AVP 上选对客户端、连上 Mac 的 Jellyfin、争取 Direct Play 流畅看 4K/3D。

11.1 客户端怎么选（逐个核实）

客户端visionOS 可用连 Jellyfin4K/高码率直连沉浸环境真 3D 立体价格
Infuse 8✅ 原生 visionOS app✅ 原生支持✅ 解码强，绝大多数直连✅ Cinema/Room/Space 等❌ 当 2D 放(见下)Pro 买断/订阅
Swiftfin(官方)✅ 原生(visionOS 1.0+)✅ Jellyfin 官方客户端✅ 直连好(VLCKit)🟡 一般❌免费
Jellyfin 网页🟡 Safari 里开✅🟡 浏览器易触发转码无❌免费
Moon / SKYBOX✅ 原生🟡 走 SMB/DLNA 直连(非 Jellyfin 库)✅✅ VR 风✅ 真立体~$9–10

✅ 推荐：2D/4K HDR 用 Infuse（首选）或 Swiftfin（免费）；真 3D 另走 Moon/SKYBOX

Infuse 8 是 AVP 上看自有媒体库的口碑标杆[11]：原生 visionOS、解码能力强（HEVC/H.264/AV1/Dolby Vision/各种字幕基本都能直接播 → 大概率 Direct Play，根本不劳烦 Mac 转码）、有 Cinema/Room/Space 等沉浸影院环境、能直连 Jellyfin。代价是要 Pro（买断/订阅）。

Swiftfin 是 Jellyfin 官方免费客户端，App Store 明确支持 Apple Vision（需 visionOS 1.0+）[12]，用 VLCKit 最大化直连兼容。想零成本先跑通，用 Swiftfin 完全够看（沉浸环境/打磨不如 Infuse）。

我的建议：先用免费 Swiftfin 把「AVP 连上 Jellyfin 看 2D/4K 片」整条链跑通；确认无误后想要最佳影院沉浸感 + 最广直连兼容，再上 Infuse。客户端推荐·App Store+口碑核实

⚠️ 关键纠正：Infuse 在 AVP 上不能真 3D 立体播放（到 2026 仍是）

很多人以为 Infuse 能放 3D——错。Firecore 官方与社区一致：Infuse 8.x（含 2026）在 AVP 上会把 SBS/OU/MVC 3D 当成 2D 平面放，不渲染立体；3D 支持一直「coming soon」无确切时间表[11]。要在 AVP 看真 3D（蓝光 3D / 左右格式），得换 Moon Player 或 SKYBOX（这俩能自动识别立体模式、走 SMB 直连 NAS）。

注意：Moon/SKYBOX 是直连文件（SMB/DLNA）的播放器，不走 Jellyfin 媒体库——所以 3D 片可以直接放在 DS418 共享里，用它们连 NAS 播，不一定要进 arr/Jellyfin 流程。3D 片源本身还涉及格式转换（BD3D MVC → MV-HEVC，需在 Mac 上单独转），超出本套自动化管线，按需单独处理。这块详见姊妹报告《Apple Vision Pro 观影全攻略》。已核实·与姊妹报告一致

11.2 在 AVP 上连 Jellyfin

1局域网内连接（同一 WiFi）
  1. 确保 AVP 和 Mac Studio 在同一个局域网/WiFi。
  2. AVP App Store 装 Infuse（或 Swiftfin）。
  3. 打开 → 添加 Jellyfin 服务器 → 地址填 http://[Mac的局域网IP]:8096（Mac 的 IP 在 系统设置 → WiFi → 详情里看，比如 192.168.1.30）→ 输 Jellyfin 账号密码。
  4. 连上后就能看到电影墙，点开播放。
填 Mac 的 IP，不是群晖的 IP。Jellyfin 跑在 Mac 上，端口 8096。

外网访问（出门也想看）—— Tailscale 简提

想在公司/旅途用 AVP 连家里的 Jellyfin，最省心安全的方式是装 Tailscale：Mac 和 AVP 各装一个、登同一账号，就组成一张私有虚拟局域网，在外面也能用「Tailscale 内网 IP」连 Jellyfin，不用做端口转发、不暴露公网。简提·按需展开

AVP 上 Infuse/Swiftfin 连上 Mac 的 Jellyfin，能看到库、能播放一部片；播放时去 Jellyfin Dashboard 看这条流最好显示 Direct Play（不转码 = 最理想）。

12Mac Studio 当常开服务器（防睡眠 + 自启）▼

目标：让 Mac Studio 7×24 在线，AVP 随时能连。核心是「别睡着」+「重启后自动恢复一切」。

12.1 防睡眠（最重要）

方式 A（推荐·图形）系统设置里关睡眠
  1. 系统设置 → 节能 / 锁定屏幕 → 找到 "防止 Mac 自动进入睡眠"（Prevent automatic sleeping when the display is off）勾上。Mac Studio 是台式机一直插电，这一项就够。[13]
  2. 把「显示器关闭后进入睡眠」设为「永不 / 较长时间」。显示器可以黑屏，但机器不能睡。
方式 B（命令行·保险）caffeinate

临时强制不睡（终端开着就生效）：

caffeinate -dimsu

各字母含义：-d 防显示器睡、-i 防系统空闲睡、-m 防磁盘睡、-s 防系统睡（插电时）、-u 模拟用户活动。[13]

想开机自动常驻 caffeinate，可做一个 LaunchAgent（macOS 的开机任务），开机就后台跑 caffeinate。进阶·可选 不过对台式 Mac Studio，方式 A 的系统设置通常已足够，先用 A，不放心再加 caffeinate。

Mac 自动安装系统更新会重启 → 服务中断。建议系统设置 → 通用 → 软件更新 → 关掉「自动安装」，改成你手动挑时间更新。

12.2 重启后自动恢复一切

1三件套自启清单
  • Docker Desktop 自启：Ch3 已设「登录时启动」→ arr 五容器因为 restart: unless-stopped 会跟着自动起。
  • SMB 自动挂载：Ch3 已加进登录项 → 开机自动重连 DS418。
  • Jellyfin 自启：原生 Jellyfin 一般装好即作为后台服务/登录项运行；确认它在「系统设置 → 通用 → 登录项」里，或随系统服务启动。
2断电自动开机（可选但推荐）

系统设置 → 节能 → 勾「停电后自动重新启动」(Start up automatically after a power failure)，这样跳闸来电后 Mac 自己开机恢复服务。

登录解锁问题：很多自启服务要在用户「已登录」状态才完整运行。若设了开机密码，重启后停在登录界面则服务可能没起全。可考虑设置该用户自动登录（系统设置 → 用户与群组 → 自动登录），但这会牺牲一点物理安全性（台式机在家通常可接受）。权衡·按需

主动重启一次 Mac，不手动碰任何东西，等几分钟后：用 AVP（或另一台设备浏览器）能直接连上 Jellyfin 看到库 = 全自动恢复成功。

13整体联调：加一部电影，走通全链路▼

所有零件装完，最后做一次端到端验收：从 Radarr 点一部片，到 AVP 上看到它播放，全程不手动干预。任何一步卡住就回对应章节排查。

① 在 Radarr 加片
↓
Radarr → Movies → Add New → 搜一部电影 → 选质量 profile(含 4K) → Add + 勾「Search on add」。

↓

↓

↓

↓

14合规提示（务必一读）▼

工具合法，内容看你怎么用

Jellyfin、Radarr、Sonarr、Prowlarr、Bazarr、qBittorrent 本身都是合法的开源软件——它们只是「媒体服务器 + 自动化管理 + 下载客户端」，本身不含任何盗版内容。

但 你接什么索引器、下什么内容，涉及版权和当地法律。下载/分享受版权保护的电影剧集（尤其通过公共盗版 tracker）在很多国家/地区违法。

合规的用法

  • 用自有媒体：把你自己买的蓝光/DVD 抓取（rip）成文件放进库，自用，是最干净的。
  • 用合规订阅/来源：从你有合法授权的渠道获取内容。
  • 这套系统的核心价值是「统一管理你已合法拥有的媒体」，而不是教你白嫖。arr 套件在「整理私人合法媒体库」这件事上同样强大。

本篇不教你踩线，只讲工具怎么搭。具体下什么、合不合规，你自行判断并遵守你所在地（海外）的法律。（这不是法律意见。）合规·客观标注

?FAQ · 故障排查▼

Q一句话：到底为什么 Jellyfin 不放 Docker？+

因为 Docker on Mac 的容器拿不到 VideoToolbox 硬件转码（Jellyfin 官方文档明文写的，根因是 macOS 的 Hypervisor.framework 不给容器虚拟 GPU）。Jellyfin 原生装才能硬解 4K/HDR。arr 套件不碰转码，放 Docker 反而最好管。

Qarr 容器连不上彼此 / Radarr 连不上 qB，Test 红叉？+

八成是填了 localhost。容器之间要用容器名互连：Radarr 连 qB 填 qbittorrent:8080，Prowlarr 连 Radarr 填 radarr:7878，Bazarr 连 Radarr 填 radarr。localhost 在容器内指容器自己，连不到别人。

Q入库（搬片）很慢，要好几分钟？+

hardlink 没生效，退化成复制了。检查：① media 和 torrents 是否都在群晖同一个 data 共享下；② compose 里每个容器是否都映射的 - /Volumes/data:/data（不能给 qB 和 Radarr 映射不同路径）；③ Radarr 的 Media Management 里「Use Hardlinks」是否开。三者都对，搬片就是秒完成。

QJellyfin 设置里没有 VideoToolbox 选项？+

说明你装的是 Docker 版 Jellyfin（看不到 VideoToolbox）。卸掉，按 Ch10 装原生 macOS 版。另确认 Jellyfin server ≥ 10.9.0、macOS ≥ 12。

QAVP 看 4K 会不会卡？硬解一定要开吗？+

理想情况是 Direct Play（不转码）——Infuse 解码强，绝大多数片直接原样播，Mac 几乎零负载，根本不卡。硬解(VideoToolbox)是兜底安全网：碰到客户端啃不动的格式时由它转码（连 M1 都能同时硬解 3 路 4K Dolby Vision）。所以：选对客户端争取直连 + 配好硬解兜底，双保险，4K 流畅。

QApple Silicon 软解 4K 到底行不行？为啥不干脆全 Docker 软解？+

单路软解 4K HEVC/AV1，M 系列 CPU 一般扛得住；但多路并发或带 HDR tone-mapping 时 CPU 会爆、风扇狂转、可能丢帧，而硬解轻轻松松。既然原生装就能白嫖硬解，没理由让强力媒体引擎闲着去软解。全 Docker 软解 = 浪费 Mac Studio。

QDS418 真的完全不用装任何东西？+

对，它只干两件事：① 开 SMB 共享；② 提供 data 文件夹存文件。所有应用都在 Mac 上跑。DS418 是 ARM 芯片装不了官方 Docker、也没核显硬解，当纯存储正好物尽其用。

Q重启 Mac 后服务没自动起来？+

检查三件套：① Docker Desktop 设了「登录时启动」；② SMB 挂载在登录项里；③ 若有开机密码、停在登录界面，服务可能没起全——考虑设自动登录。容器有 restart: unless-stopped 会跟 Docker 自动起。

QSMB 还是 NFS 挂载？+

小白起步用 SMB：Mac 连群晖默认、配置简单、单用户大文件够快。NFS 某些场景吞吐更高但权限/配置更绕。先 SMB 跑通；若确认是 NAS 读取瓶颈再研究 NFS 或上万兆网。

Q出门在外能用 AVP 看家里的片吗？+

能。最省心安全是装 Tailscale：Mac 和 AVP 登同一账号组私有内网，在外用内网 IP 连 Jellyfin，无需端口转发、不暴露公网。先把局域网内跑通，再加 Tailscale。

Q必须装 Sonarr 吗？+

不追剧就不用，它是剧集版的 Radarr。compose 里那段可删。要追剧再回 Ch8 配，步骤和 Radarr 几乎一样。

QTRaSH Guides 是啥？一定要看吗？+

arr 套件的社区圣经，专讲质量 profile、命名规范、hardlink、Custom Formats 的最佳实践。第一次先用默认配置 + 它的标准命名模板跑通，玩熟后想精细控制画质/音轨再深入它的 Custom Formats。别一上来就钻进去。
