1. 结论摘要

Moodle 是课程中心、插件化、强管理型 LMS；半米是老师驱动的个性化学习陪跑系统。两者的相似点在“内容、任务、题库、进度、报告、权限、插件边界”，但产品重心完全不同。半米不应该把 Moodle 当产品底座 fork，而应该把它当成熟教育系统的设计词典。

最值得借的东西

活动/资源插件边界、题库和答题引擎分离、完成条件、限制访问、角色权限上下文、成绩册/报告聚合、事件日志、导入导出。这些是半米长期会遇到的系统复杂度，Moodle 已经验证过边界。

不建议借的东西

不要 fork Moodle，也不要照搬 Moodle 的课程页、PHP 单体、全量管理员配置、论坛/wiki 社区重心。这些会把半米从“老师为学生设计路径”拉回传统 LMS。

代码层结论

Moodle 核心是 GPLv3。半米若按商业 SaaS/闭源路线推进，默认不直接复制核心代码。安全做法是 clean-room 重建、协议集成、导入导出兼容、或写独立 Moodle 插件。

一句话建议：半米应做“类 Moodle 的教育对象边界 + 类 AI tutor 的个性化体验”，而不是做“AI 版 Moodle”。V0.1 应只吸收 Moodle 的最小工程骨架：内容项、学习活动、题型、完成条件、事件日志、报告证据链、角色权限。

优先级最高的 12 个借鉴点

优先级 Moodle 能力 半米应该借什么 借鉴方式 代码判断
P0 Activity / Resource 模块 把阅读 LE pattern、题目、视频、作业都视作可注册的学习活动类型 借思想 不搬代码
P0 Question bank / Question engine 题目定义、题目版本、学生作答过程、评分事件分离 借思想 不搬代码
P0 Activity completion Today 任务完成条件、step 完成条件、报告生成触发条件 借思想 不搬代码
P0 Availability / Restrict access 按日期、完成、成绩、分组、学生画像决定任务是否解锁 借思想 不搬代码
P0 Events / Logging 把 `event_log` 作为事实源，报告、Mastery、推荐都可重算 借思想 不搬代码
P0 Roles / Capabilities / Context 支撑 company / school / teacher / student / parent 五层权限 借思想 不搬代码
P1 Gradebook / Report builder 把作业、测评、练习、阅读表现聚合成老师可决策的报告 借思想 不搬代码
P1 Import / Export / Backup 内部 JSON、Moodle XML、QTI-like JSON、课程包迁移 借格式/接口 clean-room 实现

P2 Badges / Completion awards 学生激励、阶段成就、家长可读里程碑 后置借鉴 不搬代码

2. 半米当前边界

本报告按 Obsidian 中 2026-05-23 后的半米定位判断，而不是按早期“纯英语学习系统”判断。

产品定位

半米已升级为“给准备出国留学学生的端到端陪跑系统”：从大学目标倒推路径，并通过内容课程、考试系统、规划系统、老师监督和数据报告持续陪跑。

V0.1 范围

V0.1 收敛为阅读闭环 demo：老师录入任意阅读产品，AI 生成学习体验，老师审核发布，学生完成 Today 单任务，事件写入 `event_log`，生成 homework report，老师在 Dashboard 处理建议。

五端架构

公司端、学校端、老师端、学生端、家长端。MVP 只做老师端和学生端 UI，但数据模型必须预留五层权限和多租户边界。

核心系统原则

老师端是产品引擎，学生端是执行器。学生不主动选学习内容，Today 展示老师设计的当前任务。AI 在第一阶段主要做提醒、记录、分析、文案和草稿，不直接改计划。

半米和 Moodle 的根本差异

维度 Moodle 半米 产品含义
中心对象 课程、活动、资源、用户、成绩 学生个人方案、Today 任务、学习事件、老师建议 半米不能把“课程页”当第一屏；第一屏应是当前学生路径和任务。
老师角色 课程建设者和班级管理者 路径设计者、内容审核者、数据决策者、人类导师 老师端应优先做 plan / content / dashboard，不是先做 LMS 管理后台。
学生体验 进入课程，选择活动，提交作业，参与讨论 执行老师分配的单任务，按 LE pattern 完成步骤，被 AI 轻提醒 Moodle 的丰富课程导航对半米 V0.1 是噪音。
AI 定位 AI subsystem 提供 provider / placement / action 插件 AI 是内容草稿、报告总结、建议生成和行为提醒层 可以借 Moodle AI 的 provider / placement 解耦思想，但不照搬交互。
事实源 日志、成绩册、活动完成、报告 `event_log` 是最可信事实源，派生报告可重算 半米可以借 Moodle 日志和 report builder 的成熟边界。

3. Moodle 功能全景

Moodle 的功能不是一个单点应用，而是一整套学习平台能力：课程组织、学习活动、资源管理、测评、成绩、进度、角色权限、集成、报告、移动端、AI 插件和后台运维。

3.1 课程与内容组织

功能 Moodle 做什么 半米可借鉴
Course / Category 用课程和课程分类组织教学空间、参与者、活动、成绩和报告。 半米不应以 Course 作为学生第一视角，但可用 `course_template` / `learning_product` 承载老师入库内容。
Course format 不同课程格式决定课程页布局，例如 topics / weekly / single activity 等。 把 LE pattern 视作“学习体验格式”：短文、绘本、分级读物、小说章节各自有 step renderer。
Sections / Subsections 课程内容可分章节、主题、周次和子章节。 可映射到 `plan_week`、`plan_day`、`task_group`、`step_group`，但学生端只显示当前必要信息。
Resources Book、File、Folder、IMS package、Page、Text and media area、URL。 半米需要素材对象：passage、book/chapter、video link、PDF、audio、image、external URL、license metadata。
Content bank / H5P 管理可复用互动内容，并在课程中引用。 V0.2 后支持 H5P/互动内容引用，事件进入 `event_log`；不要第一版自研所有互动题。
Backup / Restore / Reuse 课程内容、活动设置和数据可以备份、恢复、导入复用。 半米应尽早设计 `export_bundle` / `import_batch`，避免内容只存在数据库里不可迁移。

3.2 标准活动与资源

Moodle 用户文档列出标准活动，例如 Assignment、BigBlueButton、Choice、Database、Feedback、Forum、Glossary、H5P、Lesson、LTI、Quiz、SCORM、Wiki、Workshop；资源包括 Book、File、Folder、IMS content package、Page、Text and media area、URL。

Moodle 类型 功能用途 半米判断
Assignment 学生提交文件、文本或线下作业，老师批改和评分。 P1 借鉴作业生命周期：发布、提交、重交、批改、反馈、证据引用。V0.1 homework report 不必做完整 assignment UI。
Quiz 自动/手动评分测验，题库复用，尝试记录，反馈设置。 P0 借鉴 question bank 与 attempt/event；考试系统 spike 已确认不要 fork Moodle Quiz。
Lesson 可根据学生选择或答案走不同页面的分支内容。 P1 借鉴为 LE pattern 的 branching，但 V0.1 不做真正 adaptive branching。
Forum / Wiki / Glossary / Database 协作讨论、共同编辑、词汇表、结构化条目库。 V0.1 不借 UI。长期可借 Glossary 思想做词汇/概念库，但学生社交讨论不是半米首要路径。
Feedback / Choice 调查、投票、反馈收集。 可借作老师/学生反馈表单和课堂 pulse，后置。
Workshop 同伴互评工作流。 不进入 V0.1。写作/口语互评可以远期参考，但未成年人和质量控制风险较高。
LTI External tool 把外部学习工具嵌入课程，处理 launch、身份、成绩回传。 强烈建议 V0.2 预留。半米可成为 Moodle/Canvas 的 LTI tool，而不是替换学校 LMS。
SCORM / IMS package / H5P 兼容传统课件包和互动内容标准。 后置支持导入/引用和事件记录，不优先自研播放器。
BigBlueButton 直播课和视频会议集成。 半米第二阶段课堂工具可接现成视频会议，不第一版自建直播。

3.3 测评、题库与成绩

功能 Moodle 做什么 半米可借鉴
Question bank 老师在专门空间创建、预览、编辑、分类和复用题目；题目可跨 quiz 使用。 P0。半米必须把 `question` / `question_version` / `skill_tag` / `source_status` 做成独立资产。
Question types 多选、简答、数值、匹配、拖拽、作文、Cloze、排序等题型插件。 P0。半米不要把题型塞进一个自由 JSON，至少要有 question type registry + renderer + grader。
Question behaviours 支持 deferred feedback、immediate feedback、interactive try again 等交互行为。 P1。半米阅读练习、placement、正式模考需要不同 feedback 行为。
Quiz attempt 一次测验尝试包含多题状态、保存、提交、评分、复查。 P0。半米考试和阅读题都应有 `attempt` / `response` / `response_event`，不能只存最终答案。
Gradebook 课程内成绩聚合，支持 grade items、categories、calculations、history、scales、outcomes。 P1。半米报告不是成绩单，但需要 gradebook-like aggregation：按学生、skill、LE、时间、任务汇总。
Advanced grading rubric、marking guide 等高级评分。 P1/P2。写作、口语、项目作业需要 rubric-grounded feedback，LLM 只能辅助，不应直接终评。
Import / Export questions 支持多种题目导入格式，Moodle XML 是推荐格式之一。 P1。半米 V0.2 支持 Moodle XML/QTI-like JSON，内部仍用 clean-room schema。

3.4 进度、个性化与激励

功能 Moodle 做什么 半米可借鉴
Activity completion 老师为每个课程项设置完成标准，学生可手动标记或系统自动完成。 P0。每个 LE step/task 都要有 completion criteria：viewed、answered、passed、spent time、teacher reviewed。
Course completion 基于活动完成和其它条件判断课程完成。 P1。半米可用在一周 plan、reading product、阶段路径完成，不放到 V0.1 首屏。
Restrict access / Availability 按日期、成绩、分组、profile、完成状态控制活动可见性。 P0。Today unlock logic 可以直接借这个模型，但半米要把规则表达做得更简单。
Competencies / Learning plans 把能力框架、证据和学习计划连接，支持 competency-based education。 P2。半米的升学路径、英语能力、考试 skill taxonomy 最终需要 competency layer。
Badges 按完成或手动规则颁发徽章。 P2/P3。可做学生激励和家长可读里程碑，但避免焦虑型排名。
Analytics / Insights 提供描述和预测报告，识别风险学生。 P2。半米先把 `event_log` 和 label 采干净，再上 ML 风险预测；LLM 不直接做最终预测。

3.5 用户、权限与组织

功能 Moodle 做什么 半米可借鉴
Roles / Permissions 角色是权限集合，结合 context 决定用户在某页面能做什么。 P0。半米五层 RLS 应学 context 思想：company、school、teacher-student relation、student self、parent child relation。
Authentication plugins Email、manual、OAuth2、LDAP、LTI、Shibboleth、webservice 等。 P1。MVP 先 Email/Google，后续学校客户会需要 SSO/SAML/OIDC/roster。
Enrolment plugins Manual、自助、guest、cohort、database、LDAP、IMS enterprise、LTI、payment 等。 P0/P1。半米 code binding、老师绑定学生、学校批量导入可借 enrolment method 思想。
Groups / Groupings / Cohorts 课程内分组，跨课程 cohort 批量 enrol。 P1。半米需要 class/group/cohort，但核心仍是 per-student plan。
Privacy API / Data requests 描述、导出、删除个人数据，支撑隐私合规。 P1/P2。未成年人数据合规必须预留 consent、export、delete、audit。

3.6 沟通、报告、集成与运维

功能 Moodle 做什么 半米可借鉴
Messaging / Notifications / Calendar 站内消息、通知偏好、课程/用户/群组日历事件。 P1。半米的提醒应连接 plan、due date、teacher action，不做泛通知堆叠。
Forum / Comments 异步讨论和评论。 V0.1 只做带上下文的学生提问和老师回复，不开放社区型论坛。
Reports / Logs / Report builder 课程活动、完成、参与、日志、实时日志、安全、性能、进度、统计和自定义报告。 P1。半米需要 teacher dashboard 和可追溯 evidence_refs，不急着做自定义报表 UI。
Web services / External functions 将函数暴露为外部 web service。 P1/P2。半米要为未来移动端、Moodle/LMS 集成、学校系统同步预留 API 边界。
LTI Moodle 可作为 LTI consumer 或 publish as LTI tool。 P1。半米可以作为外部 LTI 学习活动接入学校 LMS，降低 B2B 采购阻力。
Mobile app Moodle App 支持移动端访问，并通过 API 和插件适配。 P2。半米先 Web，之后移动端 API 应从一开始保持清晰。
AI subsystem Placement、Action、Provider、Manager 解耦，支持不同 AI provider。 P1。半米可借 provider/action 分层：内容生成、提示生成、报告总结、能力解释都走统一 LLM 存证。

5. 可借鉴矩阵

下面按半米模块拆解 Moodle 借鉴方式。判断标准：是否能帮半米更快做出稳定产品，而不是 Moodle 本身功能是否强大。

半米模块 Moodle 对应能力 半米应借鉴 落地对象 阶段
老师课程入库 Resources、Activity modules、Content bank、Backup API 素材和学习活动分离；素材可复用，活动是一次教学配置；导入批次可追踪。 content_asset、learning_activity、import_batch V0.1
LE pattern renderer Activity module plugin structure、Course format 每个 LE pattern 有 renderer、step schema、event types、validation、report mapping。 le_pattern_registry、step_definition V0.1
阅读题库 Question bank、Question types、Question categories 题目作为一等资产；版本化；按 skill、难度、来源、状态、review 管理。 question、question_version、question_asset V0.1
学生答题 Question engine、Quiz attempt、Question behaviours 把作答过程拆成 open/save/submit/grade/review 事件，不只存最终答案。 attempt、response、response_event V0.1
Today 单任务 Activity completion、Availability 任务显示和解锁由 completion/availability 规则决定，但学生只看到当前任务。 task_completion_rule、task_unlock_rule V0.1
一周 plan Course sections、Calendar、Completion 一周计划是轻量 course path，但不能变成 Moodle 式复杂课程页。 plan、plan_day、plan_task V0.1
Homework report Gradebook、Reports、Logs 报告从事实事件聚合，保留 claim range、confidence、evidence_refs。 report、structured_metrics V0.1
老师 Dashboard Course reports、Insights、Report builder 老师只需要下一步行动：低置信度、未完成、未回复、待批准建议。 teacher_dashboard_view、recommendation_queue V0.1
AI 内容生成 AI subsystem provider/placement/action AI provider 和 AI 使用场景分离；所有输出落 `llm_generation` 存证。 llm_generation、ai_action V0.1/V0.2
多租户权限 Roles、Capabilities、Context、Groups、Cohorts 按 context 判断能力，不用一个粗暴 role 字段解决所有权限。 user_role、scope、RLS helper function V0.1
学校集成 LTI、Web services、Enrolment plugins、Authentication plugins 未来学校已有 LMS 时，让半米作为外部工具或数据服务接入。 LTI launch、API token、external identity mapping V0.2/V0.3
数据合规 Privacy API、logs、roles 未成年人数据导出、删除、授权、审计不能后补太晚。 consent_record、audit_log、data export job V0.1/V0.2

借鉴强度分级

A 级：直接借设计边界

Question bank/engine、completion、availability、roles/capabilities/context、events/logging。这些是半米必须早做对的底层边界。

B 级：借协议和格式

LTI、Moodle XML、QTI-like JSON、H5P/SCORM 引用、web services。这里不是照搬代码，而是为学校和内容生态留接口。

C 级：远期参考

Competencies、badges、full report builder、portfolio、payment、plagiarism、mobile app plugin support。等半米主闭环跑通后再吸收。

6. 能否直接借 Moodle 代码

默认答案：不建议直接借 Moodle 核心代码。Moodle README 和 COPYING 显示 Moodle 以 GNU GPL v3 发布。半米如果走商业 SaaS、闭源部署、未来学校私有化交付或 App 分发路线，直接复制核心代码会带来许可证和交付边界风险。

6.1 法务和工程边界

做法 是否建议 原因 半米推荐动作
直接复制 Moodle PHP 代码到半米代码库 不建议 GPLv3/copyleft 风险高，技术栈也不匹配 Next.js/Supabase/FastAPI。 只读源码理解边界，内部 clean-room 实现。
fork Moodle 做半米主产品 不建议 产品重心会变成传统 LMS，且 UI/架构/许可都会拖累半米。 不 fork。必要时部署 Moodle 作为外部 LMS demo。
写 Moodle 插件调用半米服务 可行 插件按 Moodle 生态规则发布，半米服务独立运行，边界清楚。 V0.2 后可做 `mod_banmi` 或 LTI 工具，先不用。
半米作为 LTI tool 接入 Moodle 推荐 标准协议边界清晰，适合学校已有 LMS 场景。 V0.2 预留 LTI 1.3 launch / grade passback。
支持 Moodle XML 题目导入 推荐 兼容老师已有题库和开源生态；实现可 clean-room。 V0.2 做 importer/exporter，不复制 Moodle parser。
照抄数据库表结构 不建议 Moodle 表结构服务于 PHP LMS，不服务于半米的 per-student plan 和 event_log 事实源。 借关系，不借表名和字段。
使用 Moodle 商标做营销 谨慎 Moodle 的商标政策限制商业用途、软件命名、域名、广告关键词等。 只说“支持 Moodle XML 导入”或“可通过 LTI 与 Moodle 集成”，不要把 Moodle 放进产品名。

6.2 安全的借鉴方式

  1. Clean-room 重建：先写半米自己的对象模型和验收测试，再实现 importer、renderer、grader。
  2. 协议级集成：LTI、OAuth/OIDC、webhook、CSV/OneRoster、Moodle XML、QTI-like JSON。
  3. 独立服务边界：如果必须使用 Moodle 功能，把 Moodle 当单独系统部署，通过 API/LTI 交互，不把核心代码混入半米。
  4. 插件边界：未来若服务 Moodle 用户，可写 GPL-compatible Moodle 插件，插件负责 launch/iframe/grade passback，半米核心服务保持独立。
  5. 文档化来源：在技术文档中标注“inspired by Moodle concepts”，不要复制源码注释、函数、文件结构和 UI 文案。

6.3 什么时候可以直接借代码

只有以下情况才可考虑直接用 Moodle 代码：

  • 半米决定整个相关组件按 GPLv3 兼容方式开源并接受相应义务。
  • 代码作为独立 Moodle 插件发布，不混入半米闭源核心。
  • 只用于本地研究，不进入产品仓库、部署镜像、客户交付和 App 包。

默认商业产品路线下，建议把 Moodle 当“架构参考和互操作目标”，不是代码来源。

7. 半米设计建议

7.1 V0.1 数据对象调整建议

半米当前已经有 `event_log`、`report`、`recommendation_queue`、`llm_generation` 等正确方向。结合 Moodle，建议 V0.1 明确以下对象边界：

learning_product
  // 阅读产品类型：短文、绘本、分级读物、小说章节、Reading A-Z 类体系

content_asset
  // passage / image / audio / video link / PDF / book chapter / license metadata

le_pattern
  // LE01 / LE04 / LE05 / LE06，每种 pattern 定义 step schema、renderer、event mapping

learning_activity
  // 老师把素材配置成一次可发布学习活动，类似 Moodle activity instance

question
question_version
question_asset
question_skill_tag
  // 题目本体、版本、素材、skill 标签、review 状态

plan
plan_task
task_unlock_rule
task_completion_rule
  // 一周 plan、Today 单任务、解锁与完成条件

attempt
response
response_event
  // 学生一次任务/题目尝试和过程事件

event_log
report
recommendation_queue
llm_generation
  // 事实源、报告、老师确认队列、LLM 存证

7.2 Moodle-inspired 但半米化的插件模型

Moodle 插件思想 半米对应 必须包含
Activity module LE pattern module step schema、student renderer、teacher authoring UI、event mapping、report mapping。
Question type plugin Question type registry response schema、grader、review UI、student UI、import/export mapping。
Availability condition Task unlock rule date、previous completion、score/band、teacher approval、profile/group。
Completion API Task/step completion contract viewed、submitted、passed、teacher reviewed、minimum evidence。
AI provider/placement LLM provider/action/surface provider、model_version、prompt_version、evidence_refs、input_hash、safety flags。

7.3 Today 和 Learning Screen 的规则表达

Moodle 的 availability 条件可以为半米提供一个足够简单的 V0.1 起点：

规则类型 Moodle 来源 半米 V0.1 规则 例子
日期 availability/date 任务只有在 plan_day 到达后可见。 周三的小说章节不提前显示。
完成 availability/completion 前一个 step 完成后解锁下一个 step。 泛读完成后才进入精读题。
成绩/表现 availability/grade 根据正确率、confidence、卡点触发补充练习建议。 inference 题低于阈值，生成 recommendation_queue。
分组 availability/group/grouping 按班级、学生群、项目 cohort 发任务。 雅思班统一发一组 passage，但每个学生 task 顺序可不同。
画像 availability/profile 按学生目标、年级、语言背景、能力 band 选择默认材料。 Korean international school student 与 IELTS 高中生走不同模板。

7.4 报告系统应学 Moodle，但不要变成成绩册

Moodle 的 gradebook 很强，但半米报告的第一目的不是分数管理，而是让老师做下一步决策。因此半米应该借 gradebook 的聚合能力，不借它的完整 UI 复杂度。

要借

  • 每个活动可向报告/成绩聚合层提交结构化结果。
  • 保留历史记录，避免题目或评分规则更新影响旧报告。
  • 支持按学生、时间、skill、任务、课程模板汇总。
  • 老师可展开 evidence_refs。

不要借

  • 不要第一版做复杂 grade calculations。
  • 不要把所有学习表现变成一个总分。
  • 不要让 LLM summary 替代 structured metrics。
  • 不要把家长端报告做成实时错误监控。

7.5 和学校 LMS 的关系

半米未来面对国际学校、双语学校或培训机构时，不一定要替换 Moodle/Canvas/Google Classroom。更合理的商业路径是：

  1. V0.1：半米独立运行，老师手动建学生和任务。
  2. V0.2：支持导出报告、CSV roster、Moodle XML/QTI-like 导入。
  3. V0.3：半米作为 LTI tool 接入学校 LMS，老师在 Moodle 课程里打开半米活动，成绩/完成状态回传。
  4. 后续：做 OneRoster/SIS/SSO/DPA，进入真实 B2B 采购流程。

9. 不建议借鉴的部分

不建议借 原因 半米替代方案
Moodle 课程首页信息架构 课程页适合 LMS，但半米学生端应是 Today 单任务和个性化执行。 老师端有课程/内容管理，学生端只显示当前路径必要信息。
全量论坛/wiki/social 功能 V0.1 的学习闭环不依赖开放协作，且未成年人内容治理成本高。 只做带上下文的学生提问、老师回复、证据引用。
复杂管理员配置后台 Moodle 的可配置性是成熟 LMS 的资产，但会拖慢半米 MVP。 先用固定配置 + 数据模型预留，后续再开放公司/学校端设置。
PHP 单体架构 半米已收敛 Next.js / Supabase / FastAPI / R2，不应为了借功能换技术栈。 用半米现有技术栈 clean-room 实现对象边界。
完整 gradebook UI 成绩册很强但复杂，容易把学习报告变成分数表。 先做 teacher decision dashboard，再抽象聚合层。
Moodle 多功能首屏 半米差异化是老师路径设计 + AI evidence/report，不是功能大全。 V0.1 坚持阅读闭环和老师确认队列。
