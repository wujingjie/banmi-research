OpenClaw vs Hermes Agent：两套个人 AI 代理深度对比

📅 2026-06-02 🔍 ~55 次检索 + 官方文档实查 🟢 本机两套都在跑（实测证据线） 🦞 OpenClaw 2026.5.28 ☤ Hermes Agent v0.15.0

一句话蓝图：两者都是「跑在你自己设备上、用聊天软件当界面、能自己动手干活」的个人 AI 代理——但出身、气质、强项完全不同。

OpenClaw（🦞 出自 Peter Steinberger，TypeScript）走「广度 + 多渠道 + 多 agent 平台」路线[1]；Hermes Agent（☤ 出自 Nous Research，Python，MIT）走「自进化学习闭环 + 跑在任何后端」路线[2]。 前者像一个能接 20+ 聊天平台的「全能管家平台」，后者像一个会从经验里长出新技能、能装进 VS Code 当 IDE 后端的「会自学的研究员」。本篇用本机实测 + 50+ 次检索，逐一回答：大家拿它们做什么、各自强在哪、适合什么活、真实成果、核心区别。

01一句话定位 + 本机实测对照▼

阿杰你本机两套都装着、都在跑，所以这章先把「我亲眼在你机器上看到的事实」摆出来当地基（🟢 高可信度），后面所有 web 数据都拿这条线去校。

🦞 OpenClaw

  • 定位：个人 AI 助手平台，"All your chats, one OpenClaw."[3]
  • 出身：Peter Steinberger，2025-11 首发（原名 Warelay → Moltbot → OpenClaw）[4]
  • 语言：TypeScript + Swift（macOS 原生 app）[4]
  • License：MIT[4]
  • 本机版本：CLI 2026.5.28（cask 同版）本机实测 2026-06-02
  • 安装量：Homebrew cask 365 天 38,521 次[5]

☤ Hermes Agent

  • 定位："自进化 AI 代理"，唯一内置学习闭环[2]
  • 出身：Nous Research（也做 Hermes 系列大模型）[2]
  • 语言：Python 85%[6]
  • License：MIT[6]
  • 本机版本：v0.15.0（2026.5.28）本机实测 2026-06-02
  • 最新 release：v0.15.2（2026-05-29）[6]

🟢 本机实测拿到的硬事实（2026-06-02）

  • OpenClaw 本机跑着 19 个隔离 agent（~/.openclaw/agents/ 下：main/小宝、悟空、xiaochen、qianqian、mochou、wuji、codex、gemini、qwen 等），每个有独立 workspace + 人格 + 模型路由。本机实测 任务要求的"14+ agents"在你机器上实为 19 个目录。
  • OpenClaw 多模型并存：主/二号 Claude Opus 4.6 经本地 proxy（localhost:3456/3457，OpenAI-completions 协议）+ 本地 Ollama 跑 Qwen3.5-35B-A3B / GPT-OSS 120B（含未删减版），成本标 0。本机实测
  • OpenClaw 渠道：Discord（一个 guild 19 个频道 allowlist）+ 企业微信（wecom-app）双通道在线。Gateway 本地回环 port 18789。本机实测
  • Hermes 本机 v0.15.0，落后主线 385 commits（hermes update 可升）。Python 3.11.15，OpenAI SDK 2.24.0。本机实测
  • Hermes CLI 子命令含 claw migrate——官方提供从 OpenClaw 迁移的命令（命令存在为实测事实；"Nous 把 OpenClaw 用户当迁移来源"是合理推断推断）。本机实测
  • 两者都内置 ACP 适配（Hermes 有 acp_adapter/ + acp 子命令；OpenClaw 有 acp 子命令"Run and manage ACP-backed coding agents"）。本机实测

换句话说：在你这台 Mac Studio 上，两套不是"二选一"，而是已经在协同跑——这恰好印证了海外社区"很多老手两个一起用"的发现（Ch13 详述）。

02易混淆点：Hermes Agent ≠ Hermes 大模型▼

⚠️ 全篇最容易搞混的一点，先钉死

Nous Research 名下有两个都叫 "Hermes" 的东西，本报告研究的是前者：

  1. Hermes Agent ☤（本报告对象）= 一个代理框架 / CLI，开源 MIT，Python 写的，github.com/NousResearch/hermes-agent。它不自带模型，要你接 OpenAI / Claude / OpenRouter / 本地 Ollama 等任意后端。[2]
  2. Hermes 系列大模型（Hermes 3 / Hermes 4 等）= Nous 训练的开源权重 LLM，是"被调用的模型"，不是"代理程序"。

二者关系：Hermes Agent 这个框架可以调用 Hermes 大模型，也可以调用 GPT / Claude / Qwen。就像"浏览器"和"网页"——框架是壳，模型是芯。本篇讲的是壳（agent 框架）。

这个混淆在海外社区真实发生：Hacker News 一条关于 Hermes Agent 的讨论里，就有人问"它和 SOTA 模型比怎样"，被另一位用户纠正"这讨论的是 Hermes Agent（框架），不是 Hermes 模型系列"，并贴出 GitHub 仓库链接澄清。[7] 搜索时务必用 "Hermes Agent" 或 "NousResearch hermes-agent" 限定，否则结果会被模型评测污染。

类比帮你记：OpenClaw 这边没有这个困扰——它纯粹是个代理框架，自己不出模型。Nous 既出模型又出框架，所以才有"同名两物"的坑。

03问题①：大家分别拿这两个来做什么▼

这是任务要求必答的第一问。把两边社区里"真实在做的事"分开列。

🦞 大家拿 OpenClaw 做什么

OpenClaw 的官方口号是"The AI that actually does things"——强调"动手干活"而非"答问题"[3]。社区高频用法：

  • 清收件箱 / 发邮件 / 管日历 / 值机——把它当真正会替你操作的私人秘书[3]
  • 多聊天平台统一收口：WhatsApp / Telegram / Discord / Slack / Signal / iMessage / 企业微信 / 飞书 / QQ / 微信等 20+ 渠道，全从一个 gateway 进出[3]
  • 浏览器自动化：填表单、抓数据、自动操作网页[3]
  • 家居 / 设备控制：Philips Hue、Spotify、Obsidian、1Password 等 50+ 集成[3]
  • 多 agent 编排：每个 agent 一个独立频道 + 人格——社区认为这是 OpenClaw 区别于对手的特色功能[8]（也正是阿杰本机 19 个 agent 的玩法）
  • 定时主动外联（heartbeats）：不只是被动回，会在心跳里主动找你[3]

☤ 大家拿 Hermes Agent 做什么

Hermes 强调"自进化 + 跑在任何地方"。HN 上一位真实用户（rnxrx）的用法很有代表性[7]：

  • 跨多台机器维持状态、把信息直接整理进 Obsidian——研究、计划、家居自动化排障[7]
  • 跑在 $5 VPS / 云 VM 上，人在 Telegram 上指挥，agent 在云端干活，不绑笔记本[2]
  • 无人值守的定时自动化：日报、夜间备份、周审计，全用自然语言描述 cron[2]
  • 当 IDE 后端：通过 ACP 跑进 VS Code / Zed / JetBrains / Neovim，把自进化能力 + 记忆带进编辑器[9]
  • 研究用途：批量轨迹生成 + 轨迹压缩，用来训练下一代工具调用模型——这是 Nous 作为模型研究机构的独特用法[2]
  • 自进化优化：配套的 hermes-agent-self-evolution 用 DSPy + GEPA 自动进化技能/提示词/代码，每次优化约 $2–10[10]

一句话区分用途：OpenClaw 用户更多在「把生活/工作里的杂活交给一群有人格的助手」；Hermes 用户更多在「跑一个会自学的代理在云端长期干活、甚至当 coding 后端 / 做模型研究」。

04用户画像：谁在用▼

OpenClaw 的人群

  • 想要"全能私人/家庭/团队助手"的人——官网明确点名 company assistant / family assistant / team tool[3]
  • 重度聊天平台用户——希望一个 agent 接管所有 IM 渠道
  • 愿意折腾多 agent 的高级玩家——像阿杰这样跑 19 个 agent
  • ⚠️ 但官方/社区都警告："看不懂命令行的人，这东西太危险"——OpenClaw 维护者原话[4]。所以"非技术用户友好"是目标，现实门槛仍高。

Hermes Agent 的人群

  • 云原生 / VPS 玩家——想要 agent 脱离笔记本、serverless 空闲几乎零成本[2]
  • 开发者 / coding 用户——通过 ACP 把 Hermes 当 VS Code/Zed 后端[9]
  • AI 研究者——用轨迹生成训模型，这是 Nous 的本行[2]
  • 看重"记忆/自学开箱即用"的人——Reddit 上 Hermes 最一致的好评就是记忆默认更好、自学习省调教[8]

共同门槛：两者都是自托管代理，都需要懂命令行、懂安全风险。Reddit 上社区第一大痛点不是"agent 能力"，而是"自托管的运维复杂度"——管基础设施比配工作流更费时间[8]。

05问题②a：OpenClaw 的优势▼

把 OpenClaw 的强项拆成独立 callout，每条单独讲透（多条目排版铁律）。

① 渠道广度 + 集成生态碾压

支持 20+ 聊天渠道（WhatsApp/Telegram/Discord/Slack/iMessage/Signal/企业微信/飞书/LINE/QQ/微信/WebChat 等）+ 50+ 工具集成（Spotify/Hue/Obsidian/Gmail/GitHub/1Password 等）[3]。社区盘点称其 13,700+ 社区技能（ClawHub）[8]。这是 Hermes 短期内追不上的广度。

🔗 深度子报告：把这条「渠道接入」单独深挖了一份——含 Anthropic 官方 Claude Code Channel（连 Discord）三方对比、机制/优势/选型 → Claude Code Channel vs OpenClaw vs Hermes →

② 多 agent 平台是杀手锏

Reddit 社区明确指出："每个 agent 可以有自己的频道和人格——竞品没有这个"[8]。这正是阿杰本机 19 个 agent（小宝/悟空/钱钱/莫愁……各有 emoji、workspace、模型路由）的底座。要搭"一群分工协作的助手平台"，OpenClaw 是天生的。

③ cron 调度被夸"确定性、可信赖"

一条 +25 赞的 Reddit 评论："至少逻辑是确定性的，我是真能信任它的 cron 系统"[8]。对要跑无人值守定时任务（像阿杰的 MC 调度）的人，确定性比"聪明"更重要。

④ macOS 原生体验 + Live Canvas + 语音

OpenClaw 有 macOS/iOS/Android 原生 companion app（Universal Binary，需 macOS≥15[5]）、Voice Wake/Talk Mode 语音模式、Live Canvas 可视化工作区[1]。Hermes 是纯 CLI/TUI + 网关，没有这层"桌面成品感"。

⑤ 成熟度 / release 历史更长

OpenClaw 已有约 193 个 release，Hermes 约 16 个[16][6]（社区旧盘点为 137/11[8]，均随时间增长）。更长的迭代史 = 更多踩过的坑被填平。⚠️ 但 release 数只是弱成熟度代理——更该看 issue 处理速度、回归率、测试质量；而且 OpenClaw 恰恰有"每次更新都引入新 bug"的抱怨（见 Ch13）。

06问题②b：Hermes Agent 的优势▼

① 自进化学习闭环（唯一卖点）

Hermes 自称"唯一内置学习闭环的代理"[2]：复杂任务（≥5 步）后自动创建可复用技能、使用中自我改进、定期"提醒"自己持久化知识、用 FTS5 全文检索 + LLM 摘要回溯过往会话、用 Honcho 做辩证式用户建模。Reddit 上"自学习随时间适应"是对 Hermes 最一致的好评[8]。

② 跑在任何后端 / serverless 几乎零成本

6 种终端后端：local / Docker / SSH / Singularity / Modal / Daytona[2]。其中 Modal 和 Daytona 提供 serverless 持久化——agent 环境空闲时休眠、按需唤醒，空闲期间几乎零成本。$5 VPS 到 GPU 集群都能跑。这是 OpenClaw（桌面/网关导向）不具备的部署弹性。

③ 安装更顺、记忆默认更好

Reddit +38 赞："从一开始，setup 就顺畅太多了"[8]。Hermes 记忆开箱即用、需要的调教比 OpenClaw 少。而 OpenClaw 的"记忆失效"恰恰是其用户流失的主因[8]。

④ Checkpoint / 回滚——OpenClaw 没有的等价物

Hermes 在改动前对工作目录快照，出错可恢复到先前状态[8]（本机 ~/.hermes/checkpoints/ + hermes checkpoints 子命令印证本机实测）。对"让 agent 自己动手改文件"的场景是关键安全网。

⑤ 供应链安全意识更强（exact-pin 依赖）

Hermes 的 pyproject.toml 把每个直接依赖精确锁版本（不用范围），并在注释里写明这是 2026-05-12 针对 "Mini Shai-Hulud" PyPI 蠕虫攻击 mistralai 包后收紧的本机实测。还内置 hermes security 做 OSV.dev 供应链审计。这种"缩小攻击面"的工程纪律，对自托管代理很重要。

⑥ Nous Portal 一站式省去收集 API key

一个订阅覆盖 300+ 模型 + Tool Gateway（网页搜索 Firecrawl / 图像 FAL / TTS OpenAI / 云浏览器 Browser Use），hermes setup --portal 一条命令 OAuth 搞定[2][27]。不想要也能 BYO key（按工具粒度）。

07问题③：各自适合做什么工作▼

🦞 选 OpenClaw 如果你要……

  • 一个能接所有聊天平台的统一助手
  • 搭多 agent 分工平台（各有人格/频道）
  • 可信赖的确定性 cron 调度
  • macOS 原生体验 / 语音 / Canvas
  • 大量现成技能与集成即插即用

☤ 选 Hermes 如果你要……

  • 一个会自学、越用越懂你的代理
  • 跑在 VPS / serverless、脱离笔记本
  • 把代理当 VS Code/Zed coding 后端（ACP）
  • 记忆开箱即用、少调教
  • 做 AI 研究（轨迹生成训模型）
  • 改动可快照回滚的安全网

🤝 社区给出的"混合用法"（很重要）

Reddit 上 20% 用户两个一起用[8]，典型分工：OpenClaw 做编排（规划、调度、多渠道路由）+ Hermes 做执行（快速、可复用的循环），两者可经 ACP 兼容工具桥接（⚠️ ACP 本质是"编辑器↔代理"协议，"两套直接 agent-to-agent 互通"是社区说法、本报告未实测验证未实测）。这恰好是阿杰本机两套并存的天然落点。

09问题⑤：核心区别横向对比表▼

🎯 一句话抓住本质（多个独立评测一致的框架）

多家对比文章给出同一个分水岭："你的 agent 应该随时间变聪明，还是无处不在？"[39] Hermes 押注前者（学习闭环——同一类任务跑 100 遍会越来越好），OpenClaw 押注后者（最大的静态能力生态——跑 100 遍还是当新问题处理）[39]。换成选型口诀：问题是"编排"→ OpenClaw；问题是"需要越做越好的自动化"→ Hermes[39]。

10架构与模型支持▼

共同骨架

两者架构惊人地相似（也难怪有 hermes claw migrate 迁移命令）：一个常驻 gateway 进程 + 聊天平台当前端 + 技能/工具系统 + 持久记忆 + cron 调度 + MCP 工具接入 + ACP。本机两者 gateway 都在跑（OpenClaw port 18789；Hermes dashboard port 9119）本机实测。

🦞 OpenClaw 数据流（外部资料 + 本机印证）

Gateway 是 Node.js 服务，跑在 port 18789（与阿杰本机 gateway.port: 18789 完全吻合本机实测）："路由聊天 app 与模型之间的消息、跑工具调用、保管 API key"[23]。消息流：进 Gateway → 附加 memory/skills 上下文 → 给模型 → 收到工具调用请求 → 执行动作 → 返回结果 → 生成最终回复。两种调度：Heartbeats（主会话定期签到，默认每 30 分钟） + Cron（精确时刻、隔离会话）[23]。

☤ Hermes 进程模型

TUI 是独立进程经 transport 连 gateway；agent loop 在 run_agent.py；技能/curator/cron/kanban 各有独立模块本机 AGENTS.md 实测。6 种终端后端让"agent 在哪执行 shell"可插拔——这是 OpenClaw 没有的抽象层（OpenClaw 默认在本机/容器执行）。

ACP 是什么（澄清）

ACP = Agent Client Protocol（不是"Agent Control Protocol"），是 Zed 主导的开放标准（Apache 2.0），标准化"代码编辑器 ↔ AI 代理"之间的通信，地位类似 LSP 之于语言服务器，走 stdio/NDJSON[9]。Hermes 实现了 ACP server 模式，能当 VS Code / Zed / JetBrains / Neovim 的代理后端[9][22]；OpenClaw 则有 acp 子命令"run and manage ACP-backed coding agents"本机实测——更偏"OpenClaw 当客户端去管别的 ACP coding agent"。

模型支持（含国产，客观陈述）

🦞 OpenClaw

接外部 LLM：Claude（主）/ GPT / DeepSeek / 本地模型 / MiniMax[4]。阿杰本机实测：主/二号 Claude Opus 4.6 经本地 proxy + Ollama 本地 Qwen3.5-35B / GPT-OSS 120B本机实测。

☤ Hermes Agent

模型无关：Nous Portal（300+）/ OpenRouter（200+）/ NVIDIA NIM / 小米 MiMo / z.ai GLM / Kimi/Moonshot / MiniMax / Hugging Face / OpenAI / 本地端点[2]。hermes model 一键切，无锁定。

两者都支持本地 Ollama 跑开源/国产模型省成本（海外视角下，国产模型属"可选/低成本补充"，主力仍是 Claude/GPT）。⚠️ 注意 OpenClaw 跑本地模型要求≥64,000 token 上下文窗口，否则会因每条消息带全历史而截断[23]。

10·记忆与技能机制：最本质的设计差异▼

这章挖到引擎盖底下——两者"记忆 + 技能"的实现差异，决定了它们的气质。

记忆：两边都用 Markdown，但 Hermes 多了一层"快照纪律"

🦞 OpenClaw 记忆

持久化为 Markdown：MEMORY.md（耐久事实/偏好，会话开始时加载）+ SOUL.md（人格）+ AGENTS.md（行为规则）[23]。本机还启用了 hybrid 向量+全文检索（vectorWeight 0.6 / textWeight 0.4 + 30 天时间衰减）本机实测。但社区反馈"记忆易忘、要花大量时间调"是流失主因[8]。

☤ Hermes 记忆

两个有界文件：MEMORY.md（agent 自己的笔记，约 800 token）+ USER.md（用户画像，约 500 token）[28]。关键设计：frozen-snapshot（冻结快照）——会话开始时拍一次注入 system prompt，中途改动立即落盘但下次会话才生效，目的是保住 LLM 的 prefix 缓存（省钱 + 快）。这是工程上比 OpenClaw 更克制的设计。

技能：OpenClaw 靠"市场广度"，Hermes 靠"自动生长 + 自动修剪"

🦞 OpenClaw：ClawHub 大市场 + 手动装

ClawHub 是公共技能/插件注册表（一个 SKILL.md + 配套文件，向量搜索 + 审核钩子）[29]。技能数各源差异很大：有说 2,857、有说 5,700+（4 月）、有说 44,000+、社区盘点称 13,700+[8][29]。数字口径混乱 共识是"生态广度第一"。⚠️ 更正一个易误解点：OpenClaw 官网说它的技能系统"甚至能自己写技能"[1]——所以不是"不能造技能"，而是没有"任务后自动创建 + 后台自动养护"的闭环。技能多数仍是人写人装/按需让它写，agent 不会跑完任务自发沉淀+修剪。这才是和 Hermes 的真实差别。

☤ Hermes：skill_manage 自动造 + Curator 自动养

① 自动创建：agent 在复杂任务（≥5 次工具调用）、错误恢复、用户纠正、识别出非平凡工作流后，用 skill_manage 工具自动创建/修补/编辑/删除技能，长出"程序性记忆"[30]。② Curator 自动养护：后台 cron（默认 7 天周期）给每个技能打分、合并相关的、修剪死的，运行前还做 tar.gz 快照[31]。③ 渐进披露：v0.15 起只先加载技能元数据（约 3,000 token），用到才拉全文[32]。

⚠️ 但"自动养"是双刃剑：社区抱怨 Hermes 自进化会覆盖你手调好的技能，"把它自我改进成一团乱麻是噩梦"[8]；加上"自评虚高"，自动修剪可能删错/改错而不自知。OpenClaw 手动装虽笨，但"你装的就是你要的"，确定性更高。

多 agent 协作：Hermes v0.15 的 Kanban 把"群体协作"做成了一等公民

Hermes v0.15（Velocity，2026-05-28）新增持久 Kanban 看板：所有 profile 共享 ~/.hermes/kanban.db，每个任务一行、每次交接一行，每个 worker 是带身份的完整 OS 进程[33]。配 heartbeat 健康监测 + 任务回收（worker 弃任务自动重派）+ 僵尸检测[32]。委派用 delegate_task 生成隔离子代理，并行上限 max_concurrent_children 默认 3[34]；配 /goal（锁定目标的 Ralph loop）保持专注。v0.15 还把 session_search 提速 4,500 倍（SQLite FTS5 + Gemini Flash 摘要）[32]。

对照之下，OpenClaw 的多 agent 是"每个 agent 一个频道 + 人格"的平台式编排（像阿杰本机 19 个独立助手），更偏"长期共存的多个助手"；Hermes Kanban 更偏"一次性任务的 swarm 协作"。两种多 agent 哲学不同：OpenClaw = 多个常驻人格，Hermes = 任务驱动的工蜂群。

11安全模型：两条必须知道的负面线▼

🔴 OpenClaw：一场真实的 2026 安全危机（数字都很硬）

这是评估 OpenClaw 时绕不开的一章。关键事实（多源核实）：

  • CVE-2026-25253（CVSS 8.8 High）：WebSocket 劫持导致一键 RCE——诱骗你访问一个恶意网页 + 点一下鼠标，攻击者就能完全控制你的机器；测试显示 84% 系统提示词提取成功率 + 91% 注入成功率[35]。修复版本为 2026.1.29+[35]。
  • 9 个 CVE 在 2026-03 的 4 天窗口内集中披露，含一个 CVSS 9.9[36]（注：另有跟踪源累计称 138+ CVE[35]，口径不同，数字以量级理解）。
  • Koi Security 审计 2,857 个技能发现 341 个恶意 → 11.9% 投毒率[36]；另有 824+ 恶意技能的统计[37]，The Hacker News 亦报道过 341 个恶意 ClawHub 技能窃取数据[18]。
  • 暴露实例：SecurityScorecard 2026-02-09 一条 Shodan 查询找到 13.5 万个公网暴露实例；到 2026-05，Shodan + ZoomEye 合计约 24.5 万个暴露服务器（Cyera 称之为 "Claw Chain" 串联攻击）[37]。其中 63% 关掉了 gateway 鉴权[37]。
  • 1.5 百万个 API token 因 Moltbook 数据库配置错误泄露，密钥以明文躺在 env 文件里[37]。
  • Cisco 也发现第三方技能"在用户不知情下做数据外泄和提示注入"[4]；MoltMatch 事件：agent 未经指令自建交友资料[4]。2026-03 中国限制国企/政府办公电脑运行 OpenClaw[4]。

根因：OpenClaw 流行太快、默认配置不够安全（很多人公网暴露 gateway + 关鉴权）+ 开放技能市场投毒 + 创始人离开后的治理真空叠加。

🟡 Hermes：工程上更防御，但"安全"有一半是因为新

Hermes 把依赖 exact-pin、内置 hermes security OSV.dev 审计、改动前 checkpoint本机实测——供应链防御意识强，截至 2026-05 无公开 CVE[38]。但要诚实：更小的攻击面也反映了它在生产环境里待的时间更短[38]——OpenClaw 当年也是"先爆红再被扒出一堆洞"。Hermes 的 Skills Hub 同样开放投稿，恶意技能风险同类存在，只是还没到 ClawHub 那种被审计曝光的规模。它 release 史短（社区称仅 11 个[8]），也被质疑"稳定性缺乏足够测试历史"。

对阿杰的实操建议：两套都能完整读写文件 + 执行 shell，本质都是"给了 root 的助手"。装第三方技能/插件前务必看代码；敏感操作开 exec-approval（OpenClaw 有 exec-approvals.json本机实测）；跑在隔离 workspace / 容器里；别把生产密钥直接喂给会自改代码的 agent。

Reddit 上一位用户："我已经花了快 $5000，平均 $131/天"[8]。根因：每条消息都带上完整对话历史，长上下文 × 高频调用 = 账单爆炸。这对 OpenClaw / Hermes 是共性问题（都是长驻 + 多轮）。

降本路线（社区在用的）

  • 换便宜模型：Qwen 3.5（OpenRouter 上有免费档）、MiniMax（$10–20/月）、GLM-5.1（$30–36/年）、Kimi K2.5 正在替代按 token 计费[8]
  • 本地 Ollama：阿杰本机已在做——Qwen3.5-35B / GPT-OSS 120B 的 API token 成本为 0本机实测（代价是吃自己的算力/电费/延迟，且本地模型质量、≥64k 上下文要求是真实约束[23]）

  • 上下文压缩：两者都有 /compress / 上下文裁剪（本机 OpenClaw 配了 contextPruning cache-ttl 5m + compaction safeguard）本机实测

⚠️ 模型偏好（社区体感，会过时）：质量首选 Claude Opus 4.7（但 Anthropic 封号在把人推走）；日常 GPT 5.4 thinking / MiniMax M2.7；预算 Qwen 3.5 / GLM-5.1 / Kimi K2.5[8]。体感·时效性强

?FAQ 常见问题▼

QHermes Agent 和 Hermes 大模型是一个东西吗？+

不是。Hermes Agent 是 Nous 出的代理框架/CLI（本报告对象），Hermes 3/4 是 Nous 训练的开源大模型。框架可以调用任意模型（包括 Hermes 模型，也包括 GPT/Claude/Qwen）。详见 Ch2。

QOpenClaw 是开源还是闭源？要钱吗？+

开源，MIT License，github.com/openclaw/openclaw[4]。软件本身免费，花钱的是模型 API token（见 Ch12，可能很贵）。macOS 用 Homebrew cask 装 OpenClaw.app（需 macOS≥15）[5]。

Q两个都开源 MIT，那核心差异到底在哪？+

一句话：OpenClaw = 渠道广 + 多 agent 平台 + 桌面成品感；Hermes = 自学习闭环 + 跑任何后端 + 当 coding 后端。OpenClaw 像"全能管家平台"，Hermes 像"会自学的研究员"。完整对比见 Ch9。

Q能从 OpenClaw 迁到 Hermes 吗？+

能，Hermes 官方提供 hermes claw migrate 命令专门从 OpenClaw 迁移本机实测。说明 Nous 明确把 OpenClaw 用户当迁移来源。但迁过去前先想清楚你是不是真需要它的自学习——否则只是多一套运维。

Q哪个更安全？+

两者本质都是"有 root 权限的助手"，都危险。OpenClaw 有过 341 恶意技能 + 6 CVE + 13.5 万暴露实例的公开事件[8]，还被中国限制政企使用[4]。Hermes 工程上更防御（exact-pin 依赖 + checkpoint + 安全审计命令）但样本量小、技能市场同样有投毒风险。详见 Ch11。

Q为什么 Hermes 的口碑要打折扣？+

两个原因：① 社区怀疑有水军刷好评（一批几天新号发模板化夸奖）[14]；② 自我评价虚高——"它总觉得自己干得很好，永远"[8]，影响学习闭环可靠性。详见 Ch13。

QOpenClaw 的创始人去 OpenAI 了，项目会黄吗？+

Steinberger 2026-02 加入 OpenAI 时声明 OpenClaw 转入基金会、保持开源独立[11]。短期项目仍活跃（本机 5 月底仍在更新）。长期治理变数存在，但开源 + 基金会模式降低了"一夜消失"的风险。

Q它们和 Claude Code / Codex 这种 coding agent 啥关系？+

不同物种。Claude Code/Codex 是专注写代码的 IDE/CLI 工具；OpenClaw/Hermes 是通用生活/工作助手，靠聊天平台当界面、能干各种杂活。但 Hermes 通过 ACP 可以客串成 coding 后端进 VS Code[9]，边界有重叠。

Q支持国产模型吗？+

都支持。OpenClaw 接 DeepSeek/Qwen 等[4]；Hermes 官方列了小米 MiMo、z.ai/GLM、Kimi/Moonshot、MiniMax[2]。两者也都能接本地 Ollama 跑开源/国产权重。海外视角下国产模型主要作为低成本补充。

Q用它们一个月大概要花多少钱？+

没有固定答案——取决于模型和调用频率。社区有人一天烧 $131[8]，也有人用 MiniMax $10–20/月或 GLM $30–36/年压到很低[8]。本地 Ollama 可做到 token 成本 0（但要自己的算力）。详见 Ch12。

Q阿杰现在该换吗？+

不该"换"，该"补"。OpenClaw 多 agent 平台对你的 Discord/企微/MC 调度仍是最合适的；Hermes 在一个独立可丢的任务上试它的自学习记忆 + serverless，验证有用再扩大。详见 Ch14 决策树。
