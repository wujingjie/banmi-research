这份是什么：阿杰让做一份 Opus 4.8 的新功能 + 快速模式 + Dynamic Workflows 实用指南。因为 4.8 很可能在我训练截止之后发布，我没凭一句记忆，先联网把它查实了 —— 全报告 100% 以 Anthropic 官方公告 / docs / release notes 为准，每个数字都挂了官方引用。

一句话先给结论：① Opus 4.8 是真的，2026-05-28 已正式发布[1][2]，model ID 就是 claude-opus-4-8[3]，价格跟 4.7 一样（$5/$25 每百万 token），是个"点版本"升级 —— 编码 / 长上下文 / 数学 / 诚实度都涨了，但不是换代级跳变。

② 快速模式（Fast mode）= 同一个模型用更快的推理配置跑，输出速度最高 2.5 倍，智能不变，API 上设 speed: "fast"，Claude Code 里 /fast on，研究预览需申请；4.8 上它比 4.7 便宜 3 倍（$10/$50 vs 4.7 的 $30/$150）[5]。

③ Dynamic Workflows（动态工作流）是 Claude Code 的新功能（不是 API、不是 Agent SDK）：Claude 现写一段 JavaScript 编排脚本，在后台跑几十到上百个 subagent，最多 1000 个 / 同时 16 个，结果会互相交叉验证后才合并[6]。它就是把"研究 SOP 里那套多 Agent 调研"做成了产品内置功能。

01摘要 + 5 条核心结论（每条独立 callout）▾

1.1 一段话总结

Claude Opus 4.8 真实存在，2026 年 5 月 28 日由 Anthropic 正式发布[1][2]，距上一代 Opus 4.7 仅 41 天 —— 升级节奏明显加快[9]。它定位为"Anthropic 目前最强的通用可用模型"，主打 更准的判断力、对自己进度更诚实、能更长时间自主工作[1][18]。技术上是个 点版本（point release）：1M token 上下文、128k 输出上限、$5/$25 价格全部与 4.7 持平[3][4]，但 benchmark 普遍上涨（SWE-bench Verified 87.6%→88.6%、SWE-bench Pro 64.3%→69.2%、长上下文 GraphWalks BFS 在 1M 子集上 40.3%→68.1% 暴涨、USAMO 2026 数学 69.3%→96.7%）[10][11]。同时随它一起上线两个对阿杰最相关的东西：4.8 版快速模式（同模型加速、比 4.7 便宜 3 倍）[5] 和 Dynamic Workflows（Claude Code 内置的多 subagent 编排，研究预览）[6]。本报告把这三件事的官方用法、Case、和对阿杰的落地建议讲清楚。

1.3 5 条核心结论

🟢 结论 #1 —— Opus 4.8 发布了没？发了，2026-05-28，是真的。最大变化是「诚实度」+「长上下文」+「编码」三项，不是换代级跳变

这是阿杰最关心的第一问，直接回答：真实发布，不是传闻、不是名字搞错。 Anthropic 官方博客《Introducing Claude Opus 4.8》[1]、官方 docs《What's new in Claude Opus 4.8》[2]、AWS Bedrock / GitHub Copilot 上架公告全都在 5 月 28 日同步落地[14]。它是 4.7 的"点版本"升级（同价、同上下文、同输出上限、无 breaking API 改动）[13]，所以别指望像 4→4.5 那种代差。真正值得注意的三个变化：

(1) 诚实度 —— 官方说 4.8"放任自己写的代码缺陷不吭声"的概率比 4.7 低约 4 倍，更愿意主动 flag 不确定性[1]；
(2) 长上下文 —— GraphWalks BFS 在 1M token 子集从 40.3% 跳到 68.1%，长 agentic 任务更少跑偏 / 更少压缩[11]；
(3) 编码 + 数学（见结论 #2 的表）。对一个重度用 Claude Code 跑研究的人，"诚实度 +4 倍少漏报"这条比 benchmark 涨几个点更有体感。

🔵 结论 #2 —— vs 4.7 全部官方 benchmark 都涨（除 GPQA 微跌 0.6），最猛的是长上下文检索和数学，编码稳步小涨

全部来自 Anthropic 官方公告 + system card 自报，第三方媒体交叉一致[10][11]：SWE-bench Verified 87.6→88.6（+1.0）、SWE-bench Pro 64.3→69.2（+4.9）、OSWorld-Verified 电脑操作 78.0→83.4、Terminal-Bench 2.1 = 74.6（换了版本号 2.0→2.1 不直接可比）、USAMO 2026 数学 69.3→96.7（巨涨）、GraphWalks BFS 1M 子集 40.3→68.1（长上下文巨涨）、Finance Agent v2 = 53.9。唯一微跌：GPQA Diamond 94.2→93.6（−0.6，基本噪声级）[10]。⚠️ 提醒：这些都是厂商自报，且有两个 benchmark 换了版本（Terminal-Bench、Finance Agent），所以官方把它们标成"独立分数"而非 delta —— 看的时候心里有数，别把"换版本后的新高分"当成纯进步。完整表见 Ch3。

🟢 结论 #3 —— 快速模式一句话：同一个 Opus 4.8，用更快推理配置跑，输出 token/秒最高 2.5 倍、智能完全不变，加价但 4.8 比 4.7 便宜 3 倍

这是阿杰核心诉求之一，先给一句话能用版：API 上加 speed: "fast" + beta header fast-mode-2026-02-01；Claude Code 里 /fast on。[5][15] 底层不是换小模型 —— 官方明确写"same model weights and behavior (not a different model)"，只是换了更快的推理配置，所以质量零损失[5]。代价：premium 定价，4.8 是 $10/$50 每 MTok（输入/输出），刚好是标准价的 2 倍；但比 4.6/4.7 的 $30/$150 便宜了整 3 倍[4]。关键限制：
① 只加速"输出 token/秒（OTPS）"，不改善首字延迟（TTFT）；
② 仍是研究预览，要 waitlist / account manager 开通[5]；
③ 切换 fast/standard 会让 prompt cache 失效。完整步骤 + 3 个 Case 见 Ch4/Ch5。

🟣 结论 #4 —— Dynamic Workflows 是什么？是 Claude Code 的新功能（不是 API / 不是 Agent SDK），让 Claude 写一段 JS 脚本在后台跑成百个 subagent，相当于把「研究 SOP 那套多 Agent」做成了产品内置

阿杰特别让查证"这到底是什么产品的功能"。官方答案：Dynamic Workflows 是 Claude Code 的功能，官方文档在 code.claude.com/docs/en/workflows[6]。定义：一个 dynamic workflow 就是一段 Claude 当场写出来的 JavaScript 编排脚本，由一个独立 runtime 在后台执行，你的会话同时保持可用。[6] 它跟 subagent / skill 的本质区别是"谁拿着计划"：subagent 是 Claude 一回合一回合决定下一步、中间结果全塞进 Claude 的 context；workflow 把循环 / 分支 / 中间结果挪进脚本变量里，Claude 的 context 只留最终答案，所以能 scale 到几十到上百个 agent[6]。三种触发：
① prompt 里写 workflow 这个词；
② /effort ultracode 让 Claude 自己决定何时编排；
③ 跑内置的 /deep-research。有意思的点：它内置的 /deep-research 工作流，逻辑跟阿杰这套研究 skill 几乎一模一样 —— 多角度 fan-out 搜索、交叉验证、对没通过验证的 claim 直接过滤、出带引用的报告[6]。怎么用 + 3 Case 见 Ch7/Ch8。

🟡 结论 #5 —— 对阿杰：值得用 4.8（无脑升，无 breaking 改动），但快速模式 + Dynamic Workflows 都有「钱包警告」，要挑场景用；有一处只能存疑

给阿杰（半米单人全栈 + 重度 Claude Code 跑研究/开发）的实用结论：

(1) 模型升级无脑做 —— Claude Code 里 /model claude-opus-4-8 即可，官方说对现有 4.7 prompt 零改动开箱即用[13]，而且 4.8 的 tool-use 系统提示从 4.7 的 675 token 砍到 290 token，agentic loop 省 token[4]。

(2) 快速模式 = 钱包换速度，且要先 waitlist 开通 —— 适合"等不及看输出、且任务短"的交互场景，不适合长研究跑批（贵一倍且不省时间，因为它不改 TTFT）。

(3) Dynamic Workflows = 重武器，官方反复警告"比普通会话烧多得多的 token"[6][16]，适合全库审计 / 大迁移 / 交叉验证研究，不适合日常小改。⚠️ 唯一只能存疑的点：4.8 版快速模式具体是否已经能在阿杰的 Claude Code 里直接 /fast on（vs 仍需 API waitlist 审批）——官方写它是"研究预览、需申请"，Claude Code 端的开通门槛官方没逐字说死，阿杰要自己 /fast 试一下才知道有没有权限。详见 Ch10。

📌 诚实声明：本报告所有 4.8 的功能 / 参数 / 价格 / benchmark 全部来自联网查到的 Anthropic 官方源（anthropic.com/news、platform.claude.com/docs、code.claude.com/docs）+ 可信媒体交叉验证。🟢 = 官方 docs/公告直接写明；🟡 = 可信媒体报道（已尽量与官方对齐）；🔴 = 社区推测（本报告基本不用）。凡官方未逐字披露的，我都明确写"⚠️ 未确认 / 存疑"，没有一处是凭训练记忆脑补的 AI 功能。

3.3 竞品定位（官方公告口径，🟡 仅供参考）

官方公告把 4.8 跟 GPT-5.5 / Gemini 3.1 Pro 做了对比，称在多个 agentic / 编码 benchmark 领先[1]。第三方整理的同表数字（🟡 媒体二手，谨慎看）[10]：SWE-bench Pro 上 4.8 = 69.2% vs GPT-5.5 = 58.6% vs Gemini 3.1 Pro = 54.2%；OSWorld 上 4.8 = 83.4% vs GPT-5.5 = 78.7%。⚠️ 竞品对比尤其要小心：不同厂商用不同 harness 跑同一 benchmark 分数差很大（如 Terminal-Bench 上 GPT-5.5 用自家 Codex CLI 能到 83.4%），所以跨厂商横比意义有限，本报告不把它当结论用。

3.4 行为变化（不是 API breaking，但可能要调 prompt）

  • 更少浪费思考 token：adaptive thinking 下 4.8 每回合自己决定要不要思考，同 effort 等级下比 4.7 更省[2]。
  • 工具触发更好：4.7 上有人反映"该调工具时跳过了"，4.8 更少漏调[2]。
  • 压缩（compaction）恢复更好：长 agentic 轨迹在 context 压缩后更少跑偏[2]。

04快速模式（Fast mode）· 是什么 + 怎么开（步骤）▾

4.1 一句话定义（官方）

快速模式 = 让支持的 Opus 模型用「更快的推理配置」跑同一个模型，输出 token/秒最高 2.5 倍，智能和能力完全不变，代价是 premium 定价。[5] 官方原话："Fast mode runs the same model with a faster inference configuration. There is no change to intelligence or capabilities... Same model weights and behavior (not a different model)."

4.2 底层是什么？换小模型还是同模型加速？（阿杰特别问的）

明确：同模型加速，不是换小模型。 官方 docs 在《How fast mode works》一节里逐字写明"same model weights and behavior (not a different model)"[5]。这跟"切到 Haiku/Sonnet 那种换小模型提速"是两回事 —— 你拿到的还是 Opus 4.8 的全部智能，只是它吐字更快。但有个关键技术细节：加速只作用在"输出 token 每秒（OTPS）"，不改善首字延迟（TTFT）——也就是说"等它开口"的时间不变，"开口后吐得多快"变快 2.5 倍[5]。所以对"长输出"任务收益大，对"短输出但要快开口"任务基本没用。

4.4 怎么开（A. 用 API / SDK）

步骤：① 申请权限（research preview，找 account manager 或 join waitlist）[5] → ② 请求里加 beta header fast-mode-2026-02-01 + speed: "fast"。Python 示例（官方）：

import anthropic
client = anthropic.Anthropic()

response = client.beta.messages.create(
    model="claude-opus-4-8",
    max_tokens=4096,
    speed="fast",                          # ← 开启快速模式
    betas=["fast-mode-2026-02-01"],        # ← 必带 beta header
    messages=[{"role": "user",
               "content": "Refactor this module to use dependency injection"}],
)
print(response.content[0].text)
print(response.usage.speed)  # 返回 "fast" 或 "standard"，可校验实际跑的哪个

cURL 等价写法：header 加 --header "anthropic-beta: fast-mode-2026-02-01"，body 加 "speed": "fast"[5]。响应的 usage.speed 字段会告诉你这次实际是 fast 还是 standard。

4.6 限制与成本影响（用之前必看）

  • 💰 premium 定价：4.8 快速模式输入/输出是标准价的整 2 倍（$10/$50 vs $5/$25）[4]。速度翻 2.5 倍、钱翻 2 倍。
  • ⏱ 只快「输出速度」不快「首字延迟」：TTFT 不变[5]。
  • 🗄 切换 fast/standard 会让 prompt cache 失效：不同速度的请求不共享缓存前缀，回退时会 cache miss[5]。
  • 🚦 独立 rate limit：快速模式有单独的速率限制，超了返回 429 + retry-after[5]。
  • 🚫 不支持：Batch API、Priority Tier、第三方云平台[5]。

05快速模式 · 具体 Case + 适用 / 不适用场景▾

5.1 判断口诀

🧭 一句话判断：任务输出长 + 你在盯着等结果 + 不在乎多花一倍钱 → 开快速模式；任务跑批 / 后台 / 长上下文研究 / 预算敏感 → 别开（贵一倍还不省你的等待时间）。

5.2 三个具体 Case

✅ Case 1（该用）—— 交互式大重构 / 长代码生成，你坐在屏幕前等

场景：阿杰在 Claude Code 里让 4.8 一次性重构半米后端一个大模块、或生成一大段 React 组件代码，输出有几千 token，你正盯着等它写完好继续下一步。为什么该用：输出长 → 2.5 倍 OTPS 直接把"看着它一行行吐"的等待砍掉一大半[5]；你在交互、时间就是体验。成本：贵一倍，但单次重构的 token 量不大、绝对金额低，换来的流畅度值。官方 docs 的示例 prompt 正是"Refactor this module to use dependency injection"[5]，就是冲这个场景。

✅ Case 2（该用）—— 低延迟交互 demo / 给客户现场演示的实时生成

场景：半米给老师 / 家长演示"AI 实时生成一篇分级阅读短文 + 题目"，现场要快、要顺。为什么该用：现场演示对"吐字速度"高度敏感，标准速可能让观众觉得卡；快速模式同质量、快 2.5 倍，演示效果好[5]。注意：因为它不改 TTFT，"点按钮到开口"那一下还是原速，所以 UI 上配个 loading 动画盖住首字延迟体验最好。

⛔ Case 3（不该用）—— 后台批量跑 / 长研究报告 / 深度调研这类「跑就跑、人不盯」的任务

场景：阿杰让无忌跑一份 50-80 次搜索的深度研究报告、或夜里批量处理一堆 SciShow 词表、或长上下文喂整个代码库做分析。为什么不该用：(1) 这些是后台任务，人不在屏幕前等，吐字快慢无所谓；(2) 贵一倍，长研究 token 量大，金额差距明显；(3) 不支持 Batch API，而批量任务本来就该走 Batch（享 50% 折扣）[5]；(4) 长上下文研究的瓶颈是"思考 + 搜索 + 验证"轮次，不是吐字速度。结论：跑批 / 长研究就用标准速（甚至 Batch），把省下的钱花在多跑几轮验证上。

5.3 速查表

任务类型开快速模式？理由

06Dynamic Workflows · 是什么（查证 + 定义）▾

6.1 查证：这到底是什么产品的功能？（阿杰特别让查）

官方答案：Dynamic Workflows（动态工作流）是「Claude Code」的功能 —— 不是 API 功能、不是 Agent SDK 功能、不是 claude.ai 的功能。 官方文档明确挂在 Claude Code 文档站：code.claude.com/docs/en/workflows，标题《Orchestrate subagents at scale with dynamic workflows》[6]。Anthropic 官方博客也叫《Introducing dynamic workflows in Claude Code》[7]。（注：它在 CLI、桌面 app、IDE 扩展、claude -p 无头模式、以及 Agent SDK 上都能用[6]，但本质是 Claude Code 这条产品线的能力，不是裸 Messages API 的参数。）

6.2 官方定义

官方原话："A dynamic workflow is a JavaScript script that orchestrates subagents at scale. Claude writes the script for the task you describe, and a runtime executes it in the background while your session stays responsive."[6]

翻译：一个动态工作流就是一段 JavaScript 编排脚本 —— Claude 根据你的任务当场写出这段脚本，由一个独立 runtime 在后台执行，期间你的会话照常可用。 它把"计划 / 循环 / 分支 / 中间结果"从 Claude 的 context 里挪进了脚本变量里，所以能 scale 到几十到上百个 subagent，而 Claude 的 context 只留最终答案。

6.3 跟 subagent / skill 的区别（官方对比表，关键在「谁拿着计划」）

📌 本质：subagent/skill 里 Claude 是编排者（一回合一回合决定派谁），结果全落进 Claude 的 context；workflow 把编排逻辑（循环 / 分支 / 中间结果）写成代码，所以能跑得更大、更可重复，还能套一个"质量模式"——比如让独立 agent 对抗式互审彼此的发现、或从几个角度各起草一个方案再权衡，得到比单次跑更可信的结果[6]。

6.4 限制（官方硬约束）

07Dynamic Workflows · 怎么用（步骤 + 命令）▾

7.1 三种触发方式（官方）

① prompt 里写 workflow 这个词 → Claude 给这个单任务写一段 workflow 脚本（不改会话 effort 等级）。
② /effort ultracode → Claude 对会话里每个实质性任务自动决定是否编排 workflow（ultracode = xhigh 推理 + 自动编排）。
③ 跑现成的 workflow → 内置的 /deep-research，或你自己存的。[6]

7.2 最快上手：跑内置的 /deep-research

1

运行命令

/deep-research
/deep-research What changed in the Node.js permission model between v20 and v22?

它会从多个角度 fan-out 网页搜索、抓取并交叉验证来源、合成一份带引用的报告[6]。需要 WebSearch 工具可用。

2

允许工作流运行

权限

Claude Code 会问是否允许，选 Yes。可以 View raw script 先读脚本再决定，Ctrl+G 在编辑器打开脚本[6]。

3

看进度

/workflows

后台跑、会话照常可用。/workflows 列出运行中/已完成的，方向键选、回车进进度视图，看每个 phase 的 agent 数 / token 总量 / 耗时。键位：p 暂停/恢复、x 停、s 保存脚本为命令[6]。

4

读报告

完成

跑完报告落进会话，每条 claim 标了来源，没通过交叉验证的 claim 已被过滤掉[6]。

7.3 给自己的任务写 workflow + 存成命令

① prompt 里带 workflow 这个词（Claude Code 会高亮它），例：

Run a workflow to audit every API endpoint under src/routes/ for missing auth checks

Claude 会写一段编排脚本而非一回合回合干。如果你不想触发，按 alt+w 忽略这个词[6]。
② 跑出满意结果后，/workflows 选中那次运行，按 s 保存，存到：

  • .claude/workflows/（项目内，clone 的人都能用）
  • ~/.claude/workflows/（个人 home，所有项目可用，只你可见）

存完它就变成 /<名字> 命令，以后在 / 自动补全里出现，跟内置工作流一样用[6]。

7.4 ultracode 模式（让 Claude 自己决定何时编排）

/effort ultracode

开了之后 Claude 对每个实质性任务自动规划 workflow，一个请求可能连开几个 workflow（一个理解代码、一个改、一个验证）[6]。只持续当前会话，新会话重置。回常规活用 /effort high 退出。

⚠️ 关键澄清（很多文章搞混）：ultracode 不是一个 API 的 effort 等级。官方 effort doc 写明 API 接受的完整 effort 等级是 low / medium / high / xhigh / max，没有 ultracode[8]。ultracode 只是 Claude Code 界面里的概念 = xhigh 等级 + 给 Claude Code「随时可发起多 agent workflow」的常驻许可（通过 mid-conversation system messages 授予）[8]。所以你在 API 里设 effort: "ultracode" 是无效的。

7.5 关 / 限制 workflow

  • /config 里把 Dynamic workflows 关掉（跨会话持久）。
  • ~/.claude/settings.json 里设 "disableWorkflows": true。
  • 环境变量 CLAUDE_CODE_DISABLE_WORKFLOWS=1。[6]

08Dynamic Workflows · 具体 Case▾

8.1 官方点名的适用场景

官方说 workflow 适合"需要的 agent 数量超过一个会话能协调的，或者你想把编排固化成可读可重跑的脚本"的任务，列了四类例子：全库 bug 扫荡、500 文件大迁移、需要来源互相交叉验证的研究问题、值得从几个独立角度各起草一遍再定的硬计划[6]。Anthropic 内部 + 早期用户已用它做：全库 bug hunt、profiler 引导的性能优化审计、安全审计、死代码清理[7]。

✅ Case 1 —— 全库安全/认证审计

官方示例 prompt：Run a workflow to audit every API endpoint under src/routes/ for missing auth checks[6]。Claude 写脚本把每个 endpoint 分给一个 agent 查认证缺失，几十个并发跑，最后汇总成一份"哪些路由缺认证"的清单。为什么适合 workflow 而不是普通 subagent：endpoint 多到一个 context 装不下，且每个独立可并行，结果存脚本变量不污染 Claude context。

✅ Case 2 —— 大规模迁移（官方的旗舰例子：Bun 重写）

官方博客举的真实案例：Bun 团队用并行 agent + 每文件双 reviewer 审查，把约 75 万行 Rust 在 11 天内重写完成[7]。官方原话"Work you'd normally plan in quarters now finishes in days"（本来按季度排的活现在几天干完）[7]。workflow 的价值：不只是"跑更多 agent"，而是能套一个"可重复的质量模式"——独立 agent 改、另一批 agent 审，结果通过验证才合并。

✅ Case 3 —— 交叉验证式深度研究（就是 /deep-research）

内置 /deep-research 工作流：多角度 fan-out 网页搜索 → 抓取并 cross-check 来源 → 对每条 claim 投票 → 出带引用的报告，没通过交叉验证的 claim 直接过滤掉[6]。对无忌的研究 SOP 极其眼熟：这跟阿杰这套 research skill 的"多轮迭代 + cross-check 同一数字至少 2 源 + freshness 检查 + 强制 citation"几乎是同一套方法论，只是 Anthropic 把它做成了产品内置命令。

8.2 什么时候别用 workflow

⛔ 不适合 workflow 的任务：(1) 日常小改（改个 bug、加个函数）——普通对话或单个 subagent 就够，开 workflow 是杀鸡用牛刀且烧 token；(2) 需要中途人工介入决策的任务——workflow 运行中不能插话，只有权限提示能暂停[6]；(3) 预算紧的时候——官方反复警告 workflow 比普通会话烧多得多的 token[6]。

8.3 成本控制（官方建议）

  • 大 run 前先 /model 确认模型（别拿最贵模型跑全部 agent）[6]。
  • 描述任务时让 Claude 给"不需要最强模型的阶段"用小模型[6]。
  • workflow 里 subagent 默认用你会话的模型，且永远在 acceptEdits 模式跑、文件编辑自动批准——长 run 前把需要的命令加进 allowlist 免得中途被打断[6]。
  • 随时可在 /workflows 里停掉，已完成的工作不丢[6]。

09其他新功能 + 用法▾

9.1 会话中途插系统消息（Mid-conversation system messages）

4.8 接受在 user 回合后直接插 role: "system" 消息（受 placement 规则限制）[2]。用处：长会话里追加新指令不用重述整个 system prompt，从而保住前面回合的 prompt cache 命中、降低 agentic loop 的输入成本。无需 beta header[2]。（前面说的 ultracode 常驻许可就是靠这个机制实现的。）

9.2 effort 默认值改为 high（含 Claude Code）+ effort 等级体系

4.8 的 effort 参数所有平台默认 high（包括 API 和 Claude Code）[2]。如果你之前显式设过 effort，不受影响。官方说 4.8 默认 high 在编码任务上花的 token 跟 4.7 默认值差不多，但表现更好[2][17]。完整等级（API 接受的全集）：

等级说明典型用途
max无 token 约束的最高能力真·前沿难题；多数任务性价比低、可能 overthink[8]
xhigh长周期工作的扩展能力编码 + agentic 的推荐起点（30 分钟以上、token 上百万的长任务）[8]
high（默认）高能力 = 不设参数复杂推理、难编码、agentic 任务[8]
medium平衡、适度省 token要平衡速度/成本/性能的 agentic 任务[8]
low最省，能力略降简单任务、追求速度/低成本，如 subagent[8]

官方对 4.8 的具体建议：编码 / agentic 从 xhigh 起步，其他智能敏感工作用 high，测过 evals 确认低等级不掉质量再降到 medium/low[8]。跑 xhigh/max 时把 max_tokens 设大（64k 起步），给模型思考和跨 subagent 行动的空间[8]。

9.3 拒绝原因细节（Refusal stop details）

4.8 公开记录了拒绝响应上的 stop_details 对象（自 4.7 起就有，现在文档化）[2]。Claude 拒绝时除了 refusal stop reason，还会给一个"拒绝类别"，方便应用区分不同类拒绝、把用户导向正确的下一步。无需 beta header[2]。

9.4 更低的 prompt cache 门槛（1,024 token）

4.8 最低可缓存 prompt 长度降到 1,024 token（比 4.7 低）[2]。用处：以前在 4.7 上太短不能缓存的 prompt，现在能建缓存了，零代码改动就省钱[2]。

9.5 Claude Code v2.1.154 的其他改动（🟡 第三方整理）

  • effort slider 标签从 "Speed/Intelligence" 改成 "Faster/Smarter"[15]。
  • 后台 shell 执行：! <command> 或 claude --bg --exec '<command>'[15]。
  • 插件管理 /plugin、浏览器选择 /chrome[15]。
  • Opus 4.8 支持 + 4.7→4.8 迁移指引已加进 /claude-api skill[15]。

9.6 Mythos（背景，跟 4.8 无直接关系但同期）

同期 Anthropic 提到一个叫 Mythos 的"研究预览模型"，用于防御性网络安全工作流（Project Glasswing），邀请制、无自助注册，预计未来几周向客户推出[3]。⚠️ 这跟 Opus 4.8 是两个东西，阿杰短期用不上，列出仅供背景。

10⭐ 对阿杰的实用建议（升不升级 / 怎么落地）▾

阿杰 = 半米（AI 英语学习系统）单人全栈开发者 + 重度用 Claude Code 跑研究/开发。下面全是冲这个画像给的具体可执行建议。

10.1 要不要升级 4.8？—— 升，无脑升，今天就升

✅ 结论：立刻升，零风险。理由：(1) 同价（$5/$25，跟 4.7 一模一样）[4]；(2) 无 breaking API 改动，现有 4.7 prompt / eval 开箱即用[13]；(3) benchmark 普遍涨，尤其长上下文（GraphWalks 1M +27.8）和编码（SWE-bench Pro +4.9）[11]；(4) 诚实度 +4 倍少漏报——对单人开发者，"AI 不偷偷放过自己写的 bug"比涨几个点 benchmark 实在得多[1]；(5) tool-use 系统提示从 675→290 token，agentic loop 还省 token[4]。怎么升：Claude Code 升到 v2.1.154+，然后 /model claude-opus-4-8 完事。半米后端调 API 的地方把 model 字符串改成 claude-opus-4-8 即可。

10.2 effort 怎么设（对阿杰最实用的一条）

🔵 日常开发用默认 high 就好（4.8 默认就是 high，不用动）。遇到长周期 agentic 编码 / 大重构 / 复杂调试，/effort xhigh——官方对 4.8 的明确建议就是"编码和 agentic 从 xhigh 起步"[8]。跑无忌这种长研究、或日常小问答想省钱，/effort medium 甚至 low。别动不动上 max——官方说多数任务 max 性价比差还可能 overthink[8]。

10.3 快速模式在阿杰流程里怎么落地

🟢 用在：交互式大重构 / 长代码生成时你坐着等的场景（Ch5 Case 1），/fast on 把吐字等待砍一半。
🔴 别用在：无忌跑的深度研究、夜里批量处理 SciShow 词表、长上下文喂代码库——这些后台跑、人不等、且贵一倍还不支持 Batch（Ch5 Case 3）。
⚠️ 先确认权限：快速模式是研究预览、要 waitlist/account manager 开通[5]。阿杰先 /fast on 试，提示无权限就去 claude.com/fast-mode 排队。这是本报告唯一我无法替你确认的点：你账号现在到底开通了没——只能你自己试。

10.4 Dynamic Workflows 在阿杰研究 + 开发流程里怎么落地

🟣 研究侧：/deep-research 跟无忌这套 research skill 是同一套方法论（多角度 + 交叉验证 + 过滤未验证 claim + 带引用）[6]。阿杰可以拿它做"快速一手扫"，再让无忌按 banmi-research SOP 出正式 HTML 报告——两者互补不冲突：/deep-research 出原料，无忌出可归档的左侧导航 HTML + popover 引用 + 半米路线建议。
🟣 开发侧：半米有几个天然适合 workflow 的活——全库审计（如 Ch8 Case 1 的"审所有 API 路由认证缺失"）、大重构 / 大迁移（如把 9 套前端 demo 统一成 1 套参数化 UI，正好是上次阅读测试报告的窄切口建议）、跨文件一致性检查。
⚠️ 钱包警告：workflow 烧 token 多[6]，单人开发者先用小任务试水、/model 选合适模型、能停就停，别一上来 ultracode 全开。

12FAQ（12 条）▾

QOpus 4.8 真的发布了吗？还是传闻？＋
真发布了。2026-05-28 由 Anthropic 正式发布，官方博客、官方 docs、AWS/GitHub 上架公告 + 多家一线媒体同日落地，互相印证[1][2][14]。本报告所有内容都是按"先查证再写"的原则做的，没有凭记忆脑补。
Qmodel ID 是什么？怎么在代码里调？＋
claude-opus-4-8（API/Vertex/Claude Code 同名，Bedrock 是 anthropic.claude-opus-4-8）[3]。它是固定快照不是会滚动的指针。半米后端把 model 字符串换成它即可，无 breaking 改动[13]。
Q4.8 比 4.7 强多少？值得换吗？＋
点版本升级，同价。benchmark 普遍涨：SWE-bench Verified 87.6→88.6、SWE-bench Pro 64.3→69.2、长上下文 GraphWalks 1M 40.3→68.1、数学 USAMO 69.3→96.7[10][11]。GPQA 微跌 0.6（噪声级）。同价 + 无 breaking + 更诚实 + 长上下文大涨 → 无脑换。
Q快速模式是换了个更小的模型吗？质量会降吗？＋
不是换小模型，质量不降。官方逐字写"same model weights and behavior (not a different model)"，只是用更快的推理配置[5]。输出 token/秒最高 2.5×，但首字延迟（TTFT）不变。
Q快速模式贵多少？＋
4.8 快速模式 $10/$50 每 MTok（输入/输出），是标准价 $5/$25 的整 2 倍[4]。但比 4.6/4.7 的 $30/$150 便宜了整 3 倍——这就是"4.8 快速模式便宜 3 倍"这句话的来源[5]。
Q快速模式怎么开？我现在就能用吗？＋
API：加 beta header fast-mode-2026-02-01 + speed: "fast"；Claude Code：/fast on[5][15]。但它是研究预览，要 account manager 或 waitlist 开通——你能不能直接用得自己试，这点官方没替每个账号说死。
QDynamic Workflows 是 API 功能还是 Claude Code 功能？＋
是 Claude Code 的功能，官方文档在 code.claude.com/docs/en/workflows[6]。它在 CLI/桌面/IDE 扩展/无头模式/Agent SDK 都能用，但本质是 Claude Code 这条产品线的能力，不是裸 Messages API 的参数。
Q怎么触发一个 dynamic workflow？＋
三种：① prompt 里写 workflow 这个词；② /effort ultracode 让 Claude 自动决定；③ 跑内置 /deep-research 或自己存的[6]。用 /workflows 看进度/管理。
Qworkflow 最多能跑多少 agent？＋
同时最多 16 个并发（CPU 核少更少），单次运行总计最多 1,000 个[6]。
Qultracode 是个新的 effort 等级吗？API 里能设吗？＋
不是 API effort 等级，API 设不了。API 接受的完整等级是 low/medium/high/xhigh/max[8]。ultracode 只是 Claude Code 界面概念 = xhigh + 给 Claude Code 常驻发起 workflow 的许可[8]。
QDynamic Workflows / 快速模式会让我账单暴涨吗？＋
会，两者都有"钱包警告"。workflow 一次跑成百 agent，官方反复说"比普通会话烧多得多 token"[6]；快速模式价格翻倍[4]。建议小任务试水、控好 /model、能停就停。
Q这报告里有没有查不到、只能存疑的地方？＋
有一处，已诚实标出：4.8 版快速模式在阿杰的 Claude Code 账号里是否已经能直接 /fast on（vs 仍需 API waitlist 审批）——官方写它是研究预览、需申请，但没逐字说死 Claude Code 端每个账号的开通门槛，只能阿杰自己 /fast 试。另外所有 benchmark 都是 Anthropic 厂商自报、且有两项换了版本，看的时候要打折。除此之外，功能/参数/价格/用法全部有官方源支撑。
