03商业 API 详评 · 9 家逐个拆▼

下面按「绘本动画化适用度」从高到低排，重点说角色一致性 + 国内可用性 + 价格三件事，这三件直接决定阿杰能不能上线。

🥇 可灵 AI 2.1 Master（快手）

国内 + 海外双区 绘本首推 ¥5.6/5s

定位：快手 2024 年推出，2026 年 5 月已迭代到 2.1 Master 版本，是 2026 年图生视频质量最稳的国产 SOTA。5-10s 单段，720p / 1080p 双档，I2V 时人物动作物理规律理解极强（打斗、转身、长发飘动）。

价格：2.1 Master $0.80 / 5s（约 ¥5.6），或 $1.40 / 5s + $0.28/s（不同平台差异）。Master 是最贵档，普通 2.1 约 1/3 价格。fal.ai / WaveSpeed / kie.ai 都能调，国内通过快手开放平台 API 可直接对接。

绘本杀手锏：Multi-Element Reference。可以同时上传多张参考图（@Element1, @Element2…），prompt 里直接引用，30 页绘本同一只 Caterpillar 几乎能保持一致。这是 2026 年 5 月所有国产视频模型里独一份的能力。

绘本动画化首选。50 学员阶段 100 段 ¥560，单本 30 页 ¥168（10s 段）或 ¥84（5s 段）。强烈建议先用 Master 跑 3 本 demo 验证学生反应。

🥈 即梦 Seedance 2.0 / Dreamina（字节跳动）

国内 + 海外双区 最便宜 ¥0.14/s

定位：字节跳动 2026 年 2 月把国内即梦的 Seedance 2.0 模型搬到海外叫 Dreamina。图生视频的无缝衔接是它强项 —— 运镜笔刷可精准控制画面，良品率极高（创作者圈普遍反馈）。

价格：火山方舟 API ¥1/s（约 $0.14）的 Doubao-Seedance-2.0；即梦订阅 69 元/月（~$9.6）含一定时长；Dreamina 海外版基础 $15/月 1575 credits。第三方代理低至 $0.022/s 但稳定性看运气。

绘本动画化适用度：单段质量比可灵略弱，但价格不到可灵 1/4。角色一致性目前主要靠 prompt 引导 + 起始帧 + 描述精确，没有可灵那样的显式 Multi-Element 接口。

量产时单本 ¥30-45（30 段 × 5s × ¥1/s）。和可灵搭配用 —— 简单场景跑即梦，复杂多主体跑可灵，混合方案性价比最优。

🥉 Hailuo MiniMax 02

国内 + 海外 $0.045/s（768p）

定位：MiniMax 2026 年的视频模型。Hailuo 02 在 768p 上 $0.045/s（约 ¥0.32/s），是当前主流商业模型里每秒成本最低之一（仅次于即梦的代理价）。6 秒 768p 单段 $0.27（≈¥2）。

订阅：Standard $9.99/月 1000 credits，Unlimited $94.99/月。fal/Replicate 都有官方接入。

缺点：单段质量在国产 top 3 里排第 3，物理一致性不如可灵；没有独立的 Multi-Element 接口。但速度快 + 便宜，适合做大批量「简单场景」（自然风光、空镜、过场）。

作为可灵的备份和大批量场景生成的主力，单本「混合方案」里 70% 简单镜头交给它。

Vidu 2.0（生数科技）

国内 多主体一致性 $0.05/s（720p）

定位：清华 + 生数科技联合出品。Multi-Subject Reference是它真正的卖点：可同时上传 3-7 张参考图（角色 + 物体 + 场景），AI 在生成视频时维持视觉一致性。绘本里「Caterpillar + 苹果 + 树」同时出现的场景，可以用 Vidu 把三个元素一起作为 reference。

价格：720p $0.05/s · 1080p $0.125/s · 360p $0.025/s。Standard $9.99/月（年付 $7.99/月），8 秒 1080p 段约 10 credits。比 Vidu 1.5 便宜 50%，比西方对手便宜 3-7 倍同质量。

缺点：动作物理质量略弱于可灵 Master；国际化访问限制相对多。

绘本「多主体一致性场景」（Caterpillar + 食物 + 蝴蝶同时出现）的最佳选择，可以和可灵分工：可灵跑「主角动作」，Vidu 跑「多元素同框」。

Runway Gen-4 Turbo

海外为主 $0.05/s

定位：欧美创作圈传统大佬，2025-2026 年迭代到 Gen-4 / Gen-4 Turbo。Turbo 版 5 credits/秒，credit 价 $0.01，约 $0.05/s。订阅 Standard $15/月 625 credits（≈125 秒 Turbo）/ Pro $35/月 2250 credits。

角色一致性：Gen-4 自带 reference 能力，加上 Act-One（角色面部表演）。但相比可灵 Multi-Element 略弱，且需要更多 prompt 工程。

国内可用性：🔴 国内 IP 直接访问受限，需海外信用卡支付，对中小团队不友好。

质量稳定但不推荐给阿杰国内场景。海外有合作伙伴或要做 toC 海外发行才考虑。

Veo 3 / Veo 3.1 Lite（Google）

海外为主 2026 年 3 月发布 Lite $0.05/视频

定位：Google 2025 年发布 Veo 3，2026 年 3 月推 Veo 3.1 Lite，主打高频低成本场景，单视频 $0.05（与 Fast 同速度但便宜 50%+）。Veo 3.1 标准 $0.40 / Fast $0.15 / Lite $0.05。Vertex AI / Gemini API / Google AI Studio 都能调。

消费级：Google AI Ultra $249.99/月（贵）。

国内可用性：🔴 完全不可用，Google API 需海外网络 + 国际信用卡。

技术上可以但国内场景下属于备选。如果阿杰未来开海外团队或合作伙伴提供 API，可重新评估。

Luma Dream Machine Ray 2

海外 $0.50/5s（API）

定位：Luma Labs，Ray 2 标准 32 credits/秒，Ray 2 Flash 11 credits/秒。API $0.32 / 百万像素，第三方平台（fal.ai）$0.50/5s。订阅 $24/月起。

绘本动画化适用度：动作流畅但角色一致性是弱项；国内访问困难。

不推荐给国内场景，作为知识储备列入。

Pika 2.5（含 Scene Ingredients）

海外 Scene Ingredients $8-95/月

定位：Pika 2.0 起加入 Scene Ingredients（上传角色 + 物体 + 场景作为 ingredients），2.1 加 Pikaswaps / Pikadditions / Pikatwists。免费 80 credits/月 · Standard $8（年付）· Pro $28 · Fancy $76。Pika 没有官方 public API，要通过 fal/Pollo/Wavespeed 第三方接入。

绘本动画化适用度：Scene Ingredients 概念上接近可灵 Multi-Element，但生态比较封闭、API 不友好。

概念领先，但工程化对接不友好。不推荐给生产场景。

通义万相 Wan 2.6 / Tongyi（阿里）

国内首推 可免费 + 开源版本 ¥0.7/clip（API）

定位：阿里通义万相，2026 年发布 Wan 2.6 系列，第一个国内支持角色扮演功能的视频模型。Wan 2.1 是开源（见路线 B），万相平台官方网页基本免费给个人开发者，App 端日不限量。API 约 $0.10/clip 起（火山引擎对标的阿里百炼版）。

路线图：阿里官方公告 Wan 3.0 60B 参数 2026 年中支持 4K + 30 秒连续生成，2-5 分钟多镜头自动生成。

国内全套国产工具链友好。可以和可灵双轨：可灵跑「质量优先」高端场景，万相跑「免费 + 海量」批量场景。

⛔ Sora（OpenAI）— 已停服

2026-04-26 关停 API 2026-09-24 下线

重要更新：根据 OpenAI 2026 年公告，Sora App 已于 2026-04-26 正式关停，API 计划于 2026-09-24 全部下线。原因官方解释为算力短缺 + 成本压力 + 战略聚焦企业产品。不要再把 Sora 列入选型，所有用过 Sora 的产品都得迁移到可灵 / Veo 3 / Runway。

历史能力：ChatGPT Plus 用户原本每月可生成 50 个 480p 视频，Pro 用户 10 倍配额，含 Storyboard 和 Remix 工具。

2026 年视频生成市场格局已确定：国产可灵 / 即梦 / 万相主导国内，Veo 3 / Runway 主导海外，Sora 出局。

04开源模型详评 · Wan 2.2 / HunyuanVideo / LTX-2 / 其他▼

开源路线 = 自己买 / 租 GPU，跑 ComfyUI workflow。回报是单本成本降到 ¥10-20，代价是工程门槛 + GPU 月租。

🥇 Wan 2.2（阿里通义开源）

Apache 2.0 商用 绘本开源首选 5B / 14B 双档

定位：阿里通义 2025-2026 年迭代到 Wan 2.2，开源 Apache 2.0 协议，商用免费。三个变种：1.3B（4-6GB VRAM，480p 短片）/ 5B TI2V（FP8 8-10GB，480p 强 I2V）/ 14B（FP8 16-24GB 480p，40-80GB 720p）。

消费级可跑：5B 版在 8GB VRAM 上跑得动（RTX 3060 / 4060 都行）。14B GGUF Q4 + T5 CPU offload 在 6-8GB VRAM 也能跑（480p）。社区项目 Wan2GP 专门为消费级 GPU 优化。

绘本动画化适用度：5B 单段质量已经接近商业 API 中端档；14B 在 RTX 4090 / A100 上跑 480p 单段 5-15 分钟，质量与可灵普通版相当。配合 IP-Adapter / LoRA 可解决角色一致性（见 Ch7）。

阿杰量产阶段开源首选。一台 AutoDL A100 80GB（¥6/h）日跑 12 小时可出 50-100 段，单段算力成本 ¥0.6-1.5。建议先在 4090 上调通 workflow，再上 A100 量产。

🥈 LTX-2 / LTX-Video（Lightricks 开源）

Apache 2.0 2026-01 发布 实时生成

定位：Lightricks 2024-11 首发 LTX-Video 2B，2026-01-06 开源 LTX-2（首个 4K 真开源音视频生成模型，原生支持同步音频）。2026-03-05 LTX-2.3 升级到 22B 参数，支持 4K @ 50fps + 同步音频。

速度优势：LTX-Video 2B 在 4090 上能实时 30fps 生成 1216×704，比片子本身播放还快。LTX-2.3 22B 在消费级 GPU 上也跑得动。

独家卖点：原生支持 audio-video 同步生成 —— 一个模型同时出 mp4 + 音轨，省一个 TTS 环节（不过儿童绘本的英语朗读还是建议用专业 TTS）。

速度极快，适合「快速迭代」场景 —— 比如同一本绘本反复调 prompt 改风格时，LTX 比 Wan 快 5-10 倍。LTX-2 + Wan 2.2 双开源模型混搭是 2026 年量产方案的甜点。

🥉 HunyuanVideo / HunyuanVideo-I2V（腾讯开源）

开源 VRAM 高 13B 参数

05伪动画路线 · Ken Burns / LivePortrait / AnimateDiff▼

「伪动画」= 不真生成视频，而是把静态绘本图用各种手段「动起来」。最大优势：角色一致性 = 100%（因为根本不重生成图），缺点是质量天花板低、教学冲击力弱。

伪动画 5 种手段

① Ken Burns 推拉效果

PIL / MoviePy 几十行代码 免费 + 0 GPU

原理：把一张图通过缓慢的缩放 + 平移做成「动起来」的感觉。Ken Burns（纪录片导演）发明，纪录片 / Apple iMovie 默认动效。

实现：MoviePy ImageClip + resize lambda t: 1 + 0.1*t 一行搞定，每页 5-8 秒，纯 CPU 实时渲染。

绘本效果：单页绘本「相机推进 Caterpillar 脸 → 拉远到全景树林」这种推拉感，比纯静态强 10 倍，是最低门槛 + 最低成本的入门路径。

即使主线走商业 API，所有「不需要动作」的页面都可以走 Ken Burns 兜底 —— 节省 70% API 成本。

② LivePortrait（角色面部动）

开源 2024-07 港中文 + 快手

原理：给一张人脸图 + 一段音频（或 driving video），自动生成「面部表情 + 眨眼 + 嘴动」的视频。CVPR 2024 论文 + 开源代码 + 港中文 / 快手出品。

绘本场景适用：如果绘本主角是「有脸」的角色（小动物拟人 / 人物），LivePortrait 可以让面部动起来配合朗读，体验类似 talking head。但对纯卡通脸效果一般，对真实人脸效果最好。

小学高年级 / 初中绘本里「人物对话」场景可用。低龄绘本（动物拟人为主）效果会不自然。

③ SadTalker / MuseTalk（口型同步）

开源 CVPR 2023 + 实时

SadTalker：3DMM 建模 + 音频驱动 → 头部姿态 + 表情 + 口型，单图 + 音频出 5-10 秒说话头。

MuseTalk（腾讯 TMElyralab）：2026 年口型同步 SOTA 开源之一，实时能跑，适合直播场景。质量近写实。

绘本场景：和 LivePortrait 类似，但 MuseTalk 口型精度更高。「让 Caterpillar 朗读这句话」是不是要让它真张嘴 —— 看绘本风格。

配合 TTS 用：先生成 TTS 音频，再用 MuseTalk 让角色嘴动同步。绘本里偶尔的「角色说话」场景可用。

④ AnimateDiff（让局部纹理动）

开源 SD 插件

原理：基于 Stable Diffusion 的运动模块，给一张 SD 图加上「轻微动效」 —— 火焰摇曳 / 水波荡漾 / 头发飘动。motion module 只比 base 模型多 5-15% 参数，非常轻量。

对比 SVD：AnimateDiff 走「文本 → 视频」更顺；SVD 走「图 → 视频」更顺。绘本场景如果是「保持原图 + 局部加细微动」，AnimateDiff 更合适。

速度：AnimateLCM-SVD-Comfy 应用 latent consistency 蒸馏，加速 3-5 倍。

和 Ken Burns 互补 —— Ken Burns 处理「相机移动」，AnimateDiff 处理「画面局部动」，组合起来「图层化伪动画」效果出乎意料。

⑤ Parallax 视差 / 深度图运镜

开源 depth + 摄像机

原理：用 Marigold / DepthAnything 估计图的深度图，把图层分成前景 / 中景 / 远景，摄像机移动时前景动得快、远景动得慢，造出 3D 视差效果（类似 iOS 锁屏深度照片）。

绘本场景：绘本插画通常前景人物 / 背景树林分层清晰，视差效果尤其惊艳。MoviePy + PyTorch 几百行代码可实现。

和 Ken Burns 组合用 —— 加上深度感的「Ken Burns 3D 版」，是伪动画路线的天花板。

④ 图 → 视频生成（5-10s 单段）

import requests, time
KLING_API = "https://api.klingai.com/v1/videos/image2video"
HEADERS = {"Authorization": f"Bearer {API_KEY}"}

def gen_scene(image_url, prompt, duration=5):
    r = requests.post(KLING_API, headers=HEADERS, json={
        "model": "kling-v2.1-master",
        "image": image_url,
        "prompt": prompt,
        "duration": duration,
        "aspect_ratio": "16:9",
    })
    task_id = r.json()["data"]["task_id"]
    while True:
        s = requests.get(f"{KLING_API}/{task_id}", headers=HEADERS).json()
        if s["status"] == "succeed": return s["video_url"]
        time.sleep(5)

⑥ 背景音乐 + 音效

  • Suno v4：从文字描述生成 1-4 分钟完整 BGM。「Soft acoustic guitar children's lullaby, warm and gentle」→ 直接得到一段完整曲子。8 credits/首。
  • Stable Audio 2.0 / MusicGen：开源 BGM，本地跑 4090 即可，30s-3 分钟段。
  • ElevenLabs Sound Effects：短音效（鸟叫 / 翻书 / 苹果落地），$1 起。
  • 预制库：Pixabay / Free Music Archive 公版儿童 BGM 直接用，零成本。

⑦ 字幕同步（Whisper word-level）

WhisperX 是 2026 年单词级时间戳 SOTA：通过 wav2vec2 phoneme alignment 把每个词映射到音频精确位置，<100ms 精度，足够 karaoke 风格逐词高亮。

import whisperx
model = whisperx.load_model("large-v3", "cuda")
result = model.transcribe("narration.mp3")
align_model, meta = whisperx.load_align_model(language_code="en")
aligned = whisperx.align(result["segments"], align_model, meta, audio, "cuda")
# aligned["word_segments"] = [{"word": "Caterpillar", "start": 1.23, "end": 1.78}, ...]

输出格式：WebVTT（开始 + 结束都有时间戳，karaoke 友好）或 Enhanced LRC（单字时间戳，QQ 音乐 / 网易云风格）。前端用 React 组件逐词加 highlight CSS class 即可。

⑧ 视频拼接 + 转场（Remotion 推荐）

Remotion = React 写视频，headless Chrome 渲染每帧 → FFmpeg 拼成 mp4。优势：

  • 组件化：每页绘本 = 一个 React 组件，传 props 控制文字 / 图片 / 字幕。
  • 多输出：mp4 / HEVC / WebM / GIF。
  • Remotion Lambda：拆分任务到 AWS Lambda 并行渲染，1 本绘本能在 30s 内出片（30 页并发）。
  • 对比 MoviePy：MoviePy 简单脚本快但效果土；Remotion 投入大但效果接近影视级。

⑨ 输出格式

  • mp4 (H.264)：最兼容，1080p 30fps 30 页绘本 ≈ 150-300MB。
  • HLS：流媒体切片，前端按需加载，省流量。半米 web 端推荐。
  • 同步元数据 JSON：每页起止时间 + 字幕 word timestamps + 当前主角，前端做交互需要。

反面教材：什么不行

  • 纯 prompt 控制（描述「同一只绿色 Caterpillar 红头」）—— 第 5 页起开始漂移，第 15 页变成完全另一只虫。
  • 第一帧固定（每页用同一张图当起点）—— 动态生成后 1s 起就漂走。
  • 开源 SVD 默认（Stable Video Diffusion）—— 角色一致性几乎为零，仅适合「自然风光」类场景。
给阿杰的最终建议：50 学员阶段不要碰 LoRA，直接用可灵 Multi-Element + Vidu Multi-Subject 双国产 SaaS 服务方案。等到 500 本量产 + 开始自托管时，再把 LoRA + Flux Redux 加进 ComfyUI workflow。「过早工程化」是这个领域的最大陷阱。

🥈 CosyVoice 2（开源 + 自建）

Apache 2.0 3-10 秒零样本

定位：阿里 FunAudioLLM 团队开源，2026 年迭代到 2.0。44.1kHz 高保真，流式 latency 亚秒级，50+ 语种零样本，跨语言克隆（英语声音可以说中文）。比 1.0 错误率降 30-50%。

  • 速度：6 岁以下 0.85x（慢）· 7-10 岁 1.0x · 10+ 岁 1.1-1.2x。低龄绘本一定要降速，否则学生跟不上。

  • 多角色：旁白用一个声音，对话每个角色一个声音。30 页绘本通常 3-5 个角色 + 1 个旁白。

10自动化方案 · ComfyUI / n8n / FastAPI 三选一▼

从 PDF 到 mp4 无人值守 pipeline。三种主流编排方案：

🥇 方案 A · 单 Python 脚本（最简，50 学员推荐）

500-800 行代码 2 天搭出 demo

原理：一个 Python 脚本，串行调商业 API（PyMuPDF → Claude → 可灵 → MiniMax → WhisperX → Remotion）。失败重试 + 中间产物缓存 + tqdm 进度条 + Slack 通知完成。

优势：易维护、易调试、不引入额外架构。一个工程师 2 天能搭出来跑 3 本绘本验证。

缺点：并行能力靠 asyncio，跑 100 本时偶尔抖动需要人工补跑。

50 学员 + 100 本试点的唯一推荐方案。阿杰找一个会 Python 的工程师 2 天搭出来。

🥈 方案 B · ComfyUI workflow + API

workflow JSON 可视化 开源模型路线

原理：ComfyUI 是「节点式」AI 工作流编排器。每个节点 = 一个模型（PDF 抽 / Wan 2.2 / CosyVoice / FFmpeg），节点连成图。导出 workflow JSON，用 ComfyUI API 远程调用。

优势：

  • 可视化调试，非工程师也能改参数。
  • 开源生态成熟，2026 年 Wan 2.2 / LTX-2 / IP-Adapter 都有现成节点。
  • n8n 有官方 ComfyUI 集成 + 社区 image-to-video 节点。

缺点：单实例 ComfyUI 跑大模型容易 OOM，需要监控 + 自动重启。商业 API（可灵 / 即梦）需要自己包 HTTP node。

500+ 本量产 + 开源路线推荐。配合 n8n / Google Sheets 任务表，无人值守批量出片。

🥉 方案 C · FastAPI + Celery + Redis 自建 worker 集群

企业级 / 长期 1-2 人月

原理：FastAPI 提供 REST API（用户提交绘本 PDF）→ Celery worker 队列 → Redis 状态 → 各 worker 调对应模型。前端实时进度条。

优势：完全自主可控、水平扩展容易、可与半米现有系统深度集成。

# storybook_animate.py · 60 行端到端 demo
# 依赖: replicate, fitz (pymupdf), requests, moviepy, anthropic

import fitz, replicate, requests, anthropic, json, os
from moviepy.editor import VideoFileClip, AudioFileClip, concatenate_videoclips

os.environ["REPLICATE_API_TOKEN"] = "r8_xxx"
claude = anthropic.Anthropic()
MINIMAX_KEY = "mm_xxx"

# 1) 抽页
def extract_pages(pdf):
    doc = fitz.open(pdf)
    return [{"img": p.get_pixmap().tobytes("png"),
             "text": p.get_text()} for p in doc]

# 2) 分句 + 镜头描述（Claude）
def plan_scene(text, page_idx):
    msg = claude.messages.create(model="claude-opus-4-7", max_tokens=500,
        messages=[{"role": "user", "content": f"绘本第{page_idx}页：'{text}'。输出 JSON: prompt(给可灵的视频 prompt), camera, duration_s(5或10)"}])
    return json.loads(msg.content[0].text)

# 3) 图 → 视频（Replicate 调可灵）
def i2v(image_path, prompt, dur):
    return replicate.run("kwaivgi/kling-v2.1-master",
        input={"image": open(image_path, "rb"), "prompt": prompt, "duration": dur})

# 4) TTS（MiniMax Speech-02 HD）
def tts(text, voice="Wise_Woman"):
    r = requests.post("https://api.minimaxi.chat/v1/t2a_v2",
        headers={"Authorization": f"Bearer {MINIMAX_KEY}"},
        json={"model": "speech-02-hd", "text": text,
              "voice_setting": {"voice_id": voice, "speed": 0.9}})
    return r.content  # mp3 bytes

# 5) 主流程
def animate_book(pdf, out="out.mp4"):
    pages = extract_pages(pdf)
    clips = []
    for i, p in enumerate(pages):
        open(f"p{i}.png", "wb").write(p["img"])
        plan = plan_scene(p["text"], i)
        video_url = i2v(f"p{i}.png", plan["prompt"], plan["duration_s"])
        open(f"p{i}.mp4", "wb").write(requests.get(video_url).content)
        open(f"p{i}.mp3", "wb").write(tts(p["text"]))
        v = VideoFileClip(f"p{i}.mp4").set_audio(AudioFileClip(f"p{i}.mp3"))
        clips.append(v)
    concatenate_videoclips(clips).write_videofile(out, fps=24)

if __name__ == "__main__":
    animate_book("caterpillar.pdf")
    # 30 页 ≈ 15-25 分钟跑完，输出 out.mp4，单本花费 ¥80-120

16FAQ · 12 条常见问题▼

Q1国内能不能直接用 Runway / Veo 3 / Sora？+

Runway：国内 IP 直接访问受限，需海外网络 + 海外信用卡支付。不推荐给国内为主的团队。

Veo 3 / Veo 3.1 Lite：Google 系全套服务国内不可用，Vertex AI / Gemini API 都需要翻墙 + 海外支付。

Sora：已于 2026-04-26 关停，2026-09-24 API 也下线，不要再考虑。

国内能直接用：可灵（快手）/ 即梦 Seedance（字节）/ Hailuo（MiniMax）/ Vidu（生数）/ 通义万相（阿里）—— 五家国产模型 2026 年 5 月质量都已经达到「生产可用」，可灵 2.1 Master 是质量最强。

Q2可灵国内版和海外版有什么区别？+

模型是同一个，但 API 入口和支付通道不同：

  • 国内：klingai.com + 快手开放平台，人民币支付，需国内手机号实名
  • 海外：klingai.com/global + fal.ai / kie.ai / WaveSpeed 等第三方，美元支付

价格基本一致（汇率换算后差 5-10%）。海外版第三方平台经常有免费 quota，可以先在 fal.ai 试用再决定主线。国内用户做 K12 场景选国内版，发票 / 合规 / 客服都好。

Q3Wan 2.2 真的能本地跑得动吗？VRAM 要多大？+

能。但要分变种看：

  • Wan 2.2 5B（FP8 量化）：8-10GB VRAM，RTX 3060 / 4060 都跑得动，480p I2V 质量足够日常用
  • Wan 2.2 14B（FP8）：16-24GB VRAM 跑 480p，需要 RTX 4090（24GB）或 A100；720p 要 40-80GB
  • Wan 2.2 14B GGUF Q4 + T5 CPU offload：6-8GB VRAM 也能跑 480p，但慢（10-15 分钟/段）

社区项目 Wan2GP 专门为消费级 GPU 优化，文档齐全。建议先在 RTX 4090 上验证 workflow，量产时上 AutoDL A100 80GB（¥6/h）。

Q4ElevenLabs 给儿童绘本配音怎么调最自然？+

关键 3 个设置：

  • 声音选择：v3 库里搜 "warm" / "storyteller" / "child-friendly"，挑 30-50 岁女声（母亲式朗读最受儿童欢迎）；不要用「新闻播报」类干声
  • Stability 设置：30-40%（让情绪起伏，不要 70%+ 那种「机械稳定」）
  • v3 audio tags：在 prompt 里加 [whispering] / [excited] / [sad] / [curious] / [surprised] —— v3 才支持，v2 不识别

多角色对话：用 v3 dialogue mode，每个角色独立 voice ID。绘本旁白用一个柔和女声，Caterpillar 用稍年轻 + 好奇的声音，妈妈角色用更成熟的声音。

速度：6 岁以下 0.85x，让小孩跟得上每个词。

Q5PDF 抽页失败 / 文字提取不全怎么办？+

分两种情况：

① 原生 PDF（带文本层）：PyMuPDF4LLM 应该一击成功。如果失败，通常是 PDF 字体嵌入异常 —— 试 pdf2image 转图后用 Tesseract / Surya OCR 兜底。

② 扫描版绘本（图片型 PDF）：PyMuPDF 抽不到文字，必须 OCR。2026 年最佳选择 pdf-craft（专为扫描书设计）或 Marker（多格式 + GPU 加速 OCR）。绘本插画 + 文字混排场景，Marker 把它们分得最干净。

低龄绘本：经常每页只有 1-2 句话 + 大幅插画。这种情况可以直接人工录入文字到 JSON，省 OCR 麻烦（30 页绘本人工 5 分钟搞定）。

Q6角色一致性真做出来效果到底咋样？会不会还是漂？+

2026 年 5 月真实水平：

  • 可灵 2.1 Multi-Element Reference：30 页绘本里同一只 Caterpillar 能保持肉眼看 90%+ 一致，偶尔某一段身体段数变化或者颜色饱和度差异。学生不会出戏。
  • Vidu 2.0 Multi-Subject：多主体场景（角色 + 关键物体）一致性 80-90%，主角识别准但物体细节偶尔偏。
  • 开源 IP-Adapter + LoRA 三件套：训得好的话 95%+，是 2026 年最强方案，但门槛高 + 工时长。
  • 纯 prompt 描述（无 reference）：50% 以下，明显漂移，不能用。

实操建议：第一本 demo 用可灵 Multi-Element 跑出来，对前 3 个学生做盲测，问"你觉得这是同一只虫子吗？"——如果他们答"是"，就过关。

Q7做一本 30 页绘本到底要花多久？+

三种路线时间对比：

  • 路线 A 商业 API：脚本启动到 mp4 完成 15-30 分钟（API 并发跑）
  • 路线 B 开源 Wan 2.2 14B @ A100：2-4 小时（每段 5-15 分钟 × 30 段）
  • 路线 C 伪动画：3-5 分钟（Ken Burns + AnimateDiff 都是秒级）

这里讲的是纯生成时间，不算「人工选 prompt / 调风格 / 改字幕」时间。50 学员阶段允许人工干预，单本含人工大概 1-2 小时（含审核），可量产到日产 3-5 本。

Q8国产 TTS 跟 ElevenLabs 真实差距有多大？+

差距在缩小。2026 年 5 月真实评测：

  • 纯英语朗读：ElevenLabs v3 仍然小幅领先，自然度 + 情绪起伏 + 多角色能力领先 5-10%
  • 中文 / 中英双语：MiniMax Speech-02 HD 略胜 ElevenLabs（中文音色更准、更自然）
  • 儿童绘本场景：MiniMax 的「情绪 preset」+ interjection tag 在儿童场景里很实用
  • 价格：MiniMax $0.10/千字 ≈ 是 ElevenLabs v3 1/2 价格

结论：国际学校英语绘本场景 ElevenLabs 略优；中英双语 + 国内场景 MiniMax 更适合。可以两家都开账号，按本书需求切换。

Q9为什么不直接用抖音 / 快手散户用的工具就行了？+

能用，但天花板低。抖音 / 快手个人创作者用可灵 / 即梦官方网页端 + 剪映拼接，非自动化，每本需要人工 1-3 小时干预，规模化困难。

半米的工程化目标：

  • 无人值守批量出片（一晚上跑 20 本）
  • 统一风格 / 统一角色（学生对系列绘本视觉熟悉）
  • 字幕单词级时间戳（教学功能基础）
  • 结构化元数据（哪个词在哪一秒，便于词汇追踪）
  • 和半米现有词汇系统 / 学习路径打通

这些都是散户手工剪辑做不到的，是半米的工程护城河。

Q10Wan 2.2 / LTX-2 / Hunyuan 哪个开源最适合绘本？+

2026 年 5 月最佳组合：Wan 2.2 14B（主力）+ LTX-2 / LTX-Video 2B（快速迭代）。

  • Wan 2.2 14B：Apache 2.0 商用 + 中文社区活跃 + 480p / 720p 灵活 + ComfyUI 节点齐全。绘本场景质量最稳。
  • LTX-Video 2B：实时（4090 上 30fps）+ 速度比 Wan 快 5-10 倍。调试 prompt / 调风格用它，确定后用 Wan 出最终成片。
  • LTX-2 22B（2026-01 发布）：原生 audio-video 同步生成，但 22B 参数本地 GPU 吃力，要 A100 起步。
  • HunyuanVideo：VRAM 60GB+ 太重，不推荐。
  • CogVideoX 1.5：备份，特殊分辨率（垂直 9:16）时用。
Q11Sora 已经停服那 OpenAI 是不是退出视频生成了？+

Q12半米要不要自己训一个「绘本风」专属模型？+

50 学员 / 100 本阶段：不要。

原因：

  • 训练一个 fine-tune 模型至少 ¥50,000 算力 + 1-2 人月数据准备
  • 50 学员阶段验证的是「学生喜不喜欢」「教学有没有效」，不是「模型多酷」
  • 可灵 / Wan 2.2 已经能产出多种风格（卡通 / 写实 / 水彩 / 浮世绘），prompt 工程可覆盖 80% 需求
