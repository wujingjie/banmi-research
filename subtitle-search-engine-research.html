01给小白的一句话方案 + 决策树▼

一句话方案：用 ffmpeg 把视频里的内嵌字幕抠出来 → 用 pysubs2 解析成 (起始时间, 结束时间, 文字) → 入 SQLite 的 FTS5 全文索引表 → FastAPI 写个搜索接口 → 单 HTML 页面搜索框 + 结果列表 + HTML5 <video> 跳秒。全套加起来 300 行代码，一个 Python 文件加一个 HTML 文件就完事。

▶ 已经在跑 Jellyfin / Emby NAS？

▶ 想搜"自然语言"（"小熊见妈妈那段"）而不是精确关键词？

👉 阿杰这种情况（个人用、有 Mac M 系列、库估计十万行级别、80% 中英文需求）—— 直接 SQLite FTS5 路线，第 11 章 MVP 5 步那个 200 行脚本就是终态。别 over-engineer。

02为什么这事 2026 年可以自己做（5 年前不行）▼

5 年前要做这个需要一个小团队 + 一台 GPU 服务器，今天一个人一周晚上 + 一台 Mac 就行。变化来自 4 个真实的技术拐点：

变化 1：Whisper 把 ASR 打到白菜价

2022 年 OpenAI 开源 Whisper，2024 年 whisper.cpp 在 Mac M 系列上跑 large-v3-turbo 模型已经能做到 10× 实时速度（M2 Pro 实测：60 秒音频转录约 2.8 秒），Metal GPU 加速 + flash attention 一起开。意味着没字幕的视频（你随便录的 YouTube、家庭录像、播客）现在也能自动生成字幕，且不用花一分钱 API 费用、不传文件出本机。

📌 打个比方：5 年前 Whisper 需要一台 RTX 3090 ($1500) 跑十几分钟才能转 1 小时音频，今天你 MacBook Air M2 ($800) 跑 6 分钟就完事。差不多是 "云专属能力下放成本机零负担"。

变化 2：SQLite FTS5 + 中文分词扩展白嫖级别成熟

SQLite 原生的 FTS5 全文索引模块默认对中文按字切分（"开心"会被切成"开"+"心"两个独立 token，搜"开心"匹配不到"很开心"）。但 wangfenjin/simple 这个开源 SQLite tokenizer 把 jieba 中文分词 + 拼音搜索都做进去了，编译成一个 .so 文件加载即可，5w 行字幕响应 <10ms。Flutter / HarmonyOS 各种平台都有打包好的版本。

变化 3：FastAPI / HTMX 把 Web 开发砍到一个文件

2026 年的 Python Web 后端 = pip install fastapi + uvicorn main:app，两个命令开服务，30 行代码就有自动生成的 OpenAPI 文档。前端不写 React 不写 Vue —— 单 HTML 文件 + 一点 vanilla JS / Alpine.js 就够搜索框 + 结果列表了。不需要打包、不需要 webpack、不需要 npm install 等十分钟。

变化 4：yt-dlp 把 YouTube 字幕拿手到擒来

YouTube 自动生成的字幕在 2023 年之后质量已经接近人工字幕，yt-dlp 一个命令 yt-dlp --write-subs --sub-lang en,zh-Hans --write-auto-subs URL 就把字幕 + 视频一起拿下来，连 json3 时间戳格式都给你。

03完整技术路径（8 步全景图）▼

从"你电脑上一堆 .mp4 文件"到"在浏览器搜词点跳秒播放"，端到端 8 步。每步独立可跑、可调试、可换实现。

1

扫媒体库

Python 一个 pathlib.Path("/Volumes/Movies").rglob("*.mkv") 把所有视频文件捞出来。再用 ffprobe（ffmpeg 自带）查每个文件里有没有内嵌字幕、什么语言、什么编码。打比方：像图书管理员第一次进库房，先列一张总清单。
pathlib ffprobe guessit（提取片名）
2

拿字幕

三种来源：(a) 内嵌字幕用 ffmpeg -i file.mkv -map 0:s:0 out.srt 抠出来；(b) 同目录外挂的 .srt/.ass/.vtt 直接读；(c) 啥都没有 → OpenSubtitles API 下载 / yt-dlp 拿 YouTube 字幕 / Whisper 本地转录。
ffmpeg opensubtitles-api yt-dlp whisper.cpp
3

解析 + 规范化

SRT/ASS/VTT 格式杂、编码乱（Windows 系统下来的字幕经常 GBK 不是 UTF-8）。统一用 pysubs2 解析：自动认 6 种格式 + 处理 BOM + 时间戳转毫秒 + 去 ASS 样式标签。打比方：把各种规格的书都换成统一的标准开本。
pysubs2 webvtt-py（备用） chardet（编码检测）
4

双语对齐（可选）

如果你有英文 + 中文两个字幕文件（人人字幕组那种），按时间戳 ± 200ms 对齐成一行：(start, end, text_en, text_zh)。如果只有英文，可用 Helsinki-NLP Opus-MT / NLLB 本地翻译生成中文。打比方：左眼看英文、右眼看中文，让两个时间轴对齐。
opus-mt-en-zh NLLB-200
5

入索引

SQLite FTS5 创建虚拟表 CREATE VIRTUAL TABLE subtitles USING fts5(text_en, text_zh, library, video_path, start_ms, ...)。每行字幕一条记录。中文字段过一遍 jieba 分词后用空格连接再入表（让 FTS5 默认 unicode61 tokenizer 也能按词切）。打比方：图书馆建卡片目录，每个词都做一张索引卡指向原书页码。
SQLite FTS5 jieba wangfenjin/simple
6

搜索 API

FastAPI 写个 GET /search?q=happy&library=movies 端点。SQL 一句话：SELECT video_path, start_ms, text_en, text_zh, snippet(subtitles, 0, '<mark>', '</mark>', '...', 30) FROM subtitles WHERE subtitles MATCH ? AND library = ? ORDER BY bm25(subtitles) LIMIT 50。BM25 是 FTS5 自带的排名算法，自动返回相关性最强的结果在前。
FastAPI uvicorn BM25
7

搜索 UI + 跳秒播放

单 HTML 文件：搜索框 + 调 API + 渲染结果卡片 + 卡片里嵌 <video src="/file/..." controls>。点结果 → JS 执行 video.currentTime = startMs/1000; video.play();。打比方：搜索是图书馆电脑、点结果就像找到那本书的那一页直接打开。
HTML5 video vanilla JS Alpine.js（可选）
8

增量更新

用 watchdog 监听媒体目录，新文件加进来 → 自动入库；文件被删 → 自动从数据库清理。或者最简单：crontab 每天凌晨跑一次全量扫描，重复文件用 SHA-256 hash 去重。
watchdog crontab

👉 这 8 步不是必须全做。MVP 跑通只要步骤 1-3-5-6-7 五步，4（双语）和 8（增量）是 V2 升级项。第 11 章给具体命令。

04字幕获取方案大全▼

字幕来源决定了你最后能搜到多少有用台词。分 5 种渠道，按优先级：

渠道 1：从视频文件内部抠（最稳）

MKV / MP4 / WebM 容器经常内嵌多语字幕轨。ffmpeg 一句话搞定：

# 列出文件里的字幕轨
ffprobe -v error -select_streams s -show_entries stream=index,codec_name:stream_tags=language input.mkv

# 抠第一条字幕轨
ffmpeg -i input.mkv -map 0:s:0 -c:s srt output.srt

# 按语言抠（英文）
ffmpeg -i input.mkv -map "0:m:language:eng" -c:s srt output.srt

⚠️ 坑：有些字幕是图像格式（PGS / VobSub），不是文字，ffmpeg 抠不出 srt，要用 OCR（vobsub2srt）。蓝光 rip 经常遇到。

渠道 2：外挂字幕文件

同目录下 电影名.srt / 电影名.ass / 电影名.zh.srt / 电影名.en.srt，直接读。命名约定：{stem}.{lang}.srt 是 Jellyfin / Plex 都认的标准格式。

渠道 3：OpenSubtitles API（国外片）

2026 年现状：OpenSubtitles.com 新版 API 免费账号每天可下载 20 个字幕，未注册账号 5 个/天，请求频率 1 次/秒。Bazarr 这种自动化字幕下载工具就靠它。10M+ 字幕数据库。

注册账号 → 拿 API key → 调 POST /api/v1/login 拿 token → 调 GET /api/v1/subtitles?query=...。Python 有官方 SDK。

渠道 6：YouTube 字幕

# 拿英文 + 简体中文，包含自动生成的
yt-dlp --write-subs --sub-langs "en,zh-Hans,zh-CN" --write-auto-subs \
       --sub-format "srt/vtt/best" --skip-download \
       "https://www.youtube.com/watch?v=..."

# 拿整个频道
yt-dlp --write-subs --sub-langs "en,zh-Hans" --download-archive done.txt \
       "https://www.youtube.com/@channelname"

⚠️ 坑：YouTube 自动字幕只在 json3 格式才有词级时间戳，VTT 格式只有句级。如果你想做"点单词跳秒"级别精度，要 --sub-format json3 然后自己解析。

双语字幕对齐策略

你已经有英文 .srt + 中文 .srt，怎么对齐成一行？

  • 时间戳近邻匹配：英文行 (start=10000, end=12000) 找中文行里 start 距 10000 最近的（±200ms 容忍）。简单但有时错位。
  • 动态规划对齐：把所有英文行和所有中文行做最优一一对应，类似 DNA 序列比对算法。Python 有 biopython 或自己写。
  • 同一字幕源里双轨：人人字幕组的 ASS 字幕经常英文 + 中文双轨在同一行，pysubs2 解析后能看到 style 字段区分。

05搜索引擎选型（5 种横评）▼

打比方：搜索引擎就是图书馆的检索系统。你有几种选：抽屉式卡片柜（SQLite FTS5）、电子查询机（Meilisearch）、整套图书馆数据库（Elasticsearch）。个人用强烈推荐第一种：单文件、零配置、断电不丢。

🥇 小白默认：SQLite FTS5

为什么选它：

  • 单文件数据库：整个搜索引擎 = 一个 subtitles.db 文件，硬盘放哪都行，没有 daemon 进程要维护，断电恢复完美。
  • Python 标准库自带：import sqlite3，不用 pip install 任何东西。
  • FTS5 已经够强：BM25 排名 + snippet 高亮 + phrase search（"机 器 学 习"按精确短语搜）+ NEAR 距离运算符。
  • 5w-50w 行字幕完全够用。500w 行（一辈子电影都看不完）也才慢一点。

关键命令：

-- 建表（en + zh 双列、其他属性 UNINDEXED 节省空间）
CREATE VIRTUAL TABLE subs USING fts5(
  text_en,
  text_zh,
  video_path UNINDEXED,
  library UNINDEXED,
  start_ms UNINDEXED,
  end_ms UNINDEXED,
  tokenize = 'unicode61 remove_diacritics 2'
);

-- 搜索（自动 BM25 排序 + 高亮 + 截取片段）
SELECT
  video_path, start_ms,
  highlight(subs, 0, '', '') AS hl_en,
  highlight(subs, 1, '', '') AS hl_zh,
  snippet(subs, 0, '', '', '...', 20) AS preview,
  bm25(subs) AS score
FROM subs
WHERE subs MATCH 'happy OR glad' AND library = 'movies'
ORDER BY bm25(subs)
LIMIT 50;

🥈 中量级：Meilisearch

什么时候换：库膨胀到 50w 行以上，或者你想要这些 SQLite 给不了的：

  • typo tolerance（搜 "recieve" 也能命中 "receive"）开箱即用
  • faceted search（左侧 sidebar 显示"电影 (1234) / 纪录片 (456) / YouTube (789)"自动计数）
  • 实时索引：新文档秒级可搜，不用重建索引
  • 1.15 起原生中文：Charabia tokenizer 升级了中文分词

部署：

# Docker 一行起服务
docker run -p 7700:7700 -v $(pwd)/meili_data:/meili_data \
  getmeili/meilisearch:v1.15

# Python SDK
pip install meilisearch

🥉 高级：Typesense / Elasticsearch / Postgres

  • Typesense：和 Meilisearch 很像，C++ 性能稍强，集群部署更顺，但社区文档少。需要 10K+ QPS 才考虑。
  • Elasticsearch：小白别碰，2GB+ RAM 起步、Java 生态、配置复杂。除非你已经在公司用 ELK 才有意义。
  • Postgres FTS + zhparser：你已经有 Postgres 数据库的话最省事。zhparser 用 SCWS 分词，比 jieba 弱一点但够用。

👉 阿杰的路径：先 SQLite FTS5 跑 3 个月，等真的库膨胀到 50w 行才迁 Meilisearch。这两个引擎的数据 schema 几乎一致，迁移就是写个 100 行 Python 把 SQLite 数据 dump 成 JSON 灌到 Meili，半天工作量。

06搜索 UI 三种形态▼

形态 A：简单 Web UI（强推）

FastAPI 后端 + 单 HTML 页面前端。整个东西就 2 个文件，uvicorn main:app 一行起服务，浏览器打开 localhost:8000 用。

  • 优点：跨平台（Mac / Linux / Windows / iPad）、改起来一秒生效、零安装（书签即用）、可远程访问（家里 NAS 上跑、外面手机访问）
  • 缺点：要后台跑 Python 进程，断电后要手动启动（解决：launchctl Mac 开机启动 / systemd Linux 服务）

👉 2026 年实测对比：Tauri 比 Electron bundle 小 25×、RAM 少 75%、启动快 4×。Tauri v2 的 JS API 已经覆盖 90% 场景几乎不用写 Rust 代码。但如果你的搜索 Web UI 已经能用，桌面 app 是锦上添花、不是必须的。

形态 C：集成进 Jellyfin / Plex 插件

调研结论：基本不可行 / 不值得。

  • Jellyfin 现在的字幕插件（OpenSubtitles plugin / Bazarr plugin）只解决字幕下载，不做搜词跳秒。
  • Jellyfin 服务端用 C# .NET 写、插件 API 没有公开的"加自定义搜索页"接口，社区只有零星尝试。
  • 开发成本极高（学 .NET 插件机制 + Jellyfin 内部 API）、维护成本极高（Jellyfin 更新经常 break 插件）。

👉 更聪明的做法：你的搜索 Web UI 完全独立运行（localhost:8000），结果里直接给一个"在 Jellyfin 中打开"的按钮，跳转到 http://jellyfin/web/index.html#!/details?id={ItemId}&startPosition={ticks}。利用 Jellyfin 的深链接而不是写插件。

07播放层方案（点了能播）▼

搜到结果了，怎么"点一下跳到那一秒开始播放"？4 种方案对比：

方案 A：HTML5 <video> 跳秒（强推）

浏览器内置 video 标签，FastAPI 提供文件 + 支持 Range 请求（HTTP 206 Partial Content），JS 一行跳秒：

// 前端
const video = document.getElementById('player');
video.src = `/file?path=${encodeURIComponent(item.video_path)}`;
video.currentTime = item.start_ms / 1000;
video.play();

# 后端：FastAPI 支持 Range 请求
from fastapi import FastAPI, Request
from fastapi.responses import StreamingResponse
import os, re

@app.get("/file")
async def stream_video(path: str, request: Request):
    file_size = os.path.getsize(path)
    range_header = request.headers.get('range')
    if not range_header:
        return StreamingResponse(open(path, "rb"), media_type="video/mp4")
    # 解析 Range: bytes=0-1023
    start, end = re.match(r"bytes=(\d+)-(\d*)", range_header).groups()
    start = int(start); end = int(end) if end else file_size - 1
    def iter_chunk():
        with open(path, "rb") as f:
            f.seek(start)
            yield f.read(end - start + 1)
    return StreamingResponse(iter_chunk(), status_code=206, headers={
        "Content-Range": f"bytes {start}-{end}/{file_size}",
        "Accept-Ranges": "bytes",
    })

✅ 优点：零依赖、跨平台、跳秒丝滑、能在 iPad / 手机浏览器跑。
⚠️ 坑：MKV 容器浏览器原生不支持（要 webm 或 mp4），可以用 ffmpeg -c copy -movflags faststart input.mkv output.mp4 转封装（不重编码，秒完事）。或者预生成 5-15s 短片段。

方案 B：调起本地播放器（mpv / VLC / IINA）

体验最爽（mpv 字幕渲染漂亮、键盘快捷键）、但需要本机装播放器 + 用 IPC 控制：

mpv JSON IPC

# 启动 mpv 监听 IPC socket

# 从 Python 控制跳秒
import socket, json

sock.connect("/tmp/mpvsocket")
sock.sendall(json.dumps({"command": ["seek", 90, "absolute"]}).encode() + b"\n")

VLC HTTP 接口

# 启动 VLC 开 HTTP 接口（端口 8080，密码 mypass）
vlc --extraintf http --http-password mypass

# Python 跳秒
import requests
requests.get("http://localhost:8080/requests/status.xml",
             params={"command": "seek", "val": "90"},
             auth=("", "mypass"))

✅ 优点：mpv/VLC 字幕渲染完美、支持任何视频格式、本地全速播放。
⚠️ 坑：mpv 每次播新文件要重启进程或 loadfile 命令；VLC HTTP 接口文档老旧、API 不稳；移动端不可用。

方案 C：ffmpeg 实时切片

搜到一条字幕 (start=90s, end=92s) → 后端实时切一段 15s 短 mp4 返回浏览器：

ffmpeg -ss 88 -i input.mkv -t 15 -c copy -movflags faststart out.mp4

✅ 优点：浏览器跳秒到大文件中间会缓冲很久，切片秒开。
⚠️ 坑：需要服务器算力（FFmpeg 进程开销）、关键帧对齐问题（-ss 在 -i 前是粗定位、之后是精确定位）。

方案 D：Jellyfin API 跳秒

已经在跑 Jellyfin？直接调它的播放 API：

GET http://jellyfin:8096/Videos/{ItemId}/main.m3u8?api_key=...&StartTimeTicks=900000000

# StartTimeTicks = seconds * 10^7（.NET ticks）

或者前端用 Jellyfin 的 web/index.html#!/details?id={id}&startPosition={ticks} 深链接。

08难点专题：10 个真实坑 + 解决方案▼

坑 1：中文搜索完全不准

症状：搜 "开心" 匹配不到 "很开心"。
原因：SQLite FTS5 默认 unicode61 tokenizer 对中文按字符切分，每个汉字独立一个 token，匹配规则是"完整 token 序列"。
方案：(a) 入库前用 jieba 分词把"我很开心"切成"我 很 开心"用空格连接再入表；(b) 用 wangfenjin/simple 这个 SQLite 扩展，提供 jieba_query() 函数自动分词，编译 .so 后 SELECT load_extension('libsimple')。

坑 2：双语字幕时间戳对不齐

症状：英文字幕第 5 行 (10s-12s) 对应中文字幕第 4 行 (9.8s-12.1s)，按行号匹配会错位。
方案：用时间戳的中点 (start+end)/2 做匹配键，找最近邻（容忍 ±500ms）。如果错位严重，用动态规划做最优对齐（成本函数 = |时间差|+长度比）。

坑 3：Whisper 时间戳不准

症状：转出来的字幕第一行说"Hello"，但显示 (3s-6s)，实际声音 (2.5s-3.2s)。
原因：Whisper 的时间戳是段级 (segment-level)，每段 ~30s，段内时间戳是粗估，平均误差 200-500ms。
方案：用 WhisperX 跑一遍 wav2vec2 forced alignment，得到 word-level 时间戳，精度 <100ms。或者 faster-whisper 的 word_timestamps=True 也有 word 级时间戳（精度稍差）。

坑 4：YouTube 自动字幕格式特殊

症状：yt-dlp 下载的 YouTube 自动字幕是 .vtt 文件，看起来一行一行的，但每行 cue 之间有重叠（前一行的尾部 = 后一行的开头），用 webvtt-py 解析会得到重复内容。
方案：用 --sub-format json3 拿原始 json3 数据，解析时按 word-level timestamps 重组，每个词只入一次。或者用 --convert-subs srt 让 yt-dlp 帮你去重转 srt。

坑 5：搜错单词搜不到

症状：搜 "recieve" 没结果（拼错了），但其实想找 "receive"。
方案：(a) Meilisearch 自带 typo tolerance，前缀 1 个 typo / 整词 2 个 typo 默认就有；(b) SQLite FTS5 自带没有，可叠 spellfix1 扩展或自己存一份 3-gram 索引；(c) 不想折腾？前端搜索框旁加个"建议"按钮调拼写检查 API（pyspellchecker）。

坑 6：同义词扩展（"happy" 命中 "glad"）

方案三档：

  • 简易：人肉写一份 {"happy": ["glad", "joyful", "cheerful"]} 字典，查询时把同义词 OR 起来。10 分钟搞定。
  • 开源：用 WordNet（Python nltk.corpus.wordnet）自动扩展，覆盖英文 15w+ 同义词组。
  • 语义级：用 sentence-transformers embedding，搜 "happy" → 找 cosine similarity 高的字幕，能命中 "I love this"（情感相近但词不同）。V3 升级项。

坑 7：字幕格式杂乱（ASS 标签 / 编码 / BOM）

症状：ASS 字幕里 {\an8\b1}你好 这种样式标签会污染搜索；Windows 系统传过来的 srt 经常 GBK 编码 + BOM 头。
方案：pysubs2.load(path, encoding="utf-8") 自动处理大部分情况，line.plaintext 属性自动剥掉 ASS 标签。编码检测用 chardet 库先猜再读。

坑 8：Whisper 转 100 小时视频太慢

症状：纪录片库 100 小时，Whisper-large-v3 跑要 10 小时。
方案：(a) 用 large-v3-turbo + Mac M2 Metal 加速，10× 实时 → 100 小时只要 10 小时（隔夜跑）；(b) faster-whisper int8 量化再快 4×；(c) 真没耐心 → 租 RunPod / vast.ai 一台 RTX 4090，$0.4/h，2 小时跑完只花 ¥6。

坑 9：媒体文件命名乱（"The.Movie.2019.1080p.BluRay.x264-RARBG.mkv"）

方案：用 guessit 库一行提取干净的片名 + 年份：

import guessit
info = guessit.guessit("The.Movie.2019.1080p.BluRay.x264-RARBG.mkv")
# {'title': 'The Movie', 'year': 2019, 'screen_size': '1080p', 'source': 'BluRay', ...}

拿到干净 title + year → 调 TMDB API 抓海报 / 中文名 / 类型标签 → 入库丰富元数据。

坑 10：浏览器跳秒到 2GB 文件中间卡顿

症状：搜到一条字幕在 1h30m 处，video.currentTime = 5400 后浏览器要重新下载 + buffer，等 5-10 秒。
方案：(a) 预转封装：ffmpeg -i src.mkv -c copy -movflags +faststart out.mp4，moov atom 移到文件头，浏览器秒跳；(b) HLS 切片：ffmpeg -i src.mp4 -codec copy -f hls -hls_time 10 -hls_list_size 0 out.m3u8 切成 10s 一片段，video.js / hls.js 播放；(c) 实时 ffmpeg 切片：见 Ch7 方案 C。

额外坑 11：图像字幕（PGS / VobSub）

蓝光 rip 经常字幕是 PNG 图片不是文字，ffmpeg 抠出来是 .sup 文件没法搜。方案：用 Subtitle Edit 或 vobsub2srt 做 OCR 转文字 srt。2026 年首选：直接用 Whisper 转录音频生成新字幕（精度比图像 OCR 高、成本相近）。

额外坑 12：海量 jieba 进程启动慢

jieba 第一次 import 要加载 50MB 词典 1-2 秒。方案：用 jieba.initialize() 提前 warm up；或 paddle 模式更准但更慢；或换 pkuseg（更快、模型小）。

09AI vs 脚本职责分工▼

⚠️ 小白最常见的错觉：以为搭这个工具要"用 AI"。其实 90% 工作是确定性脚本，AI 只在 2 个地方真正需要（Whisper 转录 + 可选的语义搜索）。先看完这章再开工，能省一半冤枉路。

三层职责表

🤖 必须用 AI（不可替代）

  • Whisper ASR：没字幕的视频自动转录。这是这个项目唯一"小白真的需要 AI"的地方。本地跑 whisper.cpp 即可，不上云。

🟡 可选 AI（视需求开关）

  • 翻译生成第二语种：你只有英文字幕想要中文 → Helsinki-NLP Opus-MT / NLLB 本地翻译。
  • 语义检索：想搜 "小熊见妈妈那段" → sentence-transformers (all-MiniLM-L6-v2 22MB) 本地 embedding。
  • 同义词扩展：搜 "happy" 命中 "glad" → 如果 WordNet 字典法不够，再上 GPT API / embedding。
  • 说话人分离：标注每行字幕谁说的 → pyannote.audio / WhisperX 自带。高级用法。
  • 场景标签：每个 chunk 打 "对话/动作/转折" 标签 → 用本地 LLM (Qwen2.5-7B) 或 GPT。锦上添花。

🚫 绝对不用 AI（脚本完全够）

  • 扫目录、识别文件类型 → pathlib + 扩展名
  • 抽内嵌字幕 → ffmpeg -map 0:s:0
  • 外挂字幕配对 → 同名 stem 匹配
  • SRT/ASS/VTT 解析 → pysubs2
  • 时间戳规范化 → 毫秒整数运算
  • 入数据库 / SQL 查询 → SQLite
  • Web 后端 / API → FastAPI
  • HTML5 video 跳秒 → video.currentTime = ...
  • 文件监听增量更新 → watchdog
  • 中文分词 → jieba（基于词典 + HMM，不是神经网络）
  • 命名解析（片名年份） → guessit 规则匹配
  • BM25 排名 / TF-IDF → FTS5 内置算法
  • 编码检测 / 备份恢复 → chardet / 文件复制

👉 实操原则：MVP 阶段只用 Whisper 一项 AI（如果连这都不需要、字幕都现成可不用）。V2 再加翻译 / 同义词。V3 再加语义检索。不要一开始就堆 LLM、Embedding、RAG 三件套 —— 90% 场景关键词搜索已经够好。

import json
from pathlib import Path

ROOT = Path("/Volumes/Movies")
VIDEO_EXT = {".mp4", ".mkv", ".webm", ".mov", ".avi"}
SUB_EXT = {".srt", ".ass", ".vtt", ".ssa"}

results = []
for video in ROOT.rglob("*"):
    if video.suffix.lower() not in VIDEO_EXT:
        continue
    # 找同名字幕
    subs = []
    for ext in SUB_EXT:
        for f in video.parent.glob(f"{video.stem}*{ext}"):
            subs.append(str(f))
    if subs:
        results.append({"video": str(video), "subs": subs})

print(json.dumps(results, ensure_ascii=False, indent=2))
print(f"✅ 找到 {len(results)} 个带字幕的视频", file=__import__('sys').stderr)

DAY 2 字幕解析 + 入 SQLite
2h ~100 行

写 ingest.py：读 library.json，每个字幕 pysubs2 解析，jieba 分中文，入 SQLite FTS5。

# ingest.py - 80 行
import json, sqlite3, pysubs2, jieba
from pathlib import Path

DB = "subsearch.db"
conn = sqlite3.connect(DB)
conn.execute("""
CREATE VIRTUAL TABLE IF NOT EXISTS subs USING fts5(
  text_en, text_zh,
  video_path UNINDEXED, library UNINDEXED,
  start_ms UNINDEXED, end_ms UNINDEXED,
  tokenize = 'unicode61 remove_diacritics 2'
);
""")

def tokenize_zh(text):
    """中文用 jieba 分词，加空格让 FTS5 切开"""
    if not text: return ""
    return " ".join(jieba.cut(text))

def detect_library(path):
    """简易分库：路径含 'Documentaries' → 纪录片"""
    p = path.lower()
    if "documentar" in p: return "documentaries"
    if "anime" in p or "动画" in p: return "anime"
    if "youtube" in p: return "youtube"
    return "movies"

def is_chinese(text):
    return any('一' <= c <= '鿿' for c in text)

with open("library.json") as f:
    items = json.load(f)

for item in items:
    video = item["video"]
    lib = detect_library(video)
    for sub_path in item["subs"]:
        try:
            subs = pysubs2.load(sub_path, encoding="utf-8")
        except UnicodeDecodeError:
            subs = pysubs2.load(sub_path, encoding="gbk")
        for line in subs:
            text = line.plaintext.strip()
            if not text: continue
            if is_chinese(text):
                conn.execute(
                    "INSERT INTO subs VALUES (?, ?, ?, ?, ?, ?)",
                    ("", tokenize_zh(text), video, lib, int(line.start), int(line.end))
                )
            else:
                conn.execute(
                    "INSERT INTO subs VALUES (?, ?, ?, ?, ?, ?)",
                    (text, "", video, lib, int(line.start), int(line.end))
                )
    print(f"✓ {video}")

conn.commit()
print(f"\n📊 共 {conn.execute('SELECT COUNT(*) FROM subs').fetchone()[0]} 行入库")

DAY 3 FastAPI 搜索接口

写 server.py：搜索端点 + 视频流（支持 Range）。

# server.py - 80 行
import sqlite3, os, re, jieba
from fastapi import FastAPI, Request, HTTPException
from fastapi.responses import StreamingResponse, FileResponse
from fastapi.staticfiles import StaticFiles

app = FastAPI()
DB = "subsearch.db"

def search(q, library=None, limit=50):
    conn = sqlite3.connect(DB)
    conn.row_factory = sqlite3.Row
    q_zh = " ".join(jieba.cut(q)) if any('一' <= c <= '鿿' for c in q) else q
    # 同时搜英文字段和中文字段
    fts_query = f'"{q}" OR "{q_zh}"'
    where = "subs MATCH ?"
    params = [fts_query]
    if library:
        where += " AND library = ?"
        params.append(library)
    sql = f"""
      SELECT video_path, library, start_ms, end_ms,
             snippet(subs, 0, '', '', '...', 15) as hl_en,
             snippet(subs, 1, '', '', '...', 15) as hl_zh,
             bm25(subs) as score
      FROM subs WHERE {where}
      ORDER BY bm25(subs) LIMIT ?
    """
    params.append(limit)
    return [dict(r) for r in conn.execute(sql, params).fetchall()]

@app.get("/search")
def api_search(q: str, library: str = None):
    return {"q": q, "results": search(q, library)}

@app.get("/file")
def stream(path: str, request: Request):
    if not os.path.exists(path):
        raise HTTPException(404)
    file_size = os.path.getsize(path)
    range_h = request.headers.get('range')
    if not range_h:
        return FileResponse(path)
    m = re.match(r"bytes=(\d+)-(\d*)", range_h)
    start = int(m.group(1)); end = int(m.group(2)) if m.group(2) else file_size - 1
    length = end - start + 1
    def gen():
        with open(path, "rb") as f:
            f.seek(start); yield f.read(length)
    return StreamingResponse(gen(), status_code=206, headers={
        "Content-Range": f"bytes {start}-{end}/{file_size}",
        "Accept-Ranges": "bytes",
        "Content-Length": str(length),
    }, media_type="video/mp4")

app.mount("/static", StaticFiles(directory="static"), name="static")

# subsearch.py - 90 行端到端
import sqlite3, jieba, pysubs2, os, re
from pathlib import Path
from fastapi import FastAPI, Request, HTTPException
from fastapi.responses import StreamingResponse, HTMLResponse

DB = "subsearch.db"
ROOT = Path.home() / "Movies"

# ---------- 1. 建库 ----------
def init_db():
    conn = sqlite3.connect(DB)
    conn.execute("""CREATE VIRTUAL TABLE IF NOT EXISTS subs USING fts5(
      text, video_path UNINDEXED, start_ms UNINDEXED, end_ms UNINDEXED,
      tokenize='unicode61 remove_diacritics 2')""")
    return conn

# ---------- 2. 入库 ----------
def ingest():
    conn = init_db()
    conn.execute("DELETE FROM subs")
    for srt in ROOT.rglob("*.srt"):
        video = next((srt.with_suffix(e) for e in [".mp4",".mkv",".webm"] if srt.with_suffix(e).exists()), None)
        if not video: continue
        try: subs = pysubs2.load(str(srt), encoding="utf-8")
        except: subs = pysubs2.load(str(srt), encoding="gbk")
        for line in subs:
            t = line.plaintext.strip()
            if not t: continue
            # 中文加 jieba 分词
            if any('一' <= c <= '鿿' for c in t):
                t = " ".join(jieba.cut(t)) + " " + t
            conn.execute("INSERT INTO subs VALUES (?,?,?,?)", (t, str(video), int(line.start), int(line.end)))
    conn.commit()
    print(f"✅ 入库 {conn.execute('SELECT COUNT(*) FROM subs').fetchone()[0]} 行")

    q_jieba = " ".join(jieba.cut(q)) if any('一'<=c<='鿿' for c in q) else q
    rows = conn.execute(
        "SELECT video_path, start_ms, snippet(subs,0,'','','...',15) "
        "FROM subs WHERE subs MATCH ? ORDER BY bm25(subs) LIMIT 30",
        (f'"{q}" OR "{q_jieba}"',)).fetchall()
    return [{"path": r[0], "ms": r[1], "text": r[2]} for r in rows]

@app.get("/file")
def stream(path: str, request: Request):
    if not os.path.exists(path): raise HTTPException(404)
    size = os.path.getsize(path)
    rh = request.headers.get('range')
    if not rh:
        with open(path, "rb") as f: data = f.read()
        return StreamingResponse(iter([data]), media_type="video/mp4")
    m = re.match(r"bytes=(\d+)-(\d*)", rh)
    s, e = int(m.group(1)), int(m.group(2) or size-1)
    def gen():
        with open(path,"rb") as f: f.seek(s); yield f.read(e-s+1)
    return StreamingResponse(gen(), status_code=206, headers={
        "Content-Range": f"bytes {s}-{e}/{size}", "Accept-Ranges": "bytes",
        "Content-Length": str(e-s+1)}, media_type="video/mp4")

if __name__ == "__main__":
    import sys
    if len(sys.argv) > 1 and sys.argv[1] == "ingest":
        ingest()
    else:
        import uvicorn
        uvicorn.run(app, host="0.0.0.0", port=8000)

Q我有 2TB 电影库，SQLite 够吗？会不会爆？+
够。2TB 视频内容 ≠ 2TB 字幕数据 — 字幕本身体积极小（一部 2 小时电影双语字幕通常 <200KB），2TB 库的字幕总量大概 100-300MB；FTS5 索引后膨胀 1-2 倍，整个 subsearch.db 文件最多 500MB。SQLite 单库官方支持 281TB，距离爆远着。性能上 100w 行内查询 <50ms 体感无延迟。
QWhisper 在 Mac M1 / M2 / M3 上真跑得动吗？+
绝对跑得动。whisper.cpp + Metal GPU 加速在 M1 起步机上 large-v3 大约 5× 实时（1 小时音频 12 分钟转完），M2 Pro 用 large-v3-turbo q5_0 量化模型 + flash attention 实测 10× 实时（1 小时音频 6 分钟）。RAM 占用 2-4GB。不挑机型、M1 Air 都 OK。模型文件 750MB 一次下载永久能用。
Q中文搜索不准（搜"开心"匹配不到"很开心"）怎么办？+
入库时用 jieba 把中文文本分词后用空格连接再入 FTS5："很开心" → "很 开心"。搜索时把查询也分词："开心" → "开心"，FTS5 按词匹配就能命中。第 11 章 ingest.py 已包含这个逻辑。更彻底的方案是装 wangfenjin/simple SQLite 扩展，它直接提供支持 jieba 的 FTS5 tokenizer。
Q双语字幕怎么对齐时间戳？英文是 10:00:05，中文是 10:00:04.8+
按中点时间戳近邻匹配 + ±500ms 容忍即可（人耳感知不到）。代码：mid_en = (start_en + end_en) / 2，在中文行里找 mid 距它最近的。如果整体偏移（中文字幕全部慢 500ms），先 pysubs2 的 subs.shift(ms=500) 整体移位再对齐。错位严重场景上动态规划做最优一对一匹配。
Q已经装了 Jellyfin，能不能集成进去？+
能但不建议写 Jellyfin 插件（C# / .NET / 维护成本极高）。聪明做法：搜索 UI 独立运行（localhost:8000），结果里给一个"在 Jellyfin 中打开"按钮，跳到 Jellyfin 的深链接 http://jellyfin/web/index.html#!/details?id={ItemId}&startPosition={ticks}。视频文件路径如果和 Jellyfin 媒体库一致，你的搜索 DB 里直接存 Jellyfin ItemId 就能跳。Jellyfin 的 API 拿 ItemId：GET /Items?searchTerm=...&Recursive=true。
Q能不能搜中文意思命中英文字幕？比如搜"开心"匹配 "I'm happy"+
三档方案：(1) 简易：维护一份关键词同义词字典 {"开心": ["happy", "glad", "joyful"]}，查询时把同义词 OR 起来。10 分钟搞定。(2) 翻译：用 Helsinki-NLP opus-mt-zh-en 把查询翻译成英文再搜索。100ms 延迟。(3) 语义：sentence-transformers 多语种模型（paraphrase-multilingual-MiniLM-L12-v2 117MB）做跨语言 embedding，"开心"和 "happy" 在同一向量空间。V3 升级项。
Q我是真小白，一周晚上真能搞定吗？+
能，但有前提：(a) 你会基本 Python（能跑 hello world）；(b) 会用命令行（cd / ls / brew install）；(c) 知道什么是 HTTP / JSON。如果这三点不熟，先花一个周末过遍 fastapi 官方 tutorial（2 小时）+ 跑通一个最简 SQLite demo（30 分钟）。MVP 5 步代码我已经粘进第 11 章和第 14 章，照着抄改路径就能跑，不需要从零写。
Q浏览器播 MKV 视频卡住怎么办？+
浏览器原生只稳定支持 mp4/webm，MKV 看运气（Chrome 部分支持、Safari 不行）。两种解决：(1) 转封装（推荐）：ffmpeg -i x.mkv -c copy -movflags faststart x.mp4 不重编码、几秒搞定、文件大小不变；(2) 切片：搜到结果只切 15s 的 mp4 片段返回，ffmpeg -ss $start -i x.mkv -t 15 -c copy out.mp4。不行就改用 mpv IPC 方案（第 7 章方案 B）。
Q家里有 NAS，怎么让手机也能搜？+
让 FastAPI 监听 0.0.0.0 而不是 localhost：uvicorn server:app --host 0.0.0.0 --port 8000。同 WiFi 下手机浏览器开 http://NAS局域网IP:8000。要远程访问（咖啡厅、出差）：(a) 装 Tailscale（最简单、零配置）；(b) 装 ZeroTier；(c) 自己开 frp / nginx + Let's Encrypt 证书（折腾）。建议 Tailscale，5 分钟搞定 + 免费。
QYouTube 视频不下载、只搜字幕、跳到 YouTube 播放可以吗？+
完全可以。yt-dlp --skip-download --write-subs --sub-langs en,zh-Hans --write-auto-subs --write-info-json 只拿字幕 + 元数据（含 video_id），不下载视频。入库时存 YouTube URL 而不是本地路径。前端结果点击直接跳转 https://youtu.be/{video_id}?t={start_seconds}。这种 hybrid 用法很值得 —— 本地存电影 + 在线搜 YouTube 字幕同一界面。
QSQLite FTS5 和 Meilisearch 选哪个？怎么知道该升级了？+
3 个信号该上 Meilisearch：(1) 库膨胀到 50w+ 行字幕、单次搜索 >200ms 卡顿；(2) 想要 typo tolerance（搜错单词也命中）；(3) 想要 faceted search 左侧 sidebar 自动统计各分类计数。其他场景 SQLite 完胜（部署零成本、无 daemon、备份 = cp 一个文件）。从 SQLite 迁 Meili 写 100 行 Python 半天工作量，schema 几乎一致。
Q维护成本怎么样？以后会不会变成屎山没人能改？+
维护成本极低，因为：(1) 整个工具就一个 Python 文件 + 一个 HTML 文件，几百行；(2) 所有依赖（SQLite / FastAPI / pysubs2 / jieba）都是 5-10 年稳定项目、API 几乎不变；(3) 没有数据库迁移问题（SQLite 单文件、schema 加列直接 ALTER）。最大风险是 Whisper / Meilisearch 大版本升级，但你只用基本 API、影响有限。建议每 6 个月升一次依赖、年底备份一次 subsearch.db 文件即可。
